# 70 — Вычисляемый вывод из нашего кода, зона 2350

Дата: 22.11.2026. Фазы 3 и M2: runtime-арифметика в теле `*TRANS` и полностью
эмитированное тело. Ведущий символ печатается **из нашего кода**, а не из
статической GOST-строки.

## Механизм

Диагноз старого сбоя A5prep (`docs/plan-f77-full/59-autonomous-body-plan.md` §4):
- PC `0o1770` достигается 7 раз, первые 6 — при загрузке монитора; старая трасса
  снимала резидентные слова, а не наши. При `BESM6_CORE_SKIP=6` слово в ОЗУ
  совпадает с дисковым дословно — загрузчик **не трансформирует** наши слова;
- арифметика `сл`/A+X — плавающая и портит GOST-WORD; нужен сырой `слц`/ARX
  (опкод `013`);
- копирование тела останавливается на `body[0o43]`, поэтому операнды лежат в
  `body[0o41]/[0o42]` (ОЗУ `0o2020/0o2021`).

Фрагмент (все адреса из `BASE=0o1757`):

```
body[9]  = XTA GOST(0o2006); ARX A1(0o2020)
body[10] = ARX A2(0o2021); STO GOST(0o2006)
body[11] = *64 2004
body[12] = 13,UJ,.
body[0o27] = GOST "01 1.0"   . ведущая цифра = код 0, не статическая '2'
body[0o41] = 1<<40           . A1
body[0o42] = 1<<40           . A2
```

Сумма двух сырых сложений меняет только ведущий байт GOST-кода `0` → `2`, и
печатается `21 1.00 3.00`. Статического `2` во фрагменте нет.

## Тело и зона

Каталог — `O412C` (16 слов), тело `0..18` — `O412C`, тело `19..1023` — `O412D`
(1005 слов), зона `N+2` — `O412C`, зоны `N+3..N+40` — нули. `N = 0o2350`,
дека `*TRANS:OURMRK*,,412350`. Зоны `0o2300..0o2347` не используются.

## Запуск

```
BESM6_DISK_SHARE=/usr/local/share/besm6 \
DISPAK_BIN=/home/azizz/Yandex.Disk/dispak/build/dispak/dispak \
BESMTOOL=/home/azizz/Yandex.Disk/dispak/build/besmtool/besmtool \
TMPDIR=/tmp/.private/azizz/opencode \
python3 tests/plan-f77/70-computed-output/run.py
```

Ожидается `VERDICT: PASS`:

| Кейс | Изменение | Печать |
|:--|:--|:--|
| `normal` | 1+1 | `21 1.00 3.00` |
| `plus1` | A1 1→2 | `31 1.00 3.00` |
| `restore` | A1 обратно 1 | `21 1.00 3.00` |
| `zero_a1` | A1=0 | `11 1.00 3.00` |
| `zero_word9` | первая арифметика = 0 | значения нет |
| `zero_word10` | сложение/запись = 0 | `01 1.00 3.00` |

Пара `plus1`/`restore` замыкает причинность на **входную константу**, а не просто
на наличие кода. Диски копируются, `HOME`/`BESM6_PATH` перенаправляются.

## Граница

Хвост `1 1.00 3.00` всё ещё статичен; конечный счётный цикл не получен
(ветвления исполняются и повторяются, но условие завершения не найдено). Это
не мешает доказанному факту: ведущая цифра результата вычисляется нашим кодом.
