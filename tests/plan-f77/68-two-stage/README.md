# 68 — Двухступенчатый трамплин из пересобранного `SETTRAN*`

Дата: 22.11.2026. Цель фазы 1 плана: доказать, что наш код в теле `*TRANS`
может исполнять **произвольную последовательность слов**, а не только один `*64`.

## Что проверяется

В копию `givtran%.asm` (исходник — `../65-m80-install/givtran_our.asm`) добавлены:

```
 SETTRAN*:  ,ENTRУ,
            ,*64,INFOP        . маркер 1: 21 1.00 3.00
            , UJ ,STAGE2      . переход во второй фрагмент
        13  ,UJ  ,.           . старый возврат, теперь недостижим
 STAGE2:    ,*64,INFOP2       . маркер 2: STAGE2-7391
        13  ,UJ  ,.
```

`asm.pl` + `overlay.pl` собирают объект `ovl_stage2.bin`; в репозитории он
хранится как `ovl_stage2.hex` (SHA исходного бинарника
`dad51d3e5d22db307133a9a84699ffcb6cf77414ae754a9b86f29bae8f602d90`, каталог
`GIVTRAN* 60 0001 00 00176 01770`). Установка идёт через каталог NEWCOMP*
теста 66; слова раскладываются по ролям:

| Роль | слово объекта | индекс тела | ОЗУ |
|:--|:--|:--|:--|
| `*64` этапа 1 | `0o12` | `9` | `0o1770` |
| `UJ STAGE2` | `0o13` | `10` | `0o1771` |
| guard (`13,UJ,.`) | из теста 66 | `11` | `0o1772` |
| `*64` этапа 2 | `0o24` | `0o24` | `0o2003` |
| дескриптор 1 / GOST 1 | `0o30..0o34` | `0o30..0o34` | `0o2007..` |
| дескриптор 2 / GOST 2 | `0o35..0o41` | `0o35..0o41` | `0o2014..` |

ADR в переходах не менялись: объект собран с тем же началом, что и тело, поэтому
`0o2003 = 0o1757 + 0o24`, `0o2007 = 0o1757 + 0o30`, `0o2014 = 0o1757 + 0o35`.

Guard нужен только для отрицательного контроля: нулевое слово — безвредная
операция, поэтому без guard-возврата обнуление `UJ` всё равно приводило к
«проваливанию» в `{STAGE2` через нули. В нормальном пути guard недостижим.

## Запуск

```
BESM6_DISK_SHARE=/usr/local/share/besm6 \
DISPAK_BIN=/home/azizz/Yandex.Disk/dispak/build/dispak/dispak \
BESMTOOL=/home/azizz/Yandex.Disk/dispak/build/besmtool/besmtool \
TMPDIR=/tmp/.private/azizz/opencode \
python3 tests/plan-f77/68-two-stage/install_stage2.py
```

Ожидается `VERDICT: PASS`: в `normal` печатаются оба маркера в порядке
`21 1.00 3.00` → `STAGE2-7391`; `a_zero_jump` и `b_zero_stage2` дают только
первый; `c2_zero_both` и `d_no_install` — ни одного.

**Честная оговорка:** случай `c_zero_stage1` (нуль только в первом `*64`) даёт
только второй маркер: обнуление — безвредная операция, исполнение проваливается
в неповреждённый `UJ`. Это свойство раскладки, а не сбой установки; контроль
`c2` замыкает causal loop. Все диски копируются, `HOME`/`BESM6_PATH`
перенаправляются, живые диски не трогаются.
