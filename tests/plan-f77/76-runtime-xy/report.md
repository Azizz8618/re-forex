# Limit-lifting step 2: X/Y computed at RUNTIME from structured IR tokens

Дата: 22.11.2026. Статус: **PASS**.

## 0. Что доказано

Значения `X` и `Y` печатаемой строки можно вычислить **исполняемыми словами
БЭСМ-6 в момент запуска**, а не сворачивать в GOST-слова на этапе эмиссии
(как это делает текущий тест 74). Исходные данные приходят из структурированного
потока токенов (интерфейс ниже); в GOST-словах до запуска стоят **нулевые**
цифровые байты, а ненулевые цифры появляются только после того, как наши
инструкции ARX (опкод 013, `слц`) складывают веса из ячеек данных.

Механизм установки заимствован у теста 72 без изменений: каталог/тело/N+2
в зону `0o2350`, дека `*TRANS:OURMRK*,,412350`, цепочка `N` от границы
DO сохранена. Все диски — копии, `HOME`/`BESM6_PATH` перенаправлены; правок
репозитория, git-записей, живых дисков/tmux и C-патчей dispak нет.

## 1. Интерфейс структурированных токенов

Файл `token_interface.py`. Токен — тройка `(kind, op, arg)`, выдаваемая в порядке
вычисления стековой машиной:

| kind | op | arg | смысл |
|:--|:--|:--|:--|
| `CONST` | `None` | `float` | положить числовой литерал |
| `VAR` | `None` | `str` | положить значение переменной |
| `STORE` | `str` | `None` | снять значение в переменную |
| `ADD` | `None` | `None` | снять два значения, положить сумму |

Каноническая программа для `X=1.0; Y=X+2.0`:

```python
TOKENS_X1_ADD2 = [
    ('CONST', None, 1.0),       # X = 1.0
    ('STORE', 'X', None),
    ('VAR',   None, 'X'),       # Y = X + 2.0
    ('CONST', None, 2.0),
    ('ADD',   None, None),
    ('STORE', 'Y', None),
]
# или tokens_for(x_value, add_value)
```

Интерпретатор принимает только `Y = X + <литерал>`: это позволяет разложить
вес `Y` на две независимые части (вклад `X` и вклад приращения), которые
складываются **разными инструкциями ARX** в момент исполнения. Lead подключает
реальные записи 777005, заменив список токенов; `runtime_xy.py` не зависит от
FRONT.FTN и её не редактирует.

Ограничение интерпретатора: одна цифра на `X` и одна на `Y` (как и в тесте 74,
формат `F10.2` с одной значащей цифрой в целой части для этих gate-точек).

## 2. Размещение слов ( слово-таблица )

Пример для `X=2, add=2 → Y=4`, граница `B=6` (ведущие цифры `21`). Все адреса
выводятся из `BASE=0o1757`; `body[k]` копируется в ОЗУ `BASE+k`. Все слова
лежат в окне копирования `body[0..0o43]`.

| body | RAM | octal word | GOST-байты (dec) | роль |
|--:|:--|:--|:--|:--|
| 9  | 01770 | `0010200600132020` | — | `XTA 2006 / ARX 2020` (N-tens) |
| 10 | 01771 | `0013202100002006` | — | `ARX 2021 / STO 2006` (N-units, запись слова 1) |
| 11 | 01772 | `0010200600132022` | — | `XTA 2006 / ARX 2022` (вес X в байт 3 слова 1) |
| 12 | 01773 | `0000200600102007` | — | `STO 2006 / XTA 2007` |
| 13 | 01774 | `0013201100132012` | — | `ARX 2011 / ARX 2012` (X + приращение в байт 2 слова 2) |
| 14 | 01775 | `0000200700002007` | — | `STO 2007 / STO 2007` (избыточная запись безопасна) |
| 15 | 01776 | `0064200402200000` | — | `*64 2004` (печать через дескриптор) |
| 16 | 01777 | `6700000002200000` | — | `uj 0(15)` (возврат) |
| 0o25 | 02004 | `0000200600002006` | — | дескриптор (проверен тестом 70) |
| 0o26 | 02005 | `0001000040000000` | — | дескриптор |
| **0o27** | **02006** | `0000041700007000` | `[0,1,15,0,14,0]` | GOST слово 1 = `01 0.0`, **байт3=0 (X посеян нулём)** |
| **0o30** | **02007** | `0000740003400000` | `[0,15,0,14,0,0]` | GOST слово 2 = `0 0.00`, **байт2=0 (Y посеян нулём)** |
| 0o31 | 02010 | `4620741703607417` | — | GOST-хвост / EOF (проверен) |
| 0o32 | 02011 | `0000000200000000` | `[0,0,2,0,0,0]` | данные: `XW2 = X<<24` (вклад X в Y) |
| 0o33 | 02012 | `0000000200000000` | `[0,0,2,0,0,0]` | данные: `AW2 = add<<24` (вклад приращения в Y) |
| 0o41 | 02020 | `0040000000000000` | `[2,0,0,0,0,0]` | данные: `NT = tens<<40` (N-tens) |
| 0o42 | 02021 | `0000000000000000` | `[0,0,0,0,0,0]` | данные: `NU = (units-1)<<32` (для B=6 равно 0) |
| 0o43 | 02022 | `0000000000400000` | `[0,0,0,2,0,0]` | данные: `XW1 = X<<16` (вес X в слове 1) |

Веса — сложения по байтам без переноса между байтами (значения ≤ 9), поэтому
`ARX` меняет только целевой байт. Для `B=5` меняются только `NT=1`, `NU=4`,
передние цифры становятся `15`; логика `N` полностью унаследована от теста 72.

## 3. Доказательство RUNTIME: до прогона / после прогона

До запуска `besmtool dump 2048 --start=02351 --length=1` читает **установленную
копию диска** и показывает нулевые цифровые байты (это не folding на этапе
эмиссии: в слове физически лежит 0, а не `1`/`3`):

```
PRE-RUN installed GOST words (from disk copy):
  body[0o27] RAM 2006 = 0000041700007000 bytes(dec)=[0, 1, 15, 0, 14, 0]
  body[0o30] RAM 2007 = 0000740003400000 bytes(dec)=[0, 15, 0, 14, 0, 0]
  X digit byte (body[0o27] byte3) = 0
  Y digit byte (body[0o30] byte2) = 0
```

После прогона консоль (`final/evidence/x2_add2.txt`) печатает:

```
           *TRANS:OURMRK*,,412350
 21 2.00 4.00
 ...
 КОНЕЦ ЗАДАЧИ
```

То есть байт3 слова 02006 стал `2`, байт2 слова 02007 стал `4` — **исключительно
исполняемыми ARX-инструкциями между загрузкой и `*64`**. (Сопутствующий дамп
`*70 / ОШИБКА МД ЭВМ` присутствует и в эталонном тесте 72, это штатный хвост.)

### MTR-трасса (дополнительное доказательство)

С `BESM6_DD_DEBUG=1 BESM6_MTR_LO=01770 BESM6_MTR_HI=01777 BESM6_MTR_N=400
BESM6_MTR_SKIP=6` получен чистый блок (`final/evidence/mtrace_golden.txt`,
полный шумовый лог — `mtrace_focused.txt`). `AU` — накопитель **до** команды:

```
MTR 01770L xta 2006(0) AU=0000000001146     ; загрузка GOST слова 1 (посев)
MTR 01770R arx 2020(0) AU=0041700007000     ; + N-tens  (0 -> 2)
MTR 01771L arx 2021(0) AU=40041700007000    ; + N-units (для B=6 вес 0)
MTR 01771R atx 2006(0) AU=40041700007000    ; запись слова 1
MTR 01772L xta 2006(0) AU=40041700007000    ; перезагрузка слова 1
MTR 01772R arx 2022(0) AU=40041700007000    ; + X (байт3: 0 -> 2)
MTR 01773L atx 2006(0) AU=40041700407000    ; запись X в слово 1
MTR 01773R xta 2007(0) AU=40041700407000    ; загрузка GOST слова 2 (посев)
MTR 01774L arx 2011(0) AU=0740003400000     ; + X  (байт2: 0 -> 2)
MTR 01774R arx 2012(0) AU=0740203400000     ; + add (байт2: 2 -> 4)
MTR 01775L atx 2007(0) AU=0740403400000     ; запись Y в слово 2
MTR 01776L *64  2004(0) AU=0740403400000    ; печать
MTR 01777L uj   0(15) AU=0740403400000      ; возврат
```

Видно, что все `xta/arx/atx` по адресам 2006/2007/2020/2021/2022/2011/2012
исполняются, а накопитель меняется от посеянного нуля к готовым цифрам.

## 4. A/B таблица

Все кейсы: `end_of_task=True`, `pre_x=0`, `pre_y=0`, `rc=0`.

| кейс | токены | обнулённое слово | печать | ожидалось | результат |
|:--|:--|:--|:--|:--|:--|
| `x1_add2`     | X=1, add=2 | —         | `21 1.00 3.00` | `21 1.00 3.00` | OK |
| `x2_add2`     | X=2, add=2 | —         | `21 2.00 4.00` | `21 2.00 4.00` | OK |
| `x2_add3`     | X=2, add=3 | —         | `21 2.00 5.00` | `21 2.00 5.00` | OK |
| `x1_add2_r`   | X=1, add=2 | —         | `21 1.00 3.00` | `21 1.00 3.00` | OK (restore) |
| `zero_x_code` | X=2, add=2 | body[11] | `21 0.00 4.00` | `21 0.00 4.00` | OK |
| `zero_y_code` | X=2, add=2 | body[13] | `21 2.00 0.00` | `21 2.00 0.00` | OK |

Причинность замкнута:
- смена **одного токена** меняет печать: `X 1→2` даёт `…1.00 3.00 → …2.00 4.00`,
  `add 2→3` даёт `…2.00 4.00 → …2.00 5.00`; restore возвращает исходное;
- обнуление **одного runtime-инструкционного слова** убирает только
  соответствующую цифру: `body[11]` (ARX веса X) → `X 2→0`, `body[13]`
  (ARX X+add в слово 2) → `Y 4→0`.

## 5. Граница и честность

* Это не общий Fortran-77 компилятор: печатаются одна цифра
  `X` и одна цифра `Y`, а ведущие `NN` по-прежнему берутся из проверенной
  bound-цепочки теста 72 (`B=6→21`, `B=5→15`).
* Числовое значение веса (например, `X=2`) вычисляется хост-интерпретатором
  токенов — это неизбежно, так как токены задают конкретные литералы. Суть
  доказательства в другом: **GOST-байт до запуска равен нулю и становится
  ненулевым только после исполнения наших BESM-6 ARX-слов**, чего тест 74 не
  делает (там цифра `1`/`3` запекается в GOST-слово на эмиссии).
* Используются только проверенные опкоды `XTA/ARX/STO/*64/UJ`; плавающая `сл`
  не применяется (`docs/corrections.md`).
