# 66 — Наш код исполняется через `*TRANS` (положительный результат)

Дата: 22.11.2026. Исправляет вывод теста 65 и `docs/61` §21: каталожный путь
**не закрыт**, просто у `*TRANS` другой загрузчик, чем у оверлеев монитора.

## Механизм

Существуют два независимых загрузчика:

| | оверлей монитора | NEWCOMP* (компилятор 4.12) |
|:--|:--|:--|
| вызов | стартовый OCATALOG / `sv_load` / Э70 | `*TRANS:name,,41/N` (компилятор 4.12) |
| каталог | диск 2048 зона `0o250` | 2-словные пары в зоне N |
| тело | word0 = длина, word1 = имя, код с word 2 | DMS-шапка, f0=`0o1760`, stub `уиа 1760(M16)` |

`GIVTRAN*/SETTRAN*/TTABLE*/STACOMP*/NEWCOMP*` — **резидентные** модули: их
код собирается линкером при загрузке из LINK-таблицы зоны `0o200`, и на диске
2048 нет тела с именем `GIVTRAN*`. Поэтому установка пересобранного
`overlay.pl`-объекта в зоны `0o252/0o354/0o204` не влияет на `*TRANS`
(отрицательный результат теста 65 корректен, но не является концом пути).

Рабочая установка: свежий 4.12-каталог в зоне `N=0o1744` копии диска 2048,
тело в `N+1` со словами из пересобранного `givtran%.asm`, живые слова оверлея
`0o1552` в `N+2`, нули в `N+3..N+40`. Дека:
`*TRANS:OURMRK*,,411744` + `DIS 41(2048)^`.

Пересобранный объект (см. `tests/plan-f77/65-m80-install/givtran_our.asm`):
`asm.pl` + `overlay.pl` → `GIVTRAN* 60 0001 00 00166 01770`, SHA
`98e1352d9c83d296f979dbe7f8cdf49c79eeced1a7407166eb0668b56b05a23c`.
Его слова `*64 2004`, дескриптор и GOST `21 1.00 3.00` переносятся в тело
**без изменения адресных полей**: отображение `body[k] → ОЗУ 0o1757+k`
само попадает в `0o1770`/`0o2004`/`0o2006`.

## Граница результата

Доказано, что `*TRANS` исполняет **наш код** (печать статического GOST-маркера
из пересобранного `SETTRAN*`). Не доказано, что это уже полноценный компилятор:
тело по-прежнему использует живые слова зоны `N+2` (менеджера оверлеев), а
арифметический вывод пока статичен. Следующий шаг — заменить эти слова нашими
и подключить кодогенератор `src/newcomp/*`.
