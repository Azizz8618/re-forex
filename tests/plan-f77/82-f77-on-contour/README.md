# 82 — Реальный F77-дек через наш `*TRANS`-контур

Дата: 22.11.2026. F77 track F3: берём настоящий дек `tests/f77/suite/base.b6`,
прогоняем его F77PREP/FRONT и компилируем арифметическое ядро **нашим** кодом зоны `2350`.

## Что доказано

- F77PREP pass1 реально исполнен на копиях; исполняемые строки помечены rule 0
  (keep), lowering добавляет только DO-guard.
- FRONT.FTN выдаёт 5 записей `777005` (`LIT 0`, `LIT 100`, `VAR X`, `LIT 200`, `BIN+`);
  граница DO = 6 извлекается из IR и даёт ведущие цифры `21`.
- Установка: каталог `0o2350`, тело `0o2351`, N+2 `0o2352`, нули дальше; GOST-слова
  записаны с нулевыми цифрами и наполняются нашими ARX-инструкциями при прогоне.

Результат: `21 01.00 03.00` — численно совпадает с gold `   21      1.00      3.00`
(отличается только фиксированная ширина/ведущие нули). A/B: обнуление дескриптора,
кода `body[13]` или данных `body[0o43]` ломает/меняет печать; восстановление
возвращает её. Системный `*forex` в контроле даёт gold байт-в-байт.

## Запуск

```
TMPDIR=/tmp/.private/azizz/opencode PYTHONDONTWRITEBYTECODE=1 \
python3 tests/plan-f77/82-f77-on-contour/prove_contour.py
```

Ожидается `VERDICT: PASS`. Диски копируются, HOME/BESM6_PATH перенаправляются.

## Граница

Наш контур компилирует только арифметическое подмножество (`X/Y/N` из IR): DO-цикл,
FORMAT и F77LIBR-вывод пока делает системный путь. Это не замена `*forex` для
всего BASE77, а доказанный стык F77 → IR → наш CODEGEN → печать.
