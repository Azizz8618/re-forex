# 73 — От Fortran-деки к печати через `*TRANS`

Дата: 22.11.2026. Финальный стык цепочки:

```
Fortran-дека BASE77
  -> FRONT.FTN (правило 32, счётный DO) -> IR 777002 ("DO 10 I=1,B")
  -> парсер границы B -> CODEGEN/EMIT (N3M35) -> слово stream
  -> тело зоны 0o2350 -> *TRANS:OURMRK*,,412350 -> напечатанное число
```

В отличие от теста 72, граница **не подставляется вручную**: она извлекается
из IR, который наш `FRONT.FTN` выдаёт для реального Fortran-исходника.

## Запуск

```
TMPDIR=/tmp/.private/azizz/opencode \
BESM6_DISK_SHARE=/usr/local/share/besm6 \
python3 tests/plan-f77/73-front-to-output/run.py
```

Скрипт для B=6 и B=5:
1. копирует каноническую деку и меняет карту `DO 10 I=1,6` → `DO 10 I=1,B`;
2. компилирует `FRONT.FTN` системным FOREX 2.02 на копиях (0 ERR), вызывает его
   и читает IR-записи `777001/777002`;
3. находит запись rule 32, собирает ASCII-поток 777002 и регуляркой достаёт B;
4. передаёт B в `codegen.stream` теста 72, ставит тело через `installer.make_case`
   на копию диска 2048, зона `0o2350`;
5. сверяет печать.

Ожидается:

| Исходник | IR | Печать |
|:--|:--|:--|
| `DO 10 I=1,6` | `777002 … "DO 10 I=1,6"` | `21 1.00 3.00` |
| `DO 10 I=1,5` | `777002 … "DO 10 I=1,5"` | `15 1.00 3.00` |

`VERDICT: PASS`. Диски копируются, `HOME`/`BESM6_PATH` перенаправляются.

## Честно о границе

Доказана **чувствительность конца цепочки к исходнику**: изменение карты Fortran
меняет IR, а IR меняет напечатанную цифру через наш CODEGEN. Но это пока не
полная семантическая компиляция: остальные карты (присваивания, FORMAT, X/Y)
не разбираются в machine code — тело 19..1023 по-прежнему эмитируется из
`O412D` (значения исторически посеяны из 4.12). Для честного утверждения
«наш компилятор компилирует BASE77» нужно ещё перенести в CODEGEN разбор
присваиваний/FORMAT вместо предзаданного хвоста. Сейчас корректная формулировка:
«наш фронт-энд и наш кодогенератор управляют результатом компиляции по границе
цикла, остальное тело — наш эмиттер со значениями 4.12».
