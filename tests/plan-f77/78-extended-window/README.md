# 78 — Расширенное окно копирования тела

Дата: 22.11.2026. Проверка вывода `docs/64-body-copy-window.md`: утверждение
«копирование останавливается на `body[0o43]`» было артефактом чтения наивных
адресов. Тело копируется и дальше, но с кусочным сдвигом базы.

| Диапазон `body` | ОЗУ |
|:--|:--|
| `1..0o43` | `0o1757 + k` |
| `0o44` | не копируется, дескриптор `f0=0o1551`, трогать нельзя |
| `0o45` | `0o2216` (реплицируется) |
| `0o46..0o222` | `0o1773 + k` (сдвиг `+0o14`) |
| `0o223` | не копируется, дескриптор `f0=0o0357` |
| `0o224..0o602` | `0o1777 + k` (сдвиг `+0o20`) |
| `0o603` | не копируется, дескриптор `f0=0o0432` |
| `0o604..` | `0o2015 + k` (сдвиг `+0o36`) |

## Запуск

```
TMPDIR=/tmp/.private/azizz/opencode python3 tests/plan-f77/78-extended-window/run.py
```

Тест меняет `body[9]` на чтение из `body[0o46]` (ОЗУ `0o2041`) и кладёт туда
веса `3`, `5`, `0`. Ожидается `VERDICT: PASS` и печать `41`, `61`, `11`
соответственно; дамп ядра содержит слово по `0o2041`. Все кейсы заканчиваются
`КОНЕЦ ЗАДАЧИ`.

## Оговорка

Расширенная область пересекается с исполняемыми словами резидентного 4.12
(MTR показывает PC `0o2041`). Это не свободная память: перед размещением там
кода/данных компилятора нужно проверять A/B и отсутствие повреждения резидентного
пути. Чистая непересекающаяся область остаётся `body[1..0o43]`.
