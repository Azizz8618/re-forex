# FOREX 5.00 — зафиксированные границы изделия

Этот документ фиксирует то, что **не входит** в produkt, с доказательствами,
чтобы границы не переоткрывались заново.

## 1. Память контура: 58 слов — жёсткий предел

- Каталог зоны `N` слово 3 содержит дескриптор `0o400402757101760`
  (f3=`0o400`, f2=`0o4027`, f1=`0o5710`, f0=`0o1760`). DD/MTR‑трасса
  подтверждает: загрузчик читает ровно зоны 2350..2353, в ОЗУ попадают
  58 слов `0o30114..0o30205` (`docs/101`).
- Перебор 24 значений полей дескриптора: любое изменение даёт либо
  `НЕТ РАЗДЕЛА`, либо чтение до конца диска с зависанием. MMU здесь ни при чём:
  `0o31000` лежит в той же доступной странице `0o14`.
- Следствие: канонический контур использует 57 из 58 слов. Увеличение
  фундаментально требует другого дескриптора загрузчика, а не «добавления зоны».

## 2. DSQRT — ограниченно реализован (ревизия от 24.11.2026)

Первоначальный вывод (нет double FPU; софтверная двойная точность требует
>100 команд и не помещается в 58 слов; зона `N+4` недоступна, `docs/95`)
**опровергнут документом `docs/141`**: `DSQRT(9.0D0)→21 -0003.00`,
`DSQRT(16.0D0)→-0004.00` под авторитетной SIMH при байтово том же образе;
PATCH `L_HALF 0.5→0.6` даёт `-0003.06`; SQRT/ABS/MOD/T1 без регрессии.
Механизм — двухсловный machine‑код (ACC+RMR): 6 итераций Ньютона на
одинарном FPU как затравка, затем `atx`+`yta 24` дают точные младшие 40 бит
произведения; `hi+lo=1.41421356237309514547` для `2.0D0` — ноль ошибки
против IEEE double на 20 цифрах.

Оставшиеся ограничения DSQRT (`docs/141`): печать остаётся `F4.2` (лишние
цифры внутренние); `D`‑экспонента разбирается только без знака; произвольные
DP‑литералы не разворачиваются в полную 80‑битную мантиссу (для точно
представимых `9.0D0`/`16.0D0` лексер даёт честное двухсловное
`hi=f32(x), lo=0`). Полная двухсловная арифметика (+,×,÷) и печать DP —
открытые задачи расширения, не границы «невозможного».

## 3. Дескрипторный READ(`u,fmt`) — невозможен

- `э52` векторится в `0o0552` (`0500+052`), а не в `0o0522` (`docs/92`).
- Решающая ветка `0o5162 R`: бит привилегии задачи
  `M[0o72451+0o41] & 0o100000 == 0` → `по 5164` → `ЗАПРЕЩ.ЭКСТРАКОД`.
- `э60` → `МАССИВ НЕ СУЩ-Т.`, `э70` → переполнение таблицы описаний
  (`docs/91`). Патч только бита привилегии на копии ошибку не снял (`docs/94`).
- Контекст ввода создаётся мониторным оверлеем `INPUT*`, который `*TRANS` в
  задачу контура не устанавливает; легальная установка из user mode циклична.
- Работает только буквальный/числовой ввод из сырого буфера карты `0o64012`
  через `utc 60000` + `xta 4012` (`docs/93/94`). Это **не** `READ(u,fmt)`.

Ревизия от 24.11.2026 (`docs/140`): рабочий путь ввода **доказан** под
авторитетной SIMH — 41‑словный машинный сканер в теле контура находит
data‑карту в буфере `0o64000+`, декодирует её цифры штатной цепочкой
B1/B5 и записывает значение в ячейку переменной до нетронутого LEX/parser:
`12.34 → 21 -0012.34`, `56.78 → -0056.78` (только data‑карта), PATCH →
`-0013.57`, restore → `-0012.34`, все `КОНЕЦ ЗАДАЧИ`. Дескрипторный
`READ(u,fmt)` остаётся невозможным; этот путь — его замена в границах
изделия.

## 4. Резидентные FT*002/003/571 — недоступны

15‑битная адресация работает (LONG `uj 77776` даёт M33=`0o77776`, усечения
нет), но MMU SIMH блокирует страницы `0o77776` и `0o74012`:
`Число/Команда в чужом листе` (`docs/88`). Позитивный контроль
`utc 2000 / arx 6` читает `0o2006` без трапа. Готовый float→GOST‑конвертер
рантайма поэтому недоступен; конвертер написан machine‑кодом в контуре.

## 5. Экстракод `*50` — аварийно завершается из контура

Все опробованные типы (0/2/7) под SIMH из зоны 2350 завершаются ошибкой;
обработчик ОС по `0o574` не возвращается (`docs/89/95`). Приёмочные computation
идут через FPU `a/x`, `a+x`, `a*x`, `avx`, `asx`, `aax`.

## 6. Полнота компиляции — ограничена

Канонический контур декодирует **arg1 записи `777005`** (4 цифры LIT, ×100),
выполняет ABS/SQRT/MOD и печатает результат (`docs/104/105`). Не реализованы:

- разбор `777001..777004` (IR Shift/Add/Compare/etc.);
- эмиттеры `777010` (READ) и `777011` (FORMAT) — в репозитории отсутствуют,
  известны только по ссылке в `docs/77`;
- DO‑guard F77PREP, тело цикла, вызовы F77LIBR;
- знак, пришедший прямо из карты (знак берётся из бита 40 machine‑float');
- отрицательный `arg1` FRONT не выдаёт: минус — отдельный токен операции,
  `SC=VAL*100/FRAC` неотрицательно (`docs/105` §3).

## 7. Исторические PASS не являются приёмкой

`docs/83/84/86` (baseline / I/O / FUNCTION) доказывали только, что печать идёт
из нашего контура; значения `X`, `Y`, `F(X)` подставлялись хостовым Python
(`codegen_wide.emit` → `expr_ir.digits`). По правилу «всё считается на БЭСМ‑6,
никакого питона» они приёмкой не являются (`docs/corrections.md`).

## 8. Что НЕ является ограничением изделия

- Системный ФОРЭКС 2.02 на диске используется только как **build‑компилятор**;
  в целевом деке его нет.
- `*perso` разрешён для вспомогательных программ (как в `pascal-re`), но не
  подменяет основной транслятор.
- Символ `,CONT`, нумерация зон и physical host‑файл не совпадают с OS‑меткой
  тома: в картах пишется `2048` (`docs/80`).
