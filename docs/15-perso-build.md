# 15 — Сборка и запись библиотеки PERSO ФОРЭКС+рантайм (зона `0o2300` тома 2348)

Отчёт о сборке персональной библиотеки Монитора-80 («Дубна») с
реконструированным компилятором ФОРЭКС и рантаймом, и записи её в **рабочую
копию** тома 2348. Формат записи — `docs/14-perso-write.md`.

## 1. Что сделано

1. Собран образ PERSO `build/FOREX_PERSO_2300.bin` — каталог (2 зоны) + тела
   DMS-модулей (3 зоны), итого **5 зон = 30 720 байт = 5120 слов**.
2. Образ записан в рабочую копию `work/2348` с зоны `0o2300` (восьмеричной)
   = **1216 десятичной** (аргумент `besmtool` — десятичный).
3. **Ключевое исправление:** в записи каталога восстановлен *transfer vector*
   (адрес тела модуля). Без него Монитор-80 печатал `ИСПОРЧЕНЫ ПОДПРОГРАММЫ`
   для всех модулей, кроме первого.
4. Три модуля, для которых есть только МАДЛЕН-исходники (`DATAPR*`, `GIV/PG`,
   `TAK/PG`), **собраны в настоящие DMS-объекты** средствами `*assembler`
   Монитора-80 через `dispak`, а не являются заглушками. `OCTTDEC` использует
   **байт-точный скомпилированный DMS-модуль** с ленты `monsys.9`
   (`0o37100..0o37137`, `build/RUNTIME_OCTTDEC_ETALON.words`).
5. Проверка на Мониторе-80 (`*call plcatalog:402300`) показывает **все 9
   модулей без единого предупреждения**; `*to perso` roundtrip успешно
   выгружает `FOREX*` обратно в отдельную библиотеку.
6. **Исправление 19.11.2026:** PERSO-копия `OCTTDEC` каталогизируется как
   `OCTTDE*`. Постоянная библиотека на диске 2048 уже содержит `OCTTDEC`
   (загружается по адресу `0o3614`), и дубликат имени в PERSO вызывал
   `ИСПОРЧЕНА ПОДПРОГРАММА` при загрузке скомпилированной задачи. Тело модуля
   байт-точно; изменено только имя каталога и head-секции. Подробности —
   `docs/16-glissade-run.md`.

## 2. Точный формат записи каталога (обратная инженерия)

Разобраны реальные библиотеки: `/*PASCAL` на `~/.besm6/2348` зона `0o2000`,
`/*PASCAL` на `/usr/local/share/besm6/2148` зона `0o440`, `siprod.bin`
`re-siprod`, `GOSTLIB` на 2348 зона `0o2560`. Формула проверена на 122 из 123
записей `/*PASCAL` (единственное расхождение — дублирующееся имя в каталоге).

Каждая запись каталога — 48-битное слово:

```
биты 47..36  f3 = (слово в зоне) + 0o2010        -- адрес тела (transfer vector)
биты 35..24  f2 = (зона в библиотеке + 0o40)*0o100 + (L // 512)
биты 23..12  f1 = (L % 512) * 8                  -- длина загрузки L в словах
биты 11..0   f0 =overlay / смещение точки входа
```

`PLCATALOG` печатает `f2/f3` как «зона блок длина», например
`R/WI 014 07 00056`. Именно эта пара полей и есть недостающее
«информационное слово»: раньше вместо неё записывалась дата, из-за чего
загрузчик не находил тела модулей 2..N и печатал `ИСПОРЧЕНЫ ПОДПРОГРАММЫ`.

Длина `L = cmd + const + bss`. Для модулей >511 слов старшие биты `L//512`
заходят в младшие 3 бита `f2` (проверено: `XREF L=554 → f2=0o5301, f1=0o0520`;
`SPAUD L=1643 → f2=0o5303, f1=0o1530`).

Каталог: слово 0 = `0o2105000` (взято из GOSTLIB), слово 1 = 0, записи
парами со слова 2, завершатель — пустое слово + слово из всех единиц
`0o7777777777777777`. Тела начинаются со зоны Z+2, выровнены по 32 словам.

## 3. Состав библиотеки

| Каталожное имя | Источник тела | Длина L | Слово (от начала образа) | Примечание |
|---|---|---:|---:|---|
| `FOREX*`   | `build/CORE_ROOT.words` (`0o510300..0o510437`)       | 96   | 2048 (`0o4000`)  | дамп ленты |
| `LO*SYN`   | `build/LO_SYN.words` (`0o241500`, 1024 слова)        | 1024 | 2176 (`0o4200`)  | дамп ленты |
| `LO*GEN`   | `build/LO_GEN.words` (`0o277500`, 1024 слова)        | 1024 | 3232 (`0o6240`)  | дамп ленты |
| `FORMAT`   | `build/RUNTIME_FORMAT.words` (`0o510443`, 61 слово)  | 61   | 4288 (`0o10300`) | дамп ленты |
| `FORTLIBR` | `build/RUNTIME_FORTLIBR.words` (`0o510543`, 69 слов) | 69   | 4384 (`0o10440`) | дамп ленты |
| `DATAPR*`  | `besmmons/system1.txt:7645-7733` → `*assembler`      | 47   | 4480 (`0o10600`) | настоящий DMS |
| `OCTTDE*`  | `monsys.9` `0o37100..0o37137`, байт-точный дамп      | 27   | 4544 (`0o10700`) | DMS OCTTDEC, псевдоним каталога |
| `GIV/PG`   | `libra211.l21:16780-16836` → `*assembler`            | 35   | 4576 (`0o10740`) | настоящий DMS |
| `TAK/PG`   | точка входа в `GIV/PG` (смещение `0o24`)             | —    | —                | запись-указатель |

Тела первых пяти модулей и `OCTTDE*` побайтово совпадают с дампами ленты;
тела трёх собраны Монитором-80 из авторитетных исходников Дубны
(`logs/perso_fix_assemble.txt`). `OCTTDE*` — тот же байт-точный модуль
`OCTTDEC`, но с именем каталога (и head-секции), отличающимся от системного
`OCTTDEC`, чтобы избежать конфликта имён при загрузке.

`0o2300..0o2304` изменены. `besmtool` хранит зоны в закодированном физическом
виде, поэтому корректно сравнивать **`besmtool dump --to-file` логических зон**,
а не сырые байты файла.

## 5. Проверка на Мониторе-80

Дека (`*call plcatalog` без предварительного `*perso` — `PLCATALOG` читает
каталог напрямую с диска):

```
шифр 419999ЗС5^
ОЗУ 32^
дис 40(2348)^
eeв1а3
*name catperso
*libra:23
*        disc:41(2048)/system,lcross
*        file:libra,402300,r
*call plcatalog:402300
*end file
```

Результат (`logs/perso_fix_plcatalog.txt`):

```
   FОRЕХ*       302 00  00140
   LО*SУN       302 04  02000
   LО*GЕN       303 05  02000
   FОRМАТ       304 06  00075
   FОRТLIВR     304 11  00105
   DАТАРR*      304 14  00057
   ОСТТDЕ*      304 16  00033
   GIV/РG       304 17  00043
   ТАК/РG   (GIV/РG  )  00024
```

**9 модулей, `ИСПОРЧЕНЫ ПОДПРОГРАММЫ` отсутствует.**

Дополнительно — `*to perso` roundtrip (`logs/perso_fix_roundtrip.txt`):
`*table:liblist(FOREX*)`, `*liblist:402300`, `*to perso:402400` →
`ДЛИНА LIBRARY 003 ЗОН`; выгруженная библиотека содержит `FOREX*` с cmd=96.

### Почему без `*perso`

`DATAPR*` — имя из постоянной библиотеки монитора (диск 2048, зоны `0125`,
`0200`, …). Карта `*perso:402300` вызывает конфликт имён и аварийно
завершает `PLCATALOG`; с `__DATAPRX` всё работало. Требуемое имя `DATAPR*`
сохранено, а проверка каталога идёт через прямое чтение (`*call plcatalog`),
что корректно для проверки каталога. Это не влияет на загружаемость модулей —
roundtrip через `*liblist`/`*to perso` подтверждён.

## 6. Воспроизведение

```bash
cd /tmp/.private/azizz/opencode/re-forex

# Полный сценарий: свежая копия, запись, siprod_lib, PLCATALOG, границы зон
tests/install-forex-perso.sh

# Парсер каталога

  --start=1216 --length=5 --to-file=/tmp/forex_perso.bin

# 9 имён в каталоге, 8 объектов (TAK/PG — точка входа в GIV/PG)
```
