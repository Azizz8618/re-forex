# 10 — Соглашения об именовании меток и констант в реконструированных МАДЛЕН-текстах ФОРЭКС

**Статус:** правила приняты для реконструкций `src/LO_SYN.mad`, `src/LO_GEN.mad`,
`src/FOREX_CORE.mad`, `src/FOREX_RUNTIME.mad`. Документ описывает, как
переименовывать *символические* метки, не затрагивая побайтовый образ слов.

**Связанные документы:** `docs/03-symbols.md` (37 обязательных символов),
`docs/04-register-conventions.md` (роли М1..М17), `docs/06-address-map.md`
(внешние абсолютные адреса), `docs/05-roundtrip.md` (побайтовая сверка).

---

## 1. Принципы

### 1.1. Имя отражает РОЛЬ, а не адрес

Метка называет **смысл ячейки/точки входа**, а не её номер. Запрещено
включать в имя адрес, номер слова или порядковый номер:
`L0021`, `W0532`, `WT0533`, `D00001`, `*00027` — это *автосгенерированные*
имена дампа, которые подлежат замене. (`check-labels.sh` прямо проверяет, что
в `src/*.mad` не осталось меток вида `W[0-9]{3,4}`, `WT[0-9]{3,4}`,
`D[0-9]{4,5}`.）

Правило: сначала по комментарию/xref устанавливается роль («установка
регистра», «выбор лексемы», «вывод строки»), затем подбирается имя.

### 1.2. Префиксы по подсистеме

| Префикс | Подсистема / роль | Типичный источник |
|---|---|---|
| `LEX_` | лексический анализ, выборка лексемы | `0o20151/0o20103` (Э20), `042510` |
| `SYN_` | синтаксический анализ (`LO*SYN`) | экстракоды Э65/Э66, таблица автомата |
| `CODE_` | генерация кода (`LO*GEN`) | `A+X`, `UTC`, запись в `*A*` |
| `OUT_` | вывод, печать (`PRINT8`, `WRITLIBR`) | `PRINT`, `FORTLIBR` |
| `FMT_` | форматирование, таблицы `FT*`/FORMAT | `77xxxB`, `UJ FT*/ATX 77xxxB` |
| `ERR_` | ошибки и диагностика | `ОШ. ТРАНСЛЯТОРА`, `ERROR` |
| `DATE_` | дата/время (`DATAPR*`) | `FUN 67B`, `DATE0..4`, `MARR` |
| `OCT_` | восьмеричные/десятичные преобразования (`OCTTDEC`) | `MASK15`, `OCT`, `DEC` |
| `PAGE_` | страницы/зоны/оверлеи | зоны 80/95, `0o22654`, `слова 1..1024` |
| `INIT_` | инициализация, entry-точки | `START:`, `INITFOR*`, `0o510303` |
| `LOAD_` | загрузка оверлеев | `LOADANGO`, `0o74022` |

Имя строится как `ПРЕФИКС_РОЛЬ` (например, `INIT_MOD_REG`), при необходимости
с уточнением: `FMT_OP_NAME`, `OCT_MASK_LOW`.

### 1.3. Суффиксы по управлению

| Суффикс | Значение |
|---|---|
| `_LOOP` | вход/тело цикла (`VLM`, `WTC`+`UZA` обратно) |
| `_EXIT` | выход из подпрограммы / переход вовне оверлея (`IJ`, `UJ` во внешний адрес) |
| `_RET` | возврат (`13,UJ,.`, `UJ 1(15)`) |
| `_NEXT` | переход к следующему элементу/итерации (`UTM`, `UZA` вперёд) |
| `_CHECK` | проверка условия/признака (`Э36 «втбрз»`, `ACX`, `ASN`+условие) |

Суффикс добавляется к имени роли: `LEX_NEXT`, `LEX_CHECK`, `DATE_LOOP`.

### 1.4. Язык и регистр

Имена — латиница, `UPPER_CASE`, разделитель `_`. Исключение сохраняются только
для **аутентичных внешних символов** корня (`ENTRY*`, `*A*`, `*DUMON*`,
`FLGEX*`, `FT*571`, `DATAPR*`, `ПP`) — они уже несут смысл и не переименовываются.

## 2. Правила для констант `,EQU,`

1. ALL_CAPS, слова разделены `_`.
2. Имя = роль (+ уточнение), **не** числовое значение.
3. Обязателен комментарий: роль + значение (восьмеричное с `B` и десятичное
   пояснение, если оно неочевидно) + ссылка на источник.
4. Значения пишутся в принятом в проекте виде: восьмеричные — с суффиксом `B`
   (`4000B`, `74022B`), десятичные — как есть (`100`).
5. Константа выносится в `,EQU,` тогда и только тогда, когда число используется
   как **величина** (длина, маска, граница, адрес LINK-ячейки), а не как
   номер слова в побайтовой аннотации.

Канонические примеры (рекомендуемая форма записи):

```
BUF_A_LEN     ,EQU,4000B.      . длина COMMON-буфера *A*: 0o4000 = 2048 слов
ENTRY_TAB_LEN ,EQU,50B.        . длина таблицы ENTRY*: 0o50 = 40 слов
LOADANGO_ADDR ,EQU,74022B.     . LINK-ячейка LOADANGO (docs/06 §1.3)
FT571_DISPATCH,EQU,77207B.     . точка входа FT*571/INTPRTF* (docs/06 §3.1)
MAX_PRIME     ,EQU,100.        . верхняя граница решета Эратосфена (простые 2..97)
MASK_LOW      ,EQU,77B.        . маска младших разрядов (0o77)
```

Пояснение к примерам: `BUF_A_LEN` и `ENTRY_TAB_LEN` проистекают из
`LC,4000B` / `LC,50B` корня (`docs/03-symbols.md` §1.3–1.4); `LOADANGO_ADDR` —
из подтверждённой пары `vjm 74022(15)` ↔ `LOADANGO`; `FT571_DISPATCH` — из
таблицы `UJ FT* / ATX 77xxxB` (`docs/06-address-map.md` §3.1);
`MAX_PRIME` — из решета Эратосфена (`docs/03-symbols.md` §2, п. 10);
`MASK_LOW` — типовая маска при OCT→DEC (`OCTTDEC`).

## 3. Сохранение побайтовой идентичности

### 3.1. Что НЕ переименовывается

Строки-аннотации слов — это комментарии (первый символ `С`/`C`), несущие
побайтовую приемку. Они **не являются символическими метками** и меняться не
должны ни при каких обстоятельствах:

```
С LO_SYN:  С--- слово 0000 (абс 241500), машинное слово 000000200003 ---
С LO_GEN:  С слово 0000  @0o277500  = 0o0000000000200003
```

Форматы зафиксированы в `tests/check-source-words.py` (`PAT_SYN`, `PAT_GEN`) и
в `tests/check-word-coverage.sh`. Любая правка цифр, абсолюта, пробелов или
префикса в этих строках=loses 1024-словную сверку.

### 3.2. Что переименовывается

Только **символические метки** (идентификаторы перед `:` в коде) **и все ссылки
на них** в операндах. При переименовании:

- сохраняется связь «метка ↔ слово»: метка остаётся привязанной к тому же
  слову (номер слова в соседней строке-аннотации не трогается);
- меняются **все** вхождения имени в операндах (`UZA L0021` → `UZA INIT_MOD_REG`);
- не меняется ни одно машинное слово: проверка `check-source-words.py`
  обязана остаться зелёной.

### 3.3. Обязательные проверки после переименования

```bash
python3 tests/check-source-words.py   # 1024/1024 слова совпадают с build/LO_*.words
bash tests/check-word-coverage.sh     # 1024/1024 слов аннотировано в каждом оверлее
bash tests/check-labels.sh            # авто-меток 0; таблица соответствий ≥ 10 строк
```

Требование: первые две проверки дают `OK`; третья сверяет отсутствие
авто-меток в `src/*.mad` и наличие таблиц `include/LO_SYN.labels.md`,
`include/LO_GEN.labels.md`, `include/FOREX.labels.md`.
На момент написания этого документа карты меток ещё не созданы, поэтому
`check-labels.sh` законно сообщает `FAIL ... отсутствует` — это **не** ошибка
именования, а ожидаемый пункт работы (таблица §4 — заготовка для этих карт).

## 4. Таблица примеров «было → стало → почему»

Источник «было» — реальные метки из `src/LO_SYN.mad`, `src/LO_GEN.mad`,
`src/FOREX_CORE.mad`, `src/FOREX_RUNTIME.mad`. «Стало» — предлагаемое
осмысленное имя (подлежит внесению в `include/*.labels.md`). «Почему» — роль
по комментарию исходника / xref.

| Было (источник) | Стало | Почему |
|---|---|---|
| `START:` (`FOREX_CORE`, `0o510303`) | `INIT_FOREX_ENTRY` | Entry INITFOR* корня; `INIT_` + `_ENTRY` |
| `START:` (`LO_GEN`, слово 0) | `INIT_GEN_ENTRY` | Точка входа генератора, маркер модуля |
| `START:` (`LO_SYN`, слово 0) | `SYN_ENTRY` | Entry синтаксического анализатора, `SYN_` |
| `L0021:` (`LO_SYN`, слово 21) | `INIT_MOD_REG` | `ATI 17B` — запись индексного регистра при инициализации |
| `L0315:` (`LO_SYN`, слово 315) | `LEX_NEXT` | `IJ 47516B` — переход к выбору очередной лексемы; `_NEXT` |
| `L0316:` (`LO_SYN`, слово 316) | `LEX_CHECK` | Э36 «втбрз» — проверка признака в таблице автомата; `_CHECK` |
| `L0507:` (`LO_SYN`, слово 507) | `SYN_EXTRACT_65` | Э65 — экстракод синтаксического анализатора |
| `L1005:` (`LO_SYN`, слово 1005) | `SYN_ADDR_ADD` | `7,A+X,2520B` — сложение адреса в анализаторе |
| `L1304:` (`LO_SYN`, слово 1304) | `LEX_EXIT` | `IJ 42510B` — уход в резидентную процедуру выбора лексемы; `_EXIT` |
| `L1327:` (`LO_SYN`, слово 1327) | `SYN_PTR_INIT` | `VTM 44101B` — установка индексного регистра-указателя М7 |
| `WT0533:` (`LO_GEN`, слово 533) | `FMT_OP_NAME` | `TEXT 8HPOWER` — имя оператора в таблице имён; `FMT_` |
| `W0532:` (`LO_GEN`, слово 532) | `FMT_NAME_LEN` | Дескриптор таблицы имён: длина 5 |
| `X_LOADANGO:` (`FOREX_CORE`) | `LOAD_ANGO` | Внешняя подпрограмма загрузки оверлея; `LOAD_` |
| `MASK15:` (`FOREX_RUNTIME`, OCTTDEC) | `OCT_MASK_LOW` | Маска младших 15 разрядов при OCT→DEC; `OCT_` |
| `L1:` (`FOREX_RUNTIME`, DATAPR*) | `DATE_LOOP` | Ветвление `UZA L1` при разборе даты; `_LOOP` |

После внесения каждой пары в `include/*.labels.md` переименование в `src/*.mad`
обязано пройти проверки из §3.3.

## 5. Внешние абсолютные адреса остаются адресами

Переименование применяется **только** к внутренним символическим меткам
реконструкции. Внешние абсолютные адреса оверлеев (`0o4xxxx`, `0o5xxxx`,
`0o6xxxx`, `0o77xxx`, `0o74000..74077`) остаются числами: у них нет
подтверждённого соответствия «адрес → имя», а выдумывать имя без доказательства
запрещено. См. `docs/06-address-map.md` (§3, §6, §7) и градацию `confirmed` /
`likely` / `unknown`.

- `0o74022` → `LOADANGO` — **confirmed** (`vjm 74022(15)`, S1 + лента `monsys.9`);
  только такой адрес может получить символическое имя в `,EQU,`.
- `0o77207` → `FT*571/INTPRTF*` — confirmed из S1, но в теле оверлея имя не
  подставляется без доказательства: оверлей ссылается на готовый абсолютный адрес.
- `0o57476`, `0o57325`, `0o77144`, `0o77xxx` (кроме таблицы FORMAT) —
  `unknown`/`likely`: имена резидентных модулей библиотеки 21 и MONSYS
  доступными эталонами не раскрыты, поэтому остаются адресами.

Практическое правило: если в комментарии стоит `unknown` или
`likely (имя)` — адрес не трогаем; если `confirmed` с ссылкой на S1/ленту —
можно завести поименованную `,EQU,`-константу и обязательно указать источник.

## 6. ОГРАНИЧЕНИЕ 6 СИМВОЛОВ (обязательное для МАДЛЕН)

Это правило **сильнее** всех рекомендаций §1–§5 и проверяется автоматически.

### 6.1. Суть ограничения

БЭСМ-6 хранит имя метки или `,EQU,`-константы в одном машинном слове —
шести 6-битных знаках. МАДЛЕН различает **только первые 6 символов** имени:

1. Длина имени — **≤ 6 символов** (счёт включая `*`, `/`, цифры и подчёркивание).
2. Первые 6 символов любых двух имён **в пределах одного файла** обязаны быть
   уникальными; иначе ассемблер их не различит.
3. Полное описание роли переносится в trailing-комментарий строки, в
   `include/*.labels.md` и в xref-своды — но **не в само имя**.

Имена длиннее 6 знаков и коллизии префиксов обнаруживает `tools/xref_all.py`
(раздел «НАРУШЕНИЯ 6-СИМВОЛЬНОГО ПРАВИЛА» в `docs/09-crossrefs.md`, разделы
`SIX_CHAR_VIOLATIONS` / `SIX_CHAR_COLLISIONS` в `logs/xref_all.txt`) и
`tests/check-label-length.sh` (лог `logs/label_length.txt`).

### 6.2. Схема короткого имени

Рекомендуемый шаблон: **префикс подсистемы (2–4 знака) + числовой суффикс**
(адрес, номер слова или порядковый номер). Суффикс и делает имя уникальным
там, где длинное имя раньше различалось только хвостом.

| Было (длинное, не собирается МАДЛЕН) | Стало (≤ 6) | Комментарий / полная роль |
|---|---|---|
| `BUF_WRITE_0063` | `BW0063` | запись в буфер FT_LIB_BUFFER, слово 00063 (S1:15628) |
| `INIT_FOREX` | `INITFX` | ENTRY INITFOR* корня, 0o510303 (S1:15466) |
| `JUMP_TARGET_77144` | `JT7144` | переход на абсолютный адрес 0o77144 (оверлей LO*GEN) |
| `DATE_PRINT` | `DTPRNT` | DATAPR*: печать даты DD MON YY HH.MM (S5:7645) |
| `FT_FORMAT_DISPATCH` | `FTFMTD` | диспетчер таблицы входов FT* (S1:15529) |
| `OCT_SIX_DIGIT_MASK` | `OCTMSK` | маска 6 цифр OCTTDEC (S6:5047) |
| `PAGE_GIVE` | `PGIVE` | GIV/PG — выдача страницы (FOREX_ROOT.mad) |
| `PAGE_TAKE` | `PTAKE` | TAK/PG — взятие страницы (FOREX_ROOT.mad) |

Таблица задаёт **шаблон**; фактические имена текущей реконструкции (они —
источник истины): `INIT_FOREX` → `INITFO` (`src/FOREX_CORE.mad:191`),
`DATE_PRINT` → `DATAPR` / `DPRNT`, `PAGE_GIVE` → `PAGEGV`, `PAGE_TAKE` →
`PAGETK`, `FT_FORMAT_DISPATCH` → `FTDISP` / `FMTENT`, `BUF_WRITE_0063` →
короткий вариант с префиксом `BW` и номером слова. При расхождении обновить
таблицу, а не оставлять два адресуемых имени; полные значения всегда идут
в комментарий `; полное имя: …` и в `include/*.labels.md`.

### 6.3. Как писать xref-своды после переименования

- **Основное имя в таблицах — короткое** (`BW0063`, `INITFX`, `DTPRNT`).
- Полное описание — в отдельной колонке «Роль / полное имя» либо в
  trailing-комментарии: `` `DTPRNT` — DATAPR*, печать даты ``.
- Старое длинное имя сохраняется **только** в колонке «Было» таблиц
  `include/*.labels.md` и в комментариях — как историческая справка, а не
  как адресуемое имя.
- В графе вызовов рёбра пишутся короткими именами; протяжённые подписи
  («FORMAT → FT*571 … FT*003») выносятся в примечание под графом.

### 6.4. Чек-лист переименования

1. Заменить имя во всех `src/*.mad` и `include/*.mad` (только объявления и
   операнды; комментарии — по желанию).
2. Добавить/обновить пару в соответствующем `include/*.labels.md`
   (колонки «Было» → «Стало» → role).
3. Прогнать `bash tests/check-label-length.sh | tee logs/label_length.txt`
   — ожидается `OK: во всех файлах имена <=6 и уникальны по первым 6 символам`.
4. Перегенерировать `python3 tools/xref_all.py --out docs/09-crossrefs.md`
   — раздел «НАРУШЕНИЯ 6-СИМВОЛЬНОГО ПРАВИЛА» должен быть пустым.
5. Обновить `docs/13-runtime-crossrefs.md`: короткое имя — в основной
   колонке, полное описание — в комментарии.
