> Применено в репозитории: `tools/build_forex_perso.py`, четыре FRONT‑harness
> (71/83/85/86) и списки cleanup 81/83/84/85/86 переведены на карты `2048`/`2048-wr`
> с созданием host‑файла `2048` из рабочего образа; `tools/run_besm6_deck.py` не
> трогался (пользовательская правка). Тесты 71 и 83 после правки PASS. Физический
> файл рабочей копии по-прежнему может называться `2348`, но OS‑метка тома — `2048`.

## 0. Verdict

**PASS** for the alias-based decks and the PERSO build, on COPIES only. No repo file was
modified; all work happened under `/tmp/.private/azizz/opencode/re-forex-deck-2048/`.

The user premise is confirmed by the code path: in dispak a mount card
`лен NN(2348-wr)^` is parsed as **numeric volume `2348` + write flag**, and the host
file opened is `2348` (strace proof below). The `-wr` suffix is a *mode flag*, not part
of the host filename. The OS-visible volume label of these images is `2048`; deck cards
must therefore say `2048` / `2048-wr`. The host-file copy mechanism (copy the working
image into the isolated workspace before the run) is preserved: the alias is simply
renamed `2348-wr` -> `2048-wr` while still being copied from the working `2348` image.

## 1. Evidence / method

1. **Parser proof** (`/home/azizz/Yandex.Disk/dispak/dispak/vsinput.c:324-373`):
   `get_decimal(cp)` reads the volume number; `cp[1]==GOST_W && cp[2]==GOST_R` sets
   `psp.vol[n].wr = 1`; `volno = u` (the decimal number). `disk.c:59-95,104-144`
   builds the path `/%d` from that number and opens it with `O_RDWR` when `wr=1`.
2. **strace proof** (workspace `baseline/work/spec10`, deck `лен 41(2048)^ лен 60(2348-wr)^`):
   only `.../work/spec10/2048` and `.../work/spec10/2348` are opened; the host file
   `2348-wr` copied by the harness is **never opened by dispak**. For the modified deck
   `лен 60(2048-wr)^` only `.../2048` is opened; `2048-wr` is likewise never opened.
   => Renaming the alias is a bookkeeping/consistency change; it does not change what
   dispak opens. What matters functionally is that `work/2048` exists and is writable.
3. **Baseline run** (unmodified `tests/plan-f77/71-front-base77/run.sh`, copies only):
   `IR_records=74`, `build_ERR=0 call_ERR=0`, `build_sha256=0e5ec38c...`,
   `call_sha256=98f0ab1f...`, `VERDICT: PASS`.
4. **Modified run** (copies of inject.py/compile.py with `2048`/`2048-wr` cards, alias
   `2048-wr` copied from `SHARE/2348`): `IR_records=74`, `ERR=0`,
   `cmp baseline/ir_spec10.txt modified/ir_spec10.txt` -> **byte-identical**, `VERDICT: PASS`.
   Caveat: because dispak then writes PERSO into `work/2048` (seeded from the system
   image) instead of `work/2348`, `build.out` carries a non-fatal monitor diagnostic
   difference (`PRINT8/FICMEMOR/STAR*` notice, `ДЛИHA LIBRARY 005` vs `006` ZOH) and the
   out-file SHA changes. IR and verdict do not.
5. **Exact-output variant** (also seed `work/2048` from the working `2348` image):
   `build_sha256=0e5ec38c...`, `call_sha256=98f0ab1f...` -> **byte-identical to baseline**,
   IR identical. This is the recommended form for the 4 FRONT harnesses.
6. **PERSO build** (copy of `tools/build_forex_perso.py`, with card `лен 40(2048-wr)^`,
   copy target `tmp/2048`, `besmtool dump 2048`): rebuild succeeded,
   `sha256 0bd8e5862d61a4b30358534260cf7cd06029966e4504821d4fc4d078e8a9d53b`,
   byte-identical to `build/FOREX_PERSO_2300.bin`, 9 catalog entries unchanged.
   Gates depending on that image are therefore unchanged.

## 3. Physical SIMH file vs OS-visible volume (explicit note)

SIMH `ini` files attach a *workspace host file* whose name is arbitrary:
`docs/74-simh-verification.md:133` and `docs/75-simh-wide-and-besm.md:51,169` show
`attach -e md45 .../disks/md_2348`; the stock ini uses `~/.besm6/2348`
(`/home/azizz/Yandex.Disk/simh/BESM6/OSZAGR/dispak.ini:46`). That name is only a host
path. The BESM-6 OS reads the disk passport (zone `0543`, identical on both images per
`docs/17-disks-2048-2348.md:36-40`) and sees the volume **2048**. Therefore:
`attach -e md45 .../md_2348` is fine, but the task passport card must read
`дис 45(2048)^` / `лен 60(2048)^`. In dispak the same rule appears as numeric `volno`:
the card number chooses the host filename, so the workspace must supply a file named
`2048` containing the intended image (system zones of 2348 are byte-identical to 2048;
PERSO is just the added library in zone `0o2300`).
