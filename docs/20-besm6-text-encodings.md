# 20. Универсальный сканер текстовых констант БЭСМ-6: все кодировки одного слова

Дата: 2026-11-19. Инструмент: `tools/besm6_text_scan.py`. Лог: `logs/besm6_text_scan.txt`.
Продолжение [`19-dtran-text-encodings.md`](19-dtran-text-encodings.md): там разбиралось,
что `-D` в dtran — Pascal-only и как получить четыре прочтения через синтетический
Pascal-B контейнер. Здесь — автономный декодер, который **не требует dtran** и
показывает сразу все кодировки для любого 48-битного слова.

---

## 1. Зачем

Машинное слово БЭСМ-6 не несёт метки кодировки. Одно и то же
`0o5457126371560000` читается как `LO*SYN  ` в TEXT и как `МП+УЩО00` в 6-битной
GOST-10859; `0o1502244213020060` — как `ФЕВМАР` в 8-битной GOST-10859. Раньше
каждая новая находка требовала вручную подбирать «правильную» таблицу. Теперь
сканер выдаёт таблицу «кодировка → прочтение → правдоподобие» и позволяет
массово находить слова, у которых в комментариях **нет** расшифровки.

### 2.1. 6-битные кодировки (8 символов на слово)

Слово разбивается на восемь групп по 6 бит, считая со **старших** разрядов:
сдвиги 42, 36, 30, 24, 18, 12, 6, 0. Именно так МАДЛЕН/Дубна упаковывает
TEXT-константу; Тюрин: «в одном машинном слове может быть записано …
8 символов в коде TEXT. Если число символов меньше, текст располагается в
младших разрядах, свободные позиции дополняются нулями».

**TEXT vs TEXT-DUBNA.** Это разные таблицы, которые совпадают только для
латинских заглавных, цифр, пробела, `*`, `/`, `+`, `-` (коды 0, 10, 15, 16–25,
29, 30, 33–58). Для остальных кодов расходятся:

| Код | `TEXT` (ASCII−0x20) | `TEXT-DUBNA` (`text_to_gost`) |
|---|---|---|
| 0o01 | `!` | `.` |
| 0o02 | `"` | `Б` |
| 0o04 | `$` | `Д` |
| 0o0E | `.` | `Ж` |
| 0o1A | `:` | `Ь` |
| 0o1B | `;` | `,` |
| 0o1C | `<` | `П` |
| 0o1F | `?` | `Ы` |
| 0o20 | `@` | `0` |
| 0o72 | `r` | `Ш` |

Существующие комментарии (`DEKOD … TEXT 'LO*SYN  '`) используют **dtran-таблицу**,
но для всех наших TEXT-имён (латиница + `*`/`/`) обе таблицы дают одно и то же.
Сканер показывает обе, чтобы расхождение не оставалось скрытым.

**GOST-10859, 6 бит** — это не то же самое, что `dtran -D gost:` (см. docs/19):
dtran читает 6 восьмибитных байт, а здесь — 8 шестибитных кодов из `gost10859.h`.
Именно 6-битный вариант используется в наших комментариях `DEKOD GOST 'МП+УЩО00'`.
Код 0o17 — пробел; برxic коды 0o143, 0o172–0o176, 0o200 — служебные (не PRINTABLE).

### 2.2. 8-битные кодировки (6 байт на слово)

Байты идут со старших разрядов: сдвиги 40, 32, 24, 16, 8, 0.

- **GOST8** — direct `gost_to_unicode_*`. Коды 0o000–0o137 определены в
  `gost10859.h`, 0o140–0o377 в таблице равны нулю (нет глифа). Код 0o242
  (`GOST_SPACE3`) помечен в заголовке как «used as space by forex».
- **UPP (УПП)** — ГОСТ 10861-64: тот же набор глифов GOST-10859 (lat), но
  старший бит байта — бит чётности. `PunchCardCodec.cs` ставит его, если
  чётность младших 7 бит чётная: `if ((PopCount(code) & 1) == 0) code |= 0x80`.
  Декодер просто сбрасывает бит 7. Тюрин подтверждает 6 символов УПП в слове
  и отсылает к таблице «Код устройства подготовки перфокарт УПП-1 и
  АЦПУ-128-3» (приложение, OCR в `tyurin1985-full.txt:19905`).
- **ISO / KOI-7** — в Дубне «ISO» — это `koi7_to_unicode`: байты 0x20–0x5F —
  ASCII, 0x60–0x7F — кириллица (ЮАБЦДЕФГ…), 0x05–0x1F — служебные глифы.
  `dtran.cc:get_iso_char` печатает кириллицу как двухбуквенную транслитерацию
  (`Ю`, `А`, `Б`, …) и `_NNN` для управляющих. `rukava.be` упоминает зоны
  «ПРОГРАММА В КОДАХ В КОДИРОВКЕ УПП» (0643–0647) и «ПАСПОРТОВ В КОДИРОВКЕ ISO».
- **ITM** — автокод Чайковского, таблица `itm_to_gost` разрежена (многие байты
  не определены); неопределённые байты считаются «мусором», а не цифрой `0`.
- **COSY** — COSY-поток на диске: в основном KOI-7 плюс байты 0x81..0xD3,
  означающие повтор пробела (`CosyCodec.DecodeCosy`). COSY — это не отдельный
  алфавит, а транспортный формат, поэтому его прочтение обычно совпадает с KOI-7.

## 4. Какие кодировки реально встречаются в исходниках

### 4.1. По аннотациям в комментариях (`src/*.mad`, `src/lib21/*.mad`)

| Кодировка аннотации | Число упоминаний | Комментарий |
|---|---:|---|
| `DEKOD GOST …` | 494 | 6-битная GOST-10859 (наши `GOST '…'`), **не** `dtran -D gost` |
| `DEKOD TEXT …` | 439 | 6-битная TEXT Дубны |
| `DEKOD ISO …` | 420 | 8-битная ISO/KOI-7; `···` = непечатный байт |
| `DEKOD ITM …` | 0 | ITM встречается только как *имя* (`ITM/ASS`), не как аннотация константы |
| `DEKOD UPP / KOI / COSY` | 0 | в комментариях наших 51 файла не встречаются |

Литералы в исходниках: `8H…` — 90, `nH…`/`6H…` — 274 вхождения (многие из них
`=6H` — маски/непосредственные операнды, а не текст).

Итого в комментариях зафиксированы **только три** кодировки: TEXT (6), GOST (6)
и ISO (8). UPP, KOI-7, ITM, COSY, ASCII для наших исходников — *дополнительные
гипотезы*, которые scanner показывает, но которые пока ни разу не стали
первичным прочтением в аннотации.

### 4.2. По результатам сканирования (все 2374 слов-вхождения)

| Лучшая кодировка | Вхождений | Доля |
|---|---:|---:|
| GOST6-LAT | 1105 | 46.5% |
| ISO | 406 | 17.1% |
| TEXT | 322 | 13.6% |
| KOI-7 | 288 | 12.1% |
| UPP | 111 | 4.7% |
| GOST8-LAT | 75 | 3.2% |
| COSY | 64 | 2.7% |
| ASCII | 2 | <0.1% |
| ITM | 1 | <0.1% |

⚠️ GOST6-LAT лидирует не потому, что исходники «говорящие», а потому что у
6-битной GOST-10859 **нет маски отбора**: почти любой код даёт букву/цифру. Это
самая «разрешительная» кодировка, и она же главный источник ложных срабатываний
(битовые маски вида `0o7777777777700000` читаются как `DDDDDШ00`). Настоящие
текстовые константы надёжнее искать по **совпадению TEXT и GOST6** (одно и то же
слово даёт осмысленное чтение в обеих), либо по 8-битным GOST/ISO с «словесным»
прочтением.

## 6. Как пользоваться инструментом

```bash
# все кодировки для одного слова
python3 tools/besm6_text_scan.py --word 0o5457126371560000

# только нужные кодировки, JSON для скриптов
python3 tools/besm6_text_scan.py --word 0o1502244213020060 \
    --encoding GOST8-CYR,TEXT,ISO --json

# сканирование одного файла / всего дерева
python3 tools/besm6_text_scan.py --file src/FOREX_CORE.mad
python3 tools/besm6_text_scan.py --dir src --log logs/besm6_text_scan.txt

# список кодировок; ужесточение/ослабление порога
python3 tools/besm6_text_scan.py --list-encodings
python3 tools/besm6_text_scan.py --word 0o... --threshold 0.85
```

Опции: `--word` (повторяемо), `--file`, `--dir`, `--encoding`, `--json`,
`--threshold` (по умолчанию 0.60), `--log`, `--list-encodings`.
Числа по умолчанию восьмеричные; `0x…` и `0o…` тоже принимаются.

### 6.1. Что означает правдоподобие

Для каждого прочтения считаются две доли:

- **печатная** — доля позиций, где таблица дала видимый глиф (не `\0`, не
  управление). Служебные коды GOST (`EOT`, `REPEAT` и т.п.) сюда не идут;
- **уверенность** — доля позиций с «уверенным» символом: буква (включая
  кириллицу), цифра, пробел или базовая пунктуация. Для 6-битных TEXT/TEXT-DUBNA
  дополнительно применяется маска `dtran.cc:is_likely_text` (допустимы пробел,
  `*`, `/`, цифры, `-`, `+`, `A-Z`; коды 0o01–0o11, 0o13–0o16, 0o32–0o34,
  0o37, 0o40, 0o73–0o77 отбрасываются).

Ведущие и конечные нулевые группы считаются паддингом (Тюрин: текст в младших
разрядах) и из знаменателя исключаются; внутренние нули — «мусор». Дополнительно
применяется анти-маска: если один символ занимает >40% прочтения, оценка
умножается на 0.30 (слово `0o7777…` — битовая маска, а не текст `DDDDDDDD`).
`--threshold` фильтрует по **уверенности**.

## 7. Рекомендации

1. **Первичное чтение TEXT-имён** — 6-битная таблица Дубны (`TEXT-DUBNA`),
   она же `dtran -F dms` → `,TEXT, 8H…`. Для латиницы совпадает с `TEXT`
   (ASCII−0x20). Проверять обе, если в слове есть коды <0o20 или >0o72.
2. **Месяцы DATAPR и другие русскоязычные строки в 8 бит** — `GOST8-CYR`,
   авторитет подтверждён `dtran -D gost:` (docs/19, §3.2). `GOST8-LAT` дать как
   вторичное чтение (гомоглифы `А→A`, `В→B`, `Е→E` и т.д.).
3. **`dtran -D gost:` на 6-битных словах не применять** — он читает 6 байт и
   даёт мусор; правильно использовать `GOST6-CYR`/`GOST6-LAT` из `gost10859.h`.
4. **UPP и ISO различать по биту чётности**: если старший бит каждого байта
   равен чётности младших семи — это УПП (ГОСТ 10861-64); иначе ISO/KOI-7.
5. **COSY и KOI-7** для наших исходников совпадают; COSY имеет смысл лишь при
   разборе зон COSY-вывода (модули `CM/COSY`, `COSYTISO`, `ISOTCOSY`, `PERCOSY`).
6. **ITM** — только для текстов автокода Чайковского (`ITM/ASS`); в lib21 наших
   дампов ITM-констант не найдено.
7. При добавлении аннотации в `.mad` писать `DEKOD GOST '…' / TEXT '…' / ISO '…'`
   с `[источник: …; confidence: …]` — тогда сканер перестанет считать слово
   нерасшифрованным. Для TEXT-имён из таблиц символов достаточно пометки
   `TEXT='…'` на строке `С слово`.
8. **Приоритет правки**: 140 слов из §5.1/лога (раздел «Приоритетные находки») —
   готовый список кандидатов на аннотирование, начинать с `FOREX_CORE.mad` и
   `FOREX_RUNTIME_DISASM.mad`.

## 8. Ограничения

- Сканер извлекает слова из текстового представления `.mad`: `= 0o…`, голые
  16-значные восьмеричные литералы (EQU/OCT) и `nH…`-литералы. Слова, которые
  существуют только в бинарном образе (`build/*.dms`, `lib21.bin`), не сканируются —
  для них нужен `tools/dtran_text.py --dms/--module`.
- Оценка «правдоподобия» — эвристика. 6-битная GOST-10859 почти всегда даёт
  печатные символы, поэтому её высокий балл сам по себе ничего не доказывает;
  смотрите согласие между кодировками и контекст (таблица символов, заголовок
  модуля, строка сообщения).
- Октальные escape-последовательности внутри `nH…` (`'055'`, `'231'`) разбираются,
  но составные GOST-строки с кириллицей из `.mad` (например `6HBPEMЯ-`) в
  word-представление не переводятся: для них используйте уже имеющуюся аннотацию
  или `dtran_text.py`.
- Таблица `gost10859.h` содержит служебные коды за пределами 0o137; они
  intentionally не считаются печатными.
