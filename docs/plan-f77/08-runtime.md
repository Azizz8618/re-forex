# 08 — E2: минимальный Fortran-рантайм `F77LIBR` в PERSO зоны `0o2310`

Дата: 19.11.2026. Статус: **готово, тест rc=0**.

## 1. Что сделано

Реализован этап E2 из `05-decision.md` §4: три внешние Fortran-процедуры
скомпилированы ФОРЭКСОМ 2.02 и записаны в **отдельную** PERSO-библиотеку
зоны `0o2310` рабочей копии диска 2348. Обычная Fortran-программа вызывает
их по имени через `*perso:602300` (базовый компилятор) + `*perso:602310,cont`
(рантайм) — без `EXTERNAL` и без правки компилятора.

Базовая библиотека зоны `0o2300` и рабочий тест Глиссады **не изменены**:
побайтовая сверка образа `build/FOREX_PERSO_2300.bin` (SHA256
`aab191de…7877a83`) с зонами `0o2300..0o2304` рабочей копии проходит;
`tests/run-glissade-forex.sh` → rc=0, 14/14 строк.

## 2. Процедуры

Источник: `src/f77libr/F77LIB.FTN`. Все имена ≤ 6 символов, не системные
(урок `OCTTDE*`); PANEL/TEXT-кодировка совпадает с соглашением ФОРЭКСа.

| Имя | Тип | Назначение |
|---|---|---|
| `MYABS` | `FUNCTION MYABS(X)` | абсолютная величина вещественного аргумента |
| `MYMAX` | `FUNCTION MYMAX(A,B)` | максимум двух вещественных аргументов |
| `FMTLNK` | `SUBROUTINE FMTLNK(X)` | печать строки с **явным** FORMAT: `11H...` + `F8.3` |

Источник написан строго на поддерживаемом подмножестве (`tests/plan-f77/probe.sh`):
нет `IMPLICIT`, `SAVE`, `PRINT *`, `READ(*,*,END=)`, `CHARACTER`; строки с
`C` в первой колонке — комментарии; операторы начинаются с 7-й колонки.

Вызов из программы:

```fortran
      x = myabs(-3.5)
      y = mymax(2.0, 7.0)
      call fmtlnk(9.0)
```

`FMTLNK` использует Hollerith-константу в FORMAT, поэтому печать строки
работает без типа `CHARACTER`.

## 3. Зоны и сборка

| Зона (восьм.) | Зона (dec) | Содержимое |
|---|---|---|
| `0o2300..0o2304` | 1216..1220 | базовая PERSO ФОРЭКС+рантайм (9 модулей), **не трогается** |
| `0o2310..0o2313` | 1224..1227 | новая PERSO-библиотека F77LIBR (4 зоны) |

`0o2310` выбрана из свободного интервала `0o2300..0o2477` (`docs/14` §2);
запись идёт только в свежую рабочую копию 2348, эталон
`/usr/local/share/besm6/2348` монтируется только на чтение.

### 3.1. Компиляция и запись объекта

Сценарий `tests/run-f77-runtime.sh` строит деку по шаблону
`tests/forex-glissade/glkern.b6`:

```
шифр 419999 зс5^
лен 60(2348-wr)^
ееВ1а3
*name F77lib
*call yesmemory
*perso:602300          ; базовый ФОРЭКС из зоны 0o2300
*full list
*forex
<строки src/f77libr/F77LIB.FTN>
*to perso:602310       ; ★ объект в ОТДЕЛЬНУЮ библиотеку 0o2310
*end file
``````
еконец
```

Запуск: `BESM6_PATH=<working>:/usr/local/share/besm6 dispak lib.b6`.
Монитор печатает `ДЛИНА LIВRАRУ 004 ЗОН`, `КОНЕЦ ЗАДАЧИ`. Каталог новой
библиотеки разбирается встроенным Python-парсером (TEXT 6 бит/символ,
проверка ненулевого transfer vector и завершателя `0 / FULWORD`).

### 3.2. Подключение в программной деке

`tests/f77/test-runtime.b6`:

```
шифр 419999 зс5^
лен 60(2348)^
eeв1а3
*name T77run
*call yesmemory
*perso:602300
*perso:602310,cont     ; ★ дозапись каталога F77LIBR к базовому
*no list
*forex
<FORTRAN-программа, вызывающая MYABS / MYMAX / FMTLNK>
*execute
*end file
``````
еконец
```

Соглашение вызова совпадает автоматически: и программа, и процедуры
скомпилированы одним ФОРЭКСОМ 2.02 (аргументы по адресу, возврат функции —
через те же регистры). `EXTERNAL` не требуется (проба `EXTERNAL` в
`tests/plan-f77/work/EXTERNAL/out.txt`).

## 4. Эталон и прогон

`tests/f77/output.gold.txt` — два строки результата (перед `КОНЕЦ ЗАДАЧИ`):

```
     3.0000    7.0000
 F77LIВR Х=,   9.000
```

Буквы `В` и `Х` во второй строке — кириллические: так диспак декодирует
TEXT-символы БЭСМ-6 в листинге (латинский `B` печатается как `В`, `X` как
`Х`). Это не опечатка; gold записан с побайтового вывода реального прогона.

Команда: `bash tests/run-f77-runtime.sh`.

Результат: **rc=0**, `OK: rc=0, вывод совпадает с tests/f77/output.gold.txt`.
Лог: `logs/f77_runtime_run.txt`; дополнительная проверка Глиссады —
`logs/f77_runtime_glissade.txt`.

Сценарий проверяет:
1. свежую копию эталона и запись базового образа в `0o2300`;
2. успешную компиляцию (отсутствие `ERR/ОШИБКА/НЕДОПУСТИМ/АТТ/ТИП ОП-ДА`)
   и `ДЛИНА LIBRARY` после `*to perso`;
3. наличие `MYABS`, `MYMAX`, `FMTLNK` в каталоге `0o2310` с ненулевым TV;
4. побайтовую неизменность зон `0o2300..0o2304`;
5. совпадение блока результата с gold.

## 5. Что не получилось / важные ловушки

1. **`*perso:603100,cont` — опечатка в планах.** В `03-fortran-path.md` §2.1
   и `05-decision.md` для новой библиотеки указана карта `*perso:603100`,
   но формат карты — `LU` (2 восьм. знака) + зона (4 восьм. знака).
   `603100` адресует зону `0o3100`, а не `0o2310`; при такой карте монитор
   печатает `*** ИСКЛЮЧИТЕ ИЗ ЛИЧНОЙ БИБЛИОТЕКИ…` и `ИСПОРЧЕН КАТАЛОГ
   PERSONAL LIBRARY`, а компоновщик — `ОТСУТСТВУЕТ MYABS/MYMAX/FMTLNK`.
   Правильная карта для зоны `0o2310`: **`*perso:602310,cont`**.

2. **Дубли `FOREX*` и `LO*SYN` в новой библиотеке.** При компиляции
   ФОРЭКСОМ из `*perso:602300` временный каталог задачи уже содержит
   модули базовой библиотеки; `*to perso` записывает их вместе с новыми.
   Каталог `0o2310` поэтому содержит 5 имен: `FMTLNK MYMAX MYABS FOREX* LO*SYN`.
   Это безвредно (базовая библиотека не перезаписывается, модули грузятся
   по последней загруженной копии, тест проходит), но при желании чистую
   трёхмодульную библиотеку можно получить компиляцией системным ФОРЭКСОМ
   без `*perso:602300` — проверено: каталог из 3 имен, `ДЛИНА LIBRARY 003 ЗОН`.

3. **`ИСПОРЧЕНЫ ПОДПРОГРАММЫ:` в логе компиляции.** Появляется на этапе
   `*to perso`, когда монитор выгружает унаследованные из базового каталога
   модули, тела которых не были загружены в память задачи. На загрузку
   скомпилированной программы не влияет: в прогоне `test-runtime.b6`
   предупреждений нет, все три процедуры разрешаются.

4. **Hollerith в FORMAT.** `PRINT *` неподдерживается; печать строки
   реализована через явный `FORMAT(1X,11H...,F8.3)`. Число после `H`
   должно точно равняться длине строки — иначе ФОРЭКС молчаливо сдвигает
   формат и вывод портится.

5. **Нереализуемо без правки ассемблера** (по `05-decision.md` §2): новые
   ключевые слова (`IMPLICIT`, `SAVE`, `END=`), list-directed I/O, новые
   edit-дескрипторы. Это задачи E3/E4, не E2.
