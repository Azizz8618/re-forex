# 08 — E2: минимальный Fortran-рантайм `F77LIBR` в PERSO зоны `0o2310`

`run-glissade-forex.sh` 14/14, `run-f77-full.sh` gate 20/20). Версия

## 1. Что сделано

Реализован этап E2 из `05-decision.md` §4: внешние Fortran-процедуры
скомпилированы ФОРЭКСОМ 2.02 и записаны в **отдельную** PERSO-библиотеку
зоны `0o2310` рабочей копии диска 2348. Обычная Fortran-программа вызывает
их по имени через `*perso:602300` (базовый компилятор) + `*perso:602310,cont`
(рантайм) — без `EXTERNAL` и без правки компилятора.

Базовая библиотека зоны `0o2300` и рабочий тест Глиссады **не изменены**:
побайтовая сверка образа `build/FOREX_PERSO_2300.bin` (SHA256
`aab191de…7877a83`) с зонами `0o2300..0o2304` проходит;
`tests/run-glissade-forex.sh` → rc=0, 14/14 строк.

## 2. Процедуры

Источник: `src/f77libr/F77LIB.FTN`. Все имена ≤ 6 символов, не системные
(урок `OCTTDE*`); PANEL/TEXT-кодировка совпадает с соглашением ФОРЭКСа.
Каталог `0o2310` после сборки v3 (13 процедур в исходнике, 12 из них
каталогизируются; `CONJG` резервируется ФОРЭКСОМ как встроенная — см. §5.7):

```
DINT2 DMOD2 ISTRCM SUBSTR STRCAT STRCMP IDIV ISGN0 IMAX0 FMTLNK MYMAX MYABS FOREX* LO*SYN
```

(`FOREX*`, `LO*SYN` — безвредные дубли из базовой библиотеки, см. §5.2.)

### 2.1. Вещественные (исходный набор E2)

| Имя | Тип | Назначение |
|---|---|---|
| `MYABS` | `FUNCTION MYABS(X)` → REAL | абсолютная величина вещественного аргумента |
| `MYMAX` | `FUNCTION MYMAX(A,B)` → REAL | максимум двух вещественных аргументов |
| `FMTLNK` | `SUBROUTINE FMTLNK(X)` | печать строки с **явным** FORMAT: `11H...` + `F8.3` |

### 2.2. Целые и Hollerith (новые в v2)

| Имя | Тип | Назначение |
|---|---|---|
| `IMAX0` | `INTEGER FUNCTION IMAX0(I,J)` | максимум двух целых |
| `ISGN0` | `INTEGER FUNCTION ISGN0(I)` | знак целого: `-1`, `0`, `+1` |
| `IDIV`  | `INTEGER FUNCTION IDIV(I,J)` | целочисленное деление `I/J` с проверкой делителя; при `J=0` возвращает `0` (деление не выполняется) |
| `STRCMP`| `INTEGER FUNCTION STRCMP(A,B)` | сравнение двух 4-символьных Hollerith-слов, упакованных в `INTEGER`; возвращает `-1`/`0`/`+1` |

Имя `ISIGN` (естественный кандидат) **занято встроенной функцией** ФОРЭКСа
(стандартный `ISIGN(A,B)`): объявление однопроцедурного `ISIGN` даёт
`ОШИБКА В СПИСКЕ АРГ / ЗНАЧЕН. … НЕ ОПРЕДЕЛЕНО`. Поэтому в библиотеке
используется свободное имя `ISGN0` (соглашение «суффикс 0», как у `IMAX0`).

Источник написан строго на поддерживаемом подмножестве
(`tests/plan-f77/probe.sh`): нет `IMPLICIT`, `SAVE`, `PRINT *`,
`READ(*,*,END=)`, `CHARACTER`; строки с `C` в первой колонке — комментарии;
операторы начинаются с 7-й колонки. Для `STRCMP` используется рабочий
рецепт из `07-experiments.md` §exp.5: `nH…` допустима в `DATA INTEGER`,
но не в присваивании `CHARACTER`.

### 2.3. Соглашение вызова

И program, и процедуры компилируются одним ФОРЭКСОМ 2.02, поэтому
аргументы передаются по адресу, а возврат FUNCTION идёт через те же
регистры — `EXTERNAL` не требуется (проба `EXTERNAL` в
`tests/plan-f77/work/EXTERNAL/out.txt`).

```fortran
      program demo
      integer m, s, q, c, w1, w2
      data w1 /4HABCD/
      data w2 /4HABCF/
      x = myabs(-3.5)
      y = mymax(2.0, 7.0)
      m = imax0(-4, 9)          !  9
      s = isgn0(-7)             ! -1
      q = idiv(17, 5)           !  3
      q = idiv(5, 0)            !  0  (защита от деления на нуль)
      c = strcmp(w1, w2)        ! -1  (ABCD < ABCF)
      c = strcmp(w2, w1)        ! +1  (ABCF > ABCD)
      call fmtlnk(9.0)
      end
```

`STRCMP` принимает **уже упакованные** слова: `INTEGER W; DATA W/4HABCD/`.
Четыре символа занимают младшие 24 бита слова; сравнение целых даёт
лексикографический порядок для цифр и заглавных букв TEXT-кодировки.
Прямая передача `4HABCD` как фактического аргумента не пробовалась —
используйте переменную с `DATA`.

`IDIV` не генерирует аварийное завершение при нулевом делителе: он
возвращает `0`, что удобно для переноса кода без обработчиков исключений.

`FMTLNK` использует Hollerith-константу в FORMAT, поэтому печать строки
работает без типа `CHARACTER`.

### 2.4. Новые процедуры v3 (реестр 03-fortran-path.md §4.3)

| Имя | Тип | Назначение | Контрольное значение |
|---|---|---|---|
| `STRCAT` | `SUBROUTINE STRCAT(A,B,C,LA,LB)` | конкатенация массивов ASCII-кодов: `C=A(1:LA)//B(1:LB)` | `"ABCD"//"EF"` → `65 66 67 68 69 70` (`ABCDEF`) |
| `SUBSTR` | `SUBROUTINE SUBSTR(A,I,J,C)` | подстрока `A(I:J)` (1-based) в `C` | `A(2:4)` из `ABCDEF` → `66 67 68` (`BCD`) |
| `ISTRCM` | `INTEGER FUNCTION ISTRCM(A,B)` | лексикографическое сравнение двух 6-символьных `TEXT`-слов (по 2 `INTEGER` в каждом) | `ABCD//1234` vs `ABCF//1234` → `-1`, реверс → `+1`, равные → `0` |
| `DMOD2` | `DOUBLE PRECISION FUNCTION DMOD2(X,Y)` | DP-остаток `X-AINT(X/Y)*Y` | `DMOD2(7.5D0,2.0D0)=1.5` |
| `DINT2` | `DOUBLE PRECISION FUNCTION DINT2(X)` | усечение DP к нулю (`IDINT`-эквивалент) | `DINT2(7.5D0)=7.0`, `DINT2(-3.7D0)=-3.0` |
| `CONJG` | `FUNCTION CONJG(Z)` | сопряжение `COMPLEX`: `(A,B)→(A,-B)` | `CONJG((3,4))=(3,-4)` |

**Важная оговорка о символьном представлении.** Проба на ФОРЭКСЕ 2.02
показала: `DATA W/4HABCD/` укладывает 4 символа как **8-битные ASCII-байты**
в старшие 32 бита 48-битного слова (`0x414243442020`, т.е. `ABCD` + два
пробела); 6 символов на слово. При этом арифметика над такой `TEXT`-константой
(FORTRAN-переменной, инициализированной `nH`) в 2.02 работает некорректно:
`W/256` и `W-W` дают `0`, хотя сравнение `W1.LT.W2` даёт верный порядок.
Поэтому `STRCAT`/`SUBSTR` оперируют **INTEGER-массивами ASCII-кодов** (один
символ = один элемент), где арифметика полностью работоспособна, а `ISTRCM`
использует надёжное сравнение упакованных `TEXT`-слов. Это единственное
отклонение от «6-битных групп» в плане §1.5, оправданное наблюдённым
поведением конкретного компилятора.

Имя `CONJG` в 2.02 — **встроенное**: исходник `FUNCTION CONJG` компилируется
(тело `00017` слов в листинге), но `*to perso` не заносит его в каталог
PERSO (как и в случае `ISIGN`). Программный вызов `CONJG(Z)` разрешается
встроенной процедурой и даёт тот же результат `(3,-4)`, что проверено
контрольным прогоном. Процедура оставлена в исходнике как эталонная форма
реестра и для переносимости на версии без нативного `CONJG`.

## 3. Зоны и сборка

| Зона (восьм.) | Зона (dec) | Содержимое |
|---|---|---|
| `0o2300..0o2304` | 1216..1220 | базовая PERSO ФОРЭКС+рантайм (9 модулей), **не трогается** |
| `0o2310..0o2313` | 1224..1227 | PERSO-библиотека F77LIBR (4 зоны; 14 имён в каталоге после v3) |

`0o2310` выбрана из свободного интервала `0o2300..0o2477` (`docs/14` §2);
запись идёт только в свежую рабочую копию 2348, эталон
`/usr/local/share/besm6/2348` монтируется только на чтение. Несмотря на
рост числа процедур с 3 до 13, `ДЛИНА LIBRARY` осталась `004 ЗОН` — тела
модулей по-прежнему укладываются в отведённые 4 зоны. Каталог PERSO
вмещает 12 пользовательских модулей; 13-й (`CONJG`) не каталогизируется,
поскольку имя зарезервировано компилятором (§5.7).

### 3.1. Компиляция и запись объекта

Сценарий `tests/run-f77-runtime.sh` строит деку по шаблону
`tests/forex-glissade/glkern.b6`:

```

ееВ1а3

```

Запуск: `BESM6_PATH=<working>:/usr/local/share/besm6 dispak lib.b6`.
Монитор печатает `ДЛИНА LIВRАRУ 004 ЗОН`, `КОНЕЦ ЗАДАЧИ`. Каталог новой
библиотеки разбирается встроенным Python-парсером (TEXT 6 бит/символ,
проверка ненулевого transfer vector и завершателя `0 / FULWORD`).

Расшифровка первой строки (`1X,2F10.4,8I5`):

|---|---|---|
| `2F10.4` | `3.0000`, `7.0000` | `MYABS(-3.5)`, `MYMAX(2.0,7.0)` |
| `8I5` | `9`, `6` | `IMAX0(-4,9)`, `IMAX0(6,2)` |

| | `-1`, `1` | `STRCMP(ABCD,ABCF)`, `STRCMP(ABCF,ABCD)` |

Вторая строка — вывод `FMTLNK(9.0)`. Буквы `В` и `Х` в ней — кириллические
(так диспак декодирует TEXT-символы БЭСМ-6: латинский `B` печатается как
`В`, `X` как `Х`). Это не опечатка; gold записан с побайтового вывода

Третья строка (`1X,12I4`) — 12 целых: `STRCAT` (`65 66 67 68 69 70` =

## 5. Что не получилось / важные ловушки

1. **`*perso:603100,cont` — опечатка в планах.** Формат карты — `LU` (2 восьм.
   знака) + зона (4 восьм. знака). `603100` адресует зону `0o3100`, а не
   `0o2310`: монитор печатает `*** ИСКЛЮЧИТЕ ИЗ ЛИЧНОЙ БИБЛИОТЕКИ…` и
   `ИСПОРЧЕН КАТАЛОГ PERSONAL LIBRARY`, компоновщик — `ОТСУТСТВУЕТ MYABS`.
   Правильная карта: **`*perso:602310,cont`**.

2. **Дубли `FOREX*` и `LO*SYN` в новой библиотеке.** При компиляции
   ФОРЭКСОМ из `*perso:602300` временный каталог задачи уже содержит модули
   базовой библиотеки; `*to perso` записывает их вместе с новыми. Каталог
   `0o2310` поэтому содержит 14 имён (12 пользовательских + 2 дубля). Это безвредно:
   базовая библиотека не перезаписывается, модули грузятся по последней
   загруженной копии, оба теста проходят. Чистый каталог можно получить
   компиляцией системным ФОРЭКСОМ без `*perso:602300` (проверено для 3
   модулей: `ДЛИНА LIBRARY 003 ЗОН`).

3. **`ИСПОРЧЕНЫ ПОДПРОГРАММЫ:` в логе компиляции.** Появляется на этапе
   `*to perso`, когда монитор выгружает унаследованные из базового каталога
   модули, тела которых не были загружены в память задачи. На загрузку
   скомпилированной программы не влияет: в прогоне `test-runtime.b6`
   предупреждений нет, все процедуры разрешаются.

4. **Hollerith в FORMAT и в DATA.** `PRINT *` неподдерживается; печать строки
   реализована через явный `FORMAT(1X,11H...,F8.3)`. Число после `H` должно
   точно равняться длине строки. `4HABCD` работает в `FORMAT` и как
   `DATA`-константа типа `INTEGER`, но `S=4HABCD` для `CHARACTER` даёт
   `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ` (`07-experiments.md`, exp.5).

5. **`ISIGN` — системное имя.** Попытка определить `INTEGER FUNCTION ISIGN(I)`
   разбирается ФОРЭКСОМ как встроенная двухаргументная функция и даёт
   `ERR 04052 / ОШИБКА В СПИСКЕ АРГ / ЗНАЧЕН. S НЕ ОПРЕДЕЛЕНО`. Переименование
   в `ISGN0` устраняет ошибку; это единственная причина нестандартного имени.

6. **Нереализуемо без правки ассемблера** (по `05-decision.md` §2): новые
   ключевые слова (`IMPLICIT`, `SAVE`, `END=`), list-directed I/O, новые
   edit-дескрипторы. Это задачи E3/E4, не E2.

7. **`CONJG` — тоже системное имя.** В отличие от `ISIGN`, ошибки трансляции
   нет: `FUNCTION CONJG(Z)` компилируется (тело `00017` слов), но `*to perso`
   не заносит его в каталог PERSO — компилятор 2.02 резервирует имя как
   встроенную функцию. Проверено отдельной декой с единственной процедурой:
   каталог `0o2310` пуст. Вызов `CONJG(Z)` в программе разрешается встроенной
   процедурой и даёт `(3,-4)` — контрольное значение совпадает. Попытка
   каталогизировать несистемный псевдоним `CNJG0` также не дала записи:
   каталог PERSO ограничен 12 пользовательскими модулями (уже занятыми).
   Процедура `CONJG` оставлена в исходнике как эталонная форма реестра.

8. **Арифметика над `nH`-константами.** `DATA W/4HABCD/` даёт корректную
   битовую картинку (ASCII-байты в старших разрядах), но `W/256`, `W-W` и
   печать `I`-форматом возвращают `0`; сравнение `W1.LT.W2` работает.
   Поэтому строковые процедуры v3 используют INTEGER-массивы ASCII-кодов.
