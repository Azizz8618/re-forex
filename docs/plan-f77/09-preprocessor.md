## 1. Что делает F77PREP

Программа на подмножестве F77, которую компилирует тот же ФОРЭКС 2.02
(PERSO зоны `0o2300`). Она классифицирует строки исходника по правилам и
печатает числовые записи; host-скрипт `prep_tools.py` материализует текст
`lowered.f77` с comment-якорями `C@ orig -> new`. MARK-формат записей
`777001`/`777002`/`777003` и якоря сохраняются с версии 1 без изменений.

### Версия 1 (три правила)

|rule|шаблон|действие|
|---|---|---|
|0|любая другая строка|оставить как есть|
|1|`IMPLICIT NONE`|удалить (якорь `C@ … -> (removed)`)|
|2|`SAVE …`|удалить (якорь `C@ … -> (removed)`)|
|3|`PRINT *,var`|`PRINT 9000,var` + ` 9000 FORMAT(1X,I10)` (или `F12.4`)|

### Версия 2: новые правила

|rule|шаблон|действие (lowering)|основание|
|---|---|---|---|
|4|`READ(*,*,END=LL) var`|`READ <fmt>,var` **без номера юнита** + якорь; ссылка `END=LL` удаляется с якорем, сам оператор с меткой `LL` остаётся|F1a: `READ 10,X` — единственная рабочая форма ввода карт; явные юниты 1/2/5/6/10/40/45 не читают (`07-experiments.md` §1)|
|5|`DO WHILE (cond)`|`NN CONTINUE` / `IF (.NOT.(cond)) GO TO NN+1` + якорь|lowering на подтверждённые операторы `DO…CONTINUE`, блочный `IF`, `GO TO`, `.NOT.` (`01-gap-analysis.md` §1, пробы 2.02)|
|6|`END DO`|`GO TO NN` / `NN+1 CONTINUE` + якорь (закрывает ближайший `DO WHILE`)|то же; метка `END DO` — признак конца тела цикла|
|7|`CHARACTER*n S`|`INTEGER IS` + якорь; `S` переименовывается в `IS` во всех последующих `PRINT`|E1/§5: тип `CHARACTER` в 2.02 отсутствует; рабочий рецепт `INTEGER I; DATA I/4HABCD/; FORMAT(1X,A4)`|
|8|`S='literal'`|`DATA IS/nHliteral/` + якорь|E1/§5: `nH…` работает как `DATA`-константа; присваивание строке даёт «ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ»|
|3 (расширено)|`PRINT *, A, B`|`PRINT <fmt>,A,B` + `<fmt> FORMAT(1X,I10,I10)` — дескриптор подбирается **по каждой** переменной: `I..N` → `I10`, иначе `F12.4`, `CHARACTER` → `A4`|§1 п.19 форматированный вывод; §2.1 list-directed `PRINT *` отвергнут|

Тип переменной определяется неявным правилом Фортрана (первая буква
`I..N` → INTEGER, иначе REAL). Для rule 3 в записи `777002` передаётся
весь список переменных через запятую; host разбирает его и подбирает
дескрипторы. Для новых правил host восстанавливает детали (условие,
литерал, имя переменной) из исходной строки.

Пример lowering (случай 2):

```
      DO WHILE (N .LT. 3)        C@ DO WHILE (N .LT. 3) -> 7000 CONTINUE /
         READ(*,*,END=99) M        IF (.NOT.(N .LT. 3)) GO TO 7001
         PRINT *, N, M          7000 CONTINUE
         N=N+1                     IF (.NOT.(N .LT. 3)) GO TO 7001
      END DO                    C@ READ(*,*,END=99) M -> READ 9500,M ...
      PRINT *, S                ...  PRINT 9000,N,M / PRINT 9001,IS
                                9500 FORMAT(I10)
                                9000 FORMAT(1X,I10,I10)
                                9001 FORMAT(1X,A4)
```

## 2. Два прохода (механика §1 плана)

Один запуск `dispak` = одна дека `*forex … *execute`, поэтому сценарий —
две деки на каждый случай, склеенные host-скриптом `tests/run-f77-prep.sh`:

1. **Проход 1.** Host (`prep_tools.py deck1`) превращает каждую строку
   `.f77` в 72 ASCII-кода и инъецирует в `F77PREP.FTN` вместо строки-
   маркера `DATA NL /n/` и `DATA C /…/` (1440 констант для 20 строк).
   Дека: `*perso:602300` → `*forex` (F77PREP) → `*execute`.
   F77PREP печатает:
   - `777001 <line> <rule> <itype>` — правило для каждой строки;
   - `777002 <line> <pos> <char-code>` — символы списка переменных
     (только rule 3);
   - `777003 <nlines> <nrewrites>` — итог.
2. **Host.** `prep_tools.py records` разбирает записи, `lower` собирает
   `lowered.f77`: сохраняет неизменённые строки, вставляет `C@`-якоря,
   allocate-ит метки (FORMAT 9000+, циклы 7000+, READ 9500+) и переносит
   все `FORMAT` перед итоговым `END`. Сравнение с `prep-N-expected.f77`.
3. **Проход 2.** `*forex` + `*execute` с `lowered.f77`; для случая 2 между
   `*execute` и `*end file` подаются карты `prep-case2.data`. Вывод
   сравнивается с `prep-N-expected.out`.

Метки allocate-ятся host-ом с проверкой на collide с метками исходника;
FORMAT-метка READ (`9500`) содержит `I10`/`F12.4` **без** `1X`, метки PRINT
(`9000+`) — с `1X`, как в эталоне версии 1.

### Почему DATA, а не `READ` с карт (проход 1)

E1 (`07-experiments.md` §1): `READ(*,*)` не компилируется
(«НЕДОПУСТИМ СИМВОЛ * В ВЫРАЖ»), `READ(u,fmt)` для юнитов 1–10, 37, 48
даёт «НЕ ЗАКАЗАН ТЕРМ.» или «НЕТ КАНАЛА LUN». Рабочая безъюнитная форма
`READ 10,X` читает карту **после `*execute`**, но на этапе препроцессинга
таких карт нет. Поэтому карты передаются как `DATA`-массив ASCII-кодов,
инъецированный host-скриптом. В версии 2 безъюнитный `READ` применяется
уже в целевом коде (rule 4), где карты подаются в deck2.

### Почему числовые записи, а не печать текста

`PRINT` символьной переменной через `A`/`A4`/`A6` на ФОРЭКС 2.02 даёт
«ОШИБКА СПЕЦИФИКАЦИИ ФОРМАТА» / I/O error 232. Надёжно работает только
`PRINT n, <INTEGER>` с `I`-дескриптором. Поэтому F77PREP выдаёт числа, а
host материализует текст. Строки с префиксом `C@` — корректные комментарии
(колонка 1 = `C`), проход 2 компилирует их без ошибок.

## 3. Source map

Перед каждым преобразованным фрагментом вставляется якорь
`C@ <orig> -> <new>` (для rule 4 добавляется `(END= label removed)`,
для rule 6 — `GO TO … / … CONTINUE`, для FORMAT —
`C@ (end of program) -> …`). Якоря не влияют на выполнение, но позволяют
(a) сверять lowering с эталоном и (б) сопоставлять диагностику прохода 2
с исходной строкой. Полный map пишется в
`logs/f77_prep_v2_lowered_case{1,2}.f77`.

## 4. Ограничения

- не более 20 исходных строк (`C(72,20)`) и 72 колонки в строке;
- `PRINT *` — только числовые скаляры и `CHARACTER`-скаляры, без выражений
  и массивов; число переменных не ограничено, но каждая получает отдельный
  дескриптор в GENERAL FORMAT;
- шаблоны распознаются от первой непробельной колонки (fixed-form, 6
  ведущих пробелов), без полного парсинга выражений;
- `IMPLICIT NONE`/`SAVE` удаляются **без анализа семантики**;
- rule 4: поддерживается только каноническая форма `READ(*,*,END=LL) var`
  с одной скалярной переменной; метка `LL` не удаляется из программы —
  удаляется только ссылка `END=LL`; для чтения нужны реальные карты в
  `deck2` (необязательный аргумент `DATA` у `prep_tools.py deck2`);
- rule 5/6: `DO WHILE` обязательно закрывается `END DO`; вложенные циклы
  поддерживаются (стек меток); условие переносится в `IF (.NOT.(…))` как
  есть, без проверки типов;
- rule 7/8: только простые присваивания строковых литералов длиной **1–4
  символа**, без кавычек внутри и без конкатенации; подстановка имени —
  `I` + исходное имя (усечение до 6 знаков); печать — только `A4`;
- `АВСD` вместо `ABCD` в выводе — артефакт декодирования TEXT-символов
  dispak (`B`→`В`, `X`→`Х`), не ошибка программы (`07-experiments.md` §5);
- диагностика `АТТ: F77PRE УКОРОЧЕН` при компиляции препроцессора — benign;
- базовая PERSO-зона `0o2300` не перезаписывается: в рабочую копию диска
  2348 записывается готовый `build/FOREX_PERSO_2300.bin`.
