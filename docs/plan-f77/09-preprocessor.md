# 09. F77PREP — минимальный Fortran-preprocessor (этап E3)

Дата: 19.11.2026. Статус: **реализовано и проверено** (`tests/run-f77-prep.sh`,
rc=0). Исходники: `src/f77prep/F77PREP.FTN`, `src/f77prep/prep_tools.py`.
Тест: `tests/f77/prep-case.f77`, `tests/f77/prep-expected.f77`,
`tests/f77/prep-expected.out`. Логи: `logs/f77_prep_*.txt`.

## 1. Что делает F77PREP

Программа на подмножестве F77, которую компилирует тот же ФОРЭКС 2.02
(PERSO зоны `0o2300`). Применяет только три подтверждённо необходимых
преобразования из `03-fortran-path.md` §0:

|rule|шаблон|действие|
|---|---|---|
|0|любая другая строка|оставить как есть|
|1|`IMPLICIT NONE`|удалить (comment-якорь `C@ … -> (removed)`)|
|2|`SAVE …`|удалить (comment-якорь `C@ … -> (removed)`)|
|3|`PRINT *,var`|`PRINT 9000,var` + добавить ` 9000 FORMAT(1X,I10)` (или `F12.4` для real)|

**Не делается** (уже работает на 2.02, см. `03-fortran-path.md` §0):
`END IF` → labeled IF, `COMPLEX` → 2 REAL, `DOUBLE PRECISION` → REAL.

Тип переменной для выбора `I`/`F` определяется по неявному правилу Фортрана:
первая буква `I..N` → INTEGER (`I10`), иначе REAL (`F12.4`). Поддерживается
**одна числовая переменная** в `PRINT *`.

## 2. Два прохода (механика §1 плана)

Один запуск `dispak` = одна дека `*forex … *execute`, поэтому сценарий —
две деки, склеенные host-скриптом `tests/run-f77-prep.sh`:

1. **Проход 1.** Host (`prep_tools.py deck1`) превращает каждую строку
   `prep-case.f77` в 72 ASCII-кода и инъецирует в `F77PREP.FTN` вместо
   строки-маркера `DATA NL /8/` и `DATA C /…/` (1440 констант).
   Дека: `*perso:602300` → `*forex` (F77PREP) → `*execute`.
   F77PREP печатает числовые записи:
   - `777001 <line> <rule> <itype>` — правило для каждой строки;
   - `777002 <line> <pos> <char-code>` — символы имени переменной;
   - `777003 <nlines> <nrewrites>` — итог.
2. **Host.** `prep_tools.py records` разбирает записи, `lower` собирает
   `lowered.f77`: сохраняет исходные строки, вставляет `C@`-якоря и формат
   `9000` перед итоговым `END`. Сравнение с `prep-expected.f77`.
3. **Проход 2.** `*forex` + `*execute` с `lowered.f77`; вывод сравнивается с
   `prep-expected.out`.

### Почему DATA, а не `READ` с карт

Е1-эксперименты (`07-experiments.md`) ещё не созданы. Прямые пробы показали,
что FOREX 2.02 **не может прочитать поток карт после `*execute`**:
`READ(*,*)` не компилируется («НЕДОПУСТИМ СИМВОЛ * В ВЫРАЖ»), а
`READ(u,fmt)` для юнитов 1–10, 37, 48 даёт `*70` («НЕ ЗАКАЗАН ТЕРМ.») или
«НЕТ КАНАЛА LUN». Поэтому карты передаются в программу как **`DATA`-массив
ASCII-кодов**, инъецированный host-скриптом. Это не требует проверки Fortran-юнитов
и полностью укладывается в поддерживаемое подмножество. Когда E1 найдёт
рабочий юнит, точку ввода можно заменить на `READ` без изменения правил.

### Почему числовые записи, а не печать текста

`PRINT` символьной переменной через `A`/`A4`/`A6` на ФОРЭКС 2.02 даёт
«ОШИБКА СПЕЦИФИКАЦИИ ФОРМАТА» / I/O error 232. Надёжно работает только
`PRINT n, <INTEGER>` с `I`-дескриптором и Hollerith-константы в `FORMAT`.
Поэтому F77PREP выдаёт **числа**, а host-скрипт материализует текст.
Строки с префиксом `C@` в `lowered.f77` — уже понятные ФОРЭКСУ комментарии
(колонка 1 = `C`), поэтому проход 2 компилирует их без ошибок.

## 3. Source map

Перед каждым преобразованным фрагментом вставляется comment-якорь вида
`C@ <orig> -> <new>`:

```
C@ IMPLICIT NONE -> (removed)
C@ SAVE N -> (removed)
C@ PRINT *,N -> PRINT 9000,N
      PRINT 9000,N
C@ (end of program) -> 9000 FORMAT(1X,I10)
 9000 FORMAT(1X,I10)
```

Якоря не влияют на выполнение, но позволяют (а) сверять lowering с эталоном
и (б) при ошибке прохода 2 сопоставить номер строки/comпиляторную
диагностику с исходной строкой. Полный map пишется в
`logs/f77_prep_lowered.f77`.

## 4. Ограничения

- не более 20 исходных строк (`C(72,20)`) и 72 колонки в строке;
- `PRINT *,var` — ровно одна числовая переменная, без выражений и массивов;
- шаблоны распознаются от первой непробельной колонки (fixed-form, 6
  ведущих пробелов), без полного парсинга выражений;
- `IMPLICIT NONE`/`SAVE` удаляются **без анализа семантики**: `SAVE` меняет
  поведение (сохранение значения между вызовами) — пригодно только для
  программ, где это несущественно;
- диагностика `АТТ: F77PRE УКОРОЧЕН` при компиляции препроцессора — benign:
  программа работает и выдаёт корректные записи (проверено rc=0, 8/8
  правил + 1 rewrite);
- базовая PERSO-зона `0o2300` не перезаписывается: в рабочую копию диска
  2348 записывается готовый `build/FOREX_PERSO_2300.bin`, как в
  `tests/run-glissade-forex.sh`.
