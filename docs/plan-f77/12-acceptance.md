# 12. Приёмка F77-поддержки (этап E5)

Прогон: `tests/run-f77-suite.sh`, лог `logs/f77_suite.txt`,
кросс-лог `logs/f77_cross_ftn.txt`. Дата прогона: 2026-11-19.

Контур: системный ФОРЭКС 2.02 на диске 2048, свежая рабочая копия эталона
`/usr/local/share/besm6/2348` с PERSO-библиотекой `build/FOREX_PERSO_2300.bin`
в зоне `0o2300`; каждый дек грузит `*perso:602300` (LUN 60 — рабочая копия
`2348-wr`). Даты нормализуются `DD.DD.DD` → `##.##.##`; сравнивается только
блок результата перед `КОНЕЦ ЗАДАЧИ` с `<case>.gold`.

## 1. Критерии приёмки

| Критерий | Ожидается | Факт |
|---|---|---|
| Все деки компилируются и исполняются (`rc=0`, без `БЫЛИ ОШИБКИ`, `ERR nnn`, `АТТ`, `ТИП ОП-ДА`) | 8/8 | 8/8 |
| Побайтовое совпадение блока вывода с gold после нормализации даты | 8/8 | 8/8 |
| Кросс-сверка той же программы через `*FTN` (Fortran-ГДР, диск 2048): числовые значения с допуском 1e-5 | 3/3 | 3/3 |
| Отсутствие расхождений между ФОРЭКС и `*FTN` в кросс-случаях | 0 | 0 |
| При отсутствии dispak/образов сценарий печатает `ОЖИДАЕТСЯ` и возвращает 0 | да | да (проверка кода: ветка prerequisites) |

Итог сценария: `Итог: 8/8 случаев OK; кросс-сверка *FTN: 3/3`,
`OK: F77 suite пройден полностью`, `rc=0`.

## 2. Таблица случаев

| Случай (`tests/f77/suite/`) | Подтверждённая возможность | Контрольные значения (gold) | Результат |
|---|---|---|---|
| `base.b6` / `base.gold` | BASE: `INTEGER`/`REAL`, счётный `DO`, явный `FORMAT(I,F)` | `21  1.00  3.00` | OK |
| `blockif.b6` / `blockif.gold` | `BLOCK IF/THEN/ELSE/ENDIF`, вложенный `ELSE` | `3.00`, `4.00` | OK |
| `do2d.b6` / `do2d.gold` | `DIMENSION A(3,4)`, `DATA`, вложенные `DO`, индексация 2D | `22.00`, `26.00`, `30.00` (суммы строк; `DATA` по столбцам) | OK |
| `dataparam.b6` / `dataparam.gold` | `PARAMETER (N=4)`, `DATA V/.../`, `DATA R/2.5/` | `10  2.50  4` | OK |
| `dpcomplex.b6` / `dpcomplex.gold` | `DOUBLE PRECISION` (`1.0D0`, `D22.15`), `COMPLEX`, `CABS`, `2F10.4` | `1.414213562371515+000`, `3.333333333333333-001`, `-5.0000 10.0000`, `5.0000` | OK |
| `intrinsics_ext.b6` / `intrinsics_ext.gold` | `SQRT`, `ABS`, `AMOD` + вызов внешней `FUNCTION MYFUN`, определённой в той же деке | `4.0000  3.5000  1.0000  10.0000` | OK |

| `charhollerith.b6` / `charhollerith.gold` | CHARACTER-рецепт без `CHARACTER`: `INTEGER I; DATA I/4HABCD/`, `FORMAT(1X,A4)` | `АВСD` | OK |

Все деки содержат `PROGRAM ...` — это позволяет компилировать **тот же
исходник** системным `*FTN` без правки (Fortran-ГДР требует первый оператор
`PROGRAM`).

## 3. Кросс-сверка с Fortran-ГДР

Случаи перечислены в `tests/f77/suite/cross-ftn.txt`. Сценарий вырезает
Fortran-исходник из `.b6`, собирает дек с `*system`/`*full list`/`*ftn`,
компилирует его на диске 2048 и сравнивает числа из блока результата с
результатом ФОРЭКС (regex по числам, `D`/`E`-экспоненты нормализуются,
допуск `max(1e-6, 1e-5·|x|)`).

| Случай | Формы вывода ФОРЭКС / `*FTN` | Чисел | Расхождений |
|---|---|---|---|
| `base` | `21  1.00  3.00` / то же | 3 | 0 |
| `do2d` | `22.00 / 26.00 / 30.00` / то же | 6 | 0 |
| `intrinsics_ext` | `4.0000 3.5000 1.0000 10.0000` / то же | 4 | 0 |

Подробности — `logs/f77_cross_ftn.txt`. Расхождений нет; если они появятся,
сценарий пишет в лог строки `CROSS FAIL` с обоими наборами чисел и возвращает 1.

## 4. Известные расхождения и границы подмножества

1. **`CHARACTER` как тип** на 2.02 не компилируется (`ТИП ОП-ДА НЕ СООТВЕТ
   ОПЕРАЦ`, проба `CHARSTAR`; на 4.13 `CHARACTER*30` работает — версионная
   зависимость). Приёмка использует Hollerith-рецепт `INTEGER I; DATA I/4HABCD/`
   + `FORMAT(1X,A4)`, который работает и даёт `АВСD`.
2. **List-directed I/O** (`PRINT *`, `READ(*,*,END=)`) системным ФОРЭКСОМ не
   поддерживается (`ОШИБКА В ССЫЛКЕ НА ФОРМАТ`, `НЕДОПУСТИМ СИМВОЛ *`).
   Покрыт только через F77PREP: исходник `listio.f77` → `listio.b6` с явным
   `FORMAT`. Препроцессор заменяет `PRINT *,...` на `PRINT nnnn,...` с явным
   `FORMAT` из зарезервированного диапазона меток (здесь 9000) и выбирает
   `I10` для целых / `F12.4` для вещественных / `A4` для Hollerith-строк.
   Приёмка использует минимальный случай с одной целой переменной.
3. **`IMPLICIT NONE`, `SAVE`, `END=`, `DO WHILE`, `END DO`, `CHARACTER*n`** —
   новые ключевые слова/атрибуты, системным ФОРЭКСОМ 2.02 не компилируются
   (`НЕДОПУСТИМ КЛЮЧ СЛОВО`). F77PREP v2 умеет понижать их (правила 1, 2, 4–7),
   но в приёмочный набор входит только list-directed `PRINT *` (правило 3);
   остальные правила проверяются сценарием E3 `tests/run-f77-prep.sh`.
4. **Двойная точность в `F`-формате** (`FORMAT(1X,F16.12)` с `DOUBLE PRECISION`)
   даёт `I/О-ЕRRОR 227` (`tests/plan-f77/e1/precision/dp_f_format/`). В приёмке
   используется подтверждённый `D22.15`.
5. **Внешние библиотечные процедуры F77LIBR** (`MYABS`, `MYMAX`, `FMTLNK` из
   зоны `0o2310`) проверяются отдельным сценарием E2 `tests/run-f77-runtime.sh`
   (в текущем логе `logs/f77_runtime_run.txt` gold и fact совпадают), поэтому в
   данный самодостаточный набор не включены. Случай `intrinsics_ext` проверяет
   внешний вызов через пользовательскую `FUNCTION`, определённую в той же деке,
   — механика вызова внешней Fortran-процедуры при этом та же.
6. **Dhrystone/Whetstone** из критерия E5 (`docs/plan-f77/05-decision.md`,
   строка 65) в данном пакете не прогоняются: контрольные числа DMIPS/MWIPS
   требуют отдельных дек из `besm6.net/examples/`. Это отдельный пункт,
   не закрытый данным набором.

## 5. Воспроизведение

```sh
cd /tmp/.private/azizz/opencode/re-forex
tests/run-f77-suite.sh        # сценарий сам пишет оба лога
cat logs/f77_suite.txt
cat logs/f77_cross_ftn.txt
```

Переопределения: `DISPAK_BIN`, `BESMTOOL`, `ETALON`, `IMAGE`, `TIMEOUT`.
Отсутствие dispak, `besmtool`, эталона диска или PERSO-образа → `ОЖИДАЕТСЯ`,
`rc=0` (не падение).
