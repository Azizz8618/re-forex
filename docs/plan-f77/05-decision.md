# Решение: модификация ФОРЭКС под FORTRAN 77

## 1. Исходные данные (факты)

- Всего 16 проб системного ФОРЭКС 2.02 (`tests/plan-f77/probe.sh`,
  `logs/plan_f77_probes.txt`): после исправления фильтра ошибок —
  **10 OK / 5 FAIL** (плюс базовые). Диагностика ФОРЭКСА включает не только
  `ОШИБКА`/`НЕДОПУСТИМ`, но и `АТТ …`, `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`, `ERR nnn`.
- **Работает на 2.02:** `DO`, `BLOCK IF/THEN/ELSE/ENDIF`, `DOUBLE PRECISION`
  (`1.0D0`, `SNGL`), `COMPLEX`, `DATA`, `PARAMETER`, `LOGICAL`, `SQRT/ABS`,
  вызов необъявленной внешней функции (`FOO(2.0)` → внешняя ссылка).
- **Не работает на 2.02:** `PRINT *` (list-directed I/O), `READ(*,*,END=)`,
  `IMPLICIT NONE`, `SAVE`, `CHARACTER` (на 4.13 Dhrystone подтверждает
  `CHARACTER*30` — версионная зависимость).
- Архитектура (`02-extension-points.md`): `INITFO` → `LODOVL` → `LO*SYN`
  (лексика/синтаксис, таблица автомата 1517..1777) → `LO*GEN` (генератор,
  таблица из 29 пар «дескриптор+TEXT-имя» 0532..0623) → `FORMAT/FORTLIBR`.
  Оба оверлея грузятся по одному адресу `0o22654`, без релокации, строго по
  1024 словам.
- Соглашение вызова совместимо с внешними Fortran-процедурами: аргументы через
  блок по M16/M14/M7, возврат через M13/M15. Пробы `FOO`, `SIN/MOD/EXP` проходят.

## 2. Ответ на главный вопрос

**Можно ли обойтись Fortran-модулями?** Частично — да:

| Задача | Достаточно Fortran? | Комментарий |
|---|---|---|
| Новые intrinsic-функции (`MYFUN`) | Да | внешняя Fortran-процедура, подключается `*PERSO:...,CONT` |
| Новая реализация I/O внутри существующего `FT*` | Да | `FORMAT`/`FORTLIBR` уже таблица процедур |
| List-directed `PRINT *` / `READ *` | Нет | нужна правка синтаксиса + генератора |
| `IMPLICIT NONE`, `SAVE`, `END=` | Нет | новые ключевые слова/атрибуты — только MADLEN |
| `DO WHILE`, `CHARACTER` на 2.02 | Нет (или preprocessor) | MADLEN либо source-to-source lowering |
|Inline-генерация часто используемых конструкций | Нет | требуется правка `LO*GEN` |

**Вывод:** чистый «Fortran-only» путь возможен только если все расширения
выражаются через уже поддерживаемый синтаксис + внешние процедуры. Как только
меняется *поверхность языка* (ключевые слова, синтаксис, новые edit-дескрипторы
FORMAT), без ассемблера (MADLEN) не обойтись — либо нужен Fortran-preprocessor,
который переводит новый синтаксис в поддерживаемый подмножество.

## 3. Выбранная стратегия — гибрид

1. **Для проверяемости:** основной контур — Fortran-процедуры и
   source-to-source preprocessor `F77PREP` на самом БЭСМ-6 (`03-fortran-path.md`).
   Все изменения читаемы, компилируются штатным ФОРЭКСОМ и покрываются gold-тестами.
   Preprocessor платит только за компиляцию, не за выполнение.
2. **Для эффективности:** минимальный «позвоночник» на МАДЛЕН — только там, где
   вызов процедуры на каждом операторе недопустим (inline-генерация в `LO*GEN`,
   новые табличные записи, ключевые слова в `LO*SYN`). Оценка — 10–90 слов на
   правку (`04-assembler-path.md`).
3. **Совместимость:** базовый 9-модульный PERSO-образ зоны `0o2300` и тест
   Глиссады 14/14 не трогаются; новые модули пишутся в отдельную библиотеку
   зоны `0o2310` и подключаются `*PERSO:603100,CONT`.

## 4. Этапы

| Этап | Работа | Критерий готовности |
|---|---|---|
| E0 | Зафиксировать текущее состояние: 16 регрессионных сценариев, контрольные векторы Dhrystone/Whetstone/Глиссада | все rc=0, SHA зафиксированы |
| E1 | 5 экспериментов из приложения B `03-fortran-path.md` (I/O юниты, вставка `ERR`, `*call` к Fortran-объекту, точность DP/COMPLEX, запись строк) | каждый имеет воспроизводимый deck и вывод |
| E2 | Fortran-рантайм `F77LIBR` с новыми intrinsic/I/O-процедурами в зоне `0o2310` | внешние функции вызываются из обычной FORTRAN-программы |
| E3 | `F77PREP` — Fortran-preprocessor для неподдерживаемого синтаксиса; source map | 4 FAIL-пробы преобразуются в поддерживаемый вид, листинг содержит `C@`-разметку |
| E4 | Минимальные MADLEN-правки: inline-генерация и новые ключевые слова | оверлей остаётся ровно 1024 слова, opcode-сверка, golden SHA, регрессия |
| E5 | Приёмка: полный набор F77-тестов + sliding-window сравнение с `*FTN`/`*FORTRAN` | 100% gold-пар, совпадение контрольных чисел Dhrystone |

## 5. Проверяемость

- **Уровень 0:** SHA256 эталонных decks/выводов и PERSO-образа.
- **Уровень 1:** сравнение поля КОП 6-бит в каждой паре слов (симтаблица может отличаться).
- **Уровень 2:** homeomorphic mapping меток (старое ↔ новое имя).
- **Уровень 3:** функциональные gold-тесты (FOREX.out ↔ etalon).
- **Уровень 4:** кросс-компиляция той же программы `*FTN`/`*FORTRAN` и сверка чисел.
- Локализация ошибок preprocessor'а: `C@ orig -> new` в листинге + `map.txt` →
  `ERR nnn ПК K` исходной строки.

## 6. Эффективность

- Преимущество inline-генерации: отсутствие `VJM`/передачи аргументов на оператор.
- Внешние Fortran-процедуры допустимы для редких возможностей, но **не в hot loop**
  (`**` уже компилируется как `ПВ ROWER` — приемлемо).
- Preprocessor выполняется один раз на этапе компиляции, не влияет на runtime.
- `DOUBLE PRECISION` и `COMPLEX` уже поддерживаются аппаратно/генератором — **не lowering'овать**,
  это только ухудшит код.

## 7. Риски

- 6-символьная коллизия имён >6 символов — молчаливое слияние (`P0` в gap-анализе).
- Оверлеи без релокации: любая правка должна сохранить ровно 1024 слова.
- Симтаблица при обратной сборке: полная байтовая идентичность недостижима
  (`docs/05-roundtrip.md`) — поэтому проверка многослойная (§5).
- Конфликт имён с постоянной библиотекой монитора (урок `OCTTDE*`, `DATAPRX`):
  новые имена ≤6 символов и не системные.

## 8. Ближайшие шаги

1. Выполнить E0 и E1.
2. Собрать `F77LIBR` с 2–3 процедурами и проверить вызовы (E2).
3. Написать минимальный `F77PREP` для `IMPLICIT NONE`/`SAVE` (удаление атрибутов)
   и list-directed I/O (перевод в явный FORMAT), затем расширять по результатам E1.
