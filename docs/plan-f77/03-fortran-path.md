# 03. Расширение ФОРЭКС до FORTRAN 77 **без правки ассемблера**

Дата: 19.11.2026. Статус: **проект/разведка** (ни один исходник `src/*.mad`,
`include/*` или эталон не изменён). Лог разведки: `logs/plan_f77_fortran.txt`.

Рассматриваются два взаимодополняющих пути, оба поверх **уже работающего** конвейера
«PERSO `0o2300` → `*forex` → `*execute`» (`tests/run-glissade-forex.sh`, rc=0,
14/14 строк):

1. **Fortran-preprocessing** — программа на Фортране, скомпилированная тем же
   ФОРЭКСОМ, читает исходник F77 и выдаёт подмножество, понятное текущему
   компилятору (§1).
2. **Runtime library** — новые intrinsic и I/O-процедуры как внешние
   Fortran-процедуры в PERSO, подключаемые `*PERSO:...,CONT` (§2).

§3 — проверяемость, §4 — эффективность. В §0 сначала фиксируется **важная
корректировка посылки**: часть «неподдерживаемых» конструкций на самом деле
компилируется, а часть «поддерживаемых» — нет.

## 0. Что ФОРЭКС 2.02 реально понимает (корректировка посылки)

В репозитории уже есть пробы `tests/plan-f77/probe.sh` и
`logs/plan_f77_probes.txt`. Их авто-классификация **недостоверна**: фильтр
искал `ERROR|ОШИБКА|НЕДОПУСТИМ|UNRECOGNIZED`, а ФОРЭКС печатает ошибки как
`ERR 03106 ПК 2` / `АТТ 00305 ПК 4` / `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`. Прямой
подсчёт этих строк по `tests/plan-f77/work/*/out.txt` даёт:

| Конструкция | Результат | Комментарий |
|---|---|---|
| `PROGRAM`/арифметика/`PRINT`/`FORMAT` | OK | базовый тест `BASE` |
| `DO 10 I=1,5` / `CONTINUE` | OK | |
| **`IF (X .GT. 0.) THEN … ELSE … ENDIF`** | **OK** | block-IF уже компилируется; *не требует* опускания в labeled IF |
| **`DOUBLE PRECISION X`, `X=1.0D0`, `SNGL(X)`** | **OK** | компилируется; вопрос только в точности арифметики |
| **`COMPLEX Z`, `Z=(1.0,2.0)`** | **OK** | компилируется; `COMPLEX → 2 REAL` не нужен |
| `LOGICAL L`, `.TRUE.`, `IF (L) GOTO` | OK | |
| `PARAMETER (N=5)`, `DATA N/5/` | OK | |
| `SQRT`, `ABS` (intrinsic) | OK | |
| `X=FOO(2.0)` без объявления `FOO` | OK | **неизвестное имя → внешняя ссылка**: важный факт для §2 |
| `CHARACTER*10 S`, `S="ABCDE"`, `FORMAT(1X,A)` | **FAIL** | двойные кавычки → `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`; `A` → `ДОЛЖНА БЫТЬ ЦИФРА` (нужен `A4`). Сам тип `CHARACTER*10` компилируется |
| `PRINT *,N` (list-directed) | **FAIL** | `ОШИБКА В ССЫЛКЕ НА ФОРМАТ` |
| `READ(*,*,END=99) X` | **FAIL** | `НЕДОПУСТИМ СИМВОЛ * В ВЫРАЖ` |
| `IMPLICIT NONE` | **FAIL** | `НЕДОПУСТИМ КЛЮЧ СЛОВО` |
| `SAVE N` | **FAIL** | `НЕДОПУСТИМ КЛЮЧ СЛОВО` |

**Следствие для проектируемого препроцессора.** Приоритет оптимизаций
следует переставить:

- **Не трогать** `END IF`, `COMPLEX`, `DOUBLE PRECISION`, `LOGICAL`,
  `PARAMETER` — они уже работают. Опускание `END IF` в `IF+GO TO` и разбиение
  `COMPLEX` на два `REAL` **ухудшат** результат (добавят метки и операторы,
  могут сломать уже работающий код).
- **Опускать реально нужно:** `PRINT *`/`READ *` → `PRINT/READ <fmt>,…` +
  вызов процедуры форматирования (§2); `IMPLICIT NONE` и `SAVE` → удалить/
  заменить инициализацией через `DATA` (для `SAVE` это меняет семантику —
  только с оговоркой); `END=`/`ERR=` → заменить на проверку статуса после
  `READ`; двойные кавычки → Hollerith `nH…` либо одинарные (проверить);
  дескриптор `A` → `A4`/`Aw`.
- **Семантические дыры**, которые компилятор проглатывает, но поведение надо
  проверять численно: точность `DOUBLE PRECISION` (БЭСМ-6 имеет одно слово
  48 бит; `D`-литерал, вероятно, усекается), `COMPLEX`-intrinsics
  (`CABS`, `CSQRT` — нет в таблице `LIBREFER`), `CHARACTER`-substring
  (отдельный тест с корректной записью строки).

> Рекомендация родительскому агенту: перед реализацией препроцессора
> переписать `tests/plan-f77/probe.sh` так, чтобы он ловил `ERR`/`АТТ`, и
> добавить пробы с численным выводом (`PRINT` результата). Это сэкономит
> реализацию трёх ненужных правил lowering.

## 1. Путь A: Fortran-preprocessing на самом БЭСМ-6

### 1.1. Идея и границы

Препроцессор `F77PREP` — обычная Fortran-программа, которую компилирует тот же
ФОРЭКС (можно писать **в уже поддерживаемом подмножестве** из §0, поэтому
«куриное яйцо» не возникает). Она:

1. читает исходный текст F77 как данные (массив `LINE(500)` из 72-х
   символов — символьные строки в ФОРЭКСе пока используем только как
   `INTEGER*`-массив слов или через поддерживаемый `CHARACTER*n` после
   отдельной пробы);
2. для каждой строки применяет упорядоченный набор правил (таблица
   `RULE → old → new`), Присваивает номера **генерируемым** меткам из зарезервированного
   диапазона, чтобы не пересечься с метками пользователя;
3. выдаёт на выходе корректный **fixed-form** Fortran (колонки 1–5 — метка,
   колонка 6 — продолжение, 7–72 — оператор), плюс комментарии-метки
   `C@ <orig>:<new>` для source map;
4. пишет отдельную карту/строку-завершитель `C@END` и countable summary
   (`C@STAT <nlines> <nrewrites>`) для контроля.

Правила должны быть **контекстными, но простыми**: один проход слева направо,
без полного парсинга выражений. Достаточно распознавать *начало оператора*
(первое слово после колонки 6) и шаблоны вида `PRINT *`, `READ(...,END=...)`.
Это реализуемо на Фортране без рекурсии и динамической памяти.

### 1.2. Где хранить

| Что | Путь | Примечание |
|---|---|---|
| Исходник препроцессора (Fortran, подмножество F77) | `src/f77prep/F77PREP.FTN` | новый каталог; **не** `src/*.mad` |
| Правила/тестовые случаи | `tests/plan-f77/cases/<CASE>/orig.f77`, `gold.txt`, `map.expect` | рядом с уже существующими `work/`-пробами |
| Скомпилированный объект | `build/F77PREP.words` (git-ignored) иlikes DMS-модуль в `build/FOREX_PERSO_2300.bin` | собирается ФОРЭКСОМ, **без ассемблера** |
| Каталожное имя в PERSO | **`F77PREP`** (6 знаков ≤ лимита МАДЛЕН) | см. предупреждение об именах ниже |
| Зона в PERSO | отдельная мини-библиотека в `0o2310` (свободный интервал до `0o2477`) | чтобы не трогать эталонные 9 модулей из `tests/run-glissade-forex.sh` |

**Важно про имена.** Каталог PERSO хранит 8 TEXT-символов, но МАДЛЕН и
компилятор различают только первые **6** знаков (`docs/11-runtime-disasm.md` §2,
`docs/14-perso-write.md` §1.2). Поэтому имена новых модулей и процедур
должны быть ≤6 знаков и уникальны первыми шестью: `F77PREP`, `FMTNEW`,
`STRCAT`, `DABS*` и т.п. Имя `F77PREPROC` слетит до `F77PRE` и может
коллидировать.

**Важно про конфликты.** `docs/16-glissade-run.md`: дубликат имени с
системной библиотекой (OCTTDEC) даёт `ИСПОРЧЕНА ПОДПРОГРАММА`. Новые имена
должны быть заведомо не-system: `F77PREP`, `FT*NEW` (если `* name` допустим),
`MY*FUN`.

### 1.3. Вызов в deck: два прохода

Один запуск `dispak` = один цикл `*forex … *execute` (проверено всеми деками
репозитория). Поэтому «preprocessor → FOREX → EXECUTE» реализуется как
**две деки, склеенные host-скриптом** `tests/plan-f77/run-f77.sh`:

**Проход 1 — preprocessor (компиляция препроцессора + его запуск):**

```
шифр 419999 зс5^
лен 60(2348)^
ееВ1а3
*name Prep1
*call yesmemory
*perso:602300            ; базовая библиотека (FOREX*, FORMAT, …)
*full list               ; сохраняем листинг компиляции самого препроцессора
*forex
<src/f77prep/F77PREP.FTN, подставляется script-ом>
*execute                 ; запуск F77PREP
<оригинальный F77-исходник пользователя (карты)>
*end file
``````
еконец
```

F77PREP читает карты **после `*execute`** (как описано в `docs/14` §5.2) и
выдаёт lowering-текст. Способы передачи текста в проход 2 (по приоритету):

| Способ | Механика | Статус |
|---|---|---|
| a) Печать + маркер |_PREP_ печатает каждую выходную строку с префиксом `C@` (или читаемым маркером); host-скрипт вырезает строки из `dispak -o pass1.out` и пишет `lowered.f77` | **рекомендуется**: не требует проверки Fortran-юнитов |
| b) Вставка файла `` `N `` | `dispak` подставляет содержимое `punch.inN` для строки `` `N `` (`whetstone.b6:26-28`) | требует 10-строчного experiments: работает ли на текстовых строках, а не только на бинарном punch-object |
| c) Fortran `WRITE` в дисковый файл | юнит → файл на LU 40/60 | **не проверено**; назначение юнитов в ДИСПАК надо выяснять отдельно |

**Проход 2 — FOREX + EXECUTE:**

```
шифр 419999 зс5^
лен 60(2348)^
ееВ1а3
*name Target
*call yesmemory
*perso:602300            ; компилятор
*perso:603100,cont       ; ← мини-библиотека с новыми runtime-процедурами (§2)
*full list
*forex
<lowered.f77, подставлено host-скриптом>
*execute
*end file
``````
еконец
```

Если нужные runtime-процедуры уже лежат в **`0o2300`** (пересобранный образ),
вторая карта `*perso:603100,cont` не нужна. Если препроцессор хранится как
готовый DMS-объект, проход 1 можно ускорить: загрузить `*perso:603100` и
вызвать `*call f77prep` вместо компиляции исходника — но это требует
проверки, что `*call` применим к Fortran-объекту (для `PLCATALOG` он
работает, `docs/15` §5); до проверки использовать полную компиляцию.

### 1.4. Отладочные листинги и source map

- Оба прохода запускаются с `*full list`; stdout сохраняется в
  `tests/plan-f77/work/<CASE>/pass1.lst`, `pass2.lst` (уже так делает
  `tests/run-glissade-forex.sh` → `output.new.txt`, `logs/glissade_run_full.txt`).
- Препроцессор обязан вставлять в выход **comment-якорь** перед
  каждым преобразованным фрагментом:
  ```
  C@ 12 -> 18,19  IF-THEN
  ```
  Якорь — обычный Fortran-комментарий (`C` в колонке 1), поэтому ФОРЭКС
  переносит его в листинг без ошибки (см. как комментарии `C----` переносятся
  в `output.gold.txt`, строки 1–3). Это даёт видимую привязку «оригинальная
  строка → строки листинга ФОРЭКСа» без внешних файлов.
- Одновременно скрипт собирает `C@`-строки из `pass1.out` в
  `tests/plan-f77/work/<CASE>/map.txt`. При ошибке ФОРЭКСа вида
  `ERR 03106 ПК 7` небольшой script ищет `-> … ,7` в `map.txt` и печатает исходную
  строку. Это и есть минимальный **source map preprocessor → FOREX listing**.
- Ни в коем случае не подавать `*no list` в проходе 2 при отладке: без
  листинга исходника привязка невозможна (в пробах `BLOCKIF` это привело к
  `//////` вместо текста программы).

## 2. Путь B: runtime library из Fortran-процедур

### 2.1. Механизм (аналог FORMAT/FORTLIBR)

Факт из пробы `EXTERNAL`: ФОРЭКС **уже разрешает неизвестное имя функции как
внешнюю ссылку**. Значит новая «intrinsic» процедура не требует ни одного
изменения в компиляторе — достаточно, чтобы модуль с таким именем был в
временном каталоге задачи. Это тот же путь, которым работают `FORMAT`
(`FT*571 … FT*003`, 11 точек через LINK `0o74001..0o74013`,
`docs/06-address-map.md` §3.1) и `FORTLIBR` (`PRINT8`, `WRITLIBR`).

Рецепт:

1. Пишем процедуру на Фортране в подмножестве ФОРЭКСа, например
   ```
   function dabs2(x)
   dabs2 = abs(x)          ! пример; имя ≤ 6 знаков
   return
   end
   ```
2. Компилируем ФОРЭКСОМ (`*forex` + исходник), получаем DMS-объект.
3. Добавляем объект в мини-PERSO-библиотеку зоны `0o2310` через
   `*to perso:40 2310` (`docs/14` §1.3), регистрируя имя в каталоге.
4. В deck: `*perso:602300` (базовая) + `*perso:603100,cont` (новая),
   затем `*forex` пользовательской программы и `*execute`.
5. Пользовательская программа вызывает новую процедуру **по имени**, без
   `EXTERNAL` (проба `EXTERNAL` показала, что объявление не обязательно;
   при желании — с ним, это безвредно).

Соглашение вызовов получается автоматически: и вызывающая программа, и
новая процедура скомпилированы **одним и тем же ФОРЭКСОМ**, поэтому
передача аргументов по адресу (`УИА`/`СЧМ` в листинге ГЛИССАДЫ) и возврат
значения функции совпадают. Это главное преимущество перед написанием
процедур на МАДЛЕНе.

### 2.2. Что реализуемо этим путём

| Класс | Пример | Почему работает |
|---|---|---|
| Новые математические функции | `ERF`, `GAMMA`, `J0`, `DNORM`, `CABS`, `CSQRT` | неизвестное имя → внешняя ссылка; LINK-слот заполняется загрузчиком |
| Новые функции для CHARACTER | `STRCAT`, `SUBSTR`, `ICHAR`, `CHR`, `INDEX2` | реализации на Фортране/через системные DECORDER/BCD-процедуры |
| Новые I/O-процедуры с **именем** | `PRINTL(X)`, `READV(A,N)`, `DUMPA(A,N)` | процедура сама вызывает существующие `FT*nnn`/`PRINT8` (аналог `FORTLIBR`) |
| Доп. сервис | `TIME`, `DATE2`, `MEMFREE`, `TRACEON` | как `DATAPR*`/`OCTTDE*`, но на Фортране |
| Эмуляция list-directed вывода | `CALL PRINTL(...)` + lowering `PRINT *,X` → `CALL PRINTL(X)` | комбинация §1 + §2 |

### 2.3. Что **не** реализуемо без правки ассемблера

| Ограничение | Причина | Обход |
|---|---|---|
| Новое **ключевое слово/оператор** (`IMPLICIT`, `SAVE`, `END=`, `PRINT *`) | разбирается в `LO*SYN` на этапе синтаксиса; процедура не может повлиять на парсер | только preprocessor (§1) |
| Новый **edit descriptor** (`ES`, `EN`, `G`-расширения, `A` без ширины) | FORMAT — это закрытая таблица из 11 `FT*` entry (`UJ FT*nnn / ATX 77xxxB`, `libra211.l21:15565-15586`); замена таблицы = правка ассемблера | preprocessor переписывает дескриптор в поддерживаемый (`A` → `A4`) |
| **Точность DOUBLE PRECISION** | БЭСМ-6 слово 48 бит; арифметика генерируется компилятором, внешняя процедура не изменит формат чисел | preprocessor: масштабирование/парная REAL- арифметика (только если численно доказано расхождение) |
| Inline-генерация intrinsic | компилятор сам решает inline vs call (например `**` → `ПВ ROWER`, см. листинг ГЛИССАДЫ) | можно добавить только **новое имя**, нельзя переопределить генерацию существующего |
| Изменение соглашения вызовов/регистров | фиксировано генератором `LO*GEN` | нельзя; писать процедуру на Фортране и принимать соглашение |

### 2.4. Ограничения проекта сборки

- `*to perso` должна писать в **рабочую** копию (`лен 40(2348-wr)^`), эталон
  `/usr/local/share/besm6/2348` — только на чтение (`docs/14` §3).
- Новые имена не должны совпадать с системными (`OCTTDEC`-прецедент,
  `docs/16` §2).
- `tests/run-glissade-forex.sh` ждёт ровно **9** модулей и завершатель
  `(0, FULWORD)`; если внешние процедуры кладутся в `*общий* образ
  `0o2300`, нужно обновить проверку (9 → 9+K). Если класть в отдельную
  библиотеку `0o2310`, базовый тест **не трогается** — рекомендуемый вариант.

## 3. Проверяемость

### 3.1. Эталонные program + output (основа регрессии)

По образцу `reference/forex.b6` + `output.gold.txt` и
`tests/forex-glissade/glkern.b6` + `output.gold.txt` завести
`tests/plan-f77/cases/<NAME>/{orig.f77,gold.txt,run.sh}` по одному случаю на
**правило lowering**:

| Case | Что проверяет | Ожидаемый вывод |
|---|---|---|
| `BLOCKIF_KEEP` | что препроцессор **не** трогает `IF/THEN/ELSE` | тот же результат, что без препроцессора |
| `DP_KEEP` | `DOUBLE PRECISION` без изменения | число с заданной точностью |
| `CMPLX_KEEP` | `COMPLEX` без разбиения | вещественная/мнимая части |
| `STRQUOTE` | `S='ABCD'` / `4HABCD` вместо `S="ABCD"` | `ABCD` |
| `FMT_AW` | `FORMAT(1X,A4)` вместо `A` | `ABCD` |
| `LISTOUT` | `PRINT *,N` → `CALL PRINTL(N)` | `5` |
| `ENDREAD` | `READ(...,END=99)` → проверка статуса | переход на метку 99 |
| `LOGIC` | `LOGICAL`, `.TRUE.`, `IF(L)…` | ветвление |
| `LABELCLASH` | пользовательские метки 90000–99999 + gенерируемые | компиляция без `DUPLICATE LABEL` |
| `DEEPLY` | вложенные DO/IF, 5 уровней | корректный порядок ветвлений |

Каждый `run.sh` — копия логики `tests/run-glissade-forex.sh`: свежая рабочая
копия 2348, запись зоны `0o2300` (+ `0o2310`), две деки, нормализация дат,
`diff`/`cmp` итогового блока. Критерий — **побайтовое совпадение с gold**
после нормализации даты (как 14/14 в ГЛИССАДЕ).

### 3.2. Сверка с системным Fortran-ГДР и Fortran-Дубна

В `dispak/tests/` есть два независимых компилятора на той же машине:

- `fortran-gdr/fortran-gdr.b6` — `*FTN`, Fortran ГДР;
- `fortran-dubna/fortran-dubna.b6` — `*FORTRAN`/`*super`, Дубна;
- `whetstone/whetstone.b6` — переключатели `FORTRAN / FOREX / FTN /
  *TRANS:FOREX3*,,411550` в одной деке.

Тест: **один и тот же исходник** компилируется (a) FTN, (b) FORTRAN,
(c) FOREX с препроцессором. Сравниваются **численные значения** с
допуском (не байты — форматы и заголовки у компиляторов разные). Это
отделяет «препроцессор ошибся» от «ФОРЭКС считает иначе»: если (a) и (b)
совпадают, а (c) расходится — виноват lowering или рантайм.

### 3.3. Dhrystone / Whetstone

Готовые декы есть в `besm6.net/examples/`:
`dhrystone-{baseline-ftn,forex,pascal}.dub`,
`whetstone-{baseline-ftn,forex,longbottom-forex}.dub`, плюс
`tools/verify_forex_dhrystone.ps1`, `verify_longbottom_whetstone.ps1`.
Использовать в двух режимах:

1. **Корректность:** прогон lowering-версии и сравнение DMIPS/MWIPS и
   контрольных чисел с `*-ftn` и `*-forex` baseline. Dhrystone давит на
   INTEGER/RECORD/CHARACTER, Whetstone — на REAL/`**`/`SQRT`/`EXP`/`ATAN`,
   то есть как раз на зоны риска §0.
2. **Производительность:** измерение накладных расходов (§4) — сравнить
   время счёта до/после препроцессинга и с внешними процедурами.

### 3.4. Позаимствованные и граничные тесты

- **Позаимствованные:** решето Эратосфена (`reference/forex.b6`), HELLO
  (`reference/expect_forex.txt`), ГЛИССАДА (`tests/forex-glissade`), Floating
  point stress из `besm6-new/besm6.net/examples/`. Они уже имеют эталонный
  вывод — это готовые регрессии «ничего не сломалось».
- **Граничные:** пустой исходник; одна строка без `END`; отсутствующий
  `FORMAT`; 72-я колонка и продолжение в колонке 6; метки lengths;
  `nH`-литералы с пробелами; 500+ строк (переполнение массива `LINE`);
  двойное применение препроцессора (идемпотентность: `PREP(PREP(x)) == PREP(x)`).

### 3.5. Локализация ошибок: source map → FOREX listing

Схема (реализуется в `tests/plan-f77/run-f77.sh`):

```
orig.f77 line 12  ──PREP──▶  lowered.f77 lines 18,19
                              C@ 12 -> 18,19  (comment в исходнике)
FOREX: ERR 03106 ПК 19  ──map.txt──▶  "orig line 12: IF (X .GT. 0.) THEN"
```

- `map.txt` собирается из `C@`-строк вывода прохода 1 (формат
  `orig -> new[,new…] kind`).
- При ошибке ФОРЭКСа (`ERR NNNNN ПК K`, `АТТ NNNNN ПК K`,
  `ОШИБКА В ССЫЛКЕ НА ФОРМАТ`) скрипт ищет `,K` в правой колонке `map.txt`
  и печатает исходную строку + номер.
- Дополнительно в `pass2.lst` сохраняется **полный листинг ФОРЭКСа** с
  нумерацией строк (как в `output.gold.txt`), чтобы визуально сверить
  сгенерированный оператор.

## 4. Эффективность

### 4.1. Накладные расходы preprocessor — только на компиляцию

- Препроцессор **не участвует в исполнении** целевой программы: он
  выполняется в проходе 1, его стоимость не влияет на время счёта
  пользовательской программы. Это ключевое отличие от runtime-пути.
- Стоимость прохода 1: компиляция `F77PREP` ФОРЭКСОМ (фиксированная,
  ~1–2 зоны кода) + один прогон по `N` строк. Алгоритм — O(N) при
  построении на шаблонах; массив `LINE(500)` фиксирован, без динамики.
  Для программы в 1000 строк это порядок секунд эмуляции — приемлемо.
- Возможность: хранить **скомпилированный DMS-объект `F77PREP`** в PERSO
  и вызывать его картой вместо перекомпиляции исходника каждый раз
  (проверить `*call f77prep` на Fortran-объекте, §1.3). Это убирает
  основную фиксированную стоимость.
- Кэширование: host-скрипт может пропускать проход 1, если `orig.f77` не
  менялся (по mtime/sha), и переиспользовать `lowered.f77`.

### 4.2. Runtime-вызовы внешних процедур vs inline-генераторы

- В текущем ФОРЭКСе внешние вызовы — **норма**, а не исключение:
  в листинге ГЛИССАДЫ `**` компилируется в `ПВ ROWER(’15’)`,
  `EXP` — в `ПВ POWER`, `CALL` — в `ПВ SBATM(’15’)` через LINK.
  То есть добавление ещё одной внешней процедуры не меняет *класс*
  накладных расходов.
- Цена одного вызова: подготовка параметров (`УИА`/`СЧМ`), `ПВ` через
  LINK-слот, возврат. Это единицы–десятки команд против inline-
  арифметики. Внутри **внутренних циклов** вызовы могут доминировать.
- FORMAT уже платит такую цену за **каждый элемент вывода** (11 `FT*`
  entry на `PRINT`), то есть I/O и так дорого.
- Опасные случаи lowering:
  - `COMPLEX → 2 REAL` — без вызовов, но удваивает число арифметических
    команд; **не применяется** (§0).
  - `DOUBLE PRECISION → REAL + масштабирование` — на каждый `+` нужна
    выравнивающая процедура; в цикле это **много вызовов**. Применять только
    при доказанной численной необходимости и только вне hot loop.
  - `CHARACTER` → внешние `SUBSTR`/`STRCAT` — каждый вызов в цикле дорого;
   Preference: оставить нативную поддержку (после исправления синтаксиса
    строки) и использовать внешние функции только для отсутствующих операций.

### 4.3. Рекомендации

1. **Приоритет 1 — не делать лишнего.** Убрать из плана lowering для
   `END IF`, `COMPLEX`, `DOUBLE PRECISION`, `LOGICAL`, `PARAMETER`: они
   работают (§0). Каждое лишнее правило — источник ошибок и лишней работы.
2. **Приоритет 2 — syntactic fix.** Исправить пробные исходники (`"…"` →
   Hollerith/`'…'`, `A` → `A4`), затем повторить пробы. Возможно, реальный
   объём препроцессора сократится до 4–5 правил.
3. **Приоритет 3 — комбинации.** `PRINT *` и `READ(...,END=)` реализовать как
   `preprocessor + extern procedure` (§1+§2), а не пытаться расширять
   FORMAT.
4. Хранить препроцессор и runtime-процедуры в **отдельной** PERSO-библиотеке
   `0o2310`, подключаемой `,CONT`: базовая ГЛИССАДА-регрессия остаётся
   побайтово прежней (9 модулей).
5. Все генерируемые метки — из диапазона, не используемого пользователем;
   все новые имена — ≤6 знаков и не системные.
6. Измерять эффективность **только после** корректности: сначала gold-тесты
   и сверка с FTN/FORTRAN, потом Dhrystone/Whetstone.
7. Не трогать `src/*.mad`, `include/*`, `reference/*` — весь путь лежит в
   Fortran-исходниках, PERSO-образе и host-скриптах.

## Приложение A. Минимальный скелет двухпроходного сценария

```bash
# tests/plan-f77/run-f77.sh  (скелет; НЕ создаётся этим документом)
CASE=$1                       # tests/plan-f77/cases/$CASE
WORK=$(mktemp -d ...)
cp /usr/local/share/besm6/2348 "$WORK/2348"

# проход 1: скомпилировать F77PREP и запустить его на orig.f77
build_pass1 "$CASE/orig.f77" > "$WORK/pass1.b6"
BESM6_PATH="$WORK" dispak -o "$WORK/pass1.lst" "$WORK/pass1.b6" > "$WORK/pass1.out"

# вырезаем C@-строки -> lowered.f77 и map.txt
awk '/^C@->/ {print substr($0,8)}' "$WORK/pass1.out" > "$WORK/lowered.f77"
grep '^C@ ' "$WORK/pass1.out" > "$WORK/map.txt"

# проход 2: FOREX(lowered) + EXECUTE
build_pass2 "$WORK/lowered.f77" > "$WORK/pass2.b6"
BESM6_PATH="$WORK" dispak -o "$WORK/pass2.lst" "$WORK/pass2.b6" > "$WORK/pass2.out"

# сравнение результата с gold + источник ошибки через map.txt
compare_result "$WORK/pass2.out" "$CASE/gold.txt"
locate_errors   "$WORK/pass2.out" "$WORK/map.txt"
```

## Приложение B. Что обязательно проверить экспериментом до реализации

1. Фортрановский `READ` с какого юнита читает карты после `*execute`
   (нужен номер юнита); `WRITE` — можно ли направить в дисковый файл.
2. Работает ли `` `N ``-вставка (`punch.inN`) с **текстовыми** строками, а не
   только с бинарным object punch (`whetstone.b6:26-28`).
3. Применим ли `*call <fortran-object>` к DMS-объекту на Фортране
   (аналог `*call plcatalog`).
4. Точность `DOUBLE PRECISION` и `COMPLEX`-intrinsics — численным тестом,
   а не фактом компиляции.
5. Корректная запись строковых литералов (`nH…` vs `'…'`) и дескриптора
   `A4` — повторить `CHARSTAR` с исправленным исходником.
