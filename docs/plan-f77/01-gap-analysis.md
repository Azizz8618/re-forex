**Оговорка 1 (обратная совместимость).** Старые таблицы `dubna-languages.md:106-134,240-275` строились при безусловной подмене `*forex` → `*fortran` в загрузчике (`dubna-languages.md:9-14`). Поэтому приписанные ФОРЕКСУ «−» для многомерных массивов и «ч» для блок `IF` (**`:115,124`**) относятся к Фортран-Дубна и **опровергнуты** исполняемыми пробами 2.02 и 4.13. для строк (**`:121`**) картина **версионно-зависимая**: в 2.02 `CHARACTER*10` действительно отвергается (§2.1, но с другой диагностикой, чем у ГДР), а в 4.13 `CHARACTER*30` работает. Таблицу §3 нельзя использовать как единый статус ФОРЕКСа.

**Оговорка 2 (объём проб).** Проба 2.02 проверяет только базовые формы одной конструкции. `OK` не означает «все варианты конструкции работают`; `NO` означает «данная форма отвергнута», а не «весь класс конструкций отсутствует».

**Обозначения статусов:** `OK` — confirmed работает (версия в скобках); `NO` — confirmed не работает; `~` — частично / нестабильно; `?` — unknown, нужна проба.

### 2.3 Требуют пробы (`?`) — не подтверждено ни «да», ни «нет»

| Конструкция F77 | Почему неизвестно |
|:---|:---|
| `READ` с меткой FORMAT (formatted input) | В пробах и 4.13-бенчмарках READ нет; `d_besm6/swhet.for:47-48` содержит `READ(*,*)` без лога исполнения |
| list-directed `READ *` отдельно | В пройденной пробе была составная форма `READ(*,*,END=99)`; точка отказа не локализована |
| `END=` / `ERR=` отдельно | Та же причина: `END=` был в составе отвергнутой формы; `ERR=` не пробовался вообще |
| Неформатированный `READ(u,...)`, `WRITE(u,...)` | Нет ни одной исполняемой пробы; FT\*nnn в LO_GEN — только преобразование форматированного вывода |
| `REWIND`, `BACKSPACE`, `ENDFILE`, `REWRITE` | Генератор имеет `*REWIN` (0o615), `*BACKS` (0o617), `*ENDFI` (0o621) — `src/LO_GEN.mad:528-530`, но исходный синтаксис и выполнение не проверены |
| Вычисляемый `GO TO (10,20),I` | Для Фортран-ГДР — `ERROR 106` (`dubna-languages.md:557`); для ФОРЕКСа данных нет |
| `ASSIGN 10 TO I` + `GO TO I` (код метки) | Не probed; в корпоративных текстах не встречено |
| H-константы (`4HABCD`) и Hollerith как данные | `ERROR 123` в `dubna-languages.md:213,619` относится к Фортран-ГДР/старым пробам; в 4.13 работают обычные строковые литералы `'…'` (`dhrystone-forex.dub:31,114`), но `nH` не пробован |
| `ENTRY`, `MOD`, `CHR` | Для ГДР отсутствуют (`dubna-languages.md:215-216`); для ФОРЕКСа нет данных. В glissade используется `AMOD` — **работает** (`glkern.b6:107`), но это другая функция |
| Арифметика `COMPLEX` сверх присваивания | Проба только `Z=(1.0,2.0)` (`logs/plan_f77_probes.txt:6`) |
| `DOUBLE PRECISION` в вычислениях/функциях | Проба только `X=1.0D0; Y=SNGL(X)` (`:5`); 4.13 в бенчмарках DOUBLE не использует |
| `CHARACTER*n` при `n`, не кратном 6 | Слова БЭСМ-6 = 6 байт (`dhrystone-forex.dub:128-129`). В 4.13 подтверждены n=1 (`:15,320`), n=6 (`:14`), n=30 (`:12`); в 2.02 n=10 отвергается на этапе проверки типов (§2.1), причина — сам тип, а не кратность длины. Поведение печати для некратных `n` отдельно не проверено |
| Рекурсия | F77 не имеет `RECURSIVE` (это F90); как свойство компилятора — данных нет, считать не применимым к F77 |

**Итого: 5 позиций `NO` (включая `CHARACTER` в 2.02), 3 позиции `~` (6-символьные имена, печать `CHARACTER*30`, печать элементов массивов), 17 позиций `?` (4 в §2.2 + 13 в §2.3).**

## 3. Критичность для переноса реальных F77-программ

### 3.1 Dhrystone 2.1 — риск **низкий**

Проверено на **4.13**: `CHARACTER*30`, подстроки, сравнение строк, блок `IF` с `ELSE IF`, `COMMON`, передача массивов, `LOGICAL FUNCTION` с символьными параметрами, `DATA`, `FORMAT`, `5A6` — 18 контрольных значений + 4 строки (`dhrystone-forex.dub:90-115`; `besm6-performance/article.md:296` — все 48 прогонов прошли проверки). **На 2.02 этот порт не переносится напрямую:** `CHARACTER` там отвергается (§2.1). Перенос на 4.13 потребовал **адаптации программы** (записи → параллельные массивы `:7,22-24`; указатели → индексы 1/2; `CTIME` вместо `SECOND`), но это не расхождение диалекта. Единственная «осторожность» — временные переменные для печати (`:121-131`).

### 3.2 Whetstone (Longbottom) — риск **низкий**

Порт сознательно ограничен подмножеством: нет `DOUBLE PRECISION`, `CHARACTER`, `COMPLEX`, list-directed I/O, `SAVE` (`whetstone-longbottom-forex.dub:19-25`); `COMMON` заменён явными параметрами, `SECOND` → `CTIME`. Длинные циклы разбиты на блоки из-за ограничения констант `DO` в *устаревшем* Фортране-Дубна (`:16-18`) — для нативного 4.13 отдельно не проверено. Итог: 8 секций, 0.809 MWIPS, проверки пройдены (`article.md:296-301`).

### 3.3 re-glissade / Глиссада-6 — риск **низкий для текущего регрессионного ядра, неоценённый для полных исходников**

`glkern.b6` использует 2D `COMMON`, `BLOCK DATA`, DATA-инициализацию массивов, `**`, `AMOD/EXP`, `PRINT/FORMAT` — всё подтверждено на 2.02, full-прогон даёт 14/14 (`docs/16-glissade-run.md:7-14`). Однако полные `SRC/GLGAIN.FTN`, `SRC/GLNUMR.FTN` в этом репозитории отсутствуют; наличие в них `SAVE`, `IMPLICIT`, `CHARACTER`, list-directed I/O или `END=` **не проверено**. Рекомендуется отдельный аудит перед заявкой о полной переносимости.

### 3.4 Приоритеты расхождений (для плана расширений)

| Приоритет | Расхождение | Почему критично |
|:---:|:---|:---|
| **P0** | 6-символьное усечение имён с молчаливой коллизией | Любой реальный F77-исходник с длинными описательными именами компилируется в неверную программу **без диагностики**; хуже явного отказа. Dhrystone/Whetstone/glissade уже адаптированы, но произвольный код — нет |
| **P0** | `SAVE` (`NO`) | Распространён в численных процедурах с сохраняемым состоянием; его отсутствие меняет семантику молча или требует переписывания через COMMON |
| **P1** | `CHARACTER` — `NO 2.02` / `OK 4.13` | Критическая **версионная** зависимость: один и тот же исходник со строками работает в 4.13 и отвергается в 2.02 («ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ»). Dhrystone 4.13 переносится как есть; для 2.02 нужна эмуляция строк массивами целых (`dubna-languages.md:627-632`) |
| **P1** | `PRINT *` / list-directed I/O (`NO`) | Стандартный способ диагностики и вывода в подавляющем большинстве современных F77-программ; обход — явный `FORMAT` (во всех трёх бенчмарках он и используется) |
| **P1** | `IMPLICIT NONE` (`NO`) | Типичная «шапка» современного F77-кода; обход — явные объявления всех типов.Typed `IMPLICIT` (`?`) может работать, но требует пробы |
| **P1** | `READ(*,*,END=…)` (`NO`, причина не локализована) | END=/ERR= — стандартные механизмы обработки EOF/ошибок; без них невозможно надёжно читать данные до конца файла. Требуется раздельная проба `READ *`, `END=`, `ERR=` |
| **P2** | `CHARACTER*n` печать через `5A6`, временные для элементов массивов | Не отказ, но сказывается на точности переноса строкового вывода; документировано в порте Dhrystone |
| **P2** | `EXTERNAL`/`INTRINSIC`, вычисляемый/assign GO TO, H-константы, REWIND/BACKSPACE/ENDFILE | `?`; влияют на перенос библиотечного кода, но не на три исследованных бенчмарка |
| **P3** | RECORD/DO…REPEAT/ARM | Не подтверждены как синтаксис ФОРЕКСа; перед включением в план расширений нужно уточнить источник утверждения |

## 4. Границы выводов (что НЕ утверждается)

1. `OK 2.02` не распространяется на 4.13 и наоборот: единого «ФОРЕКС» нет, это по меньшей мере 2.02 / 4.12 / 4.13 (`docs/08-forex3.md:190-199`).
2. `NO` для `CHARACTER*10`, `PRINT *`, `READ(*,*,END=99)`, `IMPLICIT NONE`, `SAVE` установлено **только для базовых форм 2.02** в dispak; для 4.13 эти формы не пробовались (кроме `CHARACTER*30`, который в 4.13 **работает**). Экстраполировать `NO` на 4.13 нельзя — именно так старые пробы ошибочно приписали ФОРЕКСУ отсутствие блочного IF и многомерных массивов (§0, оговорка 1).
3. Корпус `kermit.ftn` и `swhet.for` не имеет логов исполнения в доступных материалах: это свидетельство «такой синтаксис встречался», а не «такой синтаксис работает».
4. Настоящий документ не оценивает семантику чисел (48-битное слово, 40-битная мантисса — `article.md:70-85`) и не измеряет производительность; только синтаксис/доступность конструкций.
5. Источники §3–§4 `dubna-languages.md` (ГДР, `ERROR 021/035/106/123/138` и т.п.) к нативному ФОРЕКСУ не применяются без отдельной пробы.
