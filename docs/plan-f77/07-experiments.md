## 1. Fortran-юниты ввода/вывода

**Ввод.** Каноническое чтение карт после `*execute` — `READ 10,X` без номера
юнита: компилируется в вызов входной очереди (Э60), карта `  3.50` читается и
печатается как `3.50`. Явный номер юнита ведёт в `БCDATA/Э70`:

| юнит | результат `READ(u,10)` | строка out.txt |
|---:|---|---|
| 1 | `ИСПОРЧЕН РЕКОРД`, `LUN 1 RET 01165 DEV 00041` | `units/read_u1/out.txt:69` |
| 2 | `ОШ.В ИНФ.СЛ.ЭКСТ` | `units/read_u2/out.txt:69` |
| 5 | `ОШ.В ИНФ.СЛ.ЭКСТ` | `units/read_u5/out.txt:69` |
| 6 | `ОШ.В ИНФ.СЛ.ЭКСТ` | `units/read_u6/out.txt:69` |
| 10 | `ОШ.В ИНФ.СЛ.ЭКСТ` | `units/read_u10/out.txt:69` |
| 40 | `НЕТ КАНАЛА LUN 40` | `units/read_u40/out.txt:69` |
| 45 | `НЕТ КАНАЛА LUN 45` | `units/read_u45/out.txt:69` |
| 54 | карта не прочитана, `3.50` не напечатано | `units/read_u54/out.txt` |

Пояснение из исходника dispak: `dispak/extra.c:2126-2153` — «MONREAD идёт по
шаблону УИР 45/0 на диск; МОНИТОР при старте задачи по `*execute` НЕ ставит
указатель KCOUNT на карты данных»; для Экспериментального обхода предусмотрены
env `BESM6_LUN45_DRUM/TRACT/KCOUNT/DRUM_SEED` (`extra.c:2130-2194`), но в этих
пробах они не использовались.

**Вывод.** `WRITE(u,10) 12345`: u=1 → `ОШИБКА МД ЭВМ`; u=2/5/6/10 →
`ОШ.В ИНФ.СЛ.ЭКСТ`; u=40/45 → `НЕТ КАНАЛА`; u=54 → `12345` в stdout.
Монтирование тома на LUN 40 (`лен 40(2348-wr)^`) ситуацию не меняет.
Хостовое перенаправление `> out.txt` сохраняет и `WRITE(54)`, и `PRINT`;
`dispak -o` в этой сборке не создаёт файл.

**Следствие для F77PREP (план 03 §1.3, способ c):** писать `lowered.f77` через
Fortran `WRITE` в дисковый файл **нельзя** без правки монитора/рантайма;
использовать способ (a) печать с префиксом `C@` или способ (b) — но (b) тоже
непригодно (см. §2). Остаётся печать + host-скрипт.

## 2. Вставка `` `N `` (`punch.inN`)

* Контроль: `punch.in3`, сгенерированный `dispak --punch-binary -c punch.in3
  gen_punch.b6` (диска 120 байт/карта), вставленный строкой `` `3 `` после
  `*execute`, принимается без ошибок: программа печатает `1.00`
  (`punchinsert/bin_control/out.txt:63`).
* Текст: те же 5 строк Fortran-исходника в `punch.in0` (plain ASCII) и
  `punch.in1` (GOST-10859 с чётностью) дают `0005..0009 ОШИБКА`, `УПП …`,
  `БЫЛИ ОШИБКИ ВВОДА`, `БЫЛИ ОШИБКИ ПРИ ТРАНСЛЯЦИИ ИЛИ В НАБИВКЕ`
  (`text_ascii/out.txt:27,36-47,77,82`; `text_gost/out.txt:27,36-47,77,82`).
  Вывод текста на экран в `УПП` (в second case) подтверждает, что байты
  дошли, но Монитор отверг их как некорректную перфокарту.

**Вывод:** `` `N `` — механизм **только для бинарного punch-образа**; передача
`lowered.f77` текстом через него не работает (противоположное предположение
`03-fortran-path.md:152` опровергнуто).

## 3. `*call` к Fortran-объекту

Сборка: `*forex` компилирует `SUBROUTINE HELLO` (`PRINT 10`,
`FORMAT(1X,12H*CALL WORKS*)`), `*to perso:602310` пишет объект в зону `0o2310`
(`build/out.txt:43`: `ДЛИНА LIВRАRУ 004 ЗОН`). Вызов: `*perso:602300` +
`*perso:602310,cont` + `*call hello` — маркер `*САLL WОRКS*` напечатан
(`call/out.txt:34`). Предупреждение `ИСПОРЧЕНЫ ПОДПРОГРАММЫ:` при сборке
(`build/out.txt:35-42`) безвредно (см. `08-runtime.md` §5.3). Карта
`*perso:603100` из плана неверна — зона `0o3100` (`08-runtime.md` §5.1).

**Вывод:** да, `*call` применим к DMS-объекту, скомпилированному ФОРЭКСОМ;
препроцессор можно хранить как готовый объект и вызывать вместо полной
компиляции.

## 4. Численная точность

| Вычисление | Результат прогона | Ожидаемое | Строка out.txt |
|---|---|---|---|
| `SQRT(2.0D0)`, `D22.15` | `1.414213562371515+000` | 1.4142135623730951 | `precision/double/out.txt:66` |
| `1.0D0/3.0D0`, `D22.15` | `3.333333333333333-001` | 0.3333333333333333 | `:67` |
| `SQRT(2.0)` (SP), `F20.15` | `1.414213562371515` | — | `:68` |
| `1.0/3.0` (SP), `F20.15` | `0.333333333333485` | — | `:69` |
| `(1+2i)*(3+4i)`, `2F10.4` | `-5.0000   10.0000` | −5+10i | `precision/complex/out.txt:70` |
| `CABS(3+4i)`, `F10.4` | `5.0000` | 5 | `:71` |
| `CSQRT(3+4i)`, `2F10.4` | `2.0000    1.0000` | 2+i | `:72` |
| DP + `F16.12` | `I/О-ЕRRОR 227` в `IOSCNTD*` | — | `precision/dp_f_format/out.txt:67` |

БЭСМ-6 имеет 40-битную мантиссу (~12 десятичных знаков); DP в ФОРЭКСе
реально повышает точность 1/3 примерно на 2 знака. `CABS`/`CSQRT`
исполняются, хотя отсутствуют в таблице `LIBREFER` (`03-fortran-path.md:63`).

**Следствие:** не опускать `DOUBLE PRECISION`/`COMPLEX` в lowering;
использовать `D`-дескриптор для DP при печати.

## 5. Строковые литералы и `A4`

| Форма | Результат | Доказательство |
|---|---|---|
| `CHARACTER*10 S` (только объявление) | компилируется | `strings/charstar_original/out.txt` (нет ошибок на объявлении) |
| `S='ABCDE'` / `S='ABCD'` | `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`, `НЕДОПУСТИМ СИМВОЛ =` | `strings/charstar_original/out.txt:33,35`; `charstar_fixed/out.txt:33` |
| `S=4HABCD` (CHARACTER) | та же ошибка типа | exploratory (`s_CASSIGNQ`), не зафиксировано в e1 |
| `DATA S/4HABCD/` (CHARACTER) | `АТТ 04426`, затем `I/О-ЕRRОR 232` | `strings/char_data_a4/out.txt:31,64` |
| `FORMAT(1X,4HABCD)`, `PRINT 10` | `АВСD` | `strings/hollerith_format/out.txt:62` |
| `FORMAT(1X,'ABCD')`, `PRINT 10` | `АВСD` | `strings/quote_format/out.txt:62` |
| `INTEGER I; DATA I/4HABCD/` + `FORMAT(1X,A4)` | `АВСD` | `strings/hollerith_data_a4/out.txt:62` |
| `FORMAT(1X,A4)` с `INTEGER 12345` | `I/О-ЕRRОR 232` в `IOSKIP*` | `strings/a4_wrong_type/out.txt:62` |

`АВСD` вместо `ABCD` — артефакт декодирования TEXT-символов dispak (`B`→`В`,
`X`→`Х`), не ошибка программы.

**Вывод:** для F77PREP строковые литералы нужно преобразовывать в `nH…` внутри
`FORMAT` или в `DATA INTEGER`, а не в присваивание `CHARACTER`; простая
замена `'`→`nH` в выражениях не помогает. Дескриптор `A4` корректен, но
требует операнда-Hollerith/`CHARACTER`, который ФОРЭКС 2.02 не умеет
присваивать.

## Что не удалось / оговорки

1. Альтернативный путь передачи текста в проход 2 (`` `N ``) **опровергнут**
   (§2); это не «не удалось проверить», а отрицательный результат.
2. READ с явным юнитом не заработал ни на одном из 1/2/5/6/10/40; рабочая
   форма только безъюнитная. Механизм Э70-перенаправления LUN45 описан в
   `dispak/extra.c`, но не активировался — для полного ответа о дисковом
   вводе нужно отдельное исследование с `BESM6_LUN45_*`.
3. Проверка на PERSO-библиотеке `0o2300`: по строковым
   конструкциям её диагностика совпадает с системным 2.02. Чистого
   компилятора 4.13 с поддержкой `CHARACTER*30` в этой среде нет, поэтому
   версионная зависимость из `01-gap-analysis.md` здесь не подтверждена и
   не опровергнута.
