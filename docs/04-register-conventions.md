# Соглашения об использовании регистров М1..М17

Методика взята из `re-siprod/notes/registers.md` (проверена на 98 модулях
СИПРОДа, написанных на том же автокоде). Для ФОРЭКС оверлеев она является
**рабочей гипотезой**, подтверждаемой листингами (`LO_*.bemsh.lst`).

## Карта регистров

| Рег | Смысл | Как проявляется в листинге ФОРЭКС |
|---|---|---|
| М7 | указатель кадра, `N(М7)` — слоты рабочей области | встречается в адресации данных |
| М10 | адрес блока, переданного вызывающим; второй канал возврата `ПБ (М10)` | — |
| М12 | указатель магазина (стека), первый канал возврата `ПБ (М12)` | — |
| М13 | счётчик цикла/длины | `ЦИКЛ` / `СЛИА` |
| М14 | смещение/длина в буфере | `VTM 30274B(М14)`, `XTA 15(М14)` — см. слово 10..14 SYN |
| **М15** | **адрес возврата**; вызовы через `ПВ X(М15)` | `13,VJM,20116B` в слове 17 SYN/GEN — вызов резидентной процедуры |
| **М16** | **модифицированный адрес** (`МОДА` вызывающего), адрес общего блока | `VTM 30274B(М14)`, `ITS 16`, `VTM 36017B(М16)`, `ITS 16` |
| М17 | контекст задачи (ИПЗ), `0(М17)` — признак состояния | `ITA 17`, `ATX 17(М14)`, `ATI 15` |

## Типовой вызов

```
МОДА  <блок>          , модификатор адреса := адрес общего блока
СЧИМ  М16             , в магазин; СМ := М16
ПВ    <процедура>(М15), вызов через стек возврата М15
```

Соответствие в MADLEN-листинге dtran:
```
 ,WTC,<адрес>          ; МОДА — подготовка адреса
 ,ITS,16               ; СЧИМ М16 — передача параметра
 13,VJM,20116B         ; ПВ через М15 — вызов процедуры по 0o20116
```

Вызываемый принимает адрес блока через `М16` и работает с кадром через `М7`.

## Интерпретация малых смещений

`N(Мk)` — это смещение внутри блока, адрес которого лежит в `Мk`.
Например `ATX 15(М14)` = записать аккумулятор по адресу `М14 + 15`,
где `М14` — указатель буфера/таблицы (в FOREX* — буфер исходного текста `*A*`).

При аннотации в `src/LO_*.mad` указывай:
- исходное значение регистра (константа из `VTM`),
- где оно перезаписывается (`ITS`, `ATI`, `MTJ`),
- первое применение как адрес (`N(Мk)`) или как счётчик.
