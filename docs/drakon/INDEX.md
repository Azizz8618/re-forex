# ДРАКОН-схемы проекта ФОРЭКС (версия изделия 5.00 / 19.11.2026)

Все двенадцать схем несут метку `[5.00 19.11.2026]` в `ЗАГОЛОВОК` и
комментарий `FOREX 5.00 / 19.11.2026 (re-forex)` в заголовке; разметка и печать пересозданы
`drakon_markup.py` и `tests/siprod/run.sh` из `re-siprod`. Системный баннер
`ВЕРСИЯ 2.02` печатает хост (диск 2048), он внешний — см. `docs/16-glissade-run.md` §6.

Подписи иконок описывают смысл шага — ЧТО делается и ЗАЧЕМ — человекочитаемым
русским текстом. Мнемоники, адреса, номера зон, команды и формулы вынесены в
комментарии `*` в шапке схемы (допустимы также иконы `КОММЕНТАРИЙ:`).

Исходники схем лежат в `docs/drakon/*.drakon`. Для каждой схемы другие агенты
создают два производных артефакта:

- `docs/drakon/markup/<имя>.txt` — разметка `*RED`, эталонный вывод
  `drakon_markup.py` (репозиторий `re-siprod`, `tools/drakon_markup.py`);
- `docs/drakon/printed/<имя>.txt` — реальная печать встроенного редактора
  ДРАКОН на БЭСМ-6 (`python3 tools/drakon_markup.py S | tests/siprod/run.sh -`).

Проверка всех трёх уровней: `tests/check-drakon.sh`
(лог — `logs/drakon_check.txt`). Таблица сценария:
`ФАЙЛ | ИКОН | МАРКИРОВКА | СТАТУС`.

## Критерии приёмки

1. Схема непустая, есть `ЗАГОЛОВОК`, хотя бы одна `ВЕТКА` и `КОНЕЦ`,
   икон ≥ 15, длина любой строки ≤ 80 знаков.
2. Вложенных `ВЕТКА` нет: `ВЕТКА` — только строк без ведущих пробелов.
3. Есть непустой `markup/<имя>.txt`, первая строка — `*RED`.
4. Идемпотентность: два запуска `drakon_markup.py` дают одинаковый sha256,
   равный sha256 сохранённой разметки.
5. Есть непустой `printed/<имя>.txt` с иконами (`+----`, боковина `|---`/`|`,
   `(`, `/`) и без диагностики `ОШИБКА|ERROR|Illegal`.
