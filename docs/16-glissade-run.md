## 2. Истинная причина сбоя (уточнение предыдущего отчёта)

Ранее считалось, что загрузчик отвергает `OCTTDEC` из-за «плохого» sym-элемента
`0o0000000040077773`. Это **неверно**. Проверено:

1. Байт-точный скомпилированный модуль найден на эталонной ленте
   `monsys.9`, слова `0o37100..0o37137` (3 заголовка + 15 cmd + 12 const +
   1 head/имя + 1 sym). Он **побайтово совпадает** с объектом, который выдавал
   `*assembler` из `besmmons/system2.txt:5042-5084`, — в том числе sym-элемент
   `0o0000000040077773`.
2. Замена тела на байт-точный дамп, на EXFOR-вариант
   (`build/RUNTIME_OCTTDEC.words`), на объект без sym-секции и на синтетический
   DMS-заголовок — **ни одно из этих изменений не убирает ошибку**.
3. Перебор всех полей записи каталога (f0/f1/f2/f3) при имени `OCTTDEC` —
   **ErrorCode=1** во всех вариантах.
4. Достаточно изменить **только имя в каталоге** (оставив тело и запись
   неизменными) — тест сразу даёт rc=0 и 14/14 строк.

**Причина — конфликт имён.** Постоянная библиотека монитора на диске 2048 уже
содержит подпрограмму `OCTTDEC`; загрузчик ФОРЭКСа грузит её по адресу `0o3614`
(это видно в карте загрузки эталона). PERSO-библиотека с точным именем
`OCTTDEC` создаёт дубликат, и монитор печатает
`ИСПОРЧЕНА ПОДПРОГРАММА` (TERR6 загрузчика, `besml21/loader.txt:1241`), после
чего карта загрузки обрывается и 14 строк результата отсутствуют.
Аналогичный конфликт для `DATAPR*` описан в `docs/15` §5; в этом тесте он не
проявляется, потому что программа не ссылается на `DATAPR*`.

## 3. Исправление

1. Байт-точный модуль выгружен в `build/RUNTIME_OCTTDEC_ETALON.words`
   (32 слова, SHA256 `7a147709…15a4338`) и используется в
   `tools/build_forex_perso.py` вместо сборки через `*assembler`.
2. PERSO-копия каталогизируется под псевдонимом **`OCTTDE*`** по образцу
   `DATAPR*`, `FOREX*`. Внутреннее слово head-секции модуля (слово 30 дампа)
   перезаписывается тем же псевдонимом, чтобы `siprod_lib.Library` находил
   объект для каждой записи каталога. Машинные слова (cmd/const/sym) остаются
   байт-точными.
3. Программа по-прежнему вызывает системный `OCTTDEC` через LINK `0o74013`,
   поэтому результат побайтово равен эталону. `tests/install-forex-perso.sh`
   обновлён: ожидаемое имя `OCTTDE*` (`ОСТТDЕ*` в выводе PLCATALOG).

Ни `src/`, `include/`, эталонные носители, ни `tests/run-glissade-forex.sh`
не изменялись.
