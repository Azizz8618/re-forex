## 2. Изоляция неисправного модуля

Из одного и того же исправленного образа собирались варианты каталога с
исключением по одному модулю; прогон того же самого теста:

| Исключённый модуль | байт вывода | `ИСПОРЧ` | 14 строк результата |
|---|---:|---:|---|
| **OCTTDEC** | 30910 | 0 | **есть, побайтово = эталону** |
| DATAPR* | 26249 | 1 | нет |
| GIV/PG | 26273 | 1 | нет |
| TAK/PG | 26249 | 1 | нет |
| (ничего — полная библиотека) | 29423 | 1 | нет |

Вывод: виноват **только `OCTTDEC`**. Остальные три модуля, собранные из
исходников Дубны (`DATAPR*`, `GIV/PG`, `TAK/PG`), загружаются корректно;
при удалении одного OCTTDEC тест проходит полностью, без предупреждений,
и даёт эталонный результат.

## 3. Причина

`tools/build_forex_perso.py` получает `OCTTDEC` не из побайтового дампа
ленты (как `FOREX*`, `LO*SYN`, `LO*GEN`, `FORMAT`, `FORTLIBR`), а сборкой
через мониторный `*assembler` из `besmmons/system2.txt:5042-5084`.
Полученный DMS-объект:

* `cmd=15`, `const=12`, `sym=1`, `long=0`;
* заголовок `0o10001 / 0o0 / 0o140000000017`;
* символьный элемент `0o0000000040077773`.

Судя по реакции загрузчика, поле `sym` этого объекта содержит ссылку,
которую монитор Дубны не может разрешить, и он печатает
`ИСПОРЧЕНА ПОДПРОГРАММА`. (Ср. известный случай в `re-siprod`: объекты, собранные
в другой сборке монитора, дают «ИСПОРЧЕНЫ ПОДПРОГРАММЫ» из-за другой
таблицы входов.) Каталог при этом корректен: transfer vector и длина
загрузки для OCTTDEC выставлены верно (`f1 = 27*8 = 0o330`).

**Предлагаемое исправление:** использовать для `OCTTDEC` проверенный
побайтовый word-dump из эталонного носителя (как для `FORMAT`/`FORTLIBR`),
либо повторно собрать объект мониторным `*assembler` на том же томе/сборке
монитора Дубны и сверить его sym/long-секции с эталонным `OCTTDEC`.

## 4. Состояние реконструкции

**Компилятор пригоден, рантайм — нет.** Компилятор `FOREX* + LO*SYN + LO*GEN`
из PERSO `0o2300` надёжно загружается и компилирует тест: листинг побайтово
совпадает с системным ФОРЭКСОМ 2.02 во всех прогонах. Проблема локализована
в одном модуле рантайма `OCTTDEC`, ломающем печать скомпилированной
программы.

Сценарий `tests/run-glissade-forex.sh` намеренно **не содержит обходов**:
он проверяет 9 модулей, transfer vector и завершатель каталога, пишет
полный образ в зону `0o2300` и сравнивает результат с эталоном. С текущим
образом он честно возвращает **rc=1**. Как только `OCTTDEC` будет заменён
на рабочий объект, тот же сценарий должен вернуть 0 без правок.
