# Прогон вычислительного теста ГЛИССАДЫ с реконструированным ФОРЭКСОМ из PERSO 0o2300

Дата: 19.11.2026. Исполнитель: субагент прогона.
Входные артефакты других агентов: `tests/forex-glissade/{glkern.b6,output.gold.txt,run.sh}`,
`tests/install-forex-perso.sh`, `docs/14-perso-write.md`, `tools/build_forex_perso.py`,
`build/FOREX_PERSO_2300.bin`, рабочая копия `work/2348`.

Итоговые файлы: [`tests/run-glissade-forex.sh`](../tests/run-glissade-forex.sh) (exit 0),
`tests/forex-glissade/output.new.txt`, `logs/glissade_run.txt`.

## 1. Что делалось

Дека смешанного типа (монитор Дубны, LU 60 = рабочая копия 2348):

```
шифр 419999 зс5^
лен 60(2348)^
ееВ1а3
*name GlkernRec
*call yesmemory
*perso:602300          ; загрузка реконструированного компилятора из PERSO
*     no list
*full list
*forex                 ; запуск FOREX* из временного каталога задачи
… исходник glkern.b6 (строки 10..111: main + BLOCK DATA GLGAIN + SBATM + SBRND) …
*execute
*end file
``````
еконец
```

Запуск: `BESM6_PATH=<рабочая копия>:/usr/local/share/besm6 dispak job.b6`.
Эталон — системный ФОРЭКС 2.02 на диске 2048 (`output.gold.txt`, 31920 байт).
Сравнение: нормализация дат `DD.DD.DD → ##.##.##` плюс побайтовая сверка
14 строк результата (между концом листинга и `КОНЕЦ ЗАДАЧИ`).

## 2. Хронология: три состояния библиотеки и точные сообщения монитора

### 2.1. Первый доставленный образ — каталог отвергнут (ложный позитив)

С первым доставленным образом (`build/FOREX_PERSO_2300.bin` до правок) монитор выдал:

```
 *** ДЛЯ ПРАВИЛЬНОЙ РАБОТЫ СИСТЕМЫ ИСКЛЮЧИТЕ
 *** ИЗ ЛИЧНОЙ БИБЛИОТЕКИ СЛЕД. ПОДПРОГРАММЫ:
                    РRINТ8
                    FIСМЕМОR
                    SТАR*
 ИСПОРЧЕН КАТАЛОГ РЕRSОNАL LIВRАRУ
```

Листинг и 14 строк результата при этом совпали с эталоном. **Контрольный
прогон без карты `*perso` дал те же 14 строк** — компилировал системный
ФОРЭКС, а наш каталог был отвергнут; это был бы ложный позитив.

Причина — пословная сверка каталога зоны `0o2300` с исправным PERSO-каталогом
зоны `0o2500` эталонного тома: завершатель каталога — **пара** слов
`(0, FULWORD = 0o7777777777777777)`, а в образе было только одно слово `0`.
**Исправление:** `catalog_words.append((1<<48)-1)` — применено агентом сборки
в 11:36.

### 2.2. Промежуточный образ (завершатель исправлен, нет transfer vector)

Каталог принят, монитор напечатал:

```
                  ИСПОРЧЕНЫ ПОДПРОГРАММЫ:
                          LО*SУN
                          LО*GЕN
                          FОRМАТ
                          FОRТLIВR
                          DАТАРR*
                          ОСТТDЕС
                          GIV/РG
                          ТАК/РG
```

По данным `re-siprod` это предупреждение загрузчика; загрузка наших модулей
подтверждается изменением карты (`PRINT8` `04012 → 03760`, `HID/*`
`05075 → 05043` и др.). Листинг компиляции совпадал с системным, но
**выполнение не печатало результат**. Причина (проверена экспериментом):
в каталоге присутствуют 4 модуля с `cmd=0` (DATAPR*, OCTTDEC, GIV/PG,
TAK/PG), для которых есть только MADLEN-исходник, но нет машинного кода.

### 2.3. Финальный образ (transfer vector добавлен, 11:42)

Сборщик стал вычислять в записи каталога не «дату», а **вектор передачи**:
`f3 = (word-offset in zone) + 0o2010`, `f2 = (zone + 0o40)*0o100`, длина
разнесена по `f2`/`f1` (реконструировано по каталогу `/*PASCAL`).

* Как доставленный (9 модулей): предупреждения `ИСПОРЧЕНЫ ПОДПРОГРАММЫ`
  больше нет, но в карте загрузки появляется `ИСПОРЧЕНА ПОДПРОГРАММА`,
  карта обрывается и результат снова не печатается — те же 4 `cmd=0`-заглушки.
* С исключёнными заглушками (наш сценарий): **ни одного предупреждения**,
  листинг и 14 строк результата полностью совпадают с эталоном, два
  последовательных прогона дают побайтово равный `output.new.txt`.

## 3. Сравнение с эталоном (финальный прогон)

`output.new.txt`: 30910 байт; `output.gold.txt`: 31920 байт. Полный
нормализованный diff (9 блоков, 44 строки) содержит только ожидаемые
различия шапки/сервисной печати:

1. ASCII-баннер `ЖЖЖ` (зависит от шифра и набора LU: 2348 вместо 2048);
2. `*NAME GLКЕRNRЕС` вместо `*NAME GLКЕRN`, дополнительная строка
   `*РЕRSО:602300`;
3. отсутствуют `*SУSТЕМ LОАD LISТ` и напечатанные им строки

## 4. Вывод о пригодности реконструкции

**Компилятор пригоден.** Реконструкция `FOREX* + LO*SYN + LO*GEN`
(побайтовые слова ленты `monsys.9`) из PERSO зоны `0o2300` загружается,
компилирует тест и вместе с побайтовыми `FORMAT`/`FORTLIBR` даёт
вычислительный результат, полностью равный эталону системного ФОРЭКСА 2.02.
Прогон детерминирован, мониторных предупреждений в рабочей конфигурации нет.

**Оговорка по образу PERSO.** В собранном библиотечном образе остаются
четыре модуля-заглушки без машинного кода (`DATAPR*`, `OCTTDEC`, `GIV/PG`,
`TAK/PG`). С ними каталог корректен (transfer vector на месте), но загрузчик
портит карту и программа не печатает результат. Это не опровергает
реконструкцию компилятора, но требует доработки сборщика. Пока она не
выполнена, корректным считается прогон через `tests/run-glissade-forex.sh`,
который сам убирает заглушки и восстанавливает завершатель каталога.

Итог: `tests/run-glissade-forex.sh` → **exit 0**, 14/14 строк результата
совпадают с эталоном; расхождения полного вывода объясняются только
шапкой/сервисной печатью и отсутствием карты `*SYSTEM LOAD LIST`.

## 5. Рекомендации сборщику

1. Завершатель каталога — два слова `(0, 0o7777777777777777)` — **выполнено**.
2. Transfer vector в записи каталога — **выполнено**.
3. Не включать в PERSO-образ модули без машинного кода: `DATAPR*`,
   `OCTTDEC`, `GIV/PG`, `TAK/PG` (или собрать настоящие объекты с кодом и
   таблицей символов из проверенных исходников). Это единственный
   оставшийся блокер автономной работы.
4. Для побайтового совпадения полного листинга с эталоном можно добавить
   в деку `*system load list` и имя `*NAME GLКЕRN`; на результат не влияет.
