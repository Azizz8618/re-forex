# Методика работы с SIMH при проверке компилятора FOREX 5.00

Документ сводит правила, проверенные прогонами `docs/74-simh-verification.md`
и `docs/75-simh-wide-and-besm.md`. Обязателен после каждого этапа разработки.

## 1. Изоляция

- Все образы дисков, лент, барабанов и принтерные файлы — **копии** в рабочем
  каталоге. Живые образы (включая `~/.besm6/2348`) в прогонах не используются.
- Свой tmux‑сокет: `TMUX_TMPDIR=<ws>/tmux` задаётся перед **каждым** вызовом tmux.
  Сессию `0` и чужие процессы не трогать.
- Консоль читать только `tmux capture-pane -p -S -2000 -t <session>`; команды
  подавать `tmux send-keys ...`, затем `Enter`. `tmux pipe-buffer` в сборке 3.7b
  отсутствует; сохранённые pane‑дампы не являются доказательством.
- `tools/run_besm6_deck.py` использовать только как образец механики; его
  пользовательская правка не изменяется. Его `wait_for(CM1П)` в этой среде
  зависает, поэтому применяется внешний драйвер.

## 2. Маркер загрузки и подача колоды

Признак готовности ОС — строка даты/времени в панели:

```
ДATA:23.11.26 BPEMЯ:00.31.00
```

`CM1П` и `sim>` как regex‑маркеры не используются. После `ДATA:` выдерживается
небольшая пауза, подаются `ДАЙ А0` / `ДАЙ А1`, затем `Ctrl+G`, и в sim> подаются команды:

```
at vu0 <deck>
d 6 1
d 5 10
set cpu req
go
```

Завершение задачи брать из файла АЦПУ (`prn0`) и из `КОНЕЦ ЗАДАЧИ` / `ОЗ(...)` в
панели. Не ждать `КОНЕЦ ЗАДАЧИ` по одному regex, если ACPU уже записан.

**Про АЦПУ (проверено на живой сессии `0`):** до колоды подавать `ДАЙ А0`,
`ДАЙ А1`, затем `НОМВ`; в исправном состоянии `НОМВ` печатает только `HET`
(очередь пуста), а не `НЕТ A1` / `СБО A1`. После колоды снова `НОМВ`.
`СБОЙ АЦПУ0` в наших изолированных прогонах был вызван **
перезаписью строк `attach -n prn0/prn1`** в собственном ini. Строки
`attach -n prn0 ~/Yandex.Disk/simh/BESM6/ACPU/output.txt` и `prn1 ...output1.txt`
из базового ini менять нельзя; `-n` сохранять обязательно. Если нужен
изолированный вывод, копировать файл АЦПУ после прогона, а не подменять attach.

## 3. LUN и образы

- В SIMH **LUN 41 = md41**: при стоковом ini загрузка печатает `2070 - 41`,
  с нашим образом на md41 — `2048 - 41`.
- Карта `ДИС 41(2048)^` и параметр `*TRANS:OURMRK*,,412350` поэтому требуют
  установки каталога/тела именно в образ, подключённый к `md41`.
- `md45` — отдельный рабочий диск 2348; в проверках подключается только копия.
- Образ `/usr/local/share/besm6/2048` — уже 8‑байтовый тегированный SIMH‑образ,
  а не плотный 6‑байтовый. `tools/convert_dense_to_simh.py` к нему неприменим.
- Запись зон: физическая = логическая + 4; данные начинаются со смещения 64
  физической зоны. Заголовок SIMH, принятый ОС:

```
w0 = (phys_zone << 36) | 0x038ca3c918
w1 = 0x000005f1c7800000
w2 = 0x0000410300000000
w3 = end-around-carry sum of the 1024 data words
w4..w7 = те же слова для phys_zone+1
```

Заголовок, записанный C `besmtool`, даёт `2048 ДРУГАЯ ДОРОЖКА`, а нулевой
заголовок — `2048 НЕТ СОВП.КС`. Оба варианта непригодны.

## 4. Обязательный A/B‑набор

Для каждого этапа:

1. `normal` — установленный образ, наш маркер/значение в ACPU.
2.mutation — обнулить наше слово (`body[9]`, дескриптор, вес цифры, слово
   процедуры) → маркер исчезает или цифра меняется.
3. `restore` — восстановить тот же SHA образа → результат возвращается.
4. `no_install` — образ без каталога → `ОТСУТСТВУЕТ OURMRK*`.
5. Зафиксировать SHA всех образов и вырезки ACPU/консоли в отчёте.

## 5. Критерий приёмки этапа

Этап считается принятым только если:

- компилятор собран **из наших текстов** системным ФОРЭКСОМ (это этап сборки);
- целевой дек не содержит `*forex`, `*FTN`, `*perso`, F77LIBR или другого
  системного вызова компилятора;
- A/B пройден в C `dispak` **и в SIMH**;
- в SIMH ACPU содержит ожидаемое число, а MTR/CORE подтверждают исполнение
  наших слов, если речь о рантайм‑арифметике.
