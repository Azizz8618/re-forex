## 2. Приёмочные гейты (полная ОС ДИСПАК под SIMH)

| Гейт | Воздействие | ACPU | Результат |
|---|---|---|---|
| A (baseline) | канонический образ + IR `1234` | `21 -0012.34  3000.00` | PASS |
| B (deck A/B) | тот же образ, IR `5678` (4 байта деки) | `21 -0056.78  3000.00` | PASS |
| C (code A/B) | одно слово `SIGNBIT` 1<<40 → 0 | `21  0012.34  3000.00` | PASS |
| D (restore) | байтово тождественный образ | `21 -0012.34  3000.00` | PASS |

Все четыре дошли до `КОНЕЦ ЗАДАЧИ`; `НОМВ` подавался только после подтверждённой
строки запуска задачи. Число и знак получены machine‑кодом: LIT‑операнд
декодируется из `0o64014`, ABS/SQRT — на FPU, float→GOST — `aex/e+x/aax/asx`,
знак — из бита 40 через `avx/aax/asx/aex`. Host‑вычисленных цифр в выводе нет.

## 3. Независимая проверка главного агента

После пересборки SIMH (`BIN/besm6`, SHA `9ef71b260e8a780d12fa63c152c5979dd8dc50e8959a57849bd73fb5252a8254` (актуальный; `b555acc0…` — устаревший builders‑SHA)) гейты A/B/C
повторены на каноническом образе: `21 -0012.34`, `21 -0056.78`,
`21  0012.34`. Результаты совпали с отчётом субагента.

## 4. Критерии, которые НЕ считаются приёмкой

- C `dispak` — только oracle (MTR/CORE); там нет MMU и другой ход загрузки.
- Ранние PASS `docs/83/84/86` — с хостовыми значениями, приёмкой не являются.
- Совпадение вывода без PERSO/с системным ФОРЭКСОМ — не доказательство:
  на диске стоит та же версия системного ФОРЭКСА (`docs/82`).
- Команда `send-keys` вне подтверждённого запуска задачи даёт ложный «stall»
  (`docs/79` откат).
