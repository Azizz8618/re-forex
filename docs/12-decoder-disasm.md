# 12 — Дизассемблирование скомпилированных тел DATAPR* и OCTTDEC (DECODER)

**Статус:** тела на ленте/дисках **не найдены**; честно документирован поиск.
Скомпилированные тела получены **компиляцией подлинных исходников Дубны**
через DTRAN в эмуляторе dispak и дизассемблированы обратно. Машинные слова
сверены по адресам/константам с найденными на ленте фрагментами.

## 1. Задача

Корень `FOREX*` вызывает две внешние подпрограммы через LINK-ячейки:

| LINK | Символ | Где вызов | Роль |
|---:|---|---|---|
| `0o74010` | `DATAPR*` | `INIT_FOREX`, S1:15479 / S2 `0o510306` | печать даты |
| `0o74013` | `OCTTDEC` | `PRINT_TIME`, S1:15498 / S2 `0o510322` | число → 6 ISO-цифр |

Требование: дизассемблировать **скомпилированные тела**, а не только
воспроизвести исходники (как это было сделано для FORMAT/FORTLIBR в `docs/07`).

## 2. Поиск тел (отрицательный результат)

### 2.1 LINK-область — только заглушки

Родительский агент проверил `monsys.9 --start 0o74000 --count 40`: все слова
`0o74000..0o74047` идентичны (`yta,ati 15`). Это стандартные МАДЛЕН-заглушки
внешней ссылки; редак связей заменяет их на переход к entry-точке. **Тела там
отсутствуют** (подтверждено также `docs/06-address-map.md` §1.3).

### 2.2 DMS-заголовки на ленте

Сканирование всей ленты (294912 слов = 9 полей) на маркер `0o200003`
 DMS-модуля дало 13 попаданий. Имена (поле `+1`, 6-бит TEXT):

```
0o115440 CBDPR     0o121500 CONTROL   0o133712 (нет)
0o135200 ENDPRO    0o137140 GLINK     0o163407 (нет)
0o176000 A/PRINTM  0o224500 BCDAPRT*  0o225600 F/OPT
0o234340 ERRDIAG*  0o241500 LO*SYN    0o277500 LO*GEN
0o1061100 TASK73
```

`DATAPR*` / `OCTTDEC` **среди имён модулей нет**.

### 2.3 Имена в LIBREFER-каталогах

6-битный TEXT `DATAPR*` (`0o4441644160621200`) встречается 25 раз,
`OCTTDEC` (`0o5743646444454300`) — 25 раз. Это каталоги имён, а не тела:
напр. `0o536167/0o536172`, `0o610053/0o610066`, `0o653571/0o653573`,
`0o743016`. Рядом с ними идут unrelated code/таблицы, но это не тела
DATAPR*/OCTTDEC (нет сигнатур FUN 67B / MASK15 + REAL-таблицы).

### 2.4 Найденный скомпилированный фрагмент OCTTDEC

В поле 4 ленты обнаружен **пул констант EXFOR-варианта**:

| Константа | Источник | Адрес на ленте | Значение |
|---|---|---:|---|
| `B40/1` | S7:454 | `0o411316` | `0o0177777777777777` |
| `C10` | S7:455 | `0o411327` | `0o4000000000000012` |
| `C1/10` | S7:456 | `0o411332` | `0o4001463146314632` |

Три точных совпадения в окне 25 слов — надёжная улика, что фрагмент
скомпилированного `OCTTDEC` (EXFOR) присутствует на ленте. ПоискREAL-констант
SYSTEM2-варианта (100000.0 … 1.0) на ленте не дал попаданий.

### 2.5 Диски

Поиск по всем доступным образам (`2048`, `2053`, `2063`, `2086`, `2099`,
`2113`, `2148`, `2153`, `2222`, `2248`, `2348`, `4001`, рабочий `80`)
дал только случайные совпадения маски `0o360741703607417`; ни B40/1, ни
C10, ни C1/10 на дисках не найдены.

**Итог поиска:** полные тела на носителях недоступны → применён путь из
задания: «дизассемблировать по исходнику с привязкой к найденным
скомпилированным фрагментам».

## 3. Как получены машинные слова

1. Вырезки подлинных исходников Дубны:
   - `system1.txt:7645-7733` → `DATAPR%.masm` (имя файла с `%` даёт модуль
     `DATAPR*` после подстановки `% → *` в `asm.pl`);
   - `exfor.vv:427-459` → `OCTTDEC.masm`;
   - `system2.txt:5042-5084` — эталон для секции `OCTDC`.
2. Компиляция через `tools/asm.pl` (monitor80-re) в эмуляторе dispak:
   `*LIBRA:2`, `*CALL DTRAN(<module>)`. WORKVOL=80, образы дисков берутся
   из `/usr/local/share/besm6` через `BESM6_PATH`.
3. Листинг DTRAN снимается с WORKVOL:
   `besmtool dump 80 --length=10 | cosy2txt`. Сохранён как
   `disasm/RUNTIME_*.dtran_compiler.lst` — **авторитетный** результат
   компиляции (команды, метки `*NNNNB`, DOUBLE WORD-литералы).
4. Листинг перекодирован в 48-битные слова (2 МАДЛЕН-команды на слово;
   константы — полные слова) скриптом-энкодером. Бит 18 используется как
   расширение адреса **только** для кодов < `0o40000` (иначе он меняет
   `UTM → V1M` и т.п. — проверено на `dtran`).
5. К каждому дампу добавлен DMS-заголовок (`0o200003` + 6-битное имя),
   как у дампов оверлеев на ленте — это требует `tools/dtran_wrap.py`.

## 6. Ограничения

1. Нет карты загрузки MONSYS → `0o77xxx`-цели оверлеев не привязаны к
   DATAPR*/OCTTDEC (as в `docs/06` §7).
2. В `.words` внешние символы (`DATA*`, `GAK/7`) представлены числовыми
   заполнителями `0o74000/0o74001`; в аннотированном тексте — имена.
3. Отрицательные смещения в нативном `dtran` печатаются как `3774B`
   (12-битное дополнительное число), тогда как MONITOR-80 DTRAN печатает
   `-3`/`-4` — это разница в оформлении, не в битах.
4. Секции `OCTDC` (SYSTEM2) и `OCTEX` (EXFOR) обе присутствуют в `.mad`;
   какая из них собрана по адресу 4.13 `04773`, без трассы не установлено.

## 7. Воспроизведение

```bash
SRC=/home/azizz/besm6.github.io/sources/dubna
TAPE=/home/azizz/Yandex.Disk/besm6-new/besm6.net/tapes/monsys.9
TOOL=/home/azizz/Yandex.Disk/besm6-new/besm6.net/tools/besm6tape.py

# поиск на ленте
python3 "$TOOL" dis "$TAPE" --start 0o74000 --count 40
python3 "$TOOL" dis "$TAPE" --start 0o411311 --count 35 --bemsh

# компиляция (см. logs/decoder_disasm_compile.txt)
BESM6_PATH=<disks> WORKVOL=80 perl -CA \
  /home/azizz/Yandex.Disk/monitor80-re/tools/asm.pl -keep DATAPR%.masm
BESM6_PATH=<disks> WORKVOL=80 perl -CA \
  /home/azizz/Yandex.Disk/monitor80-re/tools/asm.pl -keep OCTTDEC.masm
besmtool dump 80 --length=10 --to-file=/dev/stdout | cosy2txt

# дизассемблирование артефактов
python3 tools/dtran_wrap.py build/RUNTIME_DATAPR.words \
  --out disasm/RUNTIME_DATAPR.dtran.madlen
python3 tools/dtran_wrap.py build/RUNTIME_OCTTDEC.words \
  --out disasm/RUNTIME_OCTTDEC.dtran.madlen
python3 "$TOOL" dis build/RUNTIME_DATAPR.words --start 0 --count 49 --bemsh \
  > disasm/RUNTIME_DATAPR.bemsh.lst
python3 "$TOOL" dis build/RUNTIME_OCTTDEC.words --start 0 --count 20 --bemsh \
  > disasm/RUNTIME_OCTTDEC.bemsh.lst
```
