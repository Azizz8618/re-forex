## VERDICT: PASS - 2+2 digits WITH sign fits EXACTLY 58/58 words

The two proven pieces were combined into ONE contour. The sign test was added
to the optimized 58/58 chain and three word-reclaiming edits (all in the spirit
of docs/98) brought it back to exactly 58/58. It was proved under SIMH with the
decisive A/B/C. The printed value keeps the documented `/10` scaling:

```
deck card word --utc 60000 + xta 4012--> ASCII '1','2' --SR/ARX NEG31-->
int 12 --e+x EMASK + e+x C105--> float 12 --4 Newton iters--> float sqrt(12)
-- V=EST/10; 4 floor/deposit blocks via one VJM subroutine--> 4 GOST digits
-- on-machine sign: avx SIGNBIT / aax SIGNBIT / asx SHR22 / aex GOST_A / atx GOST_A-->
" 21 -0000.34  3000.00"
```

### Decisive gates (authoritative: SIMH ACPU, stock `-n prn`)

| gate | contour image | deck | one change | SIMH ACPU printed line |
|:--|:--|:--|:--|:--|

| **B (sign off)** | `2048_SIGN_B` SHA `21325b50...` | `X=12.0` | ONE machine word: low-RAM `T8` = SIGNBIT `1<<40 -> 0` (RAM `0o2137`) | ` 21  0000.34  3000.00` |
| **C (restore)** | `2048_SIGN_REST` SHA `f620c72a...` (= A) | `X=12.0` | byte-identical to A | ` 21 -0000.34  3000.00` |
| extra gate | `2048_SIGN_A` **byte-identical** | `X=34.0` | only the two deck digits (`12`->`34`) | ` 21 -0000.58  3000.00` |

All four reached `КОНЕЦ ЗАДАЧИ` (completion line
`КОНЕЦ ЗАДАЧИ  +000000000000⏨+00  0000206320000000`). Each also printed
`*NАМЕ ОURМRК` and `*ТRАNS:ОURМRК*,,412350`. Console showed `БОБ:2048 :30(41)-0004,
2048 :41(41)` and `410300000000   ЗС5`.

`cmp -l 2048_SIGN_A 2048_SIGN_B` = **3 bytes**: file offsets `10411686` (the
SIGNBIT data word, `1 -> 0`) and `10410846` / `10410878` (the two recomputed
zone-checksum copies, `135 -> 134`). `cmp -l 2048_SIGN_A 2048_SIGN_REST` is EMPTY.

The negative sign is produced by machine code from the float's own sign bit;
no minus byte is baked by the host. The `aex GOST_A` XORs `1<<18` (`15 ^ 4 = 11`,
`GOST_SPACE -> GOST_MINUS`) into the seeded sign byte of GOST word A. When
SIGNBIT = 0, `avx` does not negate, `aax` isolates 0, and the byte stays 15
(space). The four digits are unchanged by the sign patch (gate B), and the sign
persists when only the deck digits change (extra gate): the two mechanisms are
independent and both are on-machine.

## 1. Exact word budget (measured, not estimated)

Builder: `scripts/final_sign.py` (encodes the exact resolved halfword stream;
2 halfwords = 1 zone word). `code words = ceil(halfwords/2)`.

| variant | halfwords | **zone words** | verdict |
|:--|--:|--:|:--|
| proven docs/98 baseline: deck + SQRT + 2+2 digits (no sign) | 115 | 58 / 58 | prior work |
| baseline + reclaims, NO sign | 112 | 56 / 58 | room made |
| baseline + reclaims + sign block only | 119 | 60 / 58 | over |
| + sign + drop-last-`ati 5` | 117 | 59 / 58 | over |
| **+ sign + both reclaims (FINAL)** | **116** | **58 / 58** | **OK, SIMH-proven** |

Net cost of adding the full sign to the 58-word chain: **+1 halfword**
(115 -> 116), absorbed by three reclaims:

1. **Sign block inserted where ACC already holds V** (5 hw, no reload). Placed
   immediately after `atx V` in the converter; the existing following `xta V`
   (already in the baseline) reloads V for the digit path. The two `utc`s issue
   is avoided: there is exactly ONE `utc` (`utc 60000` for the card page),
   consumed by the next `xta 4012`. No second `utc` was added (two consecutive
   `utc` accumulate M20 and trap).
2. **Dead `xta SCR` removed from `floor_int` subroutine** (-1 hw; 7 -> 6 hw).
   Every one of the four call sites executes `atx SCR` immediately before `VJM`,
   and `atx` preserves ACC, so ACC already holds the floor input at subroutine
   entry. This is the same "no redundant reload" technique used in docs/98
   (`atx NUM` -> `atx EST` without reload). C-oracle MTR confirms the subroutine
   now begins at `0o30203L` with `aex EMASK`, not `xta SCR`.
3. **Dead `ati 5` removed from the last digit deposit** (-1 hw). `asn` uses
   `M[reg=0] = M[0] = 0` (`besm6_cpu.c:1412`: `Aex = ADDR(addr + M[reg])`), not
   `M[5]`; the last digit has no `out`, so `M[5]` is never read afterwards.
   C-oracle MTR shows `MTR 30200L asn 70(0) AU=...4` (correct hundredths digit).
4. **Parity/layout**: the inserted halfwords shift the `VJM` calls and the `*64`
   extracode into favorable left/right halves, removing two padding dummy
   halfwords (the `*64` returns to the next WORD; a right-half placement needs
   no dummy). This is the same `*64`/VJM halfword-padding discipline as docs/98.

### Sign constants: no new zone data

`SIGNBIT = 1<<40` and `SHR22 = (64+22)<<41` are placed in the **unused `T[8]`
and `T[9]` cells** of the low-RAM table (body `0o134/0o135`, RAM `0o2137/0o2140`).
These are inside the proven-free `body[0o110..0o135]` range from docs/98; the
A/B decks use only tens digits 1..4, so `T[8]/T[9]` are never indexed by
`arx T(6)`. No new low-RAM cell outside the proven range was used and no zone
word was consumed by data.

## 6. FACT / INFERENCE and limits

**FACT:** all four SIMH cases printed the stated line and reached `КОНЕЦ ЗАДАЧИ`;
A and REST are byte-identical; one low-RAM data word changed the printed sign
while leaving all four digits unchanged; the byte-identical A image with a
different deck changed the digits while leaving the sign unchanged. C-oracle MTR
shows the sign block, the shortened `floor_int` subroutine and the last digit.

**INFERENCE / not proven:**
- The decisive sign change was made with the **SIGNBIT patch** (explicitly
  permitted by the task), not with a deck `X=-12` literal. Parsing a card-byte
  minus is not in the proven path (docs/97 §6); baking a host minus byte was not
  done. The sign still comes from the on-machine float's bit 40.
- Only deck digits 1..4 in literals `12`/`34` were exercised; the `NEG31`
  shortcut is invalid for digit 0 (docs/98). `T[8]/T[9]` are therefore never
  indexed as table entries by these decks.
- Output keeps the documented `/10` scaling (`sqrt(X)/10`): `X=12 -> 0.34`,
  `X=34 -> 0.58`. No numeric correctness beyond what ACPU prints is claimed.
- The contour still does NOT compile the deck (no FRONT/CODEGEN/EMIT records);
  it proves deck-to-contour argument transfer plus the on-machine intrinsic,
  conversion and sign chain, as in the predecessor reports.

## 7. Zone ceiling

Zone `N+3` (`0o2353`) gives exactly 58 clean words at RAM `0o30114..0o30205`;
zones `N+4..N+40` are not copied at our entry (docs/65, docs/73). The fit is
