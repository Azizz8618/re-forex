# 11. Дизассемблирование скомпилированных тел FORMAT и FORTLIBR

## Цель и отличие от этапа 7

`docs/07-runtime.md` и `src/FOREX_RUNTIME.mad` содержат **дословную перепечатку
листинга** `libra211.l21` (S1:15529-15712). Здесь же Bodies найдены **в машинном
виде на ленте `monsys.9`** и дизассемблированы; исходник использован только для
смысловой сверки и комментариев.

## 1. Поиск границ

Сканирование ленты по 6-байтовым t6-подписям (`FORMAT  `, `FORTLIBR`, `BUFFER  `,
`WRITLIBR`, `PRINT8  `, `FT*571  ` …) дало:

| Подпись | Адрес на ленте | Что это |
|---|---|---|
| `FORMAT  ` | `0o502126` | каталог `LIBREFER` |
| `FORTLIBR` | `0o502124` | каталог `LIBREFER` |
| `FORMAT  ` | `0o510473` | имя скомпилированного модуля |
| `FORTLIBR` | `0o510650` | имя скомпилированного модуля |
| `BUFFER  `, `WRITLIBR`, `PRINT8` | `0o510656-0o510660` | экспортные имена FORTLIBR |
| `FT*571 … FT*003` | `0o510523-0o510535` | внешние имена FORMAT |

Код FORMAT начинается **до** имени (`0o510443`), код FORTLIBR — тоже
заканчивается перед именем (`0o510647`), то есть объектная обвязка library-формата
расположена после тела. Тела:

- **FORMAT:** `0o510443-0o510537`, 61 слово. Диспетчер (`ati 16 / asn 103 /
  vtm 74014(14) / vlm … / 11 пар uj 74001..74013 / atx 4015..4027`)
  полностью совпадает с S1:15541-15586. Константы `amx 7207…7775` — младшие 12 бит
  адресов ячеек передачи 77xxxB (S1:15566-15586).
- **FORTLIBR:** `0o510543-0o510647`, 69 слов. Первое слово `vtm 40061(16),atx 16(16)`
  = S1:15594-15595; 16 LOG-констант `0o510624-0o510643` совпадают со списком
  `*00061 … *00100` (S1:15691-15706); 4 слова `0o510644-0o510647` содержат
  6 ASCII-байт каждое: `ERROR `, `IN STA`, `NDART `, `ARRAY ` (S1:15707-15710).

Область `0o74000..0o77777` —LINK-заглушки `yta,ati 15`, там кода нет; это
подтверждает уточнение родительского агента. Попытка читать каталожные указатели
`0o4400` / `0o74400` (`0o502125`, `0o502127`) привела только в зоны заполнителя.

## 2. Инструменты и артефакты

1. `tools/extract_words.py`-совместимая выгрузка →
   `build/RUNTIME_FORMAT.words` (61 слово), `build/RUNTIME_FORTLIBR.words` (69 слов).
2. `tools/dtran_wrap.py` (синтетический DMS с подставленным t6-именем) →
   `disasm/RUNTIME_FORMAT.madlen`, `disasm/RUNTIME_FORTLIBR.madlen`.
3. `besm6tape.py dis --bemsh --start … --count …` →
   `disasm/RUNTIME_FORMAT.bemsh.lst`, `disasm/RUNTIME_FORTLIBR.bemsh.lst`.
4. Аннотированный МАДЛЕН → `src/FOREX_RUNTIME_DISASM.mad`:
   осмысленные короткие метки, все литералы в `,EQU,` с ролью, комментарии `С`
   и `.` на русском, перекрёстные ссылки.

**Важно (ограничение МАДЛЕН):** компилятор различает только первые 6 знаков
метки/символа. Все имена в новых файлах имеют длину ≤ 6 и уникальны первыми
6 знаками; полное имя вынесено в `; (полное: …)` и в
`include/RUNTIME_DISASM.xref.md`. Проверка — `logs/runtime_disasm_names.txt`.

## 3. Побайтовая проверка

В `src/FOREX_RUNTIME_DISASM.mad` для каждого слова помещена строка:

```
С слово NNNN @0o510443 = 0o40001670100000
```

(например, `С слово 0000 @0o510443 = 0o40001670100000`).

Сверка с `build/RUNTIME_*.words`: 61/61 и 69/69 слов совпали по значению и
индексу. `python3 tests/check-source-words.py` → rc = 0 (тест читает только
`src/LO_*.mad`, новые файлы его не затрагивают; `src/LO_*` не изменялись).

## 4. Результаты сверки с листингом

| Фрагмент | Строк | Расхождений |
|---|---|---|
| FORMAT, S1:15541-15586 | 46 | 0 (с учётом релокации LINK-адресов) |
| FORTLIBR, S1:15594-15690 | 97 | 0 (с учётом L-адресов и ISO→ASCII) |

Классы отличий машинного кода от листинга:
- символические `FT*nnn` заменены LINK-адресами `0o74001-0o74013`;
- `L <reg> ATX a-b` (относительные адреса) скомпилированы в рело-таблицу;
- `ISO ,6H...` представлены 6 ASCII-байтами в слове;
- `77766B` и `77xxxB` в FIELD-части усечены до младших 12 разрядов.

## 5. Ограничения

- Полная копия библиотеки на ленте содержит и другие версии подпрограмм
  (например, `FTNPRT` при `0o511234`, более поздний `FORTLIBR`-подобный модуль
  при `0o510661+`). Они **не отождествляются** с `libra211.l21` без отдельной
  проверки и в этот дизассембл не вошли.
- Смысл LINK-ячеек `0o740xx` восстановлен по каталогу `LIBREFER` и S3;
  их конкретное содержимое после загрузки на ленте не хранится.
