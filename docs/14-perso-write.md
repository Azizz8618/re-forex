# Запись библиотеки ФОРЭКС+рантайм в PERSO тома 2348 с зоны `0o2300`

Рабочий документ: только **рабочая копия** диска 2348; эталон и «боевая»
копия не трогаются. Все номера зон в мониторных картах — **восьмеричные**,
в `besmtool` — **десятичные** (но `besmtool` печатает адрес восьмеричным:
`2300.0000` = зона `1216` dec).

---

## 1. Формат PERSO и точные команды записи

### 1.1. Что такое PERSO-библиотека

Личная (персональная) библиотека Монитора-80 «Дубна» — это подряд идущие
зоны тома:

```
зона Z+0 ┐
         ├─ КАТАЛОГ (ровно 2 зоны = 2048 слов); слово 0 — служебное,
зона Z+1 ┘  слово 1 — 0, дальше записи идут парами со слова 2
зона Z+2 ... тело объектных модулей (DMS), выровнено по 32 словам
```

- Слово = 48 бит = **6 байт big-endian**; зона = 1024 слова = **6144 байт**
  (`besmtool dump --to-file` выдаёт именно такие 6-байтовые слова).
- Минимальная длина библиотеки — **2 зоны** (один каталог). Монитор печатает
  `ДЛИНА LIBRARY <NNN> ЗОН` **восьмеричным числом, включая 2 зоны каталога**;
  это число и есть требуемый `--length` / число занятых зон.
- Пример из `AGENTS.md:238`: личная библиотека на LU 66 с зоны `050`,
  «всего `10g` зон» = 10 восьмеричных = 8 десятичных зон.

### 1.2. Карта каталога (проверено на `re-siprod/build/siprod.bin`)

Каталог читается со **слова 2** зоны `Z+0` парами слов
(`siprod_lib.py:_read_catalog`):

| Слово | Содержимое |
|-------|------------|
| 2, 4, 6, … | имя модуля, **8 символов TEXT-кодировки**, 6 бит/символ, выравнено влево, пробелы справа |
| 3, 5, 7, … | запись каталога (48 бит) |
| первое пустое имя после последней записи | завершатель каталога |

TEXT-алфавит (индекс → символ, `siprod_lib.py:26-31`):
`0=' '`, `1='.'`, `2='Б'`, `3='Ц'`, `4='Д'`, `5='Ф'`, `6='Г'`, `7='И'`,
`8='('`, `9=')'`, `10='*'`, `11='Й'`, `12='Л'`, `13='Я'`, `14='Ж'`,
`15='/'`, `16..25='0'..'9'`, `26='Ь'`, `27=','`, `28='П'`, `29='-'`,
`30='+'`, `31='Ы'`, `32='З'`, `33..58='A'..'Z'`, `59='Ш'`, `60='Э'`,
`61='Щ'`, `62='Ч'`, `63='Ю'`.

Кодирование имени: `w = Σ code(ch_i) << (42 − 6·i)`, `i = 0..7`
(`text_encode`). Примеры: `FOREX*` (6 знаков + 2 пробела),
`DATAPR*` (7+1), `LO*SYN`, `LO*GEN`, `FORMAT`, `OCTTDEC`.

**Запись каталога (48 бит)** — `notes/loader.md`, п. 3 (реальный пример из
`siprod.bin`: `STANDA` → `0o3750640013200000`, length-поле `0o1320` = 720 =
90×8):

```
rec = (date << 24) | ((L * 8) << 12) | overlay

  биты 47..24 — date (у существующих записей младшие 2 бита = 0;
                именно поэтому сюда «затекает» переполнение длины)
  биты 25..12 — L * 8, где L = длина ЗАГРУЗКИ модуля в словах
  биты 11..0  — номер оверлея (0 для обычного модуля)
```

- **`L = cmd + const + bss`**, где `bss` — это ПАМ, **НЕ data**
  (`notes/loader.md`, п. 1). Ошибка здесь даёт «ИСПОРЧЕНА ПОДПРОГРАММА».
- `L*8 > 0o7777` (4095) спокойно заходит в младшие биты поля `date`;
  формула `(date<<24)|((L*8)<<12)` корректна при любом `L`, если у `date`
  младшие 2 бита нулевые. Практически: возьмите `date = rec_эталон >> 24`
  из любой существующей записи (например, `STANDA`) — гарантированно подходит.
- **Новые записи добавлять ТОЛЬКО В КОНЕЦ каталога**, после завершателя
  (замена завершателя новыми парами + новый завершатель). Вставка в начало
  сдвигает номера входов личной библиотеки, на которые ссылаются другие
  модули через `C=0o6700`, и ломает загрузку (`loader.md`, п. 4).

Заголовок объектного модуля (DMS): 3 слова,
`w0 = head | sym<<12 | debug<<36`,
`w1 = set | data<<15 | long<<30`,
`w2 = cmd | bss<<15 | const<<30`;
далее разделы `cmd | const | data | set | head(имя) | sym | long | debug`.
`sym`-элемент: `(0o4000+X)<<24 | C<<12 | D`; `C=0o6700` — вход личной
библиотеки, `C=0o6300` — вход постоянной библиотеки монитора
(`loader.md`, п. 5).

### 1.3. Способ А (рекомендуемый): запись задачей Монитора `*TO PERSO`

Именно этим путём создаются рабочие библиотеки в `pascal-re` и `re-siprod`.
Монитор сам строит каталог, поэтому риск ошибки в записи минимален:

```
шифр 419900 зс5^
лен 40(2348-wr)^          ; 40 — LU назначения, -wr — режим записи
ееВ1а3
*name
*call yesmemory           ; расширенная память (= *CALL FICMEMOR)
*perso:412300             ; НЕОБЯЗАТЕЛЬНО: дочитать существующую библиотеку
                          ;   с LU 41 зоны 2300, чтобы дописать модули
... модули / трансляция FOREX*, FORMAT, DATAPR*, OCTTDEC ...
*to perso:402300          ; ★ записать временный каталог в PERSO:
                          ;   LU 40, зона 2300(8) = 1216(10)
*end file
``````
еконец
```

- Формат карты: `*TO PERSO:LUZZZZ`, где `LU` — два восьмеричных знака
  (диапазон `30..67`), `ZZZZ` — начальная зона в восьмеричной системе.
  Запись идёт **только при `лен …(2348-wr)`**; без `-wr` том доступен на чтение.
- Сколько зон занято — смотрите по `ДЛИНА LIBRARY <NNN> ЗОН` в листинге.
  Это и есть граница, которую нельзя переходить следующими записями.
- Дозапись в уже загруженный каталог — карта `*PERSO:LUZZZZ,CONT`.

### 1.4. Способ Б: raw-образ через `besmtool write`

Если готовый образ библиотеки уже собран (как `re-siprod/siprod.bin`,
24 зоны, либо `lib-new.bin`), запись идёт напрямую:

```bash
export BESM6_PATH="$HOME/.besm6:/usr/local/share/besm6:$HOME/Yandex.Disk/simh/BESM6/MD/EC5061"
besmtool write 2348 --from-file=forex-lib.bin --start=1216   # --start ДЕСЯТИЧНЫЙ!
```

Число зон образа: `nzones = ceil(размер_байт / 6144)`
(в 6-байтовых словах: `ceil(nwords / 1024)`), см. `siprod_perso.py:36`,
`record2348_new.py:292`. Контроль записи — побайтовая сверка:

```bash
besmtool dump 2348 --start=1216 --length=$NZ --to-file=/tmp/readback.bin
cmp /tmp/readback.bin forex-lib.bin     # либо пословно как в record2348_new.py
```

`bsmtool` в этой среде **не установлен** (`command -v bsmtool` пусто);
доступен только `besmtool` версии 2.6.458. Важная ловушка: `besmtool` понимает
`--start` как **десятичное** число; записав `--start=0o2300`, вы получите зону 0
(парсер останавливается на `o`).

## 2. Свободна ли зона `0o2300`? Безопасное число зон

Проверено **только чтением** (`besmtool dump`) 19.11.2026:

| Образ | первая ненулевая зона после `0o2300` | зоны `0o2300..0o2477` |
|-------|--------------------------------------|------------------------|
| рабочая `~/.besm6/2348` (md5 `de309a314bccbfaf263d49f48593f14a`) | `0o2500` = 1344 dec | все нули (заполнитель) |
| эталон `~/Yandex.Disk/simh/BESM6/MD/EC5061/2348` (md5 `15e5a52c5efe7b62c53f3bbb335e16cc`) | `0o2500` = 1344 dec | все нули (заполнитель) |

Карта зон `re-dispak/rukava.be`, раздел 1.3 (ПАКЕТ 2048(2348)) подтверждает:
последняя описанная запись перед этим местом — `1740-1743 *PERSO /*МАЛИСНЕV*/`,
далее идут `2000-2027` и `5000-5027` (PERSO Паскаля), `02150-02167`
(СИПРОД новая редакция), `02570` (PERSO /ВД203/). Прямо `0o2300` в справочнике
не значится; на диске он пуст.

**Свободный непрерывный интервал: `0o2300 … 0o2477` = `1216 … 1343` dec
= `0o200` = 128 десятичных зон.** Первая занятая зона — `0o2500`.

> **БЕЗОПАСНОЕ число зон: не более 128 (`0o200`), т.е. писать строго
> `0o2300 .. 0o2477`; граница `0o2500` — трогать запрещено.**
> Практическая рекомендация: выделите под библиотеку только реально нужные
> зоны (компилятор FOREX* + LO*SYN/LO*GEN по ~1 зоне каждый + мелкие модули
> рантайма — ориентировочно 5…15 зон), оставив `0o2400..0o2477` резервом.
> Перед записью повторите проверку:
> `BESM6_PATH=$HOME/.besm6 besmtool dump 2348 --start=1216 --length=128 --to-file=/tmp/chk.bin`
> и убедитесь, что все 128 зон нулевые.

Внимание: рабочая копия `~/.besm6/2348` **уже отличается** и от эталона
`EC5061/2348`, и от «боевой» `/usr/local/share/besm6/2348`
(md5 `6193cb53a140b2c8a0b5b386de623f8f`) — там уже есть записи (в том числе
зона `0o2500` с GOSTLIB/TESTRWD). Это нормально: зона `0o2300` не затронута.
Если нужна чистая база — пересоздайте рабочую копию из эталона:
`tools/init-disk-2048.sh -f` из `pascal-re` ( VOL=2348, REF=…/EC5061/2348 ).

## 3. Как не трогать эталон

1. **Никогда не пишите** в `~/Yandex.Disk/simh/BESM6/MD/EC5061/2348` (эталон),
   `/usr/local/share/besm6/2348` (боевая копия) и `MD/2048`. Пишите только в
   `~/.besm6/2348` (или в отдельную рабочую копию
   `/tmp/.private/azizz/opencode/re-forex/work/2348`).
2. **`BESM6_PATH` — приоритет слева направо.** Рабочая копия должна быть ПЕРВОЙ:
   ```bash
   export BESM6_PATH="$HOME/.besm6:/usr/local/share/besm6:$HOME/Yandex.Disk/simh/BESM6/MD/EC5061"
   # для изолированной копии:
   # export BESM6_PATH=/tmp/.private/azizz/opencode/re-forex/work/2348:$HOME/Yandex.Disk/simh/BESM6/MD/EC5061
   ```
   Тогда `2348` берётся из рабочей копии, а `2148/2053/…` — с чтением из
   системных каталогов. (Как в `pascal-re/tools/perso-build.sh:22`.)
3. **Резерв + контрольная сумма до/после:**
   ```bash
   cp -a "$HOME/.besm6/2348" "$HOME/.besm6/2348.bak-forex-$(date +%Y%m%d)"
   md5sum "$HOME/.besm6/2348" \
          "$HOME/Yandex.Disk/simh/BESM6/MD/EC5061/2348" \
          /usr/local/share/besm6/2348 > /tmp/before.md5
   # ... запись ...
   md5sum -c /tmp/before.md5
   ```
   MD5 эталона и боевой копии обязаны остаться
   `15e5a52c…` и `6193cb53…` соответственно. Изменился хоть один — откатываем
   рабочую копию из `.bak-…`.
4. Мониторная карта должна монтировать **рабочую** копию: `лен 40(2348-wr)^`.
   Имя `2348` разрешается через `BESM6_PATH`; это важно при запуске
   `dispak` из любого каталога.
5. После записи Structure диска (каталог зон) отметить в
   `~/Yandex.Disk/re-dispak/rukava.be`, таблица зон 2348 — но это уже отдельная
   задача, не эта запись (`re-siprod/README.md:102-103`).

## 4. Загрузка библиотеки картой `*PERSO:60 2300` и разрешение имён

### 4.1. Монтирование и загрузка

`LU` — два восьмеричных знака из диапазона `30..67`, зона — восьмеричная.
Каноническая форма без пробела: `*PERSO:602300` (допускается и
`*PERSO:60 2300`, ср. `*perso: 411350, cont` в `docs/PLAN.md:115`).

```
шифр 419900 зс5^
лен 60(2348)^             ; смонтировать рабочую копию на LU 60 (без -wr!)
ееВ1а3
*name
*call yesmemory           ; *CALL FICMEMOR — режим увеличенной памяти
*perso:602300             ; прочитать PERSO с зоны 2300(8) во временный каталог
*forex                    ; или *call forex*  — запуск компилятора
... текст на Фортране ...
*execute
*end file
``````
еконец
```

Монитор ищет модули в **временном каталоге задачи**, поэтому все имена —
`FOREX*`, `LO*SYN`, `LO*GEN`, `FORMAT`, `DATAPR*`, `OCTTDEC` — должны
присутствовать в каталоге записанной библиотеки (п. 1.2). `LO*SYN`/`LO*GEN`
в исходной системе — TEXT-константы (имена) в корне `FOREX*`, тела которых
лежат на ленте `monsys.9`, зоны `0o120`/`0o137` (`docs/PLAN.md:18`);
в нашу библиотеку их надо положить **как отдельные модули** с теми же
именами в каталоге, иначе разрешение не состоится.

### 4.2. Последняя загрузка побеждает

При нескольких `*PERSO` с одинаковыми именами используется **последний
загруженный** модуль (`pascal-re/PERSO.md:59-60`). Поэтому:

- чтобы переопределить системные версии — грузите системную библиотеку
  **первой**, нашу — **последней**:
  ```
  *perso:413230        ; системная /*FORX3 (2048, зона 0o1205 и т.п.)
  *perso:602300,cont   ; ★ наша библиотека — её модули перекроют системные
  ```
- если нужна только наша библиотека — одной карты `*perso:602300` достаточно;
- `,CONT` дозаписывает в уже загруженный временный каталог (не clearing его).

ДляPascal-аналога «переключения» на модульный путь служит `*STAND`
(`pascal-re/PERSO.md:55-58`); для Фортрана напрямую `*forex` / `*call forex*`
после загрузки каталога.

## 5. Минимальный рабочий пример deck

### 5.1. Запись (сборка библиотеки в PERSO, зона `0o2300`)

```
шифр 419900 зс5^
лен 40(2348-wr)^
ееВ1а3
*name forexlib
*call yesmemory
*perso:412300
... объектные модули FOREX*, LO*SYN, LO*GEN, FORMAT, DATAPR*, OCTTDEC ...
*to perso:402300
*end file
``````
еконец
```

Ожидаемый отклик: `ДЛИНА LIBRARY <NNN> ЗОН` (восьмеричное, ≥2). Проверка:

```bash
export BESM6_PATH="$HOME/.besm6:/usr/local/share/besm6:$HOME/Yandex.Disk/simh/BESM6/MD/EC5061"
besmtool view 2348 --start=1216 --length=1 --encoding=t   # каталог, имена модулей
besmtool dump 2348 --start=1216 --length=1 --to-file=/tmp/chk.bin
```

### 5.2. Использование (решето Эратосфена, по `reference/forex.b6`)

```
шифр 419999 зс5^
лен 60(2348)^
ееВ1а3
*name Forex
*call yesmemory
*perso:602300
*full list
*forex
c---- решето Эратосфена
      program main
      integer prime (100)
      do 10 n=2, 100
 10       prime (n) = 1
      do 20 n=2, 100
          if (prime(n) .eq. 0) goto 20
              maxk = 100.0 / n
              if (maxk .lt. 2) goto 20
              do 30 k=2, maxk
 30               prime (n*k) = 0
 20       continue
      do 40 n=2, 100
 40       if (prime(n) .ne. 0) print 1000, n
      stop
 1000 format (1x, i4)
      end
*execute
*end file
``````
еконец
```

Запуск (не забыть про рабочую копию первым в `BESM6_PATH`):

```bash
BESM6_PATH="$HOME/.besm6:/usr/local/share/besm6" dispak deck.b6
```
