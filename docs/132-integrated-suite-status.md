## 3. Блокер MOD в слитом сканере

Отдельно MOD по имени из Fortran‑текста PASS (`docs/131`): `MOD(7,3)→1.00`,
`MOD(8,3)→2.00`, `MOD(7,4)→3.00`. Но при слиянии в общий однопроходный LEX
токен‑поток для `Y=MOD(7.0,3.0)` получается:

```
PROGRAM, ID(Y), EOL, ID(Y), '=', LIT(pay0), LIT(pay1), ')', EOL, END
```

То есть два литерала вместо одного и потерян `PRINT/FORMAT`. Причина —
переиспользование общего `NUM_STORE` при разборе второго аргумента. Word
budget здесь ни при чём: N+3 55/58, N+2 543/649, зона `526..900` не тронута.
Ведётся перенос состояние‑машины аргументов из `b6c_mod_full.py` (docs/131)
в слитый сканер.

## 4. Честный список неподдерживаемого F77

- DSQRT (нет double FPU; софтверная DP >100 команд, зона `N+4` недоступна).
- `READ(u,fmt)` и вообще дескрипторный ввод (привилегированный `э52`,
  docs/91/92); работает только символьный ввод из буфера карты.
- Общий `DO` с обновлением переменной цикла, шагом ≠1 и вложенными циклами
  (сейчас фиксированный счётчик и одно тело).
- Полные выражения: переменные и SKIP‑логика есть, но приоритет/скобки
  доказаны только для литеральных операндов; нет общего разбора всех
  F77‑операторов.
- Переходы `GOTO`, `IF`, `CALL`, `COMMON`, массивы, COMPLEX, двойная точность,
  `END=` / `ERR=` / `IOSTAT`, файловый I/O `OPEN/CLOSE/INQUIRE`.
- FT*002/003 резидентного монитора недоступны из‑за MMU (docs/88).

Поэтому цель «полностью автономный компилятор Fortran‑77» **пока не достигнута**:
доказано рабочее подмножество, а не весь язык.
