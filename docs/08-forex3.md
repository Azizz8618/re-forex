## 1. Почему эта ветка вообще рассматривалась

В реконструкции FOREX ИПМ АН СССР (`2.02 от 15.07.80`, `4.13 от 11.09.85`,
`FOREX 412` на `monsys.9`) оставался незакрытый пробел: в документации
упомянут ещё один транслятор с собственным именем **FOREX3\***.

| Источник | Что говорит |
|---|---|
| `monitor80-re/permanent/ttable%.asm:32-33` | `ISO 6Н*FORX3` → `TEXT 8НFOREX3*` (таблица команд монитора) |
| `monitor80-re/docs/СПРАВОЧНИК_КОМАНДЫ.md:124` | `*FORX3` → `FOREX3*`, «Фортран-3 расширенный» |
| `/home/azizz/besm6.github.io/wiki/sys-instr.txt:449` | `1130-1177 ЗОНЫ - FОRЕХ 3` (структура области `РЕЖСОВМ` МД 2048) |
| `wiki/examples/whetstone.b6:10`, `wiki/examples/whetstone/whetstone.b6:12`, `dispak/tests/whetstone/whetstone.b6:10` | `*TRANS:FOREX3*,,411550` при `DIS 41(2148)` |
| `besm6-new/DUBNA/BUILD/mk-stl-src.sh:47` | `*ТRАNS:FОRЕХ3*,,411550` — «Compilation with forex3 on 2148» |

Строка `OVERLAY:35,74, F T N` на `monsys.9` по слову `0o201046` — это
сервисная команда `*CALL OVERLAY:35,74, F T N` (см. §3.3), а не код или имя
FOREX3*.

## 3. Проверка физических указателей

### 3.1 Диск 41 = 2148, зона 1550 (deck `*TRANS`)

`DIS 41(2148)` в whetstone-деке отображает диск 41 на файл
`/usr/local/share/besm6/2148` (`svs2048.bin`, см. `install_disks.sh`).
Зона `0o1550` = слово `892928` (`0o3320000`).

Первые слова зоны — обычный кодовый массив (`0o0344036200000360`,
`0o0020027343756377`, `0o7776500100116406`, `0o0300020074000400`, …),
**без заголовка модуля и без имени**. Маркеров `0o200003` на диске 2148 нет
вообще. В зонах `0o1545–0o1627` имя `FOREX3*` ни в одной кодировке не найдено.

### 3.2 МД 2048, зоны 1130–1177 (wiki/sys-instr.txt)

Важная оговорка из `sys-instr.txt:392-396`: номера зон в таблице даны
**относительно области `РЕЖСОВМ`**:

> `N ЗОНЫ МД = N ЗОНЫ ОБЛАСТИ + 100`

Следовательно, FOREX 3 должен занимать физические зоны МД 2048
`0o1230–0o1277` (664–703₁₀). Проверено в `2048`, `2048.2448`, `2348`,
`2048.bak`: зоны `0o1230–0o1231` содержат шаблон незаписанной зоны
`(0, 0o4000000000000, 0o2000000000, 0o1000)`. В `2248` на этом месте
другие данные, но имени FOREX3* нет нигде.

### 3.3 `monsys.9:0o201046`

```
0o201045  *CALL
0o201046  OVERLA
0o201047  Y:35,7
0o201050  4, F T
0o201051   N
```

Полная строка: `*CALL OVERLAY:35,74, F T N`. Это команда монитора в
сервисной области ленты (соседствует с `FOREX 412` по `0o201762`),
не код FOREX3*.

## 4. Ключевое открытие: `*TRANS` = `NEWCOMP*`

В `monitor80-re/permanent/ltable%.asm:37-38`:

```
, ISO ,6Н*TRANS
, TEXT,8НNEWCOMP*  .+
```

То есть `*TRANS:FOREX3*,,411550` — это вызов системной процедуры
**`NEWCOMP*`** («new compiler») с аргументом `FOREX3*` и адресом `41/1550`.
Имя `NEWCOMP*` подтверждено на ленте: `monsys.9`, слово `0o423226`,
в таблице рядом с `STACOMP*`, `DINCOMP*`, `AVTOLOAD`, `PUTFLAG*`, `EXECUT`,
`EXIT` (см. `logs/forex3_pointers.txt`).

**Следствие:** `FOREX3*` в deck — это *имя-параметр загрузчика*, а не имя
модуля, хранящегося в образе. Отсюда и отсутствие TEXT-сигнатуры в дисках:
искать нужно было не «модуль с именем FOREX3*», а «тело, которое NEWCOMP*
читает с диска 41, зоны 1550».

### 4.1 Runtime-факт

В `dispak/tests/whetstone/output.txt` при активном `*TRANS:FOREX3*,,411550`
(строки 57, 230, 257, 277, 299, 322) транслятор печатает:

```
F О R Е Х ИПМ АН СССР 4.12 ОТ 25.06.85
```

Сообщений об ошибке загрузки нет. Значит, по указателю `41/1550` реально
лежит рабочий компилятор, который **идентифицирует себя как FOREX 4.12** —
сборка от 25.06.85, отличная и от `2.02 (15.07.80)`, и от `4.13 (11.09.85)`.

## 5. Вывод

1. **Исходная гипотеза**: FOREX3* — отдельный транслятор «Фортран-3
   расширенный». Она подтверждается документацией (ttable, справочник,
   sys-instr) и наличием отдельного deck-указателя.
2. **Именованный модуль FOREX3* в доступных образах ОТСУТСТВУЕТ** — ни в
   одной из проверенных кодировок, ни по одному из физических указателей.
3. Единственный материальный след — тело на диске `2148:0o1550`, загружаемое
   через `NEWCOMP*`, которое в прогоне whetstone даёт баннер **FOREX 4.12**.
4. Поэтому FOREX3* **не входит** в реконструируемый FOREX ИПМ 2.02/4.13 и
   не должен отождествляться с ним без исходника. Это отдельная ветка,
   известная пока только по документации и указателю в deck.

### 5.1 Почему не создан `src/FOREX3.mad`

Сделать его сейчас означало бы выдать произвольный 36–48-зонный дамп с
диска 2148 за «реконструированный исходник FOREX3*»: у дампа нет заголовка с именем,
неизвестна точная длина, а баннер внутри него говорит `4.12`, а не `FOREX3`.
Побайтовая сверка и round-trip для такого «исходника» невозможны.
В соответствии с заданием (ветка «если не найдено») честно фиксируем поиск.
