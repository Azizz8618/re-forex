# Предел ручного on-machine FORMAT в контуре зоны 2350

Дата: 23.11.2026. Документирует отрицательный результат, полученный при попытке перенести FORMAT/PRINT полностью в BESM-6‑код внутри 58-словной зоны `N+3`.

## Что пробовалось

- FREXT `777011 <seq> <i> <K> <R> <W> <D>` из копии `FRONT.FTN` для дескрипторов FORMAT.
- Небольшой ассемблер полуслов `codegen/b6asm.py` и программа-форматтер в high RAM, вызываемая `pb 0o30114` из `body[9]`.
- В образ устанавливались только raw‑ячейки дескрипторов, цифр и общие веса SH/SP/DT/EO; GOST‑слова — нулевые.

## Результат: FAIL

Целевой консольный лог: `ЗАПРЕЩ.КОМАНДА`, затем `64000 04 32 42601 iret`, числовой строки нет. Широкий MTR‑проход (679 042 строки) показывает монитор и наши слова, но не завершённый проход форматтера. Ни один host‑результат не был переименован в «on-machine».

## Причина (FACT)

- Полусловная инструкция БЭСМ-6 имеет **12-битное поле адреса** (`0o7777`). Обычные `XTA/ARX/STO` не адресуют ячейки high RAM вида `0o30114`; нужна структурированная 15-битная адресация, которой ручной форматтер не пользовался.
- `pe` (0x0b8000) ветвит при ACC != 0; `po`/уза в default-режиме инертно, поэтому «branch if zero» пришлось бы кодировать как `pe`+`pb`.
- Перенос ячеек данных обратно в окно `body[1..0o43]` не убрал trap.

## Следствие для архитектуры

Этот путь **не является продуктом**. Правильный путь, выбранный пользователем: строить FOREX 5.00 из текстов FOREX 4.13 (`src/FOREX_RUNTIME.mad`, `src/LO_SYN.mad`, `src/LO_GEN.mad`), где FORMAT/FORTLIBR/DATAPR* уже реализованы и компилируются системным ФОРЭКСОМ как этап сборки. Ручное написание форматтера в 58 словах не требуется.

READ в литеральной форме (`READ X/1.0/` → `777010` → ячейка тела, A/B `1.00 → 7.00`) остаётся единственным подтверждённым on-machine фрагментом этого старого контура; сквозной on-machine PRINT не доказан.
