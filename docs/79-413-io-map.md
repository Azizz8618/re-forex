## 0b. Machine constraint honoured (parent finding)

The abandoned zone-2350 formatter trapped with `ЗАПРЕЩ.КОМАНДА`: ordinary XTA/ARX/STO halfwords
carry only a 12-bit ADR field (`0o7777`), so high-RAM addresses such as `0o30114` require
structured 15-bit addressing, and `po`/уза is inert in default mode (a zero branch must be
`pe` + `pb`). **Avoided here:** no new BESM machine code was written at all. The only executable
mechanism used is the existing `FORMAT`/`FORTLIBR`/`DATAPR*`/`OCTTDEC` machinery from our texts,
compiled by the SYSTEM FOREX compiler, and every edit was a same-length word substitution inside
an existing compiled module, never a new address-space construct.

### 1.2 LO_SYN (FORMAT lexer/token path)

`src/LO_SYN.mad` structure is documented at `docs/plan-f77/02-extension-points.md:39-66`:
words `0000..1516` = state/action automaton (`L_ST300_*`, `L_ST400_*`, ..., see
`include/LO_SYN.xref.md §1`); words `1517..1777` = transition table; token fetch uses extract
codes Э20/Э36/Э47/Э60/Э63/Э64/Э65/Э67/Э70; result = token stream + symbol table in COMMON
`*A*` (2048 words at `0o4000`) and `ENTRY*` (40 words at `0o4006`).

**Important honesty note:** the annotated `src/LO_SYN.mad` contains **no symbolic `FORMAT`,
`PRINT`, `READ` or `FT*` labels** (grep returns nothing). The descriptor lexer path is
*inferred* from the automaton layout and external documentation, not proven by symbols in the
text. New syntax requires editing code in `0004..0531`/`0624..1777`, 10-40 words per construct,
HIGH risk (`docs/plan-f77-full/02-madlen-extension.md:107-110,179-192`).

## 4. Missing primitives (do not fake)
1. **G descriptor** - no free FT* slot (11/11 used, `src/FOREX_RUNTIME.mad:164-185`) and no
   G routine in lib21. Native G is rejected; only R13 lowering exists. Adding it needs a new
   FT* SUBP + free `0o77xxx` cell + LINK cell + lib21 routine (3-6 words in FORMAT + LINK),
   `docs/plan-f77-full/02-madlen-extension.md:134-157`.
2. **List-directed PRINT */READ *** - token and generator code absent from LO_SYN/LO_GEN and no
   FT*LD1 runtime routine; 10-40 words per construct + 3-6 in FORMAT + 40-120 words in a PERSO
   zone, HIGH risk (`02-madlen-extension.md:107-110,179-192`). Today only F77PREP host lowering
   is executable => not in our texts.
3. **END=/ERR=/IOSTAT=** - no EOF/status return in the input runtime and no LUN channel in the
   monitor; sentinel emulation only. Need P7c/monitor + input-runtime patch
   (`15-io.md:158-183`, `20-open-close.md:81`). IOSTAT is not lowered at all.
4. **`READ(u,fmt)`, OPEN/CLOSE/INQUIRE** - LUN table and file-name binding exist only at OS
   job-control level; impossible in Fortran texts alone (`15-io.md:188-235`,
   `20-open-close.md:145-167`).

## 6. Honest limitations
* The annotated `.mad` texts are documentation artifacts: a direct `*assembler` pass on a copy
  of `FOREX_RUNTIME.mad` produced 198 `ОШИБКА` lines (label column, `;` comments, module-local
  EQU scoping, `*00077 - FLCON` address expressions). The PERSO image is built from the
  byte-exact compiled word dumps that these texts annotate; no host code generator is a product.
* C-dispak and SIMH are different OS builds; see section 2.5 for the SIMH outcome. In particular
  the `*perso:602300` deck stalls under SIMH even with byte-verified clean md45 PERSO zones;
  this is an explicit FAIL/limit, not a claim that our texts were verified as the compiler there.
* No claim is made that list-directed I/O, G, END=/ERR=/IOSTAT or unit I/O work: they are
  lowering/monitor features, not text features, as detailed in section 4.
* The FAIL/limits are: (a) runtime-descriptor text A/B produces no output change because the
  PERSO clones are not selected by SYSTEM FOREX 2.02 for this deck; (b) the PERSO-enabled deck
  cannot be executed under the full SIMH OS in this environment. Both are stated rather than
