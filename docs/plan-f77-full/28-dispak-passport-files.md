## 1. Парсер паспорта задания в dispak

Парсер — функция `scan()` в **`dispak/dispak/vsinput.c:152-387`**. Читает
паспорт (строки до символа `E`, каждая строка обязательно заканчивается
`^` = `GOST_OVERLINE`), разбирает первый параметр (до пробела) и сравнивает
первые 3 байта с ключевыми словами.

| Карта / ключ | Место (файл:строка) | Действие |
|---|---|---|
| `шифр` / `USER` (Id) | `vsinput.c:158-228` | уровень 0: user id (6+6 цифр), опц. пароль/STPASP |
| `ВХО` / `BEG` | `vsinput.c:248-256` | `psp.entry` — точка входа |
| `АВОСТ` | `vsinput.c:257-259` | `psp.intercept` (по умолчанию `020`) |
| `АЦП` / `LPR` | `vsinput.c:261-269` | лимит печати `psp.lprlim` |
| `ТЕЛ` / `TEL` | `vsinput.c:271-275` | `psp.tele = 1` |
| `СПЕ` / `SPE` | `vsinput.c:277-281` | `psp.spec = 1` |
| `ОЗУ`, `ВРЕ`/`TIM`, `ТРА`/`TRA`, `ЛИС`/`PAG`, `РОС`/`WRI`, `ФИЗ`/`PHY` | `vsinput.c:283-318` | игнорируются /Partial |
| **`ЛЕН` / `TAP` / `ДИС` / `DIS`** | **`vsinput.c:320-375`** | **`ЛЕН <LUN-восьм.> (<том-decimal>[C│-ЗП│-WR│-<смещение>])` → `psp.vol[]`** |
| любое другое | **`vsinput.c:376-381`** | `printf("Unknown passport entry: ...")` и **молча игнорируется** |

Подробно `ЛЕН` (`vsinput.c:324-375`): `u = get_octal(cp)` — номер канала 030..067;
`cp[2] == '('`; `volno = get_decimal(cp)` — номер тома/объём в зонах (1..4095);
суффикс `C` → `wr=2` (кусок/барабан, `chunk += volno*040`), `-ЗП`/`-WR` →
`wr=1` (запись), `-<octal>` → `offset`; запись в `psp.vol[psp.nvol]`,
`++psp.nvol` (максимум 12, `vsinput.c:334-337`).

Структура паспорта — **`dispak/dispak/iobuf.h:19-34`**
(`struct passport { user, entry, intercept, tele/keep/spec, nvol, lprlim, phys,
struct vol { wr, u, volno, offset } vol[MAXVOL]; arr_end }`).
Потребление при старте задачи — **`dispak/dispak/input.c:61-79`**: из `psp.vol[]`
заполняются `disks[u].mode/.offset/.diskno` и открывается образ диска
`disk_open(no, flg)`. `ddisk_t` и массив — `defs.h:77-82` и `defs.h:319,351`.
Ещё один путь монтирования — экстракод **`Э50 0131` «attach volume to handle»**
(`extra.c:1614-1636`), который вызывается монитором, а не картой `*FILE`.

**Важно:** карты `*name`, `*call`, `*perso`, `*forex`, `*no list`, `*execute`,
`*end file` **не разбираются C-парсером dispak**. Они находятся в секции данных
деки (после `е`), загружаются в память и интерпретируются эмультируемым
супервизором (Монитор-80 / ДИСПАК: `MONREAD*` → `IDENT6` → `SWITCH` в
`star%.masm`), о чём см. `27-file-docs.md:37`.

## 2. Есть ли `*FILE` в dispak? — НЕТ

Полный grep по всему репозиторию (`*.c`, docs, `.b6`) не нашёл ни `*FILE`,
ни `FILE:`, ни `SCRATCH` как системной карты:

* в `dispak/*.c` — **ни одного** вхождения `*FILE` / `FILE:` / `SCRATCH` /
  `attach`; единственное «attach» — комментарий `Э50 0131 attach volume to
  handle` (`extra.c:1614`);
* `d_fileno` в `disk.c` — host-файловый дескриптор образа диска, не карта;
* `tests/README.md:83` — «scratch АРФА volume» (эрфовский том, не карта);
* в документации dispak `*FILE` тоже отсутствует (`27-file-docs.md:28-29`).

**Вывод:** dispak понимает только `лен NN(том)` (и `лент`/`дис`) — монтирование
**именованного тома на числовой канал**, — и монтирование дисков через Э50.
Карты `*FILE` в нём нет. (Для сравнения: в `monitor80-re/chekjob/g02407.f:53,
196-208` карта `*FILE ` распознаётся входным контролем задания — но это другой
репозиторий/ОС, в dispak этого кода нет.)

## 3. Прогоны: «карта → результат»

Все деки — `*perso:602300` + `*forex`, Fortran:
```
      PROGRAM FILETST
      X=123.0
      WRITE(41,10) X
   10 FORMAT(1X,F10.2)
      STOP
      END
```
Диагностика считается фатальной при `rc!=0` или наличии `НЕТ КАНАЛА` /
`ОШИБКА` (критерий из `17-lun-p7c.md:26-27`).

| # | Что_DECL/карта | rc | Диагностика |
|---|---|---|---|
| A1 | `*FILE:FUBAR,41,W` **в паспорте**, без `^` | **1** | `Unknown passport entry: *FILE:FUBAR,41,W ...` — строка без `^` поглотила весь файл → `НЕТ КОНЦА ВВОДА` (НС 377, `err.txt`) |
| A1′ | то же, но с `^` на конце | 0 | `Unknown passport entry: *FILE:FUBAR,41,W` (карта проигнорирована) + **`НЕТ КАНАЛА LUN 41`** |
| A2′ | `*FILE:FUBAR,41,W^` в паспорте, **без** `лен 41` | 0 | `Unknown passport entry` + **`НЕТ КАНАЛА LUN 41`** |
| A3 | `*FILE:FUBAR,41,W` в потоке `*`-команд, после `*forex`; `лен 41(2048-wr)` | 0 | **`НЕТ КАНАЛА LUN 41`**, файл `fubar.bin` не создан |
| A4 | `*FILE:FUBAR,41,W` сразу после `*name` | 0 | **`НЕТ КАНАЛА LUN 41`** |
| A5 | `*FILE:FUBAR,41,W` перед `*execute` | 0 | **`НЕТ КАНАЛА LUN 41`** |
| A6 | `*file:fubar,41,w` (строчные), после `*name` | 0 | **`НЕТ КАНАЛА LUN 41`** |
| A7 | `*FILE FUBAR,41,W` (пробел, как `6H*FILE `), после `*name` | 0 | **`НЕТ КАНАЛА LUN 41`** |
| B1 | **`лен 41(2048-wr)`** (канал 41 смонтирован на запись), без `*FILE` | 0 | **`НЕТ КАНАЛА LUN 41`** |
| B2 | `лен 41(2048)` (только чтение), без `*FILE` | 0 | **`НЕТ КАНАЛА LUN 41`** |
| C (control) | никакого объявления 41, без `*FILE` | 0 | **`НЕТ КАНАЛА LUN 41`** |
| D (control) | `WRITE(6,10) X` (стандартный LUN 6) | 0 | `НЕТ КАНАЛА` **нет** — LUN 6 принят (Fortran I/O работает) |
| эталон | `len 45(2048-wr)` + `WRITE(45,10) 45` (`base_u45`) | 0 | **`НЕТ КАНАЛА LUN 45`** |

**Ключевой результат:** `НЕТ КАНАЛА LUN 41` выдаётся **независимо** от того,
смонтирован ли канал 41 паспортом `лен 41(2048-wr)`. Это подтверждает
двухуровневую модель из `17-lun-p7c.md:14-24`:

* **Уровень A** (каналы эмулятора `disks[]`, `input.c:61-79`) — `лен` работает,
  канал 41 действительно монтируется;
* **Уровень B** (таблица допустимости LUN ФОРЭКС 2.02 / Монитора-80:
  `ERRLUN` 043xx, `LUN*MON`, `LUNTYP`; реестр `monitor80-re/permanent/erriom.asm`,
  `lun%mon.asm`) — проверка **раньше** Э70 и именно она печатает
  `НЕТ КАНАЛА LUN 41`. LUN 41 в этой таблице не зарегистрирован.

## 4. Вердикт

1. **`*FILE` в dispak не поддерживается ни в паспорте, ни в потоке системных
   карт.** В паспорте он попадает в ветку `vsinput.c:376-381` и печатает
   `Unknown passport entry`; в `*`-потоке (а также в тексте Fortran) он никак не
   влияет на I/O. Файл на хосте не создаётся.
2. **Объявить файл на LUN 41 и сделать `WRITE(41,10) X` в dispak нельзя.**
   Все 10 вариантов дают `НЕТ КАНАЛА LUN 41`; даже `лен 41(2048-wr)` не помогает
   (уровень B). Аналогичный `WRITE(45,...)` с `лен 45(2048-wr)` тоже даёт
   `НЕТ КАНАЛА LUN 45`.
3. **Закрыть J2/J4/J23 только добавлением карт `*FILE` в паспорт — нельзя.**
   Для dispak такой карты нет; а даже её гипотетический парсинг не снимает
   блокер уровня B. J2/J4/J23 требуют правки/пересборки рантайма
   (ERRLUN/LUN*MON в оверлее Монитора-80), как показано в
   `18-errlun-re.md`, `22-errlun-supervisor.md`, `23-luntyp-patch.md`
   (вердикт `NEEDS-RUNTIME-REBUILD`). Прототип с пропатченным `LUNTYP` + Э50 0131
   по-прежнему печатает `НЕТ КАНАЛА LUN 45`.

## 5. Оценка: сколько работы нужно, чтобы добавить `*FILE` в dispak

**Только синтаксис карты в C-парсере (не даёт рабочего I/O):**

| Файл | Что сделать | Объём |
|---|---|---|
| `dispak/dispak/vsinput.c` (перед `:376`) | новая ветка `else if` после разбора `ЛЕН`: распознать `*FILE:NAME,LUN,W[,N]`, разобрать имя (≤6), LUN (030..067 или F01-подобный), режим R/W, размер | ~25-40 строк |
| `dispak/dispak/iobuf.h:19-34` | новое поле `struct passport` (например `files[]`: name, u, mode, size) | ~5 строк |
| `dispak/dispak/input.c:61-79` | заполнить `disks[u]` host-файлом (`fopen`/создание `<name>.bin`) | ~15-25 строк |

Итого ~50-70 строк C в 3 файлах, ≈0.5-1 человеко-день, **плюс** тест-дек и
прогон. Ограничение: все строки паспорта должны заканчиваться `^`; формат
Dubna без `^` ломает ввод (см. A1).

**Но для цели «`WRITE(41,...)` на объявленный LUN» одного парсера мало.**
Нужна правка уровня B — регистрация LUN 41 в таблице допустимости ФОРЭКС/
Монитора-80 (пересборка оверлея `erriom.asm`/`lun%mon.asm`, запись в системную
зону 2348). Это отдельная задача того же класса, что J2/J4/J23, оценка —
несколько дней реверса/пересборки, причём `23-luntyp-patch.md` показывает, что
«дешёвый» патч `LUNTYP` не срабатывает.

**Практический вывод:** дешевле и надёжнее не добавлять `*FILE` в dispak, а
закрывать J2/J4/J23 через пересборку системного образа (уровень B), используя
уже отработанный тулчейн `21-diskpatch-toolchain.md` / `23-luntyp-patch.md`.
