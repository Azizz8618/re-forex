**Дата:** 19.11.2026. **Статус:** ИССЛЕДОВАНИЕ ЗАВЕРШЕНО, гипотеза ОПРОВЕРГНУТА.

**VERDICT: `NEEDS-RUNTIME-REBUILD` (патч `LUNTYP` — неверная цель).**
Патч исходника сделан и собирается (0 ошибок), но `WRITE(45)` НЕ вызывает `LUNTYP`:
блокер Level B живёт в `monitor80` (`ERRIOM`/`LUN*MON`), в перезагружаемом оверлее

по-прежнему печатает `НЕТ КАНАЛА LUN 45`, ожидаемого вывода `45` НЕТ.

**Владение:** созданы только этот документ, `logs/f77_23_*.txt` (5 файлов) и
прототип `/var/tmp/p7c-luntyp/**`. `src/`, `tests/`, `REFERENCE`, эталоны дисков
и исходный `dispak/monitor80-re` — READ-ONLY, не трогались. (Один случайный заход
записи на эталон 2348 из-за неверного `BESM6_PATH` немедленно откачен из pristine-копии;

## 1. Задание 1 — прочитать LUNTYP.mad и найти точку проверки

Прочитаны целиком:
- `src/lib21/LUNTYP.mad` (107 строк, аннотированная реконструкция субагента);
- `disasm/lib21/LUNTYP.madlen` (dtran-листинг скомпилированного объекта);
- **оригинальный ассемблерный исходник**
  `/home/azizz/besm6.github.io/sources/dubna/besml21/libra212.l21:4801-4868`.

`FUNCTION LUNTYP(LUN)` возвращает тип устройства (0=не заказано, 1=лента,
2=SCRATCH, 3=личный файл на диске, 4=спец.файл), `LUN = 30В..67В`.
Тип **приписан юниту при генерации системы** (`20-open-close.md:149-151`).

**Точка «не заказано» (возврат 0):**

| Представление | Место | Код |
|---|---|---|
| аннотированный | `src/lib21/LUNTYP.mad:88` | `10,VTM, . НЕЗAKAЗAHO` |
| оригинал (ассемблер) | `libra212.l21:4850` | `10,VTM,.HEЗAKAЗAHO` |
| объект | `lib21.bin @13088`, cmd-слово 16, правая половина | `10,VTM,` (return 0) |

DMS-адрес объекта в каталоге lib21 — `0o045054` (это адрес/связь intra-library,
**не** физический адрес в памяти: `(row<<11)|(0o1040+zone)`, см. `lib21_parse.py:33`).

Другие возвраты: тип 4 (спец.файл) — cmd12-L, тип 2 (SCRATCH) — cmd26-L.
`LUNTYP` дёргает Э63 502/504/57/760/20/576 **только для запроса** типа, не для обмена.

## 3. Задание 2 — пересборка и запись в рабочую копию 2348

**Тулчейн РАБОТАЕТ.** МАДЛЕН `*assembler` через dispak (как в
`tools/build_forex_perso.py:191-237`), дека `*assembler` + `*to perso:602320`:
- `rc=0`, **0 ошибок транляции** (`logs/f77_23_assembly.txt`);
- аннотированный `src/lib21/LUNTYP.mad` напрямую НЕ ассемблируется (С*-комментарии
  и `; ...` аннотации) — использован оригинальный `libra212.l21`;
- объект подтверждён дампом PERSO 0o2320: каталог `word2/3` = имя `LUN TYP`,
  запись длиной `0o36 = 30` слов (лог `f77_23_patch_source.txt` §3).

**Куда записать:**
- `lib21.bin` — build-артефакт; его байты не найдены ни на 2048, ни на 2348
  (поиск 4 характерных слов в 6-byte BE и uint64 LE → 0 совпадений). In-place патч
  системной lib21 с диска невозможен без пересборки образа MONSYS.
- Пропатченный LUNTYP записан в **PERSO 0o2320 рабочей копии 2348** (вместе с
  LUNAT из `17-lun-p7c.md` §3.2) — это технически легко; но см. §4: не помогает.

## 4. Задание 1/3 — КЛЮЧЕВОЕ: гипотеза опровергнута

Гипотеза: `LUNTYP(45)=0 → ERRLUN`. Проверена по ПОЛНОМУ MTR-трейсу `WRITE(45)`
из волны A2 (`/var/tmp/p7c-mtr/err.txt`, 2 012 550 строк):

1. **Экстракод `*63` выполнен всего 2 раза за весь трейс** (строки 122, 1047015),
   тогда как `LUNTYP` требует 6 (`502,504,57,760,20,576`). ⇒ LUNTYP НЕ выполняется.
2. Нет ни одного перехода на entry LUNTYP (`0o045054`) или в диапазон `0450xx`.
   (Jumps на 4-значные `4505/4513/4545/4561` — это монитор, не LUNTYP.)
3. В таблице символов провалившейся задачи **LUNTYP отсутствует**; присутствуют
   `LUNMUN 03163`, `LUN*MON 03164`, `ERRIOM 04241`, `ERRLUN 04321/04361` (оверлей).
4. Путь ошибки: `02506R *67 20(14)` → печать → `02522R uj 0(15)` → `00411 *74 STOP`
   = `ERRUN` (`erriom.asm:84-93`: `VTM TНETКAН '12H HET KAHAЛA'` → `вых*ERRIOM` → STOP).
5. `WRITE1.mad:104` вызывает `DRUMTAP*`; `drumtap%.asm` LUNTYP не вызывает.
   LUNTYP — пользовательская FUNCTION, вызываемая из PECYPC/PT6/IPUTS/PCPLOT
   (`reference/expect_library21.txt:260,332,1119`), а не из Fortran I/O runtime.

**Вывод:** проверка Level B НЕ идёт через LUNTYP. Патч LUNTYP не может снять блокер.
Это уточняет (не отменяет) вердикт `18-errlun-re.md`: `NEEDS-RUNTIME-REBUILD` —
и добавляет, что «реверс бинарника ERRLUN» — правильная цель, а LUNTYP — нет.

## 5. Задание 4 — прототип: пропатченная 2348 + attach + WRITE(45)

Сборка: `/var/tmp/p7c-luntyp/run/disks/2348`
- `0o2300` — `FOREX_PERSO_2300.bin` (эталонный компилятор, как в `run-f77-full.sh:171-174`);
- `0o2320` — пропатченный LUNTYP (тип 3) + `LUNAT` (МАДЛЕН `Э50 0131` attach LUN45→2048);
- дек `run/w45_patched.b6`: `CALL LUNAT` → `WRITE(45,10) 45` → `PRINT 'AFTER WRITE OK'`.

Команда:
```
BESM6_PATH=/var/tmp/p7c-luntyp/run/disks:/usr/local/share/besm6 \
  dispak run/w45_patched.b6
```

**Результат (лог `logs/f77_23_proto_write45.txt`):**

| Поле | Значение |
|---|---|
| `rc` (dispak) | **0** |
| stdout | `НЕТ КАНАЛА  LUN 45` / `КОНЕЦ ЗАДАЧИ` / `00411 … *74` (STOP) |
| ожидаемый вывод `45` | **НЕ получен** |
| `AFTER WRITE OK` | не напечатано (STOP до PRINT) |

Прямая проба `LUNTYP(45)/LUNTYP(54)` из Fortran (`f77_23_luntyp_probe.txt`) не
сработала из-за name resolution дубликата LUNTYP в PERSO+lib21 ('Пока рано', STOP
00020) — как доказательство не годится; в verdict не включена.

## 6. Что осталось для WRITE(45) / READ(45)

1. **WRITE(45):** дизассемблировать `ERRLUN`/`LUN*MON` по `core-pc.bin` в точке
   `02506R`, найти таблицу допустимости каналов монитора в перезагружаемом оверлее,
   добавить LUN 45 (и 40), **пересобрать monitor80 + системный диск 2348**
   (правка исходников `monitor80-re/permanent/{erriom,iocont%,...}`).
2. **READ(45):** дополнительно EOF/IOSTAT-сигнал в рантайме ввода (`monread%`,
   `IOEND*`; `19-eof-iostat.md`) — иначе ввод не завершится даже после снятия Level B.
3. Регрессия GATE 20/20 + золотые бинарники после пересборки.
Оценка `17-lun-p7c.md` §7: 20–40 чел.-дн. Не решается ни патчем LUNTYP, ни
`patch_system_disk.py`, ни PERSO-обёрткой. Дополнительно, параллельная волна A3
(`22-errlun-supervisor.md`) пропатчила найденную таблицу в супервизоре — и тоже
не добилась вывода `45`: требуется ещё правка уровня инициализации/каналов
эмулятора. То есть даже «правильный» патч таблицы Level B insufficient — работы
больше, чем предполагалось в исходной гипотезе.
