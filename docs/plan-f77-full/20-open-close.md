## 0. Вердикт (честно, без завышения)

| Аспект J24 | Вердикт | Обоснование |
|---|---|---|
| **Грамматика / синтаксис** `OPEN`/`CLOSE`/`INQUIRE` | **CLOSEABLE-NOW** | Host-lowering в `CALL` убирает `НЕДОПУСТИМ КЛЮЧ СЛОВО` и `БУФ ПЕРЕП` **0 словами в оверлеях**; транслятор ФОРЭКС keyword не видит вовсе |
| **Состояние юнита** (OPENED, ISTAT-подобный код) | **CLOSEABLE-NOW (прототип, исполняемо)** | 3 PERSO-процедуры + общий `COMMON /J24STT/` действительно хранят флаг открытости; `INQUIRE` возвращает его |
| **Настоящая семантика F77 OPEN**: `FILE='...'`, `STATUS=`, `ACCESS='DIRECT'`, `RECL=`, реальный обмен данными | **IMPOSSIBLE без правки монитора/рантайма** | В ФОРЭКС/ДИСПАК нет runtime-связи «имя файла → юнит»;DISPAK-области объявляются job-control директивами до запуска, а не `OPEN`-ом внутри программы; `Э50 0131` не снимает `НЕТ КАНАЛА` (`17-lun-p7c.md` §3.2) |

**Итоговый вердикт: CLOSEABLE-NOW — но ТОЛЬКО как документированный stub/профиль**
(синтаксис + unit-state). Это **не** полная реализация X3.9 `OPEN/CLOSE/INQUIRE`.
Если заказчик понимает «закрыть J24» как настоящие именованные файлы и прямой
доступ, то честный вердикт — **NEEDS-OVERLAY/IMPOSSIBLE** (те самые 20–40+ чел.-дн.
патча монитора/рантайма из `17-lun-p7c.md` §7). Ключевое слово `OPEN` больше не
блокирует — но файл по-прежнему не открывается. Завышать до `OK` нельзя.

**Главный выигрыш:** 40–80 чел.-дн. пересборки `LO_SYN/LO_GEN` **не нужны** — как
и в волне 1/2, правятся только host-часть и PERSO-зонирование, 0 machine-слов.

## 1. Задание 1 — lowering-контракт `OPEN/CLOSE/INQUIRE` → `CALL`

### 1.1 Механизм

`prep_tools.py` (rules 23–31) делает host-предсканирование исходника **до** подачи
в ФОРЭКС 2.02 и перевыпускает lowered Fortran. `OPEN`/`CLOSE`/`INQUIRE` можно
обработать тем же приёмом — как rule 33 (`R_J24`), чисто текстово:

```
ВХОД (fixed-form, cols 7-72):
    OPEN  (u [,FILE='...'] [,STATUS='...'] [,IOSTAT=ist])
    CLOSE (u [,STATUS='...'] [,IOSTAT=ist])
    INQUIRE (UNIT=u,OPENED=v [,IOSTAT=ist] [, ...])

ВЫХОД:
    CALL FOPEN (u, ist)          ! OPEN
    CALL FCLOSE(u, ist)          ! CLOSE
    CALL FINQ  (u, v, ist)       ! INQUIRE(UNIT=,OPENED=)
```

- `ist` — host-аллоцированная `INTEGER`-переменная (как `dyn_alloc`/`90000+`
  zone в правилах v3), если пользователь не задал `IOSTAT=` сам.
- `FILE=`/`STATUS=`/`ACCESS=`/`RECL=` **принимаются, но игнорируются** stub-рантаймом
  (обязательная оговорка в профиле). Синтаксически они отбрасываются при разборе,
  чтобы keyword не попал в транслятор.
- Никакой правки `LO_SYN/LO_GEN`: `FOPEN/FCLOSE/FINQ` — внешние имена ≤6 символов,
  разрешаются через PERSO (как `STRCAT/…` в `0o2310`).

### 1.2 Точные сигнатуры (исполняемый прототип, `FOPEN.FTN`)

```
SUBROUTINE FOPEN (U, ISTAT)        INTEGER U, ISTAT
    ! U=0..15 → OPN(U+1)=1; ISTAT=0. Вне диапазона → ISTAT=1.
SUBROUTINE FCLOSE(U, ISTAT)        INTEGER U, ISTAT
    ! U=0..15 → OPN(U+1)=0; ISTAT=0. Вне диапазона → ISTAT=1.
SUBROUTINE FINQ  (U, OPENED, ISTAT) INTEGER U, OPENED, ISTAT
    ! OPENED=OPN(U+1) (1=open, 0=closed); ISTAT=0/1.
COMMON /J24STT/ OPN(16)            INTEGER OPN   ! разделяется main + PERSO
```

`ОПN(16)` — таблица флагов открытости, общая для main и процедур через labeled
COMMON (стандартный механизм FOREX; тот же, что rule R_F11). Диапазон 0..15 —
увеличение размера массива тривиально; в прототипе достаточно для `U=11`.

### 1.3 Что НЕ делает lowering (обязательные оговорки)

1. `IOSTAT=` здесь — **эмулируемый код возврата**, не настоящий `IOSTAT` рантайма
   (в ФОРЭКС нет EOF/IOSTAT-сигнала: `15-io.md` §4.3).
2. `FILE='D1'` не создаёт и не связывает файл; `STATUS='NEW'|'OLD'` не проверяется.
3. `ACCESS='DIRECT'`, `RECL=` не реализованы (нет notion записи фиксированной длины).
4. Прямой доступ (random record) в ДИСПАК отсутствует как Fortran-концепция.

Демонстрация текстового lowering-а: `logs/f77_20_lowering_demo.txt`
(прототип `src/lower_j24.py`, **не** установлен в `src/f77prep`).

## 2. Задание 2 — хватает ли каталога PERSO; рецепт зоны 0o2320

**Да, хватает.** Предел в 12 модулей относится **только** к зоне `0o2310`
(`10-implementation-libr.md` §7.1), где уже заняты все 12. Зона `0o2320` —
свежая PERSO-зона со своим каталогом (уже применялась в `17-lun-p7c.md` §2 для
`MINRTN`/`LUNAT`). Три процедуры скомпилировались в неё без ошибок; в каталоге
`0o2320` (дамп `besmtool dump 2348 --start=1232`, 1232 = 0o2300+0o20):

```
0: name='    Б(TЗ'   transfer_vector=0o0     ← header zone
1: name='FINQ'       transfer_vector=0o2350
2: name='FCLOSE'     transfer_vector=0o2310
3: name='FOPEN'      transfer_vector=0o2250
4: name='FOREX*'     transfer_vector=0o2050  ← безвредный дубль из 0o2300
5: name='LO*SYN'     transfer_vector=0o2010  ← безвредный дубль
```

Каждая процедура ≈ `ДЛИНА ПОДПРОГРАММЫ 00035` (29 слов) + заголовок — ),
далеко от предела 1024 слова. **3–5 процедур помещаются с запасом.**

### Рецепт сборки (проверен, `logs/f77_20_build2320.txt`)

1. Рабочая копия эталона `2348`; записать базовую PERSO:
   `BESM6_PATH=<work> besmtool write 2348 --from-file=build/FOREX_PERSO_2300.bin --start=1216`
   (`1216` = 0o2300).
2. Dek компиляции (`decks/build2320.b6`):
   ```
   шифр 419999 зс5^ / лен 60(2348-wr)^ / еев1а3
   *name J24LIB / *call yesmemory
   *perso:602300
   *full list
   *forex
   <FOPEN.FTN: три SUBROUTINE с COMMON /J24STT/>
   *to perso:602320
   *end file / `````` / еконец
   ```
   Запуск: `BESM6_PATH=<work>:/usr/local/share/besm6 dispak lib.b6`.
   Контроль: `rc=0`, `ДЛИНА LIBRARY 004 ЗОН`, в логе нет `ERR/ОШИБКА/НЕДОПУСТИМ`.
   `ИСПОРЧЕНЫ ПОДПРОГРАММЫ: GIV/PG, OCTTDЕ*, DATAPR*, FORTLIBR, FORMAT, LO*GEN`
   — известный безвредный артефакт подключения базовой `0o2300` (см.
   `build_forex_perso.py` docstring), на загрузку наших трёх процедур не влияет.
3. Проверка каталога (см. дамп выше).
4. Рабочая дека (`decks/test_j24.b6`): `*perso:602300` + `*perso:602320,cont`,
   затем `*forex` с `CALL FOPEN/FCLOSE/FINQ`.

**Почему Fortran, а не МАДЛЕН:** компиляция через `*forex` (как `F77LIB.FTN` в
`run-f77-runtime.sh`) заставляет сам ФОРЭКС сгенерировать соглашение передачи
аргументов; ручная MADLEN-обвязка не нужна. МАДЛЕН-вариант (`*assembler` +
`*to perso:602320`, как `MINRTN`) тоже работает, но потребовал бы ручного
разбора параметров.

## 3. Задание 3 — что означает «открыть файл» на БЭСМ-6/ДИСПАК

**Есть notions имени файла и каталога — но на уровне ОС/job-control, а не Fortran.**

- `LUNTYP.mad:45-53`: `LUN=30в..67в`, тип устройства `0=не задано, 1=лента,
  2=SCRATCH-файл, 3=личный файл на диске, 4=спец. файл`. Тип **приписан юниту при
  генерации системы**, не меняется `OPEN`-ом.
- `Dispak-programmer-guide.md` §4.6–4.7: `НОВ <ИМЯ ОБЛАСТИ>[:L=,T=,И=]` — создать
  именованную область (файл); `УБРАТЬ`, `СМЕНА`, `ПРАВА`; `ОБЛАСТЬ/КАТАЛОГ`.
  Имя области → виртуальный номер через **паспорт** `ЛЕНТ 42(PROGRAM/049077-ЗП)‾`
  (`ЛЕНТ НУ(ИМЯ_ОБЛ-БАЦ)`) — всё это **до запуска задачи**, декларативно.
- `Э50 0131` (attach volume→канал) и `Э70` (обмен) работают с **номерами томов и
  каналами**, не с именами файлов. Прямого доступа с `RECL` как Fortran-концепции
  нет: адресация зон idiosyncratic и не отображается на `ACCESS='DIRECT'`.

**Вывод:** ключ `FILE='D1'` не может быть превращён в реальное связывание во время
выполнения программы — для этого нет ни системного вызова, ни таблицы в рантайме.
Даже успешный `Э50 0131` не помогает Fortran I/O: `17-lun-p7c.md` §3.2 показывает
`НЕТ КАНАЛА LUN 45` при условии, что проверка уровня B (`ERRLUN`) проходит раньше
`Э70`. Поэтому честное название нашей реализации — **unit-state stub / profile
convention**, не «OPEN/CLOSE реализованы». В профиле FOREX 5.00 надо прямо
записать: `OPEN/CLOSE/INQUIRE` = управление флагом OPENED; `FILE/STATUS/ACCESS/
RECL` = синтаксически принимаются, семантически ignore.

## 4. Задание 4 — результат прототипа

`decks/test_j24.b6` (FORTRAN → CALL → PERSO → печать), `logs/f77_20_test_j24.txt`:

```
 AFTER OPEN  IST= 0 OPENED= 1
 AFTER CLOSE IST= 0 OPENED= 0
 КОНЕЦ ЗАДАЧИ
```

`rc=0`, stderr пуст, в stdout нет `ERR/ОШИБКА/НЕДОПУСТИМ/ОТСУТСТВУЕТ/ИСПОРЧЕН/
БУФ ПЕРЕП`. (Буквы `АFТЕR ОРЕN` вместо `AFTER OPEN` — артефакт декодирования
DUBNA TEXT диспаком, тот же, что в `10-implementation-libr.md` §4.)

**Что доказано исполняемо:**
1. `CALL FOPEN/FINQ/FCLOSE` из Fortran разрешаются в PERSO `0o2320` (загрузка
   `*perso:602320,cont`) и корректно получают аргументы.
2. `COMMON /J24STT/ OPN(16)` **разделяется** между главной программой и тремя
   PERSO-процедурами: состояние `OPENED` сохраняется между вызовами.
3. Host-lowering `OPEN/CLOSE/INQUIRE` → `CALL` — чистая замена текста
   (`logs/f77_20_lowering_demo.txt`), 0 слов в оверлеях, 0 правок грамматики.

**Что НЕ доказано и не заявлено:** создание/связывание файла, STATUS='NEW',
ACCESS='DIRECT', реальный ввод-вывод через `FILE='D1'`. Это остаётся за
`P7c/monitor` (20–40+ чел.-дн., `17-lun-p7c.md` §7).
