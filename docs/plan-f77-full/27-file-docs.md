## 0. Главный результат поиска

**В документации Монитора-80 `*FILE` не описан вообще.** Полный справочник системных
карт `monitor80-re/docs/СПРАВОЧНИК_КОМАНДЫ.md` перечисляет `*NAME`, `*END FILE`,
`*READ`, `*EDIT`, `*CALL`, `*MAIN`, `*CATAL`, `*EXCLUDE`, `*LIBPUNCH`, `*LIBLIST` и т.д.,

### Что **не** задокументировано (важно)

* **Режим R/W и ёмкость как поля `*FILE` в трёх репозиториях не описаны.** Единственные
  задокументированные поля — имя и слот (`re-siprod/dtran-siprod.sh:19-25`). Любые
  формы вроде `,W` / `,40` в скоуп не входят и в отчёт не перенесены.
* **Когда файл создаётся и удаляется** — в документации не сказано. `*END FILE`
  (`docs/СПРАВОЧНИК_КОМАНДЫ.md:376`) закрывает задание, а не конкретный файл.
* **Где именно живёт файл** — прямо сказано только для эмулятора: `<name>.bin` в
  текущем каталоге (`re-siprod/dtran-siprod.sh:19`). Для Монитора-80 как ОС это
  не описано.

## 2. Программный API: OPEN / FOPEN / SETIODCB / READ* / WRITE*

**Такого API в документации нет — говорю прямо.**

* `monitor80-re/docs/**`: ни `OPEN`, ни `FOPEN`, ни `INQUIRE`, ни `SETIODCB`, ни
  `READ*`/`WRITE*` как пользовательских вызовов не найдено. Есть только перечень
  модулей `IOCONT*`, `IOX*`, `LOADF`, `LUN%MON` (`docs/СПРАВОЧНИК_КОМАНДЫ.md:139-140,
  205, 227, 533-547`) и внутренний дескриптор «LUN, формат, адрес» (`:551-555`).
* `re-dispak/docs/**`: named-file API тоже отсутствует. Ближайшее —
  **низкоуровневый обмен с устройством ЭК `0030Н`**
  (`docs/Dispak-programmer-guide.md:13320-13349`): информационный массив с
  `КОП=0` (запись ВУ1→ВУ2) / `КОП=1` (чтение ВУ1←ВУ2), типы устройств
  «МД, заказанные в паспорте — 030-067(ВОСЬМ.)», «МД файловой системы — 100-1FFН»,
  номер зоны, длина массива. Это **устройственный** уровень, а не API по имени файла.
* Архивно-файловая система **ARFA** в Диспаке реально существует: каталог областей
  и экстракод его запроса (`docs/Dispak-sysprog-guide.md:2251-2253`, `:3000-3025`),
  но это уже ФС Диспака, а не карта `*FILE` Монитора-80. Смешивать нельзя.

Итог: `OPEN/CLOSE/INQUIRE` по имени файла в рассматриваемом скоупе не задокументирован
ни в одной из трёх систем.

## 3. Сравнение `*FILE` с dispak-паспортом `лен NN(...)`

**Разные механизмы, разные уровни и разные ОС.**

| | `*FILE:<имя>,<слот>` | `ЛЕН NN(...)‾` |
|---|---|---|
| Где живёт | поток системных карт задания (`re-siprod/dtran-siprod.sh:22-25`) | **паспорт задачи**, раздел `ЛЕНТ`/`ЛЕН` (`re-dispak/docs/Dispak-sysprog-guide.md:839-859`) |
| Кто обрабатывает | командный процессор `star%.masm` + входной контроль (`docs/СПРАВОЧНИК_КОМАНДЫ.md:437-465`; `chekjob/g02407.f:196-208`) | подсистема ввода Диспака при приёмке паспорта; паспорт обязателен, 4 обязательных раздела (`Dispak-sysprog-guide.md:845-849`), разбор разделов — `Dispak-description.md:601-610` |
| Формат окончания | строка `*…` | раздел заканчивается **надчеркиванием `‾`** (код 115); имя раздела сокращается до 3 символов (`Dispak-sysprog-guide.md:839-859`) |
| Примеры | `*file:siprod,67` — имя + слот | `ЛЕН 30(2048)‾` — LUN 30, диск на 2048 зон (**стандартный паспорт Монитора-80**: `Dispak-compat-guide.md:169-195`); `ЛЕН 44(200-ЗП)‾` — МЛ, запись (`:883`); `ЛЕН 45(1С)` — один кусок (`:612`); `ЛЕН 43(ВАСЯ.МАЛЬЧИК/4199..)‾` — владелец/шифр (`:3273`) |
| Смысл | примонтировать **именованный** внешний файл к слоту/устройству | заказать **ресурс** (ленту/диск/зону) на логический номер LUN |
| Когда | до исполнения программы | до исполнения программы |
| Runtime-вызов | нет | нет (это объявление ресурса, не открытие файла) |

Оба механизма — **job-control, а не runtime**. Разница в том, что `ЛЕН` — это
декларация устройства в паспорте Диспака, а `*FILE` — карта монтирования именованного
файла в потоке задания мониторной системы. Прямой преемственности в документации не
прослеживается; единственная связь — и то косвенная: стандартный паспорт **Монитора-80**
в Диспаке содержит `ЛЕН 30(2048)‾` (`Dispak-compat-guide.md:176`).

## 4. Вердикт

**`*FILE` — не задел файловой системы в смысле F77 `OPEN/CLOSE/INQUIRE`, а только
job-control-монтирование.**

Обоснование:

1. **Нет API.** Ни в Мониторе-80, ни в Диспаке, ни в СИПРОД документация не описывает
   вызова, который по имени файла открывал бы его из программы. Ближайшее — ЭК `0030Н`
   с типом «МД файловой системы» (`Dispak-programmer-guide.md:13320-13349`) — работает
   с устройствами/зонами, а не с именованными файлами.
2. **Карта до программы.** `*FILE` разбирается входным контролем/командным процессором
   (`docs/СПРАВОЧНИК_КОМАНДЫ.md:437-465`; `chekjob/g02407.f:196-208`) до старта задачи;
   управление временем жизни файла программе не передаётся.
3. **Нет семантики каталога.** `*CATAL`/`*EXCLUDE` в Мониторе-80 — это каталог
   библиотеки/заданий (`docs/СПРАВОЧНИК_КОМАНДЫ.md:350-362`), не каталог данных,
   и к `*FILE` он не привязан.
4. **Настоящая ФС в скоупе есть, но не та.** ARFA в Диспаке (`Dispak-sysprog-guide.md:2251-2253`,
   `:3000-3025`) — подлинная архивно-файловая система с каталогом областей. Если и
   строить F77 `OPEN/CLOSE/INQUIRE`, то опору следует искать над ЭК `0030Н`/ARFA или над
   внутренним дескриптором `LUN%MON` (`docs/СПРАВОЧНИК_КОМАНДЫ.md:227, 551-555`),
   а **не** над картой `*FILE`.

**Оговорка:** это вывод «не найдено в документации», а не доказательство отсутствия
механизма в коде (код `permanent/`, `chekjob/` намеренно не анализировался). Полноценная
проверка потребовала бы реверса `star%.masm` / `iocont%.asm` / `lun%mon.asm`, что выходит
за рамки данного документального задания.
