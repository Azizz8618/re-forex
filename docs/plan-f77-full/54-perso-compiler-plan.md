# 54 — План: Фортран-компилятор из PERSO по образцу PASCOMPL

> **Финальный вердикт (21.11.2026, F3 proof):** релоцируемый корень запускается
> из PERSO через общий `*CALL` и работает как **обвязка входа** (дата/время,
> загрузка оверлеев, возврат). Но компиляцию выполняет **системный Фортран**:
> обнуление всех тел `LO*SYN`/`LO*GEN` в нашем PERSO не меняет 14/14 глиссады,
> а глиссада на нашем контуре даёт 9/14. Баннер `Ф О Р Т Р А Н /16.07.73/`
> отличается от системного `ВЕРСИЯ 2.02`, но принадлежит другому системному
> компилятору, вызванному нашей обвязкой. Цель «наш компилятор из PERSO»
> **не достигнута**; план ниже сохраняется как история выполненных работ.

Дата: 20.11.2026. Статус: **M0 выполнен, M1 частично, M2 признан заблокированным без системного загрузчика** (итоги ниже). План основан на двух исследованиях

## 0. Цель и границы

**Цель:** добиться, чтобы Fortran-77 исходник компилировался и исполнялся
**нашим** компилятором, загруженным из PERSO `0o2300`, с явно видимым в живой
распечатке маркером `FOREX 5.00 / 19.11.2026 (re-forex)`.

**Не цель:** полная замена системного `*forex` во всех регрессиях. Системный
путь остаётся рабочим и эталонным (21/21, gate 20/20).

**Заморозка:** текущий образ `build/FOREX_PERSO_2300.bin` sha256
`46149e3e...`; правки в `tools/build_forex_perso.py` уже дают релоцируемый корень,
первую зону каталога и `OCTTDEC→OCTTDE*`. Этамлоны дисков не трогать.

## 1. Почему PASCOMPL работает, а FOREX нет (база плана)

| Признак | PASCOMPL (работает) | FOREX* (не работает) |
|---|---|---|
| Происхождение | компиляция `*pascal` исходника `pascompl.b6` (8798 строк) | сырой дамп `monsys.9:0o510300..437` (96 слов) |
| Тип | DMS: `BASE M8`, SYMTAB, SET, `cmd=0o24155`, `const=0o1100`, `bss=0`, `L=0o25255` | обёртка `[1,0,len]` вокруг field-0 кода |
| Адресация | `символ + смещение` (`12,VTM,P/1D+4761`) | абсолютные поля 0: `зп 4023`, `сч 4003`, ~98 `,EQU,` |
| COMMON | 5 `,LC,`块, выделяются загрузчиком | `*A*` = `4000B` = 2048 слов по `0o4000` |
| LINK | нет | `0o74001/010/011/012/013/022` |
| Оверлеи | нет | `XTS 4031/4032` + `VJM 74022` → `LOADANGO` → `0o22654` |
| Запуск | `*perso` + `*stand` + `*CALL *PASCAL` (отдельная ветка в `givcall%.asm:38-41`) | `*forex` = системный `*SYSTEM LOAD LIST`; `*CALL FOREX*` идёт общим путём |

Вывод: достаточно перепаковать корень — **недостаточно**. Нужны либо символьная
связность всего компилятора (как у PASCOMPL), либо свой загрузчик оверлеев.

## 2. Что уже проверено и не повторять

- Порча `FOREX*`, `LO*SYN`, `LO*GEN` в нашем PERSO не влияет на `*forex` → системный путь наш образ не использует.
- `*CALL FOREX*` исполняет наш код (порча меняет отладочный `R`), но возвращается без компиляции.
- Перестановка `FOREX*` в первую зону убирает первую `TERR6`, но ошибка переходит на `*А*`, затем `OCTTDEC`, затем снова `*А*`.
- Вставка каталожной записи в начало даёт `ИСПОРЧЕН КАТАЛОГ PERSONAL LIBRARY`; замена записи `FORTLIBR` на псевдоним `FOREX` убирает `ОТСУТСТВУЕТ FOREX`, но не `ИСПОРЧЕНА ПОДПРОГРАММА`.
- `BSS` вместо `LC` для `*A*` (2048 слов) даёт модуль 2174 слова и `МАЛО ПАМЯТИ В 75377`.
- `*TRANS:FOREX3*,,411550` с сырым корнем в зоне `0o1550` даёт результат, побайтово равный оригиналу → наша запись не используется.
- `*STAND` на `*forex` не влияет (это Pascal-only переключатель).

## 3. Фазы работ

### M0 — Баннер-модуль: доказательство модульного пути (0.5–1 день)

**Идея:** точная копия приёма PASCOMPL (баннер 99.9 в зоне 5000). Собрать
минимальный DMS-модуль `FXBANNER` (ENTRY `FXBNR`), печатающий
`FOREX 5.00 / 19.11.2026 (re-forex)` и возвращающийся.

**Файлы:** новый `src/FXBANNER.mad`; `tools/build_forex_perso.py` (добавить
модуль в `SOURCE_SLICES`/`modules`); новая дека в `tests/plan-f77/`.

**Критерии:** маркер ровно 1 раз в листинге с `*perso:602300` + `*call fxbanner`;
`tests/run-glissade-forex.sh` rc=0, 14/14; `PLCATALOG` без `ИСПОРЧЕНЫ`;
SHA256 эталонов 2048/2348 не изменился.

**Риск:** низкий — не трогает `0o1770`, `0o4000`, `0o74022`, `0o22654`.

### M1 — Корректная загрузка `FOREX*` через `*CALL` (1–2 дня)

**Задача:** устранить `TERR6`/`ERLENGTH` для релоцируемого корня.

**Шаги:**
1. Проверить `L = cmd+const+bss` в записи каталога против DMS-заголовка (`w2`).
2. Номера входов для sym-элементов `C=0o6700`: пересчитать так, чтобы все `X`
   из sym-секции (`0o35..0o50`) попадали в диапазон реальных записей; новые
   записи **добавлять только после завершателя** (`re-siprod/notes/loader.md:4`).
3. `f0` взять из ENTRY `INITFOR*`, а не хардкодить 0 (сейчас `lib.catalog` даёт 0 —
   проверить, почему entry не пропатчен).
4. Убрать дубли системных имён: уже сделано `OCTTDE*`; при необходимости
   переименовать `DATAPR*`, `GIV/PG`, `TAK/PG` (с сохранением рабочих путей).

**Критерии:** `*call fxbanner` + `*call forex*` грузятся без `ИСПОРЧЕНА
ПОДПРОГРАММА`; тест на порчу слов `FOREX*` меняет поведение (доказательство,
что исполняется наш код); регрессии зелёные.

**Риск:** средний — каталог чувствителен к нумерации входов.

### M2 — Свой загрузчик оверлеев `FXLODR` (2–4 дня)

**Идея:** оверлеи остаются отдельными DMS-модулями; вместо системной `LOADANGO`
по LINK `0o74022` вызываем наш `FXLODR`, который по TEXT-имени из аккумулятора
находит `LO*SYN`/`LO*GEN` во временном каталоге, копирует 1024 слова по
`0o22654`, восстанавливает базы M1/M7 из слова заголовка `+4` и возвращается
через M15.

**Тактический пробный шаг:** сначала патч только LINK `0o74022` (без правки
исходника) — проверить, что вызов идёт туда, куда нужно (`Option C` как проба).

**Файлы:** новый `src/FXLODR.mad` (переиспользовать `GIVCALL*`/`IDENT6`/
`LOADT` из `monitor80-re/permanent/`), замена двух `,CALL,LOADAN` в срезе
`libra211.l21:15487/15489`, `tools/build_forex_perso.py`.

**Критерии:** при `*call forex*` в логе видно обращение к `FXLODR` и/String
`FOREX 5.00` printing; нет `ОТСУТСТВУЕТ LO*SYN/LO*GEN`; BASE77 компилируется.

**Риск:** высокий — оверлеи содержат 329 абсолютных целей, из которых ~100
не имеют имени; системные библиотеки 21/MONSYS остаются обязательными.

### M3 — Снятие остаточных абсолютных зависимостей (3–5 дней, частично)

**Задача:** сделать结果与 system-независимым настолько, насколько возможно без
карты «адрес → имя»: LINK `0o74010/011/012/013` поддержать нашими模块ами
(аналог `OCTTDE*`), COMMON `0o4006..0o4032` выделить в рамках допустимой памяти
(не `*A*` 2048 слов!), 5 недостающих SUBP оставить как есть (они не вызываются).

**Критерии:** BASE77 и 3–5 unit-кейсов компилируются через `*call forex*` с
нашим маркером; побайтовая сверка системного пути не нарушена.

**Риск:** высокий; полная самодостаточность (уровень PASCOMPL) без карты адресов
недостижима — это отдельная долгосрочная задача.

## 4. Отвергнутые варианты (не возвращаться без новых данных)

- **Слияние корня и оверлеев в один модуль** (Option B): 4484 слова + COMMON
  2048 дают `МАЛО ПАМЯТИ`; нет карты «адрес → имя» для ~700 полей; теряется
  побайтовая сверка.
- **Патч LINK `0o74010..0o74013`** (Option C как постоянное решение): ячейки
  переиспользуются системными FORMAT/DATAPR*, сломает эталон.
- **`*TRANS` с сырым корнем**: результат совпадает с оригинальной зоной —
  наша запись не используется.
- **Простое перепаковывание корня в DMS**: сделано, не помогло.

## 5. Риски и открытые вопросы

1. Нет карты «адрес → имя» для резидентных модулей (`docs/06-address-map.md:310-336`).
2. Точный механизм `МАЛО ПАМЯТИ В 75377` в исходниках монитора не найден.
3. Эквивалент `*STAND` для FOREX в мониторе отсутствует; `*CALL FOREX*` идёт
   общим путём, который может требовать дополнительной настройки.
4. `0o4022` — это `*DUMON*`, а не `ENTRY*` (база `ENTRY*` — `0o4006`);
   расхождение в `docs/06-address-map.md:122` нужно исправить до патча.

## Итоги выполнения (20.11.2026)

- **M0 — DONE.** Отдельный PERSO-образ с одним модулем `FXBANNER` (зона `0o2400`)
  грузится как head через `*perso:602400` + `*call fxbanner`, печатает ровно
  1 раз `FOREX 5.00 / 19.11.2026 (RE-FОRЕХ)` и возвращается `13,UJ,.` к
  `КОНЕЦ ЗАДАЧИ`. Рабочий вывод — проверенный `*64` E64 GOST-print из
  `besmmons/system1.txt`; живой листинг — `logs/f77_30_m0_banner_live.txt`.
  Воспроизводимо: `tests/plan-f77/build_fxbanner.py` + `tests/plan-f77/fxbanner.b6`.
- **M1 — частично.** Релоцируемый корень, `FOREX*` первый в каталоге, дубли
  MONSYS-имён переименованы (`XDATAPR/XGIVPG/XTAKPG`), `LC→BSS` с компактным
  `*A*` (400B), `XGIVPG` entry восстановлен. Регрессии зелёные: 21/21 real
  bridge, gate 20/20, глиссада 14/14.
- **M2 — BLOCKED по причине environment.** `ИСПОРЧЕНА ПОДПРОГРАММА` при
  `*CALL FOREX*` — **не фатальная ошибка `OCTTDE*`**, а предупреждение
  загрузчика при ≥2 внешних SUBP-ссылках в головном модуле. Удаление всех
  внешних ссылок убирает предупреждение, но вызывает trap: LINK-слоты
  `0o74010..0o74013`/`0o4024..0o4027` и таблицы оверлеев `0o22654` под
  `*CALL` не инициализированы. Для компиляции из PERSO нужно воссоздать
  системный загрузчик MONSYS (отдельная задача), как и предполагалось в M2/M3.
- Рабочая компиляция Fortran-77 остаётся системным `*forex` с нашим PERSO как
  источником рантайма; наш корень в этом пути не исполняется (доказано порчей
  кода). См. `logs/f77_30_perso_compiler_attempts.txt`.
- Дополнительное доказательство (main agent, 20.11.2026): после `LC→BSS` код
  корня в образе всё равно содержит **абсолютные адреса field 0** —
  `build/FOREX_PERSO_2300.bin` слова 2357..2381: `ATX 4005`, `ATX 4010`,
  `VJM 74010`, `ATX 4026` и т.д. Первые ~300 слов тела — нули (BSS), код
  начинается со слова 2357. То есть модуль не является по-настоящему
  релоцируемым: `13,UJ,.` возврат системного `*CALL` получает управление,
  но root работает с чужими ячейками и сразу завершается. Исправление
  требует перевода ~98 `,EQU,` корня и 329 адресов оверлеев в символические
  ссылки с базовым регистром, как у PASCOMPL (`8,BASE,*24155`).
- **F3 Diagnostic (21.11.2026):** `ВЫВОД ЗАПРЕЩЕН` в F3-прогоне — это не AЦПУ-конфигурация, а **режим задачи «запрет перфорации»** (`re-dispak/docs/Dispak-programmer-guide.md:8624,8666`). Устраняется либо директивой `ДАЙ А0` (`Dispak-operator-guide.md:1455-1470`), либо снятием режима в задаче. Проверено в dispak: `print()` (E64, `extra.c:658-676`) при `!pout_enable` просто возвращает `E_SUCCESS`, значит «ВРЕМЯ-000.00» было напечатано легально; `ВЫВОД ЗАПРЕЩЕН` (errtxt[25]) приходит из **другого** экстракода/команды по `06760`, который трассируется отдельно. Следующий блокер после RMON — загрузка оверлеев и базы M1/M7.
- **M2 — финальный verdict субагентов (20.11.2026).** `FXLODR` и `FXLINK`
  спроектированы (`logs/f77_30_fxlodr_draft.txt`, `logs/f77_30_fxlink_report.txt`),
  но **недостаточны**: LINK-ячейки в живой системе не заглушки и `*CALL` их не
  патчит; запись в `0o740xx` из пользовательского режима требует супервизора;
  системный `LOADANGO` грузит системные оверлеи; TEXT `0o4031/0o4032`, базы
  M1/M7 и COMMON `0o4000..0o4023` остаются незакрытыми. Плюс abs-адреса в коде.
  Итог: компиляция из PERSO требует **полной символической переписки корня и
  оверлеев** (аналог PASCOMPL), что ломает побайтовую сверку с эталоном —
  отдельный проект, не входящий в текущий контур верификации.
