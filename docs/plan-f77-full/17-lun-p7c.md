## 0. Метод и критерий

Прогон на системном ФОРЭКСЕ 2.02 через dispak
(`/home/azizz/Yandex.Disk/dispak/build/dispak/dispak`), диски-копии **2048** (`лен 41`)

(печать `E70at` / `DD pc=` / `E50at type=` из `cu.c:269-277`, `extra.c:2096-2125`).

аварии `*70/*71` — **фатальны** даже при `rc=0` и напечатанном `КОНЕЦ ЗАДАЧИ`.

Все деку и выводы сохранены в `logs/f77_17_*.txt`.

## 1. Адрес и формат LUN-таблицы монитора

### 1.1 Двухуровневая модель (главный результат анализа)

| Уровень | Где живёт | Формат | Кто обновляет |
|---|---|---|---|
| **A. Каналы эмулятора** | host-память dispak, `disks[]` | `ddisk_t { void *diskh; ushort offset; ushort diskno; ushort mode; }`, 64 записи, индексы `u = 030..067` (восьм.) | `Э50 0131/0157` из монитора-паспорта (`ЛЕН …`) |
| **B. LUN-таблица ФОРЭКС 2.02** | системная зона диска 2348 (libra21x), загружается в ядро; символы `ERRLUN` (043xx), `LUN*MON`/`LUNMUN` (03146–03150), `LUNTYP` | таблица допустимости юнитов + тип устройства (0=не задано, 1=лента, 2=SCRATCH, 3=личный файл, 4=спец.) | **только при сборке/загрузке системы** |

`Э70` (`ddio`, `extra.c:2063+`) читает **только уровень A**:
`u = uir.i_opcode & 077`, `zone = uir.i_addr & 07777` (для `030<=u<070`).
Уровень B проверяется **раньше**, при входе в Fortran I/O, и печатает
`НЕТ КАНАЛА LUN 45` **до любой выдачи Э70** для этой операции.

### 1.2 Точные источники (все READ-ONLY)

- `dispak/dispak/defs.h:77-82,319,351` — `ddisk_t`, `NDISKS`, `disks[]`.
- `dispak/dispak/extra.c:1310-1361` (`Э50 0157` — захват тома, поиск свободного
  канала `030..070`), `extra.c:1544-1553` (`Э50 0105` — запрос номера тома по
  каналу), `extra.c:1614-1636` (`Э50 0131` — привязка тома к каналу;
  `u = acc.l>>18`, маска `(acc.l>>12)&077 == 077`, `diskno = NDISK(acc.r)`),
  `extra.c:2082-2095` (разбор `Э70`).
- `re-forex/src/lib21/LUNTYP.mad:39-105` — `FUNCTION LUNTYP(LUN)`, запрос типа
  через `Э63` подфункции `0502/0504/0057/0760/0020/0576`.
- `monitor80-re/permanent/star%.masm:27,31,150-161` — `LUN*MON: SUBP`,
  `MONREAD*: SUBP` («Не исп. в Mониторе-80»), проход PARAMT/паспорта.
- `monitor80-re/permanent/paramt%.masm` — разбор параметров текстовых карт
  (НЕ описывает таблицу каналов; это утилита разбора, не реестр LUN).
- `monitor80-re/permanent/lun%mon.asm`, `ioxxfmr%.asm:265-304` — сервис печати
  `LUN*MON` и диспетчер `Э50 0151/0152/0156/0157`.
- `re-dispak/docs/Dispak-compat-guide.md:176,207,279` — паспорта `ЛЕН 30(2048)‾`,
  `ЛЕНТ 30(2048)‾`, `ЛЕНТ 40(2048)‾` — именно отсюда монитор делает `Э50 0131`.
- `extra.c:2126-2194` — хук `BESM6_LUN45_*`: подменяет `u==045` ТОЛЬКО внутри
  `ddio()` для чтения входного потока (`monread%`), т.е. **уже после** проверки
  уровня B; поэтому env-переменные не помогают Fortran-юниту 45.

**Вывод про «адрес таблицы»:** уровень A — host-переменная `disks[]`, её нельзя
поменять записью байтов в образ диска. Уровень B — код/данные ФОРЭКС-рантайма на
диске 2348; его символ `ERRLUN` виден в дамбе символов на адресах `04305/04317/04321`
(адрес плавает от раскладки символов). Точный адрес таблицы допустимости в ядре
в этой волне **не зафиксирован дампом ядра** (попытка `BESM6_CORE_ON_PC=04305` не
сработала: `ERRLUN` как символ вызывается не напрямую). Для честного патча
потребуется дизассемблировать `ERRLUN` по `core-pc.bin`, что — отдельная задача.

## 2. Шанс 1 — PERSO-зона 0o2320/0o2330, МАДЛЕН-процедура из Fortran

### 2.1 Что СДЕЛАНО (исполняемое доказательство механизма)

1. МАДЛЕН-процедура `MINRTN` (`MINRTN:,NAME, / 13,UJ, / ,END,`) собрана через
   `*assembler` + `*to perso:602320` в копию диска 2348 — **без ошибок трансляции**.
2. Fortran-дека с `*perso:602300` + `*perso:602320,cont` и `CALL MINRTN`
   исполняется чисто и печатает `САLL ОК` (`logs/f77_17_perso_call.txt`,
   `decks/run4/out.txt`). Без `*perso:602320,cont` получаем `ОТСУТСТВУЕТ MINRTN`.
3. Синтаксис сырых экстракодов в МАДЛЕН подтверждён (`re-dispak/testdks/dumpmb_junk.txt`:
   `,*70,INF`, `,*50,7700В`; `mbe60.txt`: `,*50,US`). Формат экстракода =
   `<IR>,<*NN>,адрес`; `reg[016] = addr + reg[IR]` (`cu.c:761-762`).
   МАДЛЕН-числа **по умолчанию десятичные**, суффикс `B` = восьмеричный
   (проверено: `,*50,131` → `type=00203`=131dec; `,*50,131B` → `type=00131`).

**Вердикт по шансу 1: МЕХАНИЗМ РАБОТАЕТ (доказано), но НЕ РЕШАЕТ блокер.**
Fortran → PERSO → raw `Э50`/`Э70` — реализуемо. Однако (§3) даже успешная
привязка канала не снимает отказ `ERRLUN`. PERSO-обёртка может либо
(a) делать **весь** обмен сама, минуя Fortran I/O (тогда это НЕ J2/J4/J23 в
смысле X3.9, а новый вызов типа `CALL DISKWRITE(...)`), либо
(b) быть использована для патча таблицы уровня B **в памяти**, что требует
её точного адреса (не найден в этой волне).

## 3. Шансы 2 и 3 — экстракоды и патч LUN-таблицы

### 3.1 Шанс 2: `*57 / *63 / *64`

- `Э57` — ENTIER / системная операция (`FOREX_.mad:58,83`, `FT_REGIM.mad:172`);
- `Э63` — время решения, АРФА/области, каталоги (`extract_codes_table.txt`);
  `LUNTYP` использует его только для **запроса** типа устройства;
- `Э64` — управление режимом листования при печати на АЦПУ.

Ни один из трёх не выполняет обмен с диском. `Э70` — единственный экстракод
обмена, но он требует управляющих слов и привязанного канала.
**Вердикт: НЕ канал для новых операций I/O** (совпадает с `11-p7-alternatives.md:51,87`).

### 3.2 Шанс 3: патч LUN-таблицы — ключевой эксперимент

Собран МАДЛЕН `LUNAT` (`build/lunat5.b6`), который из Fortran-процедуры:

```
LUNAT:,NAME,
      ,XTA,=:45770000 00020110   ; acc.l: u=045 (биты 23-18), маска 077 (17-12);
                                  ; acc.r: BCD 2048
      ,*50,131B                  ; Э50 0131 = attach volume to handle
  13  ,UJ,
      ,END,
```

Трассировка (`logs/f77_17_attach.txt`) подтверждает:
`E50at 01032R type=00131 acc=4577000000020110` — привязка диска 2048 к LUN 45
фактически выдана (и с `лен 45(2048)^` в деке, и без него).

**И всё равно:** `WRITE(45,10)` → `НЕТ КАНАЛА LUN 45` (`decks/run9`, `run10`).
Модификация `лен 45(2348-wr)^` и env `BESM6_LUN45_*` (волна 1) — тоже без эффекта.

**Вердикт: НЕВОЗМОЖНО БЕЗ ПАТЧА РАНТАЙМА ФОРЭКС.**
Блокер — не dispak-канал (уровень A), а **собственная таблица допустимости
юнитов ФОРЭКС 2.02** (уровень B, `ERRLUN`). Патч паспорта на диске 2048 или
правка `extra.c` не помогают, пока `ERRLUN` не разрешит юнит 45.

## 4. Шанс 4 — алиасирование юнитов на 54

Дек `decks/alias_demo.b6`: `WRITE(54,10) 11` + `WRITE(54,10) 12` (модель
lowering-а `WRITE(11,…)`/`WRITE(12,…)` → `WRITE(54,…)`). Обе записи
появляются в одном потоке stdout:

```
 UNIТ DАТА= 11
 UNIТ DАТА= 12
```

(`logs/f77_17_alias.txt`). Файлы не создаются, `READ` по этим юнитам не работает,
`OPEN/CLOSE/INQUIRE` отсутствуют.

**Вердикт: НЕЛЬЗЯ честно назвать поддержкой.** Это одноканальный профиль
(single-device profile), мультиплексирование вывода. Для J2 допустимо только как
**profile convention** с явной оговоркой; для J4/J23/J24 — неприемлемо вовсе.

## 6. Working prototype: что есть и что не хватает

**Есть (исполняемо):**
- `/tmp/.private/azizz/opencode/lun-proto/build/rtn2perso.b6` — сборка МАДЛЕН в PERSO 0o2320;
- `.../decks/call_rtn2.b6` — Fortran `*perso:602320,cont` + `CALL MINRTN` → `САLL ОК`;
- `.../build/lunat5.b6` — МАДЛЕН `Э50 0131` (attach disk 2048 → LUN 45), трассируется;
- `.../decks/w45_attach.b6` — Fortran вызывает `LUNAT`, затем `WRITE(45,…)`.

**Не хватает до настоящего прототипа J2:**
1. адрес/формат таблицы допустимости юнитов уровня B в ядре ФОРЭКС (`ERRLUN`);
2. либо её патч в памяти из PERSO (in-memory monkey-patch), либо патч системной
   зоны 2348 и пересборка рантайма;
3. для J4/J23 — EOF/IOSTAT-сигнал в рантайме ввода (`03-fortran-path.md:421`);
4. для J24 — распознавание ключевых слов в `LO_SYN/LO_GEN` + рантайм каталога файлов.

Без пунктов 1–4 «прототип J2/J4/J23/J24» невозможен; собранные декы —
доказательство **механизма обхода**, а не поддержки стандартного I/O.

## 7. Рекомендация родителю (что нужно, чтобы закрыть J2/J4/J23/J24 честно)

1. **Не завышать статус.** Оставить J2/J23 = PARTIAL, J4/J24 = NO
   (как в `15-io.md:§7`). Алиасирование (шанс 4) — не поддержка.
2. **Завести отдельную задачу `P7c/monitor-fortran-io`:**
   - дизассемблировать `ERRLUN` и таблицу допустимости LUN в образе 2348
     (`BESM6_CORE_ON_PC` + `core-pc.bin` + `disbesm6/dtran`);
   - добавить LUN 45 (и, при необходимости, 40) с реальным дисковым каналом;
   - реализовать EOF/IOSTAT в рантайме ввода (сигнал в очереди карт);
   - для J24 — добавить ключевые слова `OPEN/CLOSE/INQUIRE` в грамматику
     `LO_SYN/LO_GEN` и каталог файлов в рантайм.
   - **0 слов в оверлеях F77PREP/F77LIBR**, но правка системной зоны 2348 и,
     возможно, `dispak/extra.c` (C-хост). Это **не** оверлей и **не** правило F77PREP.
3. **Оценка трудозатрат:** «десятки чел.-дн.» (консервативно 20–40 чел.-дн.):
   реверс `ERRLUN` и таблицы (3–5), патч и пересборка системного диска (5–10),
   EOF/IOSTAT в рантайме (5–10), OPEN/CLOSE/INQUIRE в трансляторе+рантайме (8–15),
   регрессия золотых бинарников и gate 20/20 (3–5).
4. **В профиле FOREХ 5.00** зафиксировать: `54 = stdout`, безъюнитный `READ` =
   stdin; J2/J4/J23/J24 — в реестре исключений P7c (как уже сделано в
   `11-p7-alternatives.md:197`). PERSO-механизм из §2 оставить как **инструмент
   будущего патча**, не как замену стандартного I/O.
