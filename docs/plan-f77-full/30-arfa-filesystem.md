# 30 — P7c / ВОЛНА F / ЗАДАЧА 1: АРФА — архивно-файловая система ОС ДИСПАК как основа для F77 OPEN/CLOSE/INQUIRE

**Дата:** 19.11.2026. **Репозиторий:** `re-dispak` (READ-ONLY, ничего не изменялось).
**Логи:** `logs/f77_25_arfa_01_structure.txt` … `05_f77_compare.txt` (в `re-forex/logs/`).

## 0. Краткий вердикт (без спекуляций)

1. АРФА — это **не** «файловая система с записями», а **архивная система областей**:
   именованная область = сплошная последовательность зон внешней памяти с атрибутами
   (владелец, длина, тип, пароли, бюджет). Записи произвольного размера — уже следующий
   уровень, система **МАРС** (`re-dispak/docs/tyurin1985/tyurin1985-full.txt:6693-6694`).
2. Программный API несомненно существует и он **один**: экстракод **`Э63` с константой
   `'КЛЮЧАР'` в сумматоре**, тип работы в разрядах 48–43 первого информационного слова.
   Это системный вызов уровня задачи, а не `*CALL` и не отдельная задача/ключ.
   `re-dispak/docs/Dispak-sysprog-guide.md:2720-2725`,
   `re-dispak/ai/справочник_Э63_информационные_слова.md:16-71`.
3. Ключ `СТАРФА` / программа `АРФА.СТАРФА` в зонах 7–23 РЕЖСОВМ — это **операторская
   диалоговая/статистическая программа**, а не API для прикладной программы
   (`docs/Dispak-compat-guide.md:68,137-138`;
   `docs/Dispak-sysprog-guide.md:1064-1068`).
4. **Для F77 это пригодная основа частично.** АРФА даёт runtime-привязку
   имя→виртуальный номер (`Э63` тип 12), create/destroy/query/catalog — то, что нужно
   для `OPEN/CLOSE/INQUIRE` на уровне имени области. Но у неё нет записей, `RECL`, EOF,
   Fortran `IOSTAT`; а сквозной I/O дополнительно упирается в таблицу LUN монитора
   (`re-forex/docs/plan-f77-full/26-file-runtime.md:41-50`). Итого: тонкий слой возможен
   для «управления файлами», **недостаточен** для настоящего F77 I/O без патча монитора.

## 1. Структура АРФА

### 1.3 Сервисные (операторские) программы — НЕ API

По `sysprog-guide.md:1052-1070`: на транспортной МЛ 3 — участок 40 зон:
`1 УСТСНЯ, 2 СВОДКА, 3-6 БЮСТ, 7 ARFA(ГП), 10-17 СТАРFA, 20 ПРОАРХ,
21-24 БИБЛИОТЕКА ARFA, 25 ТОЛКАЧ, 26 МДУПЛА, 27 КОКА`.

- `ARFA` (ГП) — диалоговая сервисная программа: создание/уничтожение областей,
  изменение атрибутов, управление бюджетами; 1 зона (`sysprog-guide.md:1064-1066`).
- `СТАРFA` — диалоговая система просмотра статистики по областям, служебная задача
  мониторной системы, 10 зон (`sysprog-guide.md:1067-1068`).
- В РЕЖСОВМ зоны 7–23 содержат «АРФА.СТАРFA», вызываемую по ключу `СТАРФА`
  (`compat-guide.md:68,137-138`); по Титурину — `Старфа` в зоны 1007–10163
  (`docs/tyurin1985/ocr/page-0308.txt:36-39`).
- `УПР`/`ВОС` (упрятывание/восстановление задач) «реализована на основе архивно-
  файловой системы АРФА» (`docs/Dispak-operator-guide.md:1322-1339,3075-3090`) —
  ещё одно подтверждение, что АРФА — системный слой, а не формат данных Fortran.

## 3. Формат обращения из программы (ЗАДАНИЕ 2)

**Это экстракод, не `*CALL` и не системный ключ и не отдельная задача.**

```
Э63 АИСП                       ; АИСП — адрес нулевого информационного слова (ИС)
СМ (сумматор) = 'КЛЮЧАР'       ; код УПП, в'1242547515620060'
```
(`sysprog-guide.md:2720-2725`; `ai/справочник_Э63...:16-35`).

Механика: `Э63` → вектор `513в` → заглушка ДИСП70 (`disp70.be:321-323`) → ХЛАМ
(`khlam.be:2324-2363`): `сч СМ; нтж КЛЮЧАР` — если совпало, идём по архивному пути
`НЕАРХ → АРФА` (вход `ВХАР`, `сч (М16)` — разбор ИС); иначе РЕСУРС
(`ai/справочник_Э63...:36-56`).

**Информационное слово ИС** (`sysprog-guide.md:2727-2745`,
`ai/справочник_Э63...:90-111`):

```
48–43 Р — тип работы       42–37 Р — виртуальный номер
36–25 Р — пароль           12 Р — признак чтения
 4– 1 Р — характеристика имени
```

Способы задания имени (`sysprog-guide.md:2747-2785`, `ai/...:113-157`): 0 — нет имени
(вирт. номер или идентификатор в ИС+1); 1…7 — «по-старому», число простых имён;
`10в` — код УПП; `14в` — код МС-80; `17в` — ISO.
Идентификатор области/«ссылка» (`sysprog-guide.md:2787-2800`, `ai/...:148-157`):
`34р=1, 33–18 — внутреннее имя, 17р=0, 16–10 — продолжение, 9–1='356'(8)`;
получается через `Э50 '105'` или Э63 тип 13.

**Результат:** при успехе М16=0; при ошибке — код ответа на М16 (0…32,
таблица 5 `sysprog-guide.md:2816-2850`; внутренние `ЭКВ` в `arfa.be:3525-3558`).

**Реальный пример из системы** — `perekh.be:1775-1778`:
```
ИНФСТ КОНД В'0700000000000010'      , тип 07, имя «по-новому» УПП
      КОНД П'АRFА.П'
      КОНД П'ЕРЕХВА'
      КОНД П'Т00000'М32В'377'
```
и вызов `perekh.be:221-225`: `СЧ КЛЮЧ; СДА 64; Э63 ИНФСТ; ПИНО НЕТСТС(М16)`
(где `КЛЮЧ КОНД П'КЛЮЧАР'` — `perekh.be:1790`).

**Fortran-callable API — НЕТ.** Все вызовы `КЛЮЧАР`-found в `*.be` — БЕМШ-модули
`arfa, diski, dnepr, gidra, kit, komar, metki, perekh, rezarkh, serp, serp5,
siprog, khlam`. В ФОРЭКС/Fortran оператора Э63 нет; `Э70` — это обмен данными
(`programmer-guide.md:8463-8485`), а не файловый API. Значит, нужен мостик на
БЕМШ/МАДЛЕН, размещённый в PERSO (ср. `20-open-close.md:63-90` — уже отработанный
механизм `CALL FOPEN/FCLOSE/FINQ` → PERSO).

## 5. Структура описания файла/области (ЗАДАНИЕ 3)

### 5.1 Имя и идентификация
- Имя области — последовательность **простых имён, разделённых точками**; простое имя
  ≤ 9 символов, всего ≤ 7 простых имён (`Dispak-description.md:1365-1372`).
- Шифр хозяина — первые 6 цифр шифра пользователя; `.` = произвольная цифра
  (там же). В имени «по-старому» шифр занимает разряды 24–1 второго слова простого
  имени (`sysprog-guide.md:2755-2764`).
- Внутренний идентификатор/«ссылка»: `34р=1, 33–18 внутреннее имя, 17р=0,
  16–10 продолжение, 9–1='356'(8)` (`sysprog-guide.md:2787-2800`).
- Виртуальный номер (логический номер) — `30в…67в`; привязывается паспортом
  `ЛЕН 30(ИМЯ_ОБЛ/ШИФР)‾` до запуска (`Dispak-description.md:1411-1422`) **или**
  динамически Э63 тип 12 (`programmer-guide.md:6977-7050`).

### 5.2 Атрибуты области
По `Dispak-description.md:1384-1395`:
шифр создавшего пользователя; дата создания; число обращений; дата последнего
обращения; **длина области**; **тип области** (определяет носитель); пароли на чтение
и запись; список шифров пользователей с правами. Дополнительно из Э63 тип 07
(`programmer-guide.md:6836-6844`): группа (19–18), признак индивидуальности (17).
Из РМР тип 01 (`programmer-guide.md:6386-6392`): группа (22–21), вид (20–18).

### 5.3 Позиция / данные
- Позиция = **сдвиг по области в зонах**, Э63 14/15 (`sysprog-guide.md:3070-3090`).
- Обмен данными — те же экстракоды, что для диска, с виртуальными номерами
  (`Dispak-description.md:1419-1423`): `Э50…Э77`, включая `Э70` — «обмен между ОП и
  внешней памятью (тракты МБ, зоны наборов данных)» (`programmer-guide.md:8463-8485`).
- **Длина — в зонах; признаков записи, длины записи, FORM и POSITION нет.**

### 5.4 Отображение на F77 `OPEN`
| F77 | Аналог в АРФА | Комментарий |
|---|---|---|
| `FILE='...'` | имя области (≤7×9 символов, шифр хозяина) | требуется преобразование имени |
| `STATUS='OLD'` | Э63 07 (успех/«ТАКОГО ИМЕНИ НЕТ») / 12 | query перед open |
| `STATUS='NEW'` | Э63 01, код 6 «ОБЛАСТЬ УЖЕ ЕСТЬ» | create |
| `STATUS='SCRATCH'` | прямого нет | эмуляция: уникальное имя + Э63 02 при CLOSE |
| `ACCESS='DIRECT'` | виртуальный номер + Э70 + сдвиг в зонах | адресация зоной, не записью |
| `RECL=` | **нет** | область — массив зон; записи появляются только в МАРС |
| `FORM=`, `POSITION=` | **нет** | — |
| `IOSTAT=` | М16=0/код ответа 1…32 | архивная диагностика, не F77 IOSTAT |
| EOF | **нет** | у области фиксированная длина; END OF FILE — проблема Fortran-рантайма (`26-file-runtime.md:158-190`) |
| `INQUIRE(EXIST=)` | Э63 07; `INQUIRE` по каталогу — Э63 10/11 | |
| `CLOSE` | Э63 31 (освободить) + при SCRATCH Э63 02 | |

## 6. Сравнение и оценка (ЗАДАНИЯ 4–5)

### 6.1 Где совпадает
- имена файлов ↔ имена областей (иерархические, до 7 уровней);
- каталог ↔ Э63 10/11;
- create/destroy ↔ Э63 01/02;
- «открыть по имени» ↔ Э63 12 (это **runtime** name→virtual-number binding!);
- чтение/запись и прямой доступ ↔ виртуальный номер + `Э70`/сдвиг;
- статус/атрибуты ↔ Э63 07/13.

### 6.2 Чего не хватает для F77
1. **Записи и RECL.** АРФА оперирует зонами; записи произвольного размера — уровень
   МАРС (`tyurin1985-full.txt:6693-6694`). `ACCESS='DIRECT', RECL=n` не отображается
   один-в-один.
2. **EOF / END= / IOSTAT.** Нативный EOF-сигнал (`Э60`) в Fortran-рантайме теряется
   (`26-file-runtime.md:158-190`); коды М16 — архивные, не F77 IOSTAT.
3. **POSITION=, FORM=, STATUS='SCRATCH'** — нет; SCRATCH эмулируется.
4. **Fortran-доступ к Э63.** Прямого оператора нет; нужна PERSO/BEMSH-обертка
   (`20-open-close.md:63-90` показывает, что `CALL`-мостик через PERSO работает).
5. **LUN-слой монитора.** Э70 выдаётся только после проверки Level B (`ERRLUN`,
   `26-file-runtime.md:41-50`); даже успешный `Э63 12` сам по себе не снимает
   `НЕТ КАНАЛА` для произвольного Fortran LUN.

### 6.3 Важное уточнение к ВОЛНЕ A
`re-forex/docs/plan-f77-full/20-open-close.md:157-170` формулирует: «ключ FILE не может
быть превращён в реальное связывание во время выполнения — для этого нет ни системного
вызова, ни таблицы в рантайме». **Часть про «нет системного вызова» неточна**: Э63 тип 12
(«Дозаказ области», `programmer-guide.md:6977-7050`) — именно такой вызов, он принимает
имя области и возвращает виртуальный номер. Верным остаётся второе: в FOREX-рантайме
нет таблицы LUN↔имя, и LUN-проверка монитора блокирует сквозной I/O. То есть АРФА
снимает **первое** препятствие, но не второе и не третье (записи/EOF).

### 6.4 Можно ли построить тонкий слой? — оценка

**Да, для «управления файлами» (OPEN/CLOSE/INQUIRE); нет, для полного F77 I/O без
правки монитора.** Минимальный набор:

1. **PERSO/BEMSH-обертка** над Э63: `FOPEN`/`FCLOSE`/`FINQ` (уже есть прототип в
   `20-open-close.md:35-90`), но вместо чистого флага делать реальные Э63 01/07/12/31/02.
2. **Таблица состояния LUN** (в labeled COMMON, как `/J24STT/`): `LUN → виртуальный номер,
   имя, длина в зонах, режим чтения/записи, текущий сдвиг, признак SCRATCH`.
3. **Преобразование имён**: F77 `FILE=` (как угодно) → имя области (≤9 символов/уровень,
   ≤7 уровней, с шифром хозяина); генерация уникальных имён для SCRATCH.
4. **Эмуляция записей/RECL** поверх зон (слой «record-in-zone»), либо честный профиль
   «RECL игнорируется, ACCESS=DIRECT = зона».
5. **Патч мониторного LUN-слоя** (`erriom.asm`/`iocont%.asm`, Level B) и `monread%`/
   `IOEND*` для EOF/IOSTAT — как в оценке `26-file-runtime.md:185-212` и
   `20-open-close.md:199-210`. Это **не** «тонкий слой», а отдельный проект
   (в прежней оценке 20–40+ чел.-дн., `17-lun-p7c.md` §7).

**Итоговая формулировка для родителя:** АРФА — корректная и единственная системная
основа для «OPEN/CLOSE/INQUIRE по имени» на ДИСПАК; она уже имеет runtime-дозаказ
области по имени (Э63/12). Тонкий PERSO-слой способен дать настоящие `FILE=`,
`STATUS=NEW/OLD`, `EXIST`, `CLOSE` вместо текущего unit-state stub. Но `RECL`,
записи, `EOF/IOSTAT`, `SCRATCH` и сквозной I/O требуют либо эмуляции в этом же слое,
 либо патча монитора — и не могут быть обещаны «дешево».
