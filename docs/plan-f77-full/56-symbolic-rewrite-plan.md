# 56 — План: символическая переписка FOREX для загрузки из PERSO (п.2)

Дата: 20.11.2026. Статус: **план, не выполнено**. Основан на четырёх исследованиях:
`logs/f77_30_fxlodr_draft.txt`, `logs/f77_30_fxlink_report.txt`,
`/var/tmp/b1-f77-fix/perso-compiler-report.md` (PASCOMPL модель),
`/var/tmp/b1-f77-fix/m1-spec.md` (инвентарь корня),
отчёт субагента по оверлеям (оценка 104/225 и R0–R4, в чате сессии).

## 0. Цель и важные уточнения

**Цель:** компилятор FOREX 5.00 (корень + оверлеи) грузится из PERSO и компилирует
Fortran-77 через `*CALL`, с видимым маркером изделия в живой распечатке.

**Не goal:** ломать системный путь `*forex` (эталон 21/21, gate 20/20, 14/14)
и побайтовую сверку с эталонами. Все новые исходники — отдельные файлы.

**Ключевые поправки к исходной оценке (ФАКТ):**
1. Из «~98 абсолютных EQU корня»绝大多数 — **артефакты дизассемблера TEXT/GOST-литералов**
   (слова `0o510334..0o510437`), а не реальные зависимости. Настоящих внешних связей
   у корня всего **6 LINK-ячеек**: `0o74001, 74010, 74011, 74012, 74013, 74022`.
2. Символический источник для корня уже есть и используется сборщиком:
   `libra211.l21:15448-15528` (81 строка, только `,LC/ ,SUBP/ ,CALL/ ,EQU` без abs-адресов).
   `include/FOREX_ROOT.mad` и `src/FOREX_CORE.mad` — аннотированные дампы, не собираются.
3. PASCOMPL работает не просто как релоцируемый модуль, а через **Pascal-специфичную
   ветвь в `givcall%.asm:54-57`** (`MONITOR*+4`, `MONITOR*+1`, `LOADANGO`). Аналога для
   FOREX в мониторе нет; `*STAND` — общий бит, но не переключатель транслятора.
4. Оверлеи: `src/LO_*.mad` уже символичны (715+452 EQU), но 104+225 внешних адресов
   указывают в MONSYS/библиотеку-21, для ~100 из них нет карты «адрес→имя», 5 SUBP-тел
   отсутствуют. Полная независимость от MONSYS **недостижима по текущим доказательствам**.
5. Идея «переписать оверлеи на Фортране + библиотеки + F77 как надстройку» **не обходит
   блокер**: системный ФОРЭКС компилирует Fortran в DMS-модули дека, а не в
   `*CALL`-загружаемый компилятор; FOREX-хука в `GIVCALL` нет. При этом гибрид
   F77PREP + F77LIBR + мост `0o2320` уже реализован и зелёный.

## 1. Стратегия

Два независимых барьера:
- **B1 (загрузка):** как заставить монитор исполнять наш компилятор из PERSO —
  нужен либо `*FOREX`-хук в `GIVCALL` (как `*PASCAL`), либо полноценный DMS с BASE и
  head-каталогом + свой загрузчик оверлеев.
- **B2 (содержимое):** как сделать код позиционно-независимым и снять 329 внешних
  абсолютных адресов оверлеев.

План идёт по的顺序: сначала B1 на корне (малый объём), затем B2 на оверлеях (large,
с go/no-go). Параллельно фиксируется рабочий гибрид как продукт.

  `git diff` по эталонам пуст.

### F1. Символический корень из S1 (1–2 дня)

- Взять срез `libra211.l21:15448-15528` как вход `*assembler` (уже используется в
  `tools/build_forex_perso.py:131-136`). Не переписывать `include/FOREX_ROOT.mad`.
- Правки (~30–40 строк МАДЛЕН):
  1. Добавить первую инструкцию `8,BASE,*<base>` (аналог `8,VTM,/+24155B` в
     `recomp.b6:69`) и переход на настоящий вход; BASE-регистр M8.
  2. Заменить 4 адреса LINK: `0o74010/74011/74012/74013` на `,SUBP,` с нашими
     алиасами `XDATAPR/XTAKPG/XGIVPG/OCTTDE*`; `0o74022` → `FXLODR`.
  3. COMMON `0o4002..0o40050` — символические LC/BSS (уже частично сделано:
     `LC→BSS`, компактный `*A*` 400B в `build_forex_perso.py:226-229`); убрать
     фиктивные EQU-адреса TEXT-литералов, вернув `8H…`/`GOST,…` из S1:15495-15527.
  4. Удалить 5 невызываемых SUBP (уже сделано), сохранить порядок 4 рабочих LINK-слотов.
  5. Возврат строго `13,UJ,` (не `13,VJM,`).
- Сборка в отдельный image; сравнение ** opcode-последовательностей** с
  `disasm/CORE_ROOT.bemsh.lst` с нормализацией полей адресов (`docs/05-roundtrip.md:22-31`).
- Критерий F1: 0 операндов в `0o4000..0o4077` и `0o74000..0o74077` в дизассембле
  нового модуля; `PLCATALOG` без `ИСПОРЧЕНЫ`; тест порчи слова подтверждает запись
  в свой COMMON; системные регрессии остаются зелёными.

### F2. Загрузочный путь: мониторный хук vs head-модуль (3–8 дней, go/no-go)

Два варианта, выбрать по результату F1:

**F2a (рекомендуемый): `*FOREX`-ветвь в `GIVCALL`.**
- Добавить в `monitor80-re/permanent/givcall%.asm` сравнение карты с `*FOREX` и
  ветвь по образцу `:54-57` (`MONITOR*+4`, `MONITOR*+1`, `LOADANGO`), пересобрать
  permanent-библиотеку на копии диска.
- Неизвестное: содержимое `MONITOR*+4`/`MONITOR*+1` в исходниках отсутствует —
  снимается живой трассировкой системного `*CALL *PASCAL` на копии.
- Критерий: `*perso:602300 + *stand + *call forex*` доходит до инструкций после
  `INITFOR*`, маркер/трасса подтверждают исполнение нашего кода; `ИСПОРЧЕНА
  ПОДПРОГРАММА` отсутствует.

**F2b (fallback): head-модуль + `FXLODR`.**
- Использовать доказанный M0-путь: отдельный PERSO-образ с FOREX* как головным
  (`f2=0o42xx`, `f3=0o2010`), `*perso:<LU><ZONE>` + `*call forex*`.
- Интегрировать `FXLODR` из `logs/f77_30_fxlodr_draft.txt` (каталог-сканер и цикл
  копирования переиспользованы из `utility/overlay.asm:299-328`), заменив два
  `,CALL,LOADANGO.` → `,CALL,FXLODR.` в срезе S1.
- Критерий: маркер `M2 FXLODR ENTER 2026` ровно 2 раза, тела оверлеев побайтово
  равны `build/LO_*.words` после копирования по `0o22654`.

**Решение пользователя (20.11.2026): F2a отвергнут — монитор не трогаем.**
Выбран путь **F2b**: наш корень грузится как head-модуль через общий `*CALL`
(доказано M0), LINK/COMMON-зависимости убираются в F1, оверлеи грузит `FXLODR`.
Эксперимент с именем `PASCAL*` показал, что Pascal-ветвь всё равно запускает
системный `PASCAL COMPILER 15.0` (`/var/tmp/b1-f77-fix/f2c-pascalname/out2.txt`),
то есть хук действительно недоступен без пересборки монитора.

**Go/no-go после F2:** если F2b не даёт исполнения нашего корня — остановить п.2
и зафиксировать B1 как неподъёмный в текущем контуре.

## 3. Что НЕ делаем (и почему)

- **Не переписываем компилятор целиком на Фортране** как замену символической
  переписки: идея уже на 80% реализована гибридом (F77PREP + F77LIBR + ZF-мост),
  но не снимает B1/B2; полный Fortran-компилятор 40+ дней и нет object writer
  (оценка subagent'а).
- **Не трогаем эталонные `src/LO_*.mad`, `build/*.words`, `src/FOREX_CORE.mad`,
  `include/FOREX_ROOT.mad`** — побайтовая верификация станет невозможной.
- **Не патчим LINK-ячейки из пользовательского режима** — требуют супервизора;
  LINK per-module and reused (`06-address-map.md:178-184`).

## 4. Риски

1. **MONITOR*+4/+1 неизвестны** — без них F2a требует RE живого `*CALL *PASCAL`.
2. **BASE и word +4 в оверлеях** — гипотеза документа, не факт; нужна трассировка
   системного `*forex` на копии.
3. **Потеря эталонной сверки** — заменяется opcode-нормализацией; нужно явно
   зафиксировать новый критерий приёмки.
4. **Память** — `*A*` 2048 слов как BSS уже давало `МАЛО ПАМЯТИ В 75377`;
   использовать компактный 400B и LC-блоки, как в PASCOMPL.
5. **Управление**: `tools/run_besm6_deck.py` остаётся с несохранённой правкой пользователя.

## 5. Оценка

F0 0.5 + F1 1–2 + F2 3–8 + F3 9–19 + F4 2–4 = **~16–34 агент-дня** плюс
прогоны dispak. Первый наблюдаемый результат — F1 (1–2 дня). Полная независимость
от MONSYS (R4) — отдельный проектLevel PASCOMPL, в этот план не входит.
