# 57 — План НОВОЙ разработки: настоящий компилятор FOREX из PERSO

Дата: 21.11.2026. Статус: **план, не начато**. Основан на итогах F0–F3 (план 54/56)
и на модели PASCOMPL (`/home/azizz/Yandex.Disk/pascal-re/`).

## 0. Зачем и что именно

**Цель:** получить компилятор Fortran‑77, который **реально исполняет синтаксис и
генерацию кода из PERSO**, а не является обвязкой над системным ФОРЭКСОМ/Фортраном.

**Почему текущий путь не годится (ФАКТ, F3 proof):**
- наш релоцируемый корень из PERSO работает как wrapper (дата/время, загрузка
  оверлеев, возврат); обнуление `LO*SYN/LO*GEN` не меняет 14/14 глиссады;
- системный Фортран (`Ф О Р Т Р А Н /16.07.73/`) делает компиляцию;
- баннер отличается от `ВЕРСИЯ 2.02`, но это другой **системный** компилятор.

**Образец для подражания — PASCOMPL:** компилятор Паскаля написан на Паскале,
скомпилирован **системным** Паскаль‑компилятором, стал релоцируемым DMS‑модулем
и грузится из PERSO (`*perso` + `*stand` + `*call *pascal`). Для Фортрана аналог:
написать компилятор на Фортране‑77; **семантическая база — FOREX 4.13**
(`libra211.l21:15448-15528`, `CHARACTER*30`, Dhrystone 48/48). bootstrap в этой
среде выполняет системный ФОРЭКС 2.02 через конвейер F77PREP/F77LIBR; живой 4.13
в besm6.net грузится с ленты **`monsys.9`** (ОС «Дубна») картой `*forex`
(`runtime-assets.md:14`, `MonsysBootstrapper.cs:34-52`), а `librar.12` — это лишь
LIBREFER-библиотека подпрограмм (`expect_library12.txt`: `DATAPR*`, `OCTTDEC`,
но не `FOREX*`/`LO*SYN`/`LO*GEN`). Разведка загрузки `monsys.9` в наш simh
ведётся отдельно.

**Ограничение, которое надо принять:** 4.13 — семантический эталон и источник
gold; системный 2.02 остаётся рабочим bootstrap этой среды. Разработка ведётся
как **новый модуль**, с собственным gold‑тестом; стабильный контур (21/21,
gate 20/20, 14/14) не трогается, но его gold‑пары перебазируются под 4.13 в N4.

## 1. Архитектура (проектное решение)

| Слой | Что делаем | Переиспользование |
|---|---|---|
| Язык реализации | Фортран‑77 подмножество, которое реально компилируется системным ФОРЭКСОМ (INTEGER‑массивы, COMMON, DATA, ENCODE/DECODE, вычисляемый GOTO) | `src/f77prep/F77PREP.FTN` — доказательство, что Fortran‑программа‑фильтр работает |
| Лексер | карты → SEQ/continuation/токены в INTEGER‑массивах | `tools/prep_tools.py:344-399` (логика `logical_lines/card_codes`) портируется в Fortran |
| Правила F77 | lowerings 0–22 + 34–40 как таблица правил в Fortran | `src/f77prep/F77PREP.FTN` (337 строк), `docs/plan-f77-full/01-f77-standard-matrix.md` |
| Симтаблица/аллокатор |固定 массивы в COMMON; метки, имена ≤6, SEQ | `F77PREP.FTN:31-53`, rule 20 (A5) |
| Генератор кода | emit 48‑битных слов БЭСМ‑6 в INTEGER‑массив; запись через PERSO‑рантайм | `docs/plan-f77-full/33-arfa-perso-lib.md` (ZF* мост), `extra.c` `*64` |
| Загрузка | `*perso:6024xx` + `*call <name>` как head‑модуль через общий `*CALL` (F2b proof) | `src/reloc/FOREX_ROOT.inline.mad`, `tests/plan-f77/fxbanner.b6` |
| Внешние процедуры| **ноль** `,SUBP` в головном модуле; всё инлайнится (`13,VJM,local`) | F2b proof (commits 28bb4eb, dea2fbe) |
| Системные сервисы | адреса MONSYS/библиотеки‑21 по abs‑адресам, как в оверлеях (F3c verdict) | `docs/06-address-map.md` |

**Альтернативный путь загрузки (изучение Монитор‑80, 21.11.2026):**
`permanent/givtran%.asm:11-30` показывает, что директива транслятора (`*FOREX`,
`*FORTR`, `*FTN`) проходит через `GIVTRAN*`: карта ищется в `TTABLE*`
(`permanent/ttable%.asm:8-23`, `*FOREX → FOREX*`, `*FTN → INITFTN`), затем
вызывается `STACOMP*` с найденным именем. То есть системный `*forex` — это не
магический ROM‑код, а **выбор модуля по имени из каталога**. Если записать наш
релоцируемый компилятор в temp‑каталог под именем `FOREX*` (последняя загрузка
побеждает, `pascal-re/PERSO.md:59-60`) и затем подать `*forex`, монитор может
выбрать **наш** модуль как транслятор. Это не требует правки монитора и даёт
полноценный compiler‑driven путь вместо head‑обвязки. Дополнительно по
`permanent/stacomp%.asm:16-53,70-105`: `STACOMP*` запоминает имя в `TRNAME*`,
ищет его в каталоге `TRCAT*` (`dncomp`) и грузит запись экстракодом `*70 1` —
загрузка идёт **по имени из каталога**, а не из фиксированной зоны. Проверить
на копиях в N2.5.

**Ключевое отличие от текущего F3:** наш модуль не дёргает системный `*forex`
ни через LINK, ни через монитор; он сам порождает листинг и объектный код.

## 2. Фазы

### N0. Заморозка и контракт (1–2 дня)
- Зафиксировать стабильные SHA (`docs/plan-f77-full/logs/f77_30_f0_etalon_freeze.txt`).
- Выбрать **минимальный профиль**: BASE77 (INTEGER/REAL, counted DO, FORMAT) +
  5 unit‑кейсов; критерий — собственный листинг и `21 1.00 3.00`.
- Написать gold‑файл, который system `*forex` **не может** выдать (уникальный
  banner/marker нашего модуля).
- Критерий: `verify-dumps.sh`, `check-source-words.py`, 21/21, 20/20, 14/14 rc=0.

### N1. Каркас Fortran‑компилятора (5–10 дней)
- Перенести `logical_lines/card_codes/data_statement` из `prep_tools.py` в Fortran
  (INTEGER‑массивы, SEQ, continuation >72, метки 777001..777004).
- Реализовать вывод числового IR (уже есть в `F77PREP.FTN:292-331`: записи
  `777001/2/3/4`).
- Критерий: «компилятор» на Fortran компилируется системным ФОРЭКСОМ и печатает
  корректный IR для BASE77; host `records/lower` всё ещё собирает `.f77`.

### N2. Релоцируемый DMS‑модуль (3–6 дней)
- Собрать Fortran‑программу в DMS через `*assembler`/`*FOREX → *TO PERSO`.
- Обеспечить **ноль внешних SUBP** в head‑модуле (F2b rule): все хелперы локальные,
  вызовы `13,VJM,local`, возврат `13,UJ,.`.
- `f0` = смещение ENTRY без `+3`; `L=cmd+const+bss` без `МАЛО ПАМЯТИ`.
- Критерий: `*perso:6024xx` + `*call <ours>` даёт наш маркер, 0 ошибок сборки,
  0 `C=0o6300`, 0 `ИСПОРЧЕНА ПОДПРОГРАММА`.

### N3. Собственный кодогенератор (10–20 дней)
- Эмиттер БЭСМ‑6 слов в Fortran (INTEGER‑массив 48‑битных слов через пары
  полуслов; `ENCODE/DECODE` для TEXT).
-Lowering правил 0–22/34–40 в машинный код, а не в текст для системного ФОРЭКСА.
- COMMON `*A*` заменить локальными BSS/COMMON блоками (F1 урок: 2048B через BSS
  даёт `МАЛО ПАМЯТИ`; PASCOMPL использует `,LC,` 4791 + `,SET,`).
- Критерий: наш модуль выдаёт объектный код BASE77, не вызывая системный `*forex`;
  control с обнулёнными `LO*SYN/LO*GEN` **меняет** результат (в отличие от F3).

### N4. Верификация и приёмка (5–10 дней)
- A/B proof: обнулить наш модуль → компиляция исчезает; восстановить → возвращается.
- Glissade 14/14 на новом контуре; gold 32/32; cross 8/8; gate 20/20.
- Запрет регрессии: стабильный путь `*forex` остаётся эталоном.
- Критерий: `F77_FULL` из master‑плана выполняется **нашим** модулем.

### N5. Интеграция (2–4 дня)
- `README.md`, `checklist/STATUS.md`, `docs/16-glissade-run.md`, PLAN 57 → статус.
- Отдельные коммиты по N0/N1/N2/N3/N4, каждый с gates.

## 3. Что НЕ делаем
- Не добавляем `*FOREX`-хук в монитор (решение пользователя: монитор не трогаем).
- Не переписываем `src/LO_*.mad`, `build/*.words`, `src/FOREX_CORE.mad` — это эталоны.
- Не считаем «достижением» смену баннера: F3 показал, что системный Фортран
  тоже меняет banner при другом пути вызова.
