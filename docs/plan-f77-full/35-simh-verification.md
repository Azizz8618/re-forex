## 1. Как в simh грузится ОС и подаётся задание (исследование)

### 1.1 Загрузка
Рабочая конфигурация — `simh/BESM6/OSZAGR/dispak.ini` (READ-only). Порядок:

```
attach -n drum0 …/MB/drum1x.bin ; drum1
attach -n md06 …/MD/2052            ; scratch
set md1 ec-5061; set md4 ec-5061
attach -e md01 …/MD/2148
attach -r md02 …/MD/2248
attach -e md04 …/MD/2095
attach -e md05 …/MD/2063
attach -e md07 …/MD/2253
attach -e md21 …/MD/2061
attach -e md41 …/EC5061/2070 ; md42 2094; md43 2086; md44 RAK/2073
attach -e md45 ~/.besm6/2348        ; в разделяемой конфигурации — /usr/local/share/besm6/2348
set mg4 es ; ленты mg43..mg62
attach tty1 console ; set tty1 unicode,authbs
d -ml 1 xta, vtm 1777(1) / d -ml 2 atx (1), utm -1(1) / d -ml 3 v1m 2(1), stop ; run 1
load …/boot_dispak.b6 ; run 2000
```

`run 2000` уходит в непрерывный цикл ОС (PC `04440` / `CM1П:`-приглашение), **не** останавливаясь.
 Чтобы получить `sim>` — Ctrl+G (tmux: `tmux send-keys -t <s> C-g`).

### 1.2 Подача декы — два задокументированных пути
1. **FS8/FS0** (перфолента): `at -t fs0 input.txt` (demo/punchtape.ini).
2. **VU0** (перфокарты, рабочий путь `UVU/*.ini`, `program.dubna.ini`):
   ```
   at vu0 /abs/path/to/deck.txt
   d 6 1
   d 5 10
   set cpu req
   expect -r "B0.*\n"
   go
   ```
   Подтверждение приёма в консоли — `В0` (в логе выглядит как `ЗMB0 <шифр>000000`);
   при незакрытой колоде — `В075-1 <шифр> …` (ожидание следующих карт).
   Дальше ОС сама пишет `ДАЙ A0` и ждёт включения АЦПУ:
   `d 6 10; d 5 1; set cpu req; go`, после чего — `КОНЕЦ ЗАДАЧИ` и вывод в `prn0`.

Источники: `simh/BESM6/docs/ВВОД_АНАЛИЗ.md §3`, `README/AGENTS.md` «Находка 2026-09-08б»,
`demo/punchtape.ini`, `UVU/program.dubna.ini`.

### 1.3 Важная находка по формату колоды
Паспорт **обязан** содержать `ОЗУ` (обязательная директива по §1.1 ВВОД_АНАЛИЗ.md) и все
паспортные `^`-поля **на одной строке**, как в рабочем `VVOD/input3.txt`:
```
ШИФР 419999 ЗС5^
ОЗУ 32^ТРА 100^АЦП 64^ЛЕН 41(2048)^ЛЕН 60(2348)^
EEВ1А3
```
Терминатор: ```````` + `еконец` (как в `input3.txt`) либо `^L`(0x1d)+`ЕКОНЕЦ`
(как в `demo/input.txt`).Batch-дека из dispak (`logs/f77_26_perso_deck.txt`) содержит
`лен …` и 6 backtick, но **не содержит `ОЗУ`** — в full OS она одной строкой не проходит.

## 2. АРФА-том в simh: найден, но это НЕ 2249

| Параметр | dispak (batch) | full simh |
|---|---|---|
| Образ | `/var/tmp/p7c-arfa-lib/disks/2249` | `simh/BESM6/MD/2095` |
| Метка | `АRFА 001` (создан `besmtool arfa-format --label=АRFA`) | **`АRFА 011`** |
| Признак архивного тома | ЕСТЬ | ЕСТЬ |
| Каталог | пустой после F2/G1 | 11 записей (ГП, РЕRSО, СТАРФА, СВОДКА, БЮСТ, …) |
| Подключение | `BESM6_ARFA=2249` (env dispak) | `attach -e md04 …/MD/2095` (уже в `OSZAGR/dispak.ini`) |

В simh **нет** переменной `BESM6_ARFA` и вообще нет ARFA-кода в C-исходниках (`grep -i arfa` по
`simh/BESM6/*.c` — 0 совпадений). Экстракоды `э63`/`э70` в simh — это ловушки в
`besm6_cpu.c:1499-1541`, передающие управление в гостевую ОС по адресам `0500+063 = 0563` и
`0500+070 = 0570`; всю АРФУ реализует **гостевая ОС ДИСПАК**, а не эмулятор. Поэтому единственный
эквивалент `BESM6_ARFA` в simh — это ``ЛЕН``/``ДИС``-карта в колоде + физически подключённый
том с меткой в зоне 1, слово `0030` (GOST `А R F А` = `20 47 40 20`, см. `arfa.c:366-379`).

Мой рабочий 2249 (копия с меткой `001`) в simh также читаться как АРФА-том при сканировании
юнитов 030..067, но **штатный** том — 2095. В рабочей копии я подключал и 2095 (md04), и 2249
(md46); разница в CV (если бы они появились) была бы именно в номере тома — см. §4.

Команды проверки:
```
BESM6_PATH=/home/azizz/Yandex.Disk/simh/BESM6/MD besmtool arfa 2095
BESM6_PATH=/var/tmp/p7c-simh/disks besmtool arfa 2249
```

## 4. Блокер: точная формулировка

**simh стартует, ОС работает, АРФА-том подключён, дека доходит до консоли — но задача не
переходит в состояние `ЧП(002)`/`Ф002` и не выдаёт вывод.** Симптомы:
- после FS8 ОС отвечает `В075-1` (ждёт карты) или `В0`, но не `ЧП(002) … M=005`;
- `ДАЙ A0` не появляется;
- `prn0` пуст; каталог АРФЫ не меняется.

Вероятные причины (не доказаны, честно перечислены):
1. **Несовместимость колоды batch-dispak с full OS** — в batch-деке нет `ОЗУ`, а при
   добавлении `ОЗУ` и `^`-полей на одной строке приём всё равно остаётся в `В075`.
2. **PERSO 0o2320 с библиотекой не подхватывается full OS** — в `2348` из прототипа
   `ZFOPEN` есть, но full OS грузит PERSO из своей зоны; возможна несовместимость паспорта
   диска/`*PERSO:602320,CONT` между batch и ОС.
3. **`attach vu0` в `do`-скрипте теряется** (`show vu0` → `not attached` после подачи),
   хотя ручной `attach vu0 <abs path>` работает; FS8.then считывает не тот поток.
4. Разница конфигурации md41 (в рабочем ini `2070`, в прототипном — `2048` для `ЛЕН 41`).

**Что НЕ является блокером (проверено):** сам эмулятор, загрузчик, диски, метка АРФЫ,
наличие PERSO-библиотеки, сетевые/терминальные порты.
