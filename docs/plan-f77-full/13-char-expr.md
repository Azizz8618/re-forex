## 3. Детальные протоколы

### A5 — идентификаторы >6 знаков

- **Нативная проба** (`a05_merge.b6`): `INTEGER AAAAAAX, AAAAAAY` →
  `ЕРR 01202 … ТИП ПЕРЕМЕН ОПРЕДЕЛЕН ПОВТОРНО`, `АТТ: АААААА УКОРОЧЕН`.
  Тихая удачная компиляция не воспроизведена: 2.02 как минимум диагностирует
  дублирование укороченных имён.
- **Проба rule 20** (`a05_trunc.f77` через `prep_tools.py deck1` + dispak):
  pass 1 печатает `777004 <seq> 20 <pos> <ASCII>`:
  `AAAAAAX` → `65 65 65 65 65 65 88`, `AAAAAAY` → `65 65 65 65 65 65 89`.
- **Pass 2 конвейера** (`prep_tools.py lower`): rc=1,
  `C@ INTEGER AAAAAAX, AAAAAAY -> TRUNCATED NAME: AAAAAAX / AAAAAAY (all -> AAAAAA)`
  и stderr `TRUNCATED NAME: …`. Молчаливого слияния в F77PREP-пути нет.
- **Вывод:** статус OK. Волне 2 достаточно закрепить rule 20 в регрессе, новую
  логику писать не нужно.

### A8 — 6-битная TEXT-кодировка

- `a08_text.b6` печатает `4HABCD` (A4) и `6HABCDEF`, `6HHELLO ` (A6).
  Диагностики нет. Raw-вывод: ` АВСD` / ` АВСDЕFНЕLLО`.
- Полная таблица перекодировки, снятая пробой `tests/plan-f77-full/unit/A08_text_encoding/a8_alphabet.b6` (26 букв, a–z, 0–5; результат в `a8_alphabet.result.txt`):
  `A→А(0410) B→В(0412) C→С(0421) E→Е(0415) H→Н(041D) K→К(041A)
   M→М(041C) O→О(041E) P→Р(0420) T→Т(0422) X→Х(0425) Y→У(0423)`;
  остальные латинские буквы и цифры проходят без изменений; строчные складываются
  в те же заглавные глифы (у 6-битного TEXT нет регистра).
- Хостовый постпроцессор `tests/plan-f77-full/unit/A08_text_encoding/recode.py`
  превращает raw → `ABCD` / `ABCDEFHELLO` (строки 12→18 лога).
- **Вывод:** OK как *аппаратная оговорка + постпроцессор*; менять ядро/генератор
  запрещено условием задачи и не требуется.

### B6 — CHARACTER*n

- Нативная форма: `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ` + `НЕДОПУСТИМ СИМВОЛ = В ИНСТРУК ПРИСВАИВ`
  (`b06_native.b6`, лог строки 16–24).
- Lowered (`b06_lowered.b6`) проверяет **n = 1, 4, 6, 10, 30**:
  - `INTEGER IS(30)` + `DATA IS/65,…,51/` → 30 ASCII-кодов (`A`–`Z`,`0`–`3`),
  - упакованные слова: `W=ceil(n/6)` (для n=10 → 2 слова, последнее с паддингом
    `4HGHIJ  `; для n=30 → 5 слов `6H…` + `2HYZ`),
  - печать `A6×5`, `A6+A4`, `A1`, `A4` — все длины выведены корректно.
- **Вывод:** OK через rule 12 + rule 8.

### B12 — символьный литерал в присваивании / DATA

- Нативно: та же ошибка типа (`b12_native.b6`).
- Lowered: `S='ABCDEF'` → `DATA IS/65,66,67,68,69,70/` (ASCII-массив, печать I3),
  `DATA S/'UVWXYZ'/` → `DATA IT/6HUVWXYZ/` (упакованное слово, печать A6).
- **Вывод:** OK через rule 8 + rule 12.

### B13 — nH-константа в присваивании

- Нативно: `S=6HABCDEF` → `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`.
- Lowered: `S=6HABCDEF` → `DATA IS/6HABCDEF/` → `ABCDEF`; дубль в ASCII-кодах
  подтверждает содержимое (`65 … 70`).
- **Вывод:** OK через rule 8.

### C6 — .EQV. / .NEQV.

- Нативно: `НЕДОПУСТИМ СИМВОЛ КОП В ИНСТРУК ПРИСВАИВ` на обеих операциях.
- Lowered (A=.TRUE., B=.FALSE.):
  `R=(A .AND. B) .OR. (.NOT.A .AND. .NOT.B)` → 0 (EQV false),
  `S=(A .AND. .NOT.B) .OR. (.NOT.A .AND. B)` → 1 (NEQV true).
  Печать `L2` непроверена в 2.02, поэтому логика сведена к целым через `IF`.
- Побочный результат: `.EQ./.NE.` **над LOGICAL** тоже дают `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`
  (проба `tests/plan-f77-full/unit/C06_eqv_neqv/c6_variants.b6`), поэтому этот вариант lowering-а непригоден.
- **Вывод:** OK через булеву формулу.

### C8 — конкатенация `//`

- Нативно: CHARACTER-операнды отвергаются (`b6`-причина).
- Lowered: `IA='ABCD'` (65,66,67,68), `IB='EF'` (69,70),
  `CALL STRCAT(IA,IB,IC,4,2)` → `65 66 67 68 69 70` = `ABCDEF`.
- **Вывод:** OK через rule 13 + `F77LIBR STRCAT`.

### C9 — сравнение строк

- Нативно: CHARACTER-операнды отвергаются.
- Lowered: **упакованные 2-словные массивы** (ISTRCM сравнивает `A(1),A(2)`):
  `IA/6HABCD/`, `IB/6HABCE/`, `IC/6HABCD/`, вторые слова `6H      `.
  `ISTRCM(IA,IB)=-1`, `ISTRCM(IA,IC)=0`, `ISTRCM(IB,IA)=+1`.
- Важно: передача **скаляра** в `ISTRCM(A(2),B(2))` вызывает `БУФ ПЕРЕП`
  (выход за границу); передача ASCII-массива возвращает 0 (сравниваются только
  первые 2 элемента). Оба варианта зафиксированы и исключены из рецепта.
- **Вывод:** OK через rule 14 + `F77LIBR ISTRCM`.

### C10 — арифметика COMPLEX

- **Нативно работает без всякого lowering-а**: `+ - * /` над `(3,4)` и `(1,2)`
  дают `(4,6)`, `(2,2)`, `(-5,10)`, `(2.2,-0.4)` — все четыре результата
  совпадают с аналитическими. Диагностики нет.
- **Вывод:** OK (native). Правило/процедура волне 2 не нужна.

### D3 — символьное присваивание / подстрока

- Нативно: `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`.
- Lowered: `IS/65…70/` = `ABCDEF`, `CALL SUBSTR(IS,2,4,IW)` → `66 67 68` = `BCD`;
  статический фолд `DATA IWD(1)/6HBCD   /` + `A4` → `BCD`.
- **Ловушка (важно для волны 2):** `DATA` после исполняемого `CALL` компилируется
  без диагностики, но `SUBSTR` возвращает `0 0 0`. Все `DATA` обязаны идти
  **до** первых исполняемых операторов (это и есть требование F77 §8).
- **Вывод:** OK через rule 12/14 + `F77LIBR SUBSTR`.

## 4. Что must реализовать волна 2 (точные выражения)

### 4.1 Фактически проверенные сигнатуры F77LIBR (PERSO 0o2310)

```
SUBROUTINE STRCAT(A,B,C,LA,LB)   ! A,B,C - INTEGER; ОДИН символ = ОДИН элемент (ASCII-код)
SUBROUTINE SUBSTR(A,I,J,C)       ! C(1:J-I+1) = A(I:J), индексы от 1
INTEGER FUNCTION ISTRCM(A,B)     ! A(2),B(2) - УПАКОВАННЫЕ 6-битные слова (nH)
```

`STRCAT`/`SUBSTR` работают с ASCII-массивами, `ISTRCM` — с упакованными
TEXT-словами. Это расхождение представлений следует устранить в первую очередь (§4.3).

### 4.2 Точные выражения lowering (реализовать в `prep_tools.py` / `F77PREP`)

| Правило | Исходник (F77) | Пониженный Fortran (проверено) |
|:---|:---|:---|
| **R8/R12** | `CHARACTER*n S` | `INTEGER IS(W)`, `W=ceil(n/6)` (упакованный путь) **или** `INTEGER IS(n)` (ASCII-путь) |
| **R8** | `S='lit'`, `n≤6` | `DATA IS/kH<lit>/`, `k=len(lit)`, паддинг пробелами до 6 |
| **R12** | `CHARACTER*n S; S='lit'`, `n>6` | `DATA IS(j)/6H<кусок j>/` для `j=1..W-1`, последнее слово `6H<ост+паддинг>`; печать `A6×(W-1)+A<n mod 6>` |
| **R8-ASCII** | `S='lit'` (для выражений) | `DATA IS/<ASCII-коды символов>/` |
| **R13** | `U = S // T` | `CALL STRCAT(IS,IT,IU,LS,LT)`; `INTEGER IU(LS+LT)`; левая подстрока сначала `CALL SUBSTR(...)` |
| **R14a** | `T = S(i:j)` | `CALL SUBSTR(IS,i,j,IT)` |
| **R14a-fold** | `PRINT f,S(i:j)` при известном литерале | `DATA IW/6H<substr+паддинг>/` + печать `IW` |
| **R14b** | `IF (S .EQ. T) GOTO L` | `K=ISTRCM(IS,IT)` ; `IF (K .EQ. 0) GOTO L`; для `.NE.` → `.NE. 0`, `.LT.` → `.LT. 0`, `.GT.` → `.GT. 0` |
| **R6 (новое)** | `R = A .EQV. B` | `R=(A .AND. B) .OR. (.NOT.A .AND. .NOT.B)` |
| **R6 (новое)** | `R = A .NEQV. B` | `R=(A .AND. .NOT.B) .OR. (.NOT.A .AND. B)` |
| **R20 (сущ.)** | имя >6 знаков | `777004 <seq> 20 <pos> <ASCII>` → `C@ … -> TRUNCATED NAME: …`, rc≠0 |
| **A8 (host)** | raw dispak-вывод A-дескриптора | `recode.py`: `АВСD` → `ABCD` (12 символов, таблица §3 A8) |

### 4.3 Расхождение представлений — обязательное решение волны 2

Нужно выбрать **одно представление** и привести к ему все три процедуры:

- **Вариант A (рекомендуемый): ASCII-массив везде.**
  Переопределить `INTEGER FUNCTION ISTRCM(A,B,N)`, сравнивающую `A(i)` и `B(i)`
  лексикографически по ASCII-кодам; все строки — `INTEGER IS(n)`, один символ на
  элемент. Итог: `STRCAT`, `SUBSTR`, `ISTRCM` работают с одним представлением;
  для A-вывода добавить `IS2TEXT` (упаковка 6 символов в 6-битное слово).
- **Вариант B: упакованные слова везде.**
  Переписать `STRCAT`/`SUBSTR` на битовые сдвиги 6-битных групп; сохранить
  текущий `ISTRCM(A(2),B(2))`. Требует правки МАДЛЕН/Generator-пути.

Пока представление не выбрано, `prep_tools.py` должна проверять его и не
смешивать ASCII-массив с упакованным словом в одном выражении.

### 4.4 Landmines, уже найденные волной 1

1. `DATA` обязан предшествовать исполняемым операторам (иначе `SUBSTR` → `0 0 0`,
   без диагностики). См. §3 D3.
2. `DATA IWD/6H…/` на массиве `IWD(8)` без индекса даёт `АТТ 04426 / КОЛИЧ
   ПЕРЕМЕН В DАТА ПРЕВЫШАЕТ КОЛИЧ КОНСТ`; писать `DATA IWD(1)/6H…/`.
3. `ISTRCM` требует ровно два INTEGER-слова на аргумент; скаляр → `БУФ ПЕРЕП`.
4. `.EQ./.NE.` над LOGICAL непригодны для EQV/NEQV → только булева формула.
5. Имя процедуры F77LIBR ровно ≤6 знаков: `STRCAT`, `SUBSTR`, `ISTRCM`.
