## 0. Краткий ответ на главный вопрос

**НЕТ** — стандартный `WRITE(41,10)` остаётся отвергнутым Level B (`НЕТ КАНАЛА LUN 41`)
**даже после успешного Э63 тип 012 «дозаказ области»**, который реально привязал
LUN 41 к области АРФЫ (лог `f77_25_bridge_erllun.txt`, `f77_25_bridge_erllun.err.txt`).

**ДА (но не через Fortran I/O)** — сама АРФА даёт терминальный канал: после того же
дозаказа сырой Э70 из PERSO пишет в область по LUN 41 без `E_CWERR`, несмотря на
archivo-флаг тома (лог `f77_25_bridge_raw70.txt/.err.txt`, трасса
`DD pc=01044L r016=01060 u=51 z=0000 WR`). Это ровно исключение
`arfa_area_unit(u)` в `extra.c:2086-2091`.

Следовательно: **правка dispak для АРФА-канала НЕ нужна**; блокер — Level B
(таблица допустимости юнитов ФОРЭКС / `ERRLUN`), как и в `17-lun-p7c.md §3.2`.
Построить F77 I/O поверх АРФА без правки dispak **можно, но только с правкой
рантайма/монитора ФОРЭКС** (или как нестандартный `CALL`-API, самому делающий
Э63+Э70 в PERSO). «Бесплатно» поверх стандартного `WRITE(u,…)` — нельзя.

## 1. Точный формат информационного слова ИС (из `disp/dispak/arfa.c` целиком)

Слово 48 разрядов; `l` = разряды 48..25, `r` = 24..1.
Макросы `arfa.c:94-108`: тип `W48_43 = (l>>18)&077`; LUN `W48_37 = (l>>12)&077`;
пароль `W36_25 = l&07777`; `W24 = (r>>23)&1`; новый пароль `W24_13 = (r>>12)&07777`;
признак чтения `W12 = (r>>11)&1`; знак сдвига `W21 = (r>>20)&1`;
сдвиг `W20_5 = (r>>4)&0xffff`; верхний уровень `W5 = (r>>4)&1`;
способ имени `W4_1 = r&017`; вид `W20_18 = (r>>17)&7`; группа `W22_21 = (r>>20)&3`;
индивидуальность `W17 = (r>>16)&1`; длина `W16_1 = r&0xffff`; права `W2_1 = r&3`.
Параметры — на РМР (`accex`, берётся из `prm` в `arfa_e63()`).

| Оп | Название | ИС.l (48..25) | ИС.r (24..1) | РМР | Результат |
|---|---|---|---|---|---|
| **01** | создать | `T<<18 \| LUN<<12 \| pass` (T=1) | способ имени: `010`=8 (ГОСТ/УПП), `1..7`=«по-старому», `0`=идентификатор, `014`=МС-80 (не поддержан) | `r15..0`=длина в зонах; `r19..17`=вид (6 — ошибка); `r21..20`=группа; `r16`=индивидуальность | M16=0/код; имя обязательно с шифром хозяина (`/NNNN`), иначе `5` |
| **02** | уничтожить | `2<<18 \| LUN<<12 \| pass` | способ имени | не используется | сравнивается шифр владельца; при пароле записи нужен pass (`031`), неверный → авост |
| **07** | сведения | `7<<18 \| LUN<<12 \| pass` | способ имени (при LUN≠0 не разбирается) | не используется | `acc.l`=шифр хозяина; `acc.r`: бит23=пароль чтения, 22=записи, 18..17=группа, 16=индивидуальный, 15..0=число зон |
| **10В** | каталог (верхний уровень) | `010<<18 \| …`, бит `r4`=1 | способ имени (при `r4=0` ищет область-каталог → `024`) | `r11..0`=буфер; `l11..0`=первый номер; `l23..12`=счётчик | в буфере пары слов имя(9 байт)+шифр, терминатор `777777…`; `0` в любом поле → `2` |
| **12В** | дозаказ области | `012<<18 \| LUN<<12 \| pass` | способ имени | 32-битная шкала: бит `31−(u−030)`; у=041(10)=051(8) → `l=00000100` | M16=статус; при успехе `acc.r`=присвоенный LUN; `disks[u]` → том АРФЫ, `offset`=зона+сдвиг; `unit_area[u]` ≠ 0 |
| **30В** | захват | `030<<18 \| LUN<<12 \| pass` | способ имени; `r23`=монопольный | не используется | M16; `010`=занята; одна задача — одна область |
| **31В** | освобождение | `031<<18 \| LUN<<12 \| pass` | способ имени | не используется | M16; без захвата → авост |

Диапазон логических номеров областей `030..067` (восьм.). Имя «по-новому» — слова
от ИС+1, байты ГОСТ до кода `0377`, `/` отделяет шифр хозяина (цифры ГОСТ).
Коды ответов: 0,1,2,4,5,6,010,012,013,015,022,023,024,027,031,032 (восьм.).

### 2.3 Ограничение механизма возврата IOSTAT

Попытка вернуть M16 через dummy-аргумент (`ATI,14`, `14,XTA,1`, `11,ATX,`;
проверено отдельным `ZPROB0`, лог `f77_25_bridge_argprobe.txt`) **не сработала**:
Fortran `IST=777` остался 777. FOREX 2.02 передаёт скалярные фактические
аргументы по значению, а не по ссылке; F77LIBR возвращает состояние через
`COMMON` (`20-open-close.md §1.2`). Поэтому честный `IOSTAT=` сегодня требует
COMMON-канала или печати статуса внутри PERSO; один M16 в reg[16] до Fortran
не доходит. Это отдельный блокер для J24, не связанный с АРФОЙ.

## 4. Вердикт

| Вопрос | Ответ | Доказательство |
|---|---|---|
| Exact format ИС для 01/02/07/10В/12В/30В/31В | получен (§1) | `arfa.c:94-108, 770-1391` + трасса `ИС=…_10` |
| Fortran → PERSO 0o2320 → Э63 «КЛЮЧАР» | **РАБОТАЕТ** | `f77_25_bridge_e63_create.*`: область создана |
| Э63 012 привязывает LUN 41 к области | **РАБОТАЕТ** | `f77_25_bridge_erllun.err.txt` |
| `WRITE(41,…)` после дозаказа | **НЕТ КАНАЛА LUN 41** | `f77_25_bridge_erllun.txt`, rc=0 — фатально по критерию §0 документа 17 |
| Э70 на ARFA-связанном LUN (сырой, из PERSO) | **ДА** | `f77_25_bridge_raw70.err.txt`: `u=51 … WR`, зона изменена |
| F77 I/O поверх АРФА без правки dispak | **НЕТ как стандартный WRITE**; **ДА только как CALL-API + правка Level B ФОРЭКС** | §3 + `17-lun-p7c.md §3.2` |

**Рекомендация родителю.** Не менять `extra.c` / `arfa.c` — level A уже
позволяет АРФЕ быть терминальным каналом. Требуется (а) патч/пересборка
рантайма ФОРЭКС 2.02 Level B (`ERRLUN`, таблица допустимости LUN), чтобы
`WRITE(41,…)` доходил до Э70; (б) для `IOSTAT=` — COMMON-канал из PERSO.
Без (а) и (б) честно называть это поддержкой F77 I/O нельзя; доступен только
нестандартный `CALL`-мост, который сам делает Э63 01/12/30/31 + Э70.
