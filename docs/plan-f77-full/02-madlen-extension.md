## 0. Резюме

1. **Полная поддержка F77 только правками МАДЛЕН невозможна в один проход.**
   Суммарная оценка «позвоночника» для 12 групп из §2 — **~400…1000 слов внутри
   уже плотно упакованных 1024+1024 слов** оверлеев. Реальный резерв — единицы–десятки
   слов. Поэтому рабочая стратегия — **гибрид**: минимальный MADLEN-spine (распознавание
   + точка входа) + Fortran-рантайм `F77LIBR` в новой зоне PERSO + (где можно)
   source-to-source lowering в `F77PREP`.
2. **Три и только три точки расширения в коде компилятора:** `LO*SYN` (лексика/автомат),
   `LO*GEN` (кодогенерация + таблица имён операторов `0532..0623`), `FORMAT` (таблица
   передач `FT*` в ячейках `0o77xxx`). Корень `FOREX*` (96 слов), `FORTLIBR`, `DATAPR*`,
   `GIV/PG`, `TAK/PG`, `OCTTDE*` не трогаются.
3. **Группы делятся на 4 класса по месту правки:**
   - *только runtime* — COMPLEX/DP intrinsics (обычные внешние функции);
   - *LO_SYN + LO_GEN + FORMAT + runtime* — PRINT *, READ END=, CHARACTER 2.02, unformatted I/O;
   - *LO_SYN + LO_GEN* — IMPLICIT, SAVE, computed GO TO, ASSIGN, H-константы;
   - *почти только LO_SYN* — REWIND/BACKSPACE/ENDFILE (имена `*REWIN/*BACKS/*ENDFI` уже
     присутствуют в таблице `LO*GEN:0615..0621`).
4. **Проверяемость** при изменённой симтаблице обеспечивается многоуровневой схемой
   L0..L5 (golden SHA → opcode-поле → homeomorphic mapping → регрессия → manifest →
   воспроизводимость), заменяющей недостижимую «полную побайтовую идентичность»
   (`docs/05-roundtrip.md` §3–4).

## 1. Точки расширения

### 1.1 `LO_SYN` — новые лексемы и состояния автомата

Физическая структура (1024 слова, `src/LO_SYN.mad`):

| Область | Отн. адреса | Слов | Что делает |
|---|---|---:|---|
| Код состояний/обработчиков | `0000..1516` | 847 | линейные блоки, экстракоды `Э20/Э36/Э47/Э60/Э65/Э67/Э70` |
| **Таблица переходов/диспетчера автомата** | **`1517..1777`** | **177** | пары «сохранить См в ячейку `SCxx01` → выбор следующего состояния» |

**Куда именно добавлять:**

- **Новый символ/ключевое слово, укладывающееся в существующий класс лексем** — меняется
  либо код обработчика в теле `0000..1516`, либо **таблица признаков** по адресу аргумента
  экстракода `Э36 «втбрз»` (аргументы `0o75551`, `0o70131`, `0o52103`, `0o42440`,
  `0o66170`, …; `include/LO_SYN.xref.md` §1). Это резидентные подпрограммы BASIC/MONSYS,
  чья точная семантика в `rukava.be` не раскрыта — главный источник риска.
- **Новое состояние/класс** — дописывается entry в таблицу `1517..1777`: слово вида
  `,ATX,SC<класс>01` + команда выбора (`APX`, `*20`, `*36`, `VTM`, `ASN`). Хвост таблицы
  `1764..1777` — плотно упакованный диспетчер (см. `src/LO_SYN.mad:3809-3844`: entry
  `SC0701`, `SC0301`, `SC0401`, `SC1101`, `SC1201`, `SC1001`, `SC0601`, `SC0501`).
  Свободного слота нет: рост таблицы сдвигает все последующие слова и ломает
  относительную адресацию internal-целей `0315`, `0500`, `0507`, `0511`, … (25 целей,
  `include/LO_SYN.xref.md` §2.1).
- **Побочное требование:** 6-символьный лимит МАДЛЕН (`docs/10-naming-conventions.md` §6):
  `IMPLICIT` → `IMPLCT`, `SAVE` → `SAVE` (4), `END=` → `END=`, `ASSIGN` → `ASIGN`,
  `REWIND` → `REWND`, `H` → `H`. Полные имена — только в комментарий и `include/*.labels.md`.

**Оценка:** 20–90 слов на оператор (калибровка `docs/plan-f77/04-assembler-path.md` §3:
30–90 слов / 40–120 строк), риск **ВЫСОКИЙ** (таблично-управляемый автомат; ошибка
проявляется на случайной старой конструкции).

### 1.2 `LO_GEN` — новые генераторы и таблица имён операторов

Структура (1024 слова, `src/LO_GEN.mad`):

| Область | Отн. адреса | Слов | Примечание |
|---|---|---:|---|
| Заголовок | `0000..0003` | 4 | маркер `0o200003`, TEXT `LO*GEN` |
| Тело генератора | `0004..0531` | 342 | линейные блоки + вызовы резидентных подпрограмм |
| **Таблица имён операторов** | **`0532..0623`** | **58** | **29×2: дескриптор `NMLN5D=0o0000000000020005` + TEXT-имя** |
| Продолжение тела | `0624..1777` | 620 | та же схема |

Таблица `0532..0623` (абсолют `0o300232..0o300323`) — **не ключевые слова Фортрана**,
а внутренние имена, которые генератор подставляет в генерируемый код как внешние ссылки
(`docs/plan-f77/02-extension-points.md` §1.3):

```
POWER  A/RHOCHI  A/NOT  A/AND                    ← операторные intrinsic (0533..0541)
FT*621 FT*002 FD*002 FC*002 FT*003 FT*521 FT*721
FT*722 FD*722 FC*722 FT*723 FT*641 FT*642 FD*642 FC*642 FT*643
FT*541 FT*561 FT*571 FT*531 FT*611              ← I/O-рантайм FT/FD/FC (0543..0613)
*REWIN *BACKS *ENDFI STOP*                      ← управление лентой/останов (0615..0623)
```

**Куда добавлять:**

- **Новый тип-вариант / внутренний оператор** (например `FS*` для CHARACTER) → новая
  пара «дескриптор + TEXT» **внутри** таблицы + код, отображающий токен в индекс пары
  + Fortran-процедура + LIBREFER. Таблица плотно упакована: 58 слов на 29 пар,
  **свободного слота нет**; добавление пары сдвигает `0624..1777` на 2 слова и требует
  пересчёта всех абсолютных ссылок (в `LO*GEN` их 504, все — внешние, `include/LO_GEN.xref.md` §1).
- **Новый синтаксис оператора** (`PRINT *`, `END=`, computed GO TO, ASSIGN, unformatted I/O) →
  кодогенерация в теле `0004..0531` / `0624..1777`; 10–40 слов на конструкцию. Если
  Internal-переходов в `LO*GEN` **нет**, то при аккуратном сохранении порядка слов opcode-
  и адресные поля воспроизводятся один-в-один (см. §3).
- **Обычный function-style intrinsic** (COMPLEX/DP) — **таблицу менять НЕ нужно**:
  `SQRT`, `ABS`, `SIN`, `MOD`, `EXP`, а также вымышленные `FOO`, `MYFUN`, `VERYLONGNAME`
  компилируются как обычные внешние ссылки без правки оверлеев
  (`docs/plan-f77/02-extension-points.md` §2.а, §3.3).

**Оценка:** 2–5 слов на имя в таблице + 10–40 слов на генератор; 20–60 строк; риск
**ВЫСОКИЙ** для table/code, **НИЗКИЙ** для function-style intrinsic.

### 1.3 `FORMAT` — расширение таблицы `FT*`

`FORMAT` → `FTDISP` — отдельный 61-словный модуль (`0o510443..0o510522`), **не оверлей**;
он строит таблицу передач, записывая адреса 11 подпрограмм в ячейки `0o77xxxB`
(`src/FOREX_RUNTIME.mad:118-189`, `src/lib21/FORMAT.mad:35-57`):

| FT* | Ячейка | FT* | Ячейка |
|---|---:|---|---:|
| `FT*571` | `0o77207` | `FT*521` | `0o77257` |
| `FT*541` | `0o77237` | `FT*721` | `0o77057` |
| `FT*611` | `0o77167` | `FT*641` | `0o77137` |
| `FT*531` | `0o77247` | `FT*002` | `0o77776` |
| `FT*561` | `0o77217` | `FT*003` | `0o77775` |
| `FT*621` | `0o77157` | | |

**Процедура добавления нового `FT*` (например `FT*LD1` для list-directed):**

1. Объявить `FT*LD1 ,SUBP,` в секции SUBP `FTDISP` (после `FT*003`, строка S1:15540).
2. Выделить свободную ячейку `0o77xxxB` (диапазон `0o77057..0o77776` разрежен; например
   `0o77060` или `0o77140`), завести `,EQU,`-константу по шаблону
   `FT571_DISPATCH, EQU, 77207B` (`docs/10-naming-conventions.md` §2) — короткое имя
   `FTLD1`, полное описание в комментарий.
3. Вставить пару `,UJ, FT*LD1 / ,ATX, FLD1DS` **до** метки `FTDTE` (конец таблицы,
   строка S1:15584). Порядок пар определяет индекс, который вычисляется в `FTDOFS`
   (`ASN 103B`, `ASN 155B`, `UTC FTDCNS`, `UIA` — строки S1:15543,15547,15557-15559):
   при вставке в середину **сдвигаются индексы всех последующих FT\***, поэтому новую
   пару добавляют **в конец** и проверяют арифметику смещений.
4. Проверить цикл `FTDLOP` (`VTM FTDTBA` с базой `0o77766`, `VLM FTDLOP`, `VZM FTDSTO`,
   `IJ` — S1:15549-15556): число обходов не должно «заехать» за новую пару; при
   необходимости скорректировать константу `FTDCNS` / границу.
5. Выделить LINK-ячейку: заняты `0o74001..0o74013` и `0o74022`, свободны
   `0o74014..0o74021`, `0o74023..0o74077` (`docs/plan-f77/04-assembler-path.md` §3,
   medium/low risk — конфликт проверяется на конкретной сборке MONSYS).
6. Добавить запись в LIBREFER / каталог библиотеки 21; имя ≤6 знаков.
7. **Альтернатива с меньшим риском:** не новый entry, а новая реализация существующего
   слота (`FT*002` → INTPRT), если семантика совместима; тогда меняется только тело
   Fortran-процедуры, таблица передач не трогается.

**Оценка:** 3–6 слов в FORMAT / 5–15 строк + LINK-ячейка; риск **СРЕДНИЙ/НИЗКИЙ**.

### 2.2 Пояснения к每组

**CHARACTER 2.02.** Отказ «ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ» (`logs/plan_f77_probes.txt:4`)
указывает не на неизвестное ключевое слово (было бы «НЕДОПУСТИМ КЛЮЧ СЛОВО»), а на
**отсутствие строкового типа-варианта** в генераторе/проверке типов. В таблице `0532..0623`
есть `FT*` (real), `FD*` (double), `FC*` (complex), но нет `FS*` (string). Значит нужны:
новый тип-вариант + substring-синтаксис `S(2:4)` в `LO_SYN` + процедуры ввода/вывода
строк + записи в LIBREFER. **База 4.13:** `CHARACTER*30` работает нативно (Dhrystone, 48/48), правка МАДЛЕН
не требуется (0 слов). Для 2.02 сохраняется эмуляция строками-целыми массивами
(`01-gap-analysis.md` §2.1) через F77PREP как fallback. Приоритет — адресовать
4.13 как семантическую базу; 2.02 держать как исторический эталон и bootstrap.

**PRINT \*.** Отказ «ОШИБКА В ССЫЛКЕ НА ФОРМАТ»: генератор ждёт метку `FORMAT`. Требуется
новый класс лексемы `*` в позиции формата, генерация вызова list-directed процедуры и
новая ячейка передач. Дешёвая альтернатива — F77PREP: `PRINT *,X` → `PRINT 9000,X` +
`9000 FORMAT(...)` (синтез по типам), **0 слов в оверлеях**, runtime — обычная Fortran-
процедура. Именно этот обход используется во всех трёх researched-бенчмарках.

**READ `END=`.** Составная проба `READ(*,*,END=99)` не локализована между list-directed
`*` и `END=` (`01-gap-analysis.md` §2.3) — **перед правкой обязательны раздельные пробы**
`READ *`, `END=`, `ERR=`. `END=` требует механизма сигнализации EOF из runtime обратно
в сгенерированный код (ветка на метку) — это самая глубокая из I/O-правок.

**IMPLICIT / SAVE.** Оба дают «НЕДОПУСТИМ КЛЮЧ СЛОВО» — чистый синтаксис. `SAVE`
дополнительно меняет **класс памяти** (статический вместо кадра M7) — семантически
рискованнее, чем просто распознавание. `IMPLICIT NONE` — расширение F90, но ubiquitous;
тиped `IMPLICIT INTEGER(A-Z)` — подлинный F77 (`?`, нужна проба). Обе конструкции
идеально ложатся на F77PREP: удалить `IMPLICIT NONE` + сгенерировать явные объявления;
`SAVE`-переменные → `COMMON`-блок.

**COMPLEX / DP intrinsics.** Function-style, поэтому достаточно Fortran-процедур с
_entry_-именем в библиотеке; TABLE `0532..0623` **не трогается** (это подтверждено
пробами `FOO`, `MYFUN`, `VERYLONGNAME`, `SIN/MOD/EXP`). Исключение — если intrinsic
требует нового внутреннего оператора/типа (аналог `A/NOT`), тогда +2–5 слов в таблице
и +10–40 в генераторе; для стандартных CABS/DSQRT такого нет.

**H-константы.** Лексический вызов: `4H` + 4 байта. Нужно распознать `nH` в `Э20` и
выдать TEXT/LOG-константу. Риск средний (лексика) переходит в высокий, если ГОСТ-кодировка
6-бит/символ не совпадает с ожидаемой (TEXT-константы в таблице операторов используют
`ASCII−0x20`, `src/LO_GEN.mad:14`). Альтернатива — F77PREP: `4HABCD` → `'ABCD'`.

**computed GO TO / ASSIGN.** Чисто синтаксические операции, runtime не нужен. computed
GO TO порождает таблицу переходов, ASSIGN — запись адреса метки в переменную + косвенный
переход. Обе редки в современном коде (P2 в gap-анализе), поэтому MADLEN-правка
нецелесообразна: F77PREP → вложенный `IF … GOTO` (computed) / целочисленный код метки
+ `IF` (assign).

**unformatted I/O.** Нет ни одной исполняемой пробы (`?`). Помимо синтаксиса требуется
новый FT*-аналог для побайтовой передачи без форматирования. Самый дорогой пункт;
рекомендуется сначала проба, затем оценка пересмотра.

**REWIND/BACKSPACE/ENDFILE.** Ключевое отличие: имена `*REWIN` (`0o615`), `*BACKS`
(`0o617`), `*ENDFI` (`0o621`) **уже есть** в таблице `LO*GEN` (`src/LO_GEN.mad:529-531`,
`1586-1695`). Значит генератор уже умеет выдавать эти внешние ссылки; нужно только
распознать оператор в `LO_SYN` и связать его с существующим индексом таблицы. Перепаковка
таблицы **не требуется** — поэтому риск средний, а не высокий. Обязательна проверка, что
резидентные подпрограммы реально существуют в библиотеке 21 и что синтаксис оператора
(с unit number) принимается.

## 3. Workflow правки при проблеме симтаблицы

### 3.1 Суть проблемы

`docs/05-roundtrip.md` §3: при символьной пересборке ADRSEK (65 слов) **все коды операций
совпали**, но **27 слов разошлись только в полях операндов** — МАДЛЕН заново нумерует
метки. Без исходной симтаблицы полная побайтовая идентичность недостижима. Для оверлеев
ситуация лучше: в `LO*GEN` внутренних переходов нет (все 504 — внешние), в `LO*SYN` —
25 внутренних целей, которые и дадут «шум» (`docs/plan-f77/04-assembler-path.md` §2.1).

### 3.2 Как сохранить 1024 слова оверлея

1. **Инвариант:** `load = 1024` для обоих оверлеев, жёсткая граница зоны. Любой рост кода
   **компенсируется сжатием внутри тех же 1024 слов**; «дописать 20 слов в конец»
   невозможно. Не влезает → выносим в `F77LIBR` (новая зона PERSO).
2. **Не «сливать» SYN и GEN:** `LOADANGO` копирует 1024-словное тело как есть по
   `0o22654`, последняя загрузка перекроет первую. Правим исходник на ленте, а не
   статический `build/LO_*.words` (там только последний оверлей).
3. **Нулевой прогон до правок:** собрать неизменные `disasm/LO_*.dtran.madlen`, измерить
   базовый шум симтаблицы. Для `LO*GEN` ожидается 1024/1024 cmd-слов; для `LO*SYN` —
   расхождения не более чем в 25 позициях внутренних целей. Шум больше → стоп.
4. **Источник истины:** аннотированный `src/*.mad`; `disasm/*.dtran.madlen` — производный
   артефакт (регенерируется генератором, не редактируется руками). Строки
   `С--- слово NNNN … машинное слово …` — не символические метки, а побайтовая привязка;
   удалять/менять цифры запрещено (`docs/10-naming-conventions.md` §3.1).

### 3.3 Проверка opcode-поля

Слово БЭСМ-6 = 48 бит = два полуслова `[ИР:3][КОП:6][АДР:15]`. Новый
`tools/compare_opcodes.py` пословно сравнивает 6-битное поле КОП golden vs patched,
**игнорируя АДР**. Критерий: `0 различий вне зон правки`; в зонах правки — только
изменения, перечисленные в `expect_opcode_diff` манифеста. Это устойчиво к перенумерации
меток и ловит реальную семантическую поломку (замену операции), которую скрадывает
«честное сообщение о расхождениях» из `docs/05`.

### 3.4 Homeomorphic mapping меток

`tools/check-label-mapping.py` строит взаимно-однозначное соответствие
`φ: метка(old word N) → метка(new word N)` по номерам слов из аннотаций и проверяет
на неизменённой части (1024 − |patch|):

- `φ` — bijection, порядок сохранён;
- граф переходов (predecessor/successor, call targets) для internal-целей `LO*SYN`
  совпадает: каждое старое internal-target встречается столько же раз, сколько новое;
- нет «висячих» ссылок (ссылка на метку безropathy отображения);
- LINK-ячейки `0o74000..0o74077` и абсолютные адреса `0o4xxxx/0o5xxxx/0o6xxxx/0o77xxx`
  не изменились (сравниваются как обычные слова вне manifest).

### 3.5 Golden SHA и манифест

| Уровень | Артефакт / инструмент | Критерий |
|---|---|---|
| **L0 Golden** | `build/*.gold.bin`, `logs/f77_gold.sha256` | SHA256 эталонов (`LO_SYN` `83a7e962…9366`, `LO_GEN` `4f4d8e4c…cbfd`, PERSO `aab191de…a83`) не изменились |
| **L1 Опкоды** | `compare_opcodes.py` | 0 opcode-различий вне `allow` |
| **L2 Mapping** | `check-label-mapping.py` | bijection + сохранение графа |
| **L3 Регрессия** | `run-forex.sh`, `run-glissade-forex.sh`, 16 сценариев | rc=0, 14/14 строк, без `ОШИБКА/НЕДОПУСТИМ/АТТ/ТИП ОП-ДА` |
| **L4 Manifest** | `check-source-words.py --manifest build/patched/manifest.json` | расхождений вне `allow` = 0; в `allow` — в пределах `expect_word_diff` |
| **L5 Воспроизводимость** | две сборки одного `.madlen` | SHA256 patched-объекта совпадает (версия dispak зафиксирована) |

Формат манифеста (пример для `PRINT *`):

```json
{
  "module": "LO*GEN",
  "golden": "build/LO_GEN.words",
  "patched": "build/patched/LO_GEN.words",
  "allow": [
    {"words": ["0543", "0551"], "kind": "operator-name-table", "reason": "FT*LD1 slot"},
    {"words": ["0710", "0740"], "kind": "inline-codegen", "reason": "PRINT * fast path"}
  ],
  "expect_opcode_diff": 6,
  "expect_word_diff": 14
}
```

**Negative control:** намеренно изменить слово вне `allow` — `check-source-words.py
--manifest` обязан вернуть rc=1.

### 3.6 Порядок шагов правки (сжато)

Golden → нулевой прогон → правка `src/` + регенерация `disasm/` → `*MADLEN` на томе 2348
(критерий: `ДЛИНА LIBRARY <NNN> ЗОН`, `КОНЕЦ ЗАДАЧИ`) → извлечь DMS (`besmtool dump 2348
--start=1280 …`) → подменить `body`/`load` в `build_forex_perso.py` → `install-forex-perso.sh`
(9 или 10 модулей, без `ИСПОРЧЕН`) → L0..L5 → 16 сценариев + 4 новых F77-теста.
Новая запись в каталог PERSO — **только в конец**, после завершителя `0 / FULWORD`.

## 4. План Beach (пошаговый) и трудоёмкость

**BEACH** — локальный мнемонический шифр этапов этого документа (не встречается в
существующих `docs/`): **B**aseline → **E**mulate → **A**ssemble → **C**heck → **H**arden.
Совместим с этапами E0…E5 из `docs/plan-f77/05-decision.md`.

| Этап | Название | Работа | Критерий готовности | Оценка |
|---|---|---|---|---|
| **B0** | Baseline | Зафиксировать golden: SHA `build/*.words`, PERSO, эталонные deck/out 16 сценариев; измерить шум симтаблицы нулевым прогоном | `logs/f77_gold.sha256` неизменен; шум `LO*GEN`=0, `LO*SYN`≤25; регрессия 16/16 | 0.5–1 день |
| **B1** | Probe | Раздельные пробы: `READ *`, `END=`, `ERR=`, `IMPLICIT INTEGER(A-Z)`, typed `IMPLICIT`, unformatted I/O, `nH`, computed GO TO, ASSIGN, REWIND/BACKSPACE/ENDFILE | для каждой — воспроизводимый deck + точная диагностика в `logs/` | 1–2 дня |
| **E1** | Emulate: runtime | `F77LIBR` в зоне `0o2310`: COMPLEX/DP intrinsics, list-directed печать/чтение, EOF-флаг. Регистрация в конец каталога | внешние функции вызываются из обычной FORTRAN-программы; LIBREFER-diff чистый | 2–4 дня |
| **E2** | Emulate: preprocessor | `F77PREP`: IMPLICIT NONE / SAVE → явные объявления и COMMON; `PRINT *` → `PRINT n,FMT`; `4H…` → `'…'`; computed GO TO → IF/GOTO. Source map `C@ orig -> new` | 5 FAIL-проб transforms в поддерживаемый вид; 16/16 регрессия; 0 слов в оверлеях | 3–5 дней |
| **A1** | Assemble: FORMAT | Одна пара `UJ FT*LD1 / ATX 77xxx` + LINK-ячейка (если E2 не покрывает list-directed полностью) | `manifest.allow` только FORMAT; L1/L4 зелёные | 0.5–1 день |
| **A2** | Assemble: LO_SYN | Минимальный spine: 1–2 новых класса лексем + entry в `1517..1777` (только для того синтаксиса, который невозможно lowering-ить) | оверлей ровно 1024 слова; opcode-сверка; L2 bijection; 3 новых теста | 2–4 дня |
| **A3** | Assemble: LO_GEN | Кодогенерация «позвоночника» (5–15 команд inline на конструкцию) + при необходимости 2 слова в таблице `0532..0623` | ноль расхождений вне `allow`; 14/14 Глиссада; 16/16 | 2–4 дня |
| **C1** | Check | Полный прогон L0..L5, negative control manifest, проверка LINK-конфликта и независимости оверлеев (SYN→GEN последовательно) | все критерии §3.5; `ИСПОРЧЕНЫ ПОДПРОГРАММЫ` отсутствует | 1 день |
| **H1** | Harden | Sliding-window сравнение с `*FTN`/`*FORTRAN` (W=3, score≥0.95), контрольные числа Dhrystone/Whetstone, обновление `checklist/STATUS.md`, `docs/15-perso-build.md` | 100% gold-пар; 48/48 прогонов Dhrystone; отдельным коммитом | 2–3 дня |

**Итого по гибридному пути:** ~12–25 рабочих дней, из них **ассемблерная часть (A1–A3)
~5–9 дней**; остальное — Fortran и preprocessor.

**Если настаивать на «чистом MADLEN»** (все 12 групп без F77PREP/F77LIBR): оценка
~400–1000 слов внутри 1024+1024 + перепаковка 29-парной таблицы и полный пересчёт
504 абсолютных ссылок — **практически нереализуемо без полной перекомпоновки оверлеев**
(40–80 дней, неприемлемый риск). Это основание для выбора гибрида.

## 5. Риски и варианты отката

| # | Риск | Вероятность / влияние | Митигация | Откат |
|---|---|---|---|---|
| R1 | Симтаблица: перенумерация меток при пересборке | высокая / средняя | нулевой прогон, L1 opcode-поле, L2 homeomorphic mapping | вернуть `build/*.gold.bin`, пересобрать из неизменённого `.dtran.madlen` |
| R2 | Рост оверлея >1024 слов | высокая / критичная | компиляция в новую зону PERSO; shrinking + manifest; `load=1024` как жёсткая проверка | откат патча, оставить только Fortran-путь (E1/E2) |
| R3 | Перепаковка таблицы `0532..0623` сдвигает 504 абсолютные ссылки | средняя / критичная | **не добавлять пары**; использовать существующие слоты (`FT*002`, `*REWIN`…) | откат к golden `LO_GEN.words`; новая процедура как обычная внешняя функция |
| R4 | Экстракоды `Э20/Э36/Э65/Э67/Э70` не расшифрованы — ошибка в автомате проявится на старом синтаксисе | средняя / критичная | правки только в объявленных manifest-зонах; полная регрессия 16 сценариев | momentальный откат `LO_SYN.words`, повтор нулевого прогона |
| R5 | LINK-конфликт / `ИСПОРЧЕНЫ ПОДПРОГРАММЫ` | средняя / высокая | занять `0o74014..21` / `0o74023..77`; проверить `OCTTDE*`; PLCATALOG | убрать новую запись, перейти на существующий FT*-entry |
| R6 | Нет карты «адрес → имя» для `0o4xxxx/0o5xxxx/0o6xxxx` | высокая / средняя | адреса не переименовывать (`docs/10` §5); только `0o74022→LOADANGO` confirmed | — (контроль L4) |
| R7 | Версионная зависимость: патч 2.02 сломает совместимость с 4.13 | средняя / высокая | не смешивать баннеры; тестировать на одной сборке | откат; зафиксировать версионную оговорку в документации |
| R8 | 6-символьная коллизия имён (P0 gap-анализа) | высокая / критичная (молчаливая неверная программа) | `check-label-length.sh`, `xref_all.py`; имена ≤6, уникальны по первым 6 | переименовать, обновить `include/*.labels.md` |
| R9 | Новая диагностика не помещается (таблица ошибок плотная: `***FOREX ERROR ADDR …` в зонде CHARSTAR) | средняя / средняя | заранее выделить диапазон кодов в `include/FOREX.labels.md` | использовать существующие коды; диагностику вынести в preprocessor |
| R10 | Исходная симтаблица утрачена безвозвратно | низкая / высокая | аннотированные побайтовые исходники + manifest вместо символьной пересборки | вернуть golden-дампы; признать L2 SKIP, но L0/L1/L3/L4 обязательны |

**Общая стратегия отката:** каждый патч — отдельный коммит и отдельный manifest; golden-бинарник
и golden-дампы неизменяемы, patched-артефакты идут в `build/patched/`. Откат = копирование
gold + пересборка PERSO + повтор L0/L3. Если после двух итераций L1/L2 не зелёные —
признаём MADLEN-путь неприемлемым и остаёмся на гибриде E1/E2 (0 слов в оверлеях).
