# 61. Находки: программа выбора транслятора в Мониторе-80 (22.11.2026)

Сводка всех находок по вопросу «как Монитор-80 определяет вызов нового
транслятора и где он лежит». Исправляет более ранние ошибочные выводы F1
(см. `logs/f77_30_60_f1_monitor80_search.txt` с исправлением в конце).

## 1. МАДЛЕН-исходник ЕСТЬ (нашёл главный агент)

Программа называется не `NEWCOMP*`, а **`GIVTRAN*` / `SETTRAN*` / `TTABLE*`**:

- `monitor80-re/permanent/givtran%.asm` (43 строки) — полный МАДЛЕН-исходник:
  - `GIVTRAN*: , NAME,` — "Монитор-80" ИАЭ;
  - `TTABLE* : , SUBP,` — таблица трансляторов;
  - `SETTRAN*: , ENTRY,` — точка входа (вызывается из `star%.masm:118`:
    `M13, VJM, SETTRAN*`);
  - логика: `XTA MONCARD*` (карта `*TRANS`) → `M14, VTM, TTABLE*` (чтение
    таблицы) → `AEX для*тип*трн` (сравнение) → `UZA в*STACOMP` →
    `UJ STACOMP*`.
- `monitor80-re/permanent/ltable%.asm:37-38`:
  ```
  , ISO ,6Н*TRANS
  , TEXT,8НNEWCOMP*  .+
  ```
  это продолжение таблицы `TTABLE*`: `*TRANS` maiden'ится в `NEWCOMP*`.
- `monitor80-re/permanent/star%.masm` (STAR*, «новые транслиторы»):
  `SETTRAN*: , SUBP,` (строка 32), `TRCAT*: , LC ,17` (каталог трансляторов).

**Вывод:** F1 ошибался, ища файл по имени `NEWCOMP*`; исходник — `givtran%.asm`.

## 2. Скомпилированный бинарник на диске

- диск `/usr/local/share/besm6/2048`, **зона `0o422`**, слова `0o777..`;
- файловые смещения `0x2315b8..` (формат: 1032×uint64 LE, зона+4, заголовок 64 байт);
- первые 7 слов совпадают с RAM `0o3000..0o3006` байт-в-байт;
  (`0042001500030017 0036011200360066 0040001356502000 ...`);
- остальные слова при загрузке трансформируются (полного 64-словного
  непрерывного совпадения нет);
- дизассемблинг `reference/m80/NEWCOMP_zone422.dis` (disbesm6; слова `0o770..0o1007`
  — данные/TEXT, код от `0o1010`); сырая зона `reference/m80/zone422.bin`.

## 3. Элемент, формирующий VJM-слово (E1)

- источник: RAM `0o36621` ← диск 2048, логич. зона `0o227`, слово `0o621`;
- в файле (8-байтовые uint64 LE) смещение `0x139388`, байты `00 00 09 02 80 dc`;
- рантайм-цикл `0o64415..0o64427` собирает из него слово по RAM `0o455`:
  `6710000202200000` = `vjm 64002(15)`;
- two-byte patch `0x13938b/0x13938c: 02 80 → f8 9b` даёт
  `6711577002200000` = `vjm 1770(15)` на непатченном dispak (E1,
  `logs/f77_30_59_e1_binary_patch.txt`);
- блокер: RAM `0o1770` пуст в момент первого VJM; trampoline в зоне `0o201`
  дал `КОНТРОЛЬ КОМАНДЫ`, пробовать зону `0o207`.

## 4. Быстрая правка таблицы TTABLE на диске (рекомендация пользователя)

Пользователь указал: **патчить таблицу `TTABLE` прямо на диске — как вариант
быстрой правки**. Это проще, чем патч кода/монитора:

- `TTABLE*` читается `SETTRAN*` (`M14, VTM, TTABLE*` в `givtran%.asm`), её
  отображение `ltable%.asm` задаёт `*TRANS → NEWCOMP*`;
- нужно найти физические слова таблицы на диске 2048 (зоны каталога
  трансляторов) и заменить имя `NEWCOMP*` на имя нашего модуля — тогда
  `*TRANS:...` выберет его без правки кода загрузчика;
- точные смещения TTABLE на диске ещё не определены — следующий шаг.

## 5. Ограничение на правки (пользователь)

`docs/corrections.md` (коммит `ce7fab3`): **dispak править только если в нём
не реализована функция/экстракод**; во всех остальных случаях — задача
пользователя, включая монитор‑80. Поэтому C3-патч `cu.c`/`defs.h` — только
доказательство механизма, не целевое решение; целевое — бинарный патч
монитора/таблиц на диске.
