# План 59. Автономное тело компилятора для `*TRANS`

## 0. Постановка

M4d (`bc0c7da`) доказал FULL-вызов: `*TRANS:OURMRK*,,411744` печатает наш
маркер `M4D-O412B-MARK`, но тело для зон `N+2..` заполняется **живыми
оверлеями 4.12** (LO*SYN/LO*GEN). Значит компиляция всё ещё выполняется
чужим кодом. Цель плана 59 — заменить чужие оверлеи **нашим телом**, чтобы
наш компилятор был полностью автономным при вызове через `*TRANS`.

## 1. Что уже есть (фундамент)

- `src/newcomp/O412B.FTN` — Fortran-эмиттер каталога+префикса тела (30 слов, PASS);
- живой 4.12 баннер и рецепт: `tests/plan-f77/t412/run-4.12.sh`;
- точная точка входа M80 NEWCOMP*: `pc=0o00455 VJM 0o64002`;
- `f0` = поле дескриптора (маска `0o7777`, XOR с `0o1760`), f1/f2/f3 → INF-слово
  (`0o660..0o674`), зона тела `N+1`;
- B5 (`UIA 1760(M16)/UJ 464`) — данные загрузчика (не код);
- реконструкции 4.12: `reference/412/disk412_{forex3_root,lo_syn,lo_gen}.words`;
- наш Fortran-эмиттер слов `src/newcomp/EMIT.FTN`, кодогенератор BASE77
  (N3: 18 слов), front-end `FRONT.FTN`.

## 3. Риски

- **Многословность:** живой 4.12 корень имеет `cmd=0o1760` (~1000 слов кода) + 38 зон; наш autonomный модуль может оказаться сравнимым по размеру. Тогда A3/A4 требуют полноценного Fortran-компилятора, что выходит за рамки 30 слов.
- **LINK-схема:** внешние SUBP `FT*003/FT*571/PRINT8` должны решаться через монитор (2048), а не через PERSO; нужно проверить, доступны ли они в `*TRANS`-пути.
- **Точка входа:** `VJM 0o64002` может указывать внутрь загрузочной таблицы, а не на пользовательский код; требуется трасса для точного определения.

**ВЫВОД:** наш скомпилированный код РЕАЛЬНО исполняется через пропатченный `*TRANS`
Монитора-80. Для полной замены компилятора остаётся заменить саму логику
компиляции (наш CODEGEN/FRONT вместо резидентного 4.12) — но механизм вызова и
исполнения нашего кода доказан.

## 5. Финальный вердикт плана 59

**Цель «наш компилятор вызывается как 4.12» достигнута ФОРМАЛЬНО** (каталог,
дескриптор, имя `OURMRK*`, баннер, `*TRANS` работают; все слова тела генерируются
нашими Fortran-эмиттерами, A/B замкнуты). **НО по существу компиляцию выполняет
резидентный FOREX 4.12**: `*TRANS` — это загрузчик компилятора, а не путь
исполнения пользовательского тела. Полная автономия (наш код реально компилирует)
через `*TRANS` **невозможна без замены резидентного компилятора в мониторе**,
что запрещено (монитор не трогать). Честный путь для будущего: обычная загрузка
`N`/`*CALL` (где наш код исполняется, N2/N3 доказано) или отдельный mini-loader,
но это уже НЕ `*TRANS`-путь.
