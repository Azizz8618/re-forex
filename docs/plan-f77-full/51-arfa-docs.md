## 1. Э63: полная семантика экстракода обращения к архивной системе

### 1.1 Механика вызова и РМР

`Э63 АИСП`, на СМ предварительно `’КЛЮЧАР’` в коде УПП
(`sysprog:2724-2733`; дубль в `tyurin1985-full.txt:19261-19271` — там ещё
`СЧ ЯЧРМР / НТЖ 0`, то есть РМР готовится через младшие разряды).

```
Э63 АИСП
СМ = в'1242547515620060'   ; 'КЛЮЧАР'
РМР = параметры операции
АИСП -> адрес нулевого информационного слова (ИС)
```

Диспечеризация (по `ai/справочник_Э63_информационные_слова.md:19-70`,
основано на `disp70.be:321-323`, `khlam.be:2324-2363`, `arfa.be:6-13,179-186`):

* вектор `513в`;
* `СМ == 'КЛЮЧАР'` → архивный путь: ХЛАМ проверяет принадлежность ИС памяти
  задачи, загружает нерезидент АРФА, вход `ВХАР`, разбор `сч (М16)`;
* `СМ != 'КЛЮЧАР'` → РЕСУРС: малый АИСП 0..4 = функции времени,
  АИСП ≥ 10в = запрос содержимого физической ячейки ОЗУ.

После завершения М16 = 0 при успехе, иначе код ответа; содержимое СМ, РМР
младших разрядов и группы операций **не определено**, если не оговорено
(`sysprog:2819-2823`; `programmer:1996-2001`).

### 1.2 Структура информационного слова (ИС)

`sysprog:2737-2745`, `programmer:6817-6829`, `ai/справочник_Э63…:90-111`:

```
48-43 Р — тип работы
42-37 Р — виртуальный (логический) номер
36-25 Р — пароль (12 разрядов = 4 восьмеричные цифры)
    12 Р — признак чтения
  4- 1 Р — характеристика имени (способ задания имени)
```

Все неописанные разряды должны быть нулевыми, иначе авост
`ОШ.В ИНФ.СЛ.ЭКСТ` (`programmer:1992-1994,6427`, `sysprog:2829-2830`).

Ключевое правило для экстракодов, работающих и с виртуальным номером, и с именем:
**либо 42-37 = 0, либо 4-1 = 0**; если оба нуля — это способ 4
(34-разрядный идентификатор в ИС+1) (`sysprog:2814-2817`;
`ai/справочник_Э63…:123-124`).

### 1.3 Способы задания имени и смысл `010 / 014`

По `programmer:6383-6387` (идентично в `:6453-6459,6530-6531,6607-6608,6682-6683,
6754-6755,6821-6828,6893-6894,7003-7010,7078-7085` и т. д.):

| `4-1 Р` (восьм.) | Значение |
|---|---|
| 0 | имени нет: область задана логическим номером в ИС **или** 34-разрядным идентификатором в ИС+1 |
| 1..7 | число простых имён, имя «по-старому» |
| **10в** | имя «по-новому» в коде **УПП (ГОСТ)** |
| **14в** | имя «по-новому» в коде **МС-80** |

Восемь/двенадцать в десятичной — **не** «десять/четырнадцать». Поле имеет
4 разряда (`ai/справочник_Э63…:41` — маска `r&017`), поэтому максимальное значение — `17в`.

Представление имён (`programmer:2024-2041`):

* «по-старому»: каждое простое имя — два слова; ИС+1 = символы 1..6,
  ИС+2 `48-25` = символы 7..9, ИС+2 `24-1` = **шифр хозяина** первого
  простого имени (в следующих словах там нули);
* «по-новому»: текст в ИС+1, ИС+2, … (до 17в слов, по 6 символов на слово,
  `ai/справочник_Э63…:134-139`); символ `143в` (УПП) / `000в` (МС-80)
  игнорируется; терминатор `;` или `377в` (УПП), `012в` (МС-80);
* шифр хозяина — 6 цифр в двоично-десятичном, `.` = код `16в` в тетраде.

Рабочий пример из системы: `perekh.be:1775-1778` →
`ИНФСТ = в'0700000000000010'` (тип 07, способ `010в`, имя `АРФА.ПЕРЕХВАТ`)
(`ai/справочник_Э63…:140-146`; `30-arfa-filesystem.md:147-155`).
Наши рабочие константы из `31-fortran-arfa-bridge.md:58-75`:
`ИС тип 12 = 12510000 00000010` (тип 012в, LUN 051в=41₁₀, способ 010в),
имя `14422510 14406004 / 00204411 02204777` = `TEST/419999` + `377в`.

**Расхождение в документации (важно):** `sysprog:2747-2812` и
`tyurin1985-full.txt:19282-19320` описывают **3 или 4 «способа»** иначе:
1) `4Р=0, 3-1Р=число уровней`; 2) `4Р=1, 3-1Р=0` (текст в коде УПП,
`143` — пустой символ); 3) `4-1Р=все единицы` = ISO; 4) идентификатор.
Там нет явных `10в/14в`, а «все единицы» (`17в`) proclaimed как ISO.
`ai/справочник_Э63…:121` помечает это ⚠ «проверить». Практический вывод:
**описание `programmer` §5.2/§5.3 и реальные константы ОС/PERSO согласованы
между собой (`010в`/`014в`), а формулировка `sysprog` §8.7.1.1 устарела
или содержит опечатку в адресации имени.** В МАДЛЕН-движках используется
именно `010в`; `014в` эмулятором не поддержан
(`31-fortran-arfa-bridge.md:46`) и дал бы код 2/авост, а не повтор.

## 2. Имена, шифры, ключи и пароли

### 2.1 Можно ли создать область `TEST/419999` из задачи с шифром 410300?

**Да, технически можно, но бесполезно.** Дословно:

> «При выполнении экстракода из бюджета пользователя, выдавшего экстракод,
> создается область с заданными параметрами. В общем случае **шифр хозяина
> области может не совпадать с шифром бюджета; при этом пользователь,
> создавший область, не сможет с ней работать**. Если это было сделано по
> ошибке, то лишь администратор бюджета может уничтожить эту область.»
>
> — `Dispak-programmer-guide.md:6373-6377`; идентично для директивы `НОВ`: `:1130-1135`

Если шифр хозяина в имени не совпадает с шифром задачи, АРФА ищет область
по цепочке (`programmer:871-897`):

```
PROGRAM/661313   (шифр задачи)
PROGRAM/6613..   (библиотека группы: 4 цифры шифра + '..')
PROGRAM/660099   (библиотека отдела: 2 цифры отдела + '0099')
PROGRAM/999999   (общая библиотека)
```

`419999` **не входит** в эту цепочку для шифра `410300`: group library была бы
`4103..`, department — `410099`, common — `999999` (по умолчанию).
Следовательно, при шифре задачи 410300 жёстко заданное имя `TEST/419999`
будет или не найдено (код 1), или найдено, но доступ запрещён (код 5/23),
если область реально существует с другим хозяином. В рабочих прототипах
задача шла **под шифром 419999**, поэтому хардкод и работал:
`31-fortran-arfa-bridge.md:60,90` и `36-besm6-deck-runner.md:58,63`
(«419999 — это системный», шифр задачи по умолчанию `410300`).
См. также `tyurin1985/ocr/page-0308.txt:57-65` — «общий шифр»,
рекомендуемое значение `999999`, настраивается при генерации;
`tyurin1985/ocr/page-0309.txt:71` (`ОБЩИЙ ШИФР — 6 ЦИФР и/или ТОЧЕЮ`).
То есть 419999 **может** быть локально сконфигурированным общим шифром,
но в документации рекомендован 999999; подтверждения, что на нашей машине
настроен именно 419999, в прочитанных документах нет.

### 2.2 Что такое «шифр хозяина», «пароль», «ключ администратора»

| Понятие | Определение по документации |
|---|---|
| **Шифр хозяина** | первые 6 цифр шифра пользователя ОС; любая цифра может быть `.` = произвольная (`programmer:859-867`; `description:1368-1372`). Хранится в `ИС+2 24-1` при имени «по-старому» (`programmer:2028-2030`). Для Э63/01 — обязателен (`programmer:6364`). |
| **Пароль области** | 4-значное восьмеричное число; есть пароль на чтение и на запись (`programmer:934-939`; `tyurin1985/ocr/page-0307.txt:38-44`). В ИС — поле `36-25` (12 разрядов), новый пароль — `24-13` (`sysprog:2902-2910`). Даже хозяин обязан подтвердить пароль. |
| **Ключ администратора** | шестисимвольный пароль администратора **бюджета**, задаётся директивой `АДМИН Ш=<ШИФР БЮДЖЕТА>[,К=<КЛЮЧ>]` (`programmer:1585-1600`); нулевой ключ = отсутствие ключа (`:1594-1595`). В Э63/16 — ИС+1 `48-1` в УПП (`sysprog:3099-3102`); в Э63/17 — новый/старый ключ в ИС+1/ИС+2 (`:3109-3113`). Неверный ключ = фатальный авост `НЕВЕРНЫЙ ПАРОЛЬ` (`programmer:1617-1621`). |

После создания области правом доступа обладает **только её хозяин**
(`programmer:924`); список доступа — до 6 шифров с правами

## 3. Дозаказ области по имени (тип 12) и зачем он перед Э70

`sysprog:3034-3049` и `programmer:6977-7051`, дубль в
`tyurin1985-full.txt:19461-19476`.

```

     42-37 = виртуальный номер области
              или 0 — взять первый свободный из шкалы РМР
```

(`programmer:8461-8495`), и «основная группа экстракодов по виртуальным
номерам работает точно так же, как если на виртуальный номер заказан диск»

## 4. Что АРФА делает с носителем: запросы, ожидание, таймауты

### 4.1 Уровень паспорта (до старта задачи)

* Область доступна, только когда она на **первичном** носителе; на вторичный
  «выталкиваются» давно неиспользуемые области (`programmer:831-838`;
  `description:1374-1382`).
* При обработке задачи архивом для каждой заказанной в паспорте области
  определяется том; оператор видит его через `СКВ` и `УСТ`
  (`programmer:1555-1557`).
* Если область на неустановленном томе, вытолкнута на вторичный том, или
  находится в монопольном владении — `СКВ` показывает
  **`ЗАПР.АРХ`**: «архивная система запрещает включение задачи в решение»
  (`programmer:1546-1562`; `operator:880-891`, `:2727-2730`).
* Если область несуществующая/каталог — задача **выбрасывается** с
  диагностикой `НЕТ ОБЛАСТИ <ИМЯ>` (`programmer:1524-1531`;
  `tyurin1985/ocr/page-0312.txt:39-44`). Нет прав —
  `НЕСАНКЦИОНИРОВАННЫЙ ДОСТУП` (`:1534-1544`; `page-0312.txt:46-52`).
* При прямом заказе **физической бобины** в паспорте (наш случай
  `дис 45(2048)^`) причина простоя — **`НЕТ Б <N БОБИН>`**:

  > «Из-за отсутствия заказанной в паспорте бобины задача не выбирается
  > программой-планировщиком в рабочую смесь системы.»
  > — `operator:2496-2511`; список причин в `operator:880-891`.

  Аналог `ЗАНЯТ Б<N>` — «Сразу же после освобождения данной бобины задача
  выбирается в решение» (`operator:2118-2133`).
* Директива `УСТ` печатает требуемые бобины; знак `+` означает, что бобина
  установлена (`operator:737-765`).

### 4.2 Уровень решения (Э63 / Э70)

* `Э63 12` возвращает `12 НЕ УСТАНОВЛЕН ТОМ` или `26 ИДЕТ ВТАЛКИВАНИЕ`
  (`programmer:7037-7039`); это **код ответа**, а не ожидание.
* `Э63 14/15` работают со сдвигом; `Э70` — обмен зонами. Ни в одном описании
  Э63/Э70 нет «запроса ленты» или таймаута.
* Запрос на установку тома из *программы* описан в `sysprog:3287-3306`:
  `ИР 050 А`, `АИСП = 1206в`, на СМ (1-16 Р) номер тома в дв.-десят. виде,
  индекс-регистр 3 = код `71717`; на терминал выдаётся
  `УСТ.СР.К.N БХХХХ`. Если том уже установлен — СМ содержит его номер в
  восьмеричном виде, запроса на терминал нет; иначе СМ=0 и выдаётся запрос.
  Проверка наличия тома — `ИР 050`, `АИСП = 110в` (`sysprog:3315-3330`).
* В Tyurin: `(2) УСТАНОВИ МД АРХ` и `(5) УСТ. CPY.K20B(HOMEP TOMA)` —
  «сообщение об отсутствии архивного тома» (`tyurin1985/ocr/page-0312.txt:25-29`);
  `(2) ПРОВЕРИТЬ ПАРАМЕТРЫ АРХ.` — нет параметров на системном диске 2053
  (`page-0312.txt:20-23`); `(2) АРХИВ ЖДЕТ` — заблокировано `НЕТ АРХ`
  (`page-0312.txt:54-59`).
* Для упрятывания: `ДЛЯ УПР/ВОС УСТ.СРОЧНО ТОМ <N>` — нет архивной бобины
  (`operator:1936-1959`), причина `НЕТ АРХИВА` в `НЕТ УПР/ВОС`
  (`operator:2527,2539-2547`).

### 4.3 Про «ЗМЛ» и таймауты — важное уточнение

* В документации ре-диспак **`ЗМЛ` = «замятие»** перфокарты/перфоленты при
  вводе, сообщение вида `ЗМЛ-<M УСТРОЙСТВА>` (`tyurin1985-full.txt:13287`,
  OCR `page-0234.txt:65-71`). Это **не** «запрос магнитной ленты» и не
  имя сообщения об ожидании носителя.
* В наших логах `ЗМЛ0 410300000000` / `ЗMB0 419999000000` — это
  транслитерированное сообщение приёма задачи; в
  `40-hang-repro.md:60` прямо сказано: «только `ЗMЛ0 …`, `B075` НЕТ, PC 04440
  — лента не читается как карты». То есть «ЗМЛ0» — метка приёма колоды,
  а не документированное сообщение АРФА.
* Числовые таймауты в документации встречаются только три:
  1. **2 минуты** — «в течение 2 минут после постановки заказа на
     упрятывание … не удалось инициировать процесс» → `ДИСПАК ПРОТИВ`
     (`operator:2538`);
  2. **10 минут** — «не позднее чем через 10 минут после [ДАЙ АРХ]
     архивная система начнет работу» (`sysprog:1363-1367`);
  3. «повторно через некоторое время» для `СЛУЖЕБНЫЕ РАБОТЫ`
     (`programmer:7039`) — без числа.
  Ни один не является таймаутом ожидания бобины планировщиком:
  документация описывает это ожидание как **бессрочное**.

## 7. Гипотезы

### 7.1 Причина зависания (ранжированы по подтверждённости документами)

**H1 (наиболее вероятная, совпадает с `40-hang-repro.md:20-29,111-113`).**
Паспорт просит физический том `2048` на канале 45 (`p7ct.txt~:5`, по
`42-arfa-hang-analysis.md:139,154`), а в конфигурации на этом канале стоит
образ `2348`. По `operator:2496-2511` задача не выбирается планировщиком и
висит на буфере ввода с причиной `НЕТ Б 2048` (`operator:880-891`). `B075-1`
— подтверждение приёма колоды, значит Э63/Fortran ещё не исполнялись.
Документация **не знает таймаута** для этого состояния, поэтому «вечное»
ожидание ожидаемо. Дополнительный фактор: диск 2048 в эталоне — архивный
(`compat-guide:45-52`) с областью `РЕЖСОВМ` (`sysprog:1377`), то есть прямой
заказ его как `дис` — по меньшей мере нестандартная форма заказа; по
`tyurin1985-full.txt:7087-7089` это вообще должно дать фатальный авост
(жёсткость противоречия с `compat-guide:49` требует проверки на конкретной
версии ОС).

**H2.** Архивная система не в решении (`НЕТ АРХ` / `АРХИВ ЖДЕТ`,
`sysprog:1363-1367,1649-1657`; `operator:891`), и задача, так или иначе
связанная с архивом, не выбирается. Диагностируется директивой `РЕЖ` →
`АРХИВ ОТКЛ.` Документы не позволяют исключить это без проверки на машине.

**H3.** PERSO-директива `*personal library:452300/:452320` указывает в зоны,
где на томе 2348 наших `ZF*` нет (`42-arfa-hang-analysis.md:140`). Это не
даёт зависания само по себе (это лишь отказ при трансляции/загрузке), но если
задача всё же дойдёт до исполнения, CV не будут получены.

**H4 (менее вероятная, опровергается документами).** «Э63 с битом имени
`010/014` уходит в бесконечный retry». Документация описывает только один
повтор — `СЛУЖЕБНЫЕ РАБОТЫ` (`programmer:7039`), и он адресует программе,
а не ядру; неверный способ имени даёт код 2/авост, а не повтор. См.
`42-arfa-hang-analysis.md:94-122`.

**H5 (противоречие в предыдущих отчётах).** `43-operator-cmds-hang.md:119-133`
утверждает, что после `B075-1` СчАС пробегает по кодам `0666xx/074776/021211`
и машина «активно исполняет FOREX-трансляцию», а не простаивает;
`40-hang-repro.md:76-99` трактует те же `066642/066643` как спин
планировщика. Оба отчёта согласны в одном: **это код ОС, не наш Fortran-мост**.
Разрешить противоречие без запуска эмулятора и без чтения исходников
невозможно; в отчёте фиксирую как открытый вопрос.

### 7.2 Хардкод `419999`

* Это **системный/рабочий шифр** в этой сборке: `36-besm6-deck-runner.md:58,63`
  явно говорит «419999 — это системный», а по умолчанию для задач — `410300`.
  В исторических рабочих колодах шифр был `419999` (`31-fortran-arfa-bridge.md:90`,
  `tyurin1985/tyurin1985-full.txt:18893`).
* Область `TEST/419999` была создана на копии 2249 с ARFA-flag
  (`31-fortran-arfa-bridge.md:6-8`), откуда и хардкод в МАДЛЕН-движках.
* По `programmer:6373-6377`, формально создание области с хозяином 419999
  из бюджета 410300 возможно, но **дальнейшая работа с ней невозможна**
  без прав/пароля; по `programmer:871-897`, `419999` не входит в стандартную
  цепочку поиска хозяина для шифра 410300.
* По сравнению с документацией: рекомендуемый «общий шифр» — `999999`
  (`sysprog:1408`, `tyurin1985/ocr/page-0308.txt:57-65`), настраивается при
  генерации (`page-0309.txt:71`), так что 419999 — локальная привычка,
  а не требование ОС.
* **Вывод:** хардкод нужно либо убрать (передавать имя из Fortran,
  см. `34-arfa-lowering.md:112`), либо запускать задачу под шифром 419999,
  либо выдать права через Э63 04 / `ПРАВА` для 410300. Но это **не**
  причина текущего зависания, потому что Э63 ещё не вызывался
  (`42-arfa-hang-analysis.md:10-33`).
