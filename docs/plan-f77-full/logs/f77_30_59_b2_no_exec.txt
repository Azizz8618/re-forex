- `DO 10 I=1,6` → консоль ` 21 1.00 3.00`
- `DO 10 I=1,5` → консоль ` 15 1.00 3.00`

**НО:** вычисление делает **резидентный компилятор 4.12 из обычного Fortran-исходника в деке**,
а не наши машинные слова, вставленные в тело зоны N+1. Попытка A5prep вставить арифметику
в тело — **принципиально неworking**: наши слова тела **никогда не исполняются как код**
(см. §2–3). Это и есть точный ответ на «почему цикл идёт один раз»: он **не идёт вообще**.

## 1. ВОСПРОИЗВЕДЕНИЕ И ФАКТЫ ПРО `*TRANS`-БАННЕР

Харнесс: копия `a3core.py`/`a5mtr.py` из `59-a5prep`, 25 слов `a5_seq_body.bin` в теле со
слова **9**, зоны N+3..N+40 обнулены (`--zero-from 2`), зона N+2 живая, каталог O412B.
Deck (из `a3core.py`) содержит `PROGRAM MAIN / PRINT 100 / FORMAT('M4D-O412B-MARK') / END`.

**ФАКТ 1.** `runs/a5_seq_1/out.txt`: ` 21 1.00 3.00`, хотя deck печатает `M4D-O412B-MARK`.
Подмена FORMAT в деке на `DECKDECKDECK` (`runs/a5_seq_1/deck_mod.b6`, `out_mod.txt`) —
вывод **не меняется**. Значит строка comes из нашего тела, не из дека.

**ФАКТ 2 (A/B, уточнение отчёта A5prep).** Настоящиеvariant'ы, проверены побайтово:

| опыт | что обнулено | консоль |
|:--|:--|:--|
| `a5_seq_1` | — | ` 21 1.00 3.00` |
| `a5_seq_no64` | `body[18]` (наша `*64`) | только `КОНЕЦ ЗАДАЧИ` |
| `a5_seq_nostart` | `body[9]` (первое слово арифметики) | **` 21 1.00 3.00`** |
| `a5_seq_nodesc` | `body[20]` (дескриптор) | только `КОНЕЦ ЗАДАЧИ` |

То есть A5prep ошибочно заявил, что «все три группы слов в исполняемом пути»:
`body[9]` (арифметика) **не влияет на печать**. Печать управляется только
`body[18]` + `body[20]` + GOST-словами `body[22..24]`.

**ФАКТ 3 (изменение GOST).** Замена двух байт в `a5_seq_body.bin[13]` (= `body[22]`):
`0040041700207000` → `1603441700207000` даёт ` ШЩ 1.00 3.00` (`runs/a5_core_diff/out.txt`).
GOST-байты слова (проверено побайтово): `body[22]=[2,1,15,1,14,0]` = `21 1.`,
`body[23]=[0,15,3,14,0,0]` = ` 3.00`, `body[24]=[153,15,15,15,15,15]` = `0o231`+пробелы.

**ФАКТ 4 (CORE DIFF — решающий).** Дампы ядра (192 КБ = полные 32K слов) на PC `0o3155`
(Print-цикл `*60`) и на PC `0o06150` (поздний участок) для эталона и варианта с изменёнными
GOST-байтами **побайтово IDENTICHNY** (0 отличий во всех 32768 словах). Более того:
последовательность GOST-байт `[2,1,15,1,14,0]` **не найдена ни по одному адресу ОЗУ**
(только слово `body[24]` случайно совпадает с общим хвостом `0o231`+пробелы по `0o3342`).

**ВЫВОД (ФАКТ):** `*TRANS` читает GOST-строку баннера **непосредственно из зоны N+1 на диске**,
не загружая её в ОЗУ как исполняемый/данный код. Наши machine-слова в зоне N+1 **не копируются
в RAM и не исполняются** — они лишь «ленточка» для built-in печати баннера `*TRANS`.

## 2. ТОЧНАЯ ТРАССА: ЧТО ИСПОЛНЯЕТСЯ ПО PC 0o1770..0o2001

`BESM6_MTR_LO=1770 HI=2040 N=5000`, `runs/a5_seq_mtr3/trace.err` (формат строки из
`strings dispak`: `MTR %05o%c %-6s %o(%o) AU=%013llo` — адрес **восьмеричный**).

```
MTR 01770L ita    15(0)      ; expected 'сч 0o2014' → НЕТ
MTR 01770R utc    2050(0)    ; expected 'зп 0o2010' → НЕТ
MTR 01771L atx    2050(0)
MTR 01771R xta    0(0)
MTR 01772L atx    2237(0)
MTR 01772R xta    73(0)
MTR 01773L asn    134(0)
MTR 01773R utc    2047(0)
MTR 01774L aax    2047(0)
MTR 01774R utc    2051(0)
MTR 01775L atx    2051(0)
MTR 01775R asn    44(0)
MTR 01776L aex    73(0)
MTR 01776R atx    73(0)
MTR 01777L uza    2001(0)    ; переход — но это НЕ наш back-jump
MTR 02001L vtm    2261(16)   ; НЕ наша *64 (наша была 0064200302200000)
MTR 02002R vjm    2435(15)   ; уход в резидентный код
```

Декод слов ОЗУ по макросам `Lopcode/Laddr` из `besm6-legacy/dispak/defs.h:134-161`
(сделан скриптом в отчёте) показывает:

| RAM | наше слово (ожидание) | Decoded | слово реально в RAM (core) | Decoded |
|---:|:--|:--|:--|:--|
| 0o1770 | `0010201400002010` | op=10 adr=2014 / op=00 adr=2010 | `0042001502202050` | op=42 adr=15 / struct op=20 adr=2050 |
| 0o1771 | `0010201500002011` | op=10 adr=2015 / op=00 adr=2011 | `0000000000100000` | op=00 adr=0 / op=10 adr=0 |
| 0o1772 | `0010201000042011` | op=10 adr=2010 / op=04 adr=2011 | `0000223700100073` | op=00 adr=2237 / op=10 adr=73 |
| 0o1775 | `0005201602701772` | op=05 adr=2016 / **struct op=70 adr=1772** | `0000000000360044` | op=00 adr=0 / op=36 adr=44 |
| 0o1777 | `0010201200042020` | op=10 adr=2012 / op=04 adr=2020 | `0260200172402033` | op=60 / op=40 |

Ни одного совпадения — **траснформированных копий наших слов в ОЗУ нет**. По PC 0o1770
исполняется **резидентный код 4.12** (comparison с `ref/disk412_forex3_root.words` и
A2 REPORT.md §1 подтверждает: первые слова 0o1760+ —TEXT `MONITOR*`/шапка 4.12).

### Почему «цикл executedsя один раз»
**ГИПОТЕЗА A5prep (ранг 2) ОПРОВЕРГНУТА.** Дело не в back-jump `0o1772` и не в счётчике.
Наш back-jump word `0o1775` (`...02701772`) **не исполняется вовсе**. `uza 2001(0)` в трассе —
это переход внутри живого кода 4.12. Счётчик N/I в наших данных (RAM 0o2010/0o2011) не меняется,
потому что наши `сч/зп/сл` никогда не исполняются. therefore вывод статический.

**Точное правило «трансформации» (ФАКТ):** это не перестановка битов/релокация field'ов, как
предполагалось. `*TRANS` **вообще не загружает тело зоны N+1 в исполняемую память**; он
(1) читает каталог N, находит имя, (2) берёт баннер-GOST из зоны N+1 и печатает его,
(3) передаёт управление резидентному компилятору по `VJM 0o64002` (A2 REPORT.md §2).
Отсюда «ни одно слово не встречается дословно» (A2 §1) — наши слова просто не являются
теми словами, которые populate RAM.

и дать компилятору настоящий Fortran-исходник в деке. Харнесс: `a3core.py a5_nopatch_compute`

Deck (`deck_exact3.b6`):

```
шифр 419999 зс5^

*TRANS:OURMRK*,,411744
      PROGRAM MAIN
      N=0
      DO 10 I=1,6
   10 N=N+I
      X=1.0
      Y=X+2.0

``````
ЕКОНЕЦ
```

Консоль (ФАКТ, `out_deck_exact3.txt` / `out_deck_exact5b.txt`, rc=0):

```
   DO 10 I=1,6  →  21 1.00 3.00
   DO 10 I=1,5  →  15 1.00 3.00
```

**A/B замкнут в обе стороны по строке `DO 10 I=1,6/5`.** ЗначенияbI вычислены (N=21=1+..+6,
N=15=1+..+5), X/Y из арифметики. Дополнительно с `FORMAT(I2,1X,F4.2,1X,F4.2)` и bound=6
получается **точная** строка `21 1.00 3.00` (без ведущего пробела); с bound=5 FOREX-форматтер
I2 глючит и печатает ` 5` вместо `15` (баг форматтера I2 для двузначных чисел), поэтому для
A/B корректнее I3.

Контроль: с **нашим** телом (`a5_basecomp`, `a5_seq_body.bin`) тот же computing-deck даёт
только статический баннер ` 21 1.00 3.00` (независимо от bound) — наша подмена тела ломает
путь компиляции. То есть «или баннер из тела, или вычисление из дека», не одновременно.

## 5. ЭКЗАКТНЫЕ СЛОВА И ЭМИТТЕР (что отдать в main agent)

### 5.1 Статический баннер (A5prep level 4, проверен)

25 слов в зоне N+1 со слова **9** (`a5_seq_words.txt`, `a5_seq_body.bin`). Рабочая подGROUP:

| body | RAM | слово (8) | роль |
|---:|---:|:--|:--|
| 18 | 0o2001 | `0064200302200000` | `*64` → дескриптор 0o2003 (обязательно) |
| 19 | 0o2002 | `0000000067000000` | возврат |
| 20 | 0o2003 | `0000200500002005` | дескриптор w0: addr0=addr1=0o2005 |
| 21 | 0o2004 | `0001000040000000` | w1: fmt=0, off=1, final=8 |
| 22 | 0o2005 | `0040041700207000` | GOST байты `2,1,15,1,14,0` = `21 1.` |
| 23 | 0o2006 | `0000740303400000` | GOST байты `0,15,3,14,0,0` = ` 3.00` |
| 24 | 0o2007 | `4620741703607417` | `0o231` terminator + пробелы |

A/B: обнуление `body[18]` или `body[20]` убирает печать; `body[9]` — нет.

### 5.2 Для вычисляемого вывода (рекомендация)

Эмиттеру **не нужно** генерировать 25 слов с арифметикой в теле. Достаточно:

1. Оставить каталог/тело O412B **нетронутыми** (живой 4.12 + зоны N+2 живые,
   N+3..N+40 можно нулить).
2. Генерировать в деке Fortran:
   ```
   N=0
   DO 10 I=1,<BOUND>
10 N=N+I
   X=1.0
   Y=X+2.0
   PRINT 100,N,X,Y
100 FORMAT(I3,1X,F4.2,1X,F4.2)
   ```
3. `<BOUND>` — параметр эмиттера (6 → `21`, 5 → `15`). Это и есть «малый форматтер»:
   `I3` для целого N, `F4.2` для вещественных X/Y, всё через системный `FT*003/FT*571`
   (доступны в обычном пути компиляции; LINK-ячейки в `*TRANS`-пути не патчатся — LINK REPORT.md,
   но здесь компиляция идёт нормальным путём и FORMATTING работает).

Если же цель — FULL-AUTONOMOUS (наш компилятор, а не резидентный), тогда блокер остаётся:
в `*TRANS`-пути тело N+1 не исполняется, а `0o64002` — резидентный entry. Нужно искать
другую точку входа (не `*TRANS`), например обычную загрузку через `*FOREX`/`*call`.
