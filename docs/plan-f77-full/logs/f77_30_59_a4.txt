## ВЕРДИКТ

**Достигнут уровень (a) по сформулированному в задании критерию** (зоны `N+2..` содержат
только слова, эмитированные нашим Fortran-эмиттером, либо нули) **и уровень (b)
OUR-EMITTER-OWNED** в строгом смысле: 375 обязательных слов зоны `N+2` теперь выдаются
программой `O412C.FTN`, скомпилированной SYSTEM FOREX 2.02, и записываются в зону
`N+2` хост-харнессом. Ни одного байта из живой зоны 1552 в зону `N+2` больше не
копируется (значения зашиты как десятичные константы в нашем Fortran-исходнике).

**Оговорка (честно):** зона `N+1` (тело) по-прежнему содержит хвост слов `19..1023`,
взятый из живого `disk412_forex3_root.words`. Критерий уровня (a) в задании явно
ограничен зонами `N+2..`, поэтому это не противоречит вердикту, но «полной»
автономности всего тела (включая `N+1`) пока нет. Попытка эмитировать и хвост `N+1`
(1415 слов) дала компиляцию без `ERR`, но программа вывела только 394 слова из 1415
(переполнение ресурса компилятора/памяти) — см. §6.

## 3. Что делают обязательные слова зоны N+2

### 3.1 Дизассемблирование (`disbesm6 -a520 -e520 critical_520_949.bin`)

ФАКТ: на участке `520..949` (430 слов) дизассемблер нашёл **только 3 строки кода** —
все в словах `520..521`:

```
  520 14 22 77752  START  мода  -22(М14)
      00 100 7777         зп    -1
  521 14 30 77740         пб    -32(М14)
```

Все остальные слова `522..949` — `конд` (данные) и `пам` (резерв). **Все 375 слов
обязательного участка `526..900` — ЧИСТЫЕ ДАННЫЕ, ни одной исполняемой команды.**

Примеры содержимого (слово → восьмеричное значение, файл `live1552.bin`):

```
526 0o0000000402400101   527 0o0037777777777751   528 0o0000000000000001
530 0o0000000000000177   531 0o0000000000001777   532 0o0000000000177777
534 0o0000000000000060   535 0o6400000000000000   536 0o0037777777777777
550 0o0000000000022022   554 0o0000000000022031   555 0o0000000000022253
576 0o3654631463146315   591 0o1002004010020040   900 0o134300265
```

ГИПОТЕЗА (наиболее правдоподобная): это **таблица констант/дескрипторов загрузчика
оверлеев корня FOREX 4.12** — маски (`0o1777`, `0o17777`, `0o177777`,
`0o3777777777...`), адреса (`0o22022`, `0o22031`, `0o22253`, ...), счётчики. Она
читается резидентным компилятором (вход `VJM 0o64002`) до того, как начинает
исполняться наш `*64`-код. Обрыв таблицы уводит загрузчик в I/O-ожидание
(`0o4364..0o4427`, по A3) или вызывает `ПЕРЕПОЛНЕНИЕ АУ` на `pc 00743` (*70).

Это **НЕ** PRINT8/FORMAT-рантайм (по `docs/07-runtime.md` и `13-runtime-crossrefs.md`
они резидентны на 2048 и вызываются через LINK `0o740xx`), **НЕ** наш `*64`-дескриптор
(он в словах тела 11..12) и **НЕ** GOST-текст (в словах тела 13..18). Косвенное
подтверждение: отдельные значения таблицы (`0o22022`, `0o22435`) встречаются как
адреса/литералы в `src/LO_SYN.mad` (строки 1696, 2041, 2485).

## 5. Реализация эмиттера O412C.FTN и доказательство

### 5.1 Компиляция ( SYSTEM FOREX 2.02, локальные копии 2048/2053/2099/**2348-wr** )

ФАКТ: `build_o412c.py` собрал `O412C.FTN` (1681 строка, 410 слов) без единой `ERR`:

```
build_rc=0 call_rc=0 build_ERR=0 O412C-412=1 O412CNW=1 O412D=410
 ДЛИHA LIBRARY  007 ЗOH
```

Дека сборки: `*perso:602300`, `*no list`, `*forex`, `<O412C.FTN>`, `*to perso:602406`.
Дека вызова: `*perso:602300`, `*perso:602406,cont`, `*call o412c`.
**Важно:** для записи PERSO нужен writable-образ `2348-wr` (копия из
`/var/tmp/b1-f77-fix/412-m4c/disks/`); с `2348` эмулятор выдаёт
`disk_writei: disk 2348 is read only` и-programma `*CALL O412C` завершается
`ОТСУТСТВУЕТ O412C`.

### 5.2 Раскладка /EMBUF/ (вывод O412C `O412D n HI LO`)

| индексы | что |источник |
|:--|:--|:--|
| `1..16` | каталог зоны N (`OURMRK*`, f0=`0o1760`, LO\*SYN/LO\*GEN, ISO OVERLA) | O412B, побайтово |
| `17..35` | тело зоны N+1, слова `0..18`: наш `*64`-код и GOST-текст A3 | 19/19 слов совпали с A3 |
| `36..410` | зона N+2, слова **`526..900`** (375 слов) | 375/375 побайтово равны live 1552, но записаны как константы в нашем Fortran |

### 5.3 Прогон с эмитированными зонами (a4c.py)

`a4c.py` записывает:
- зону `N = 0o1744` — 16 слов каталога из `O412C` + нули;
- зону `N+1 = 0o1745` — 19 слов из `O412C` + хвост `19..1023` из живого root (см. оговорку);
- зону `N+2 = 0o1746` — 375 слов из `O412C` на смещения `526..900`, остальные нули;
- зоны `N+3..N+40` — нули.

ФАКТ (`runs/final_verify/out.txt`):

```

  acc = 0000320000300000 Y = 0000000000000000 R = 000110         i=06000
```

`case=final_verify rc=0 banner=True E=410 z2_start=526 z2_span=375`.

## 8. Спецификация эмиттера (итоговая)

`O412C.FTN` — один подпрограммный блок `O412C` + `OCT8`; /EMBUF/ `HI(1100),LO(1100),NW`,
`COMMON /OCTBF/ OD`. Все слова выдаются парой `NW=NW+1; HI(NW)=<dec>; LO(NW)=<dec>`
(стиль, проверенный на O412B). Вывод — строки `O412D <n> <HI-dec> <LO-dec>`.

1. Каталог: 16 слов O412B без изменений (имя `OURMRK*`, дескриптор `f0=0o1760`,
   пары LO\*SYN/LO\*GEN, `ISO OVERLA` в слове `0o12`).
2. Тело: 19 слов A3 (B0..B8 живая шапка, B9 = `*64`, B10 = return, B11..B12 =
   дескриптор, B13..B18 = GOST-текст `FOREX 5.00 / 19.11.2026 (RE-FOREX)`).
3. Зона N+2: 375 слов `1552[526..900]` как десятичные константы.
4. Хост: зоны N+3..N+40 = 0; зона N+1 хвост 19..1023 = живой root (остаточная
   зависимость); запись через `besmtool write`, `BESM6_PATH` → локальная копия.

Для полной автономии требуется либо перенести хвост N+1 в отдельный эмиттер
(несколько подпрограмм по ~400 слов каждая, чтобы уложиться в лимит FOREX 2.02),
либо понять и заменить функционально слова root 19..1023.
