## 2. Что именно написано в Fortran (шаг 1)

`O412` — пятый program unit, добавленный к `/EMBUF/` из `EMIT.FTN`.

**ФАКТ.** Единственное изменение трёх унаследованных unit на КОПИИ:
`INTEGER HI(8),LO(8)` → `INTEGER HI(32),LO(32)` в `N3EMT`-совместимом объявлении,
`EMIT48` и `GOSTEN`. Слоты 1..8 сохраняют смысл, `NW` остаётся последним полем
`COMMON`, прозрачность для проверенного кода сохранена.

**ФАКТ.** Порядок выдачи (1-based индексы `/EMBUF/`):

| индекс | слово (восьм.) | смысл |
|--:|:--|:--|
| 1 | `5557565164576212` | K0 TEXT `MONITOR*` |
| 2 | `0000000000000370` | K1 дескриптор монитора |
| 3 | `5765625562531200` | K2 TEXT `OURMRK*` |
| 4 | `0400402757101760` | K3 main-дескриптор, **f0=0o1760** |
| 5 | 0 | B0 служебное слово зоны тела |
| 6 | 1 | B1 `w0`: head=1, sym=0, debug=0 |
| 7 | 0 | B2 `w1`: set=data=long=0 |
| 8 | `0000000000000003` | B3 `w2`: **NC=3**, bss=const=0 |
| 9 | `0000000000073461` | B4 маркер 30513 |
| 10 | `7240176003000464` | B5 `уиа 1760(M16)/пб 464` |
| 11 | `6700000002200000` | наш код: `13,UJ,` (`EMIT48(6,56,0, 0,18,0)`) |
| 12 | `5765625562531200` | head-секция: TEXT `OURMRK*` |

**ФАКТ (важное исправление скеча §5).** `NC` вычисляется из фактического числа
выданных слов: `NBASE = NW+1` перед B3, после кода `NC = NW - NBASE`, затем
`LO(NBASE) = NC`. Поле `cmd` лежит в **младших 15 битах младшего полуслова**
(ср. эталон `0o0002220000001760`); первая попытка записать `NC` в `HI` дала
`0o0000000300000000` и была исправлена. `NC` не захардкожен.

**ФАКТ (вторая ловушка скеча §5).** Примеры кода из §5 (`EMIT48(14,0,0,...)`,
`EMIT48(0,0,0,13,0,0)`) **не являются валидными полусловами**: IR — 3 бита,
`IR=14` даёт `29 360 128 > 2**24-1`, слово выходит за 48 бит (в первом
прогоне `O412D 12` не влезло в 6 байт). Заменено на проверенное слово
`13,UJ,` = `EMIT48(6,56,0, 0,18,0)` → `0o6700000002200000`.

## 4. Хост-шаг (шаг 3)

Запись шла `besmtool write 2148 --from-file=... --start=01744/01745` с
`BESM6_PATH=runs/<case>/disks`. **ФАКТ (ловушка):** `besmtool` понимает
`--start=01744` как восьмеричное (зона 996), а `--start=1744` как десятичное
(зона 3016). Все записи использовали префикс `0`.

Колода (одинаковая во всех опытах, `deck.b6`):

```
шифр 419999 зс5^
DIS 41(2148)^
eeв1а3
*name M4CTEST
*TRANS:OURMRK*,,411744
      PROGRAM MAIN
      PRINT 100
  100 FORMAT('CALLER-OK')
      END
*execute
```

**ФАКТ (трасса `BESM6_DD_DEBUG=1`, `runs/base2/dbg.err`):**

```
DD pc=03022L r016=53405 u=41 z=1744 RD ...
DD pc=00671L r016=00145 u=41 z=1745 RD uil=10/0/3200 ...
DD pc=00744L r016=00145 u=41 z=1746 RD uil=10/0/3200 ...
... z=1747..1773 подряд ...
```

То есть каталог прочитан, `НЕТ РАЗДЕЛА` **нет**, тело читается как непрерывный
пробег зон 1745+. Дальше поведение зависит от шапки (таблица ниже).

| опыт | B0 (зона 1745.0000) | шапка | rc | консоль (ключевое) |
|:--|:--|:--|:--|:--|
| `base2` | `0` (как в §5 скече) | минимальная, cmd=3 | TIMEOUT | `*NAME M4CTEST`, `*TRANS:OURMRK*,,411744`, дальше тишина |
| `b0live2` | `0o1600043` (живой 4.12) | минимальная, cmd=3 | 0 | `ПЕРЕПОЛНЕНИЕ АУ`, `00707  05 125 2525 e-x`, `acc=6625252525252525 ... i=01760` (дважды) |
| `restore2` | `0` (возврат) | минимальная | TIMEOUT | снова тишина — A/B воспроизводим |
| `fullhdr` | `0o1600043` | **живая 4.12**: `w0=4657624570231200`, `w1=0003770010073377`, `w2=0002220000001760` (cmd=0o1760, const=0o222), 40 зон | 0 | `OTCYTCTBYET  OURMRK*`, `CBOБOД   01770`, `КОНЕЦ ЗАДАЧИ` — без Interrupt |
| `fullhdr_zero` | то же, но код по адресу 0o470 обнулён | то же | 0 | консоль **побайтово равна** `fullhdr` |
| `stub1766` / `markzero` | то же, но `UJ 1766` / маркер=0 | то же | 0 | консоль равна `fullhdr` |

**ФАКТ.** `N2MARK-7391` и `CALLER-OK` не напечатаны **ни в одном** опыте.

|:--|:--|
| B0 = `0` → `0o1600043` | TIMEOUT/тишина → `ПЕРЕПОЛНЕНИЕ АУ` + `00707 e-x` (**консоль меняется**) |

слово и DMS-шапку. Он **не исполняет** наши машинные слова B4/B5/код: их
обнуление никак не отражается на консоли.

## 6. ФАКТ / ГИПОТЕЗА — диагноз

* **ФАКТ.** `f0=0o1760` в дескрипторе K3 обязателен: при других значениях M4/M4b
  получали `НЕТ РАЗДЕЛА`. Здесь `НЕТ РАЗДЕЛА` нет — дескриптор корректен.
* **ФАКТ.** Служебное слово B0 критично: `0` → загрузчик уходит в таймаут/ `*70`,
  `0o1600043` → доходит до исполнения и падает на `00707`. Скеч §5 предлагал
  B0=0; этого недостаточно.
* **ФАКТ.** С минимальной шапкой (`cmd=3`, `const=0`) NEWCOMP* падает на
  `00707 e-x` с `M16=0o1760`. С живой шапкой (`cmd=0o1760`, `const=0o222`,
  40 зон) падения нет, но появляется `ОТСУТСТВУЕТ OURMRK*` / `СВОБОД 01770`:
  TRANS-модуль был принят, но не предоставляет компиляторский интерфейс для
  следующей за `*TRANS` программы.
* **ФАКТ.** `--coverage` в опыте `fullhdr` показывает исполнение `01764` и
  `01770..01777`; обнуление слова, которое мы считали маркером, не меняет
  карту — локализовать наш код по coverage не удалось.
* **ГИПОТЕЗА (ранг 1).** B5 `уиа 1760(M16)/пб 464` — не исполняемый stub, а
  **данные загрузочной таблицы**: dtran читает это слово как пару
  `:14,VTM,1760B` / `,UJ,464B`. NEWCOMP* передаёт управление на cmd[0] (маркер
  `0o73461`), а не на B5; поэтому замена адреса `UJ` (опыты `stub1766`,
  `stub1762`) ни на что не влияет.
* **ГИПОТЕЗА (ранг 2).** Маркер `0o73461` — служебная метка загрузчика, которая
  инициирует переход к следующему блоку (у живого 4.12 — к таблицам и
  38 зонам оверлеев). Без полной LINK-таблицы и оверлеев LO*SYN/LO*GEN
  управление уходит в резидент и падает на `00707`.
* **ГИПОТЕЗА (ранг 3).** Даже при правильной длине `cmd=0o1760` для FULL
  недостаточно «нашего кода»: NEWCOMP* ожидает от TRANS-модуля реализацию
  компиляторских ENTRY (CONST/COMEQ/OPRTR/ПP/FOREX), о чём косвенно говорит
  `ОТСУТСТВУЕТ OURMRK*` после нормального возврата.

## 7. Следующие шаги для FULL (с доказательствами)

1. **Проверить точку входа трассировкой**, а не A/B по B5: снять
   `BESM6_DD_DEBUG=1` + `--coverage` для живого `FOREX3*` и для `fullhdr` и
   сравнить адреса первых исполненных слов. Факт из M4b: у FOREX3*
   `DD pc=00671L u=41 z=1551 RD uil=10/0/3200`; у нас `DD pc=00671L ... z=1745`,
   но дальше идут `pc=00744L` (код самого загрузчика).
2. **Использовать полную живую 4.12-шапку** (`w0/w1/w2` из
   `reference/412/disk412_forex3_root.words`): это уже убирает `00707`
   (опыт `fullhdr`). Минимальная шапка скеча §5 в этом смысле проигрывает.
3. **Разместить наш код по адресу, который действительно исполняется**, после
   того как п.1 даст точный адрес. Кандидаты: cmd[0] = base+4, base+0o10;
   опыты с подменой B5 и маркера показали, что base+2/base+6 не являются
   рабочей точкой входа.
4. **Добавить 38 зон оверлеев LO*SYN/LO*GEN и LINK 0o74010..0o74022** —
   без них `ОТСУТСТВУЕТ OURMRK*` / `СВОБОД 01770` сохраняется даже при
   корректной шапке (опыт `fullhdr`).
5. **Для печати маркера** нужен `*64`+GOST-дескриптор: невалидные слова из скеча
   (`IR=14/13`) заменены; нужен дескриптор формата `extra.c:630-660` и строка
   GOSTEN. Прямой `*64` в нашем теле ещё не проверялся, потому что тело не
   исполняется.
6. **База M16**: в дампе `b0live2` `M16=0o1760` — база выставлена верно,
   сдвиг `0o40011` из N2 здесь больше отсутствует. Гипотеза §7 спецификации
   подтверждена, но сама по себе FULL не дала.
