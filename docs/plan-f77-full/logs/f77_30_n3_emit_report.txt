## 2. Что именно реализовано

### 2.1 `EMIT48` — эмиттер opcode+адрес → 48-битное слово

`EMIT.FTN:66-73`:

```fortran
      SUBROUTINE EMIT48(IR1,K1,A1,IR2,K2,A2)
      INTEGER IR1,K1,A1,IR2,K2,A2
      INTEGER HI(8), LO(8), NW
      COMMON /EMBUF/ HI,LO,NW
      NW = NW + 1
      HI(NW) = IR1*2097152 + K1*32768 + A1
      LO(NW) = IR2*2097152 + K2*32768 + A2
      RETURN
      END
```

Полуслово = `[IR:3][КОП:6][АДР:15]` = `IR*2**21 + КОП*2**15 + АДР`.
Максимум `7*2097152+63*32768+32767 = 16777215 = 2**24-1` — ровно укладывается
в 24-битный FOREX INTEGER (проба `probe.out`: `32768 2097152 16777215 ...`
арифметика и деление работают). Слово собирается как `HI*2**24 + LO` — тот же
big-endian порядок, что в `tools/build_forex_perso.py:85,175-180` (6 байт,
старший байт первым). `EMIT16` в явном виде не нужен: пара полуслов уже
покрывает и 16-, и 24-битные константы; при необходимости достаточно
`EMIT48(0,0,A1, 0,0,A2)`.

### 2.2 `GOSTEN` — ASCII → GOST-10859 → 2 слова

`EMIT.FTN:75-111`. Вход: `IA(12)` (ASCII-коды, в прогоне `DATA IA /78,51,.../`
= `"N3EMIT FOREX"`) и `NI` в `COMMON /TXTBF/`. Таблица `GT(64)` —

свёртка ASCII → TEXT (Дубна) → GOST:

```
GT(IC) = text_to_gost[ TEXT_DUBNA.index(chr(IC+31)) ],  IC = ASCII-31
```

(ASCII 32..95 → индекс 1..64). Первичный источник таблицы:
`monitor80-re/tools/encoding.cpp:614-679` (имена макросов) +
`monitor80-re/tools/gost10859.h:57-101` (значения). Упаковка — **6 ГОСТ-байт
на 48-битное слово** (GOST8):

```
HI = ((b1*256 + b2)*256 + b3),  LO = ((b4*256 + b5)*256 + b6)
```

### 2.3 `OCT8` — печать octal без I-формата с восьмеричным полем

`EMIT.FTN:113-122`: делением на 8 получаем 8 octal-цифр (OD(1) — младшая) в
`COMMON /OCTBF/`. Драйвер печатает их от старшей к младшей, `FORMAT(...,8I1)`
даёт ровно 16 окт. цифр на слово. Прямой восьмеричный вывод в FOREX 2.02
отсутствует, `I`-формат печатает только decimal — поэтому такой обход.

### 2.4 `N3EMT` — самотест

`EMIT.FTN:31-64`: маркер `N3EMIT-7391`, 4 вызова `EMIT48` с известными
`IR/КОП/АДР`, 1 вызов `GOSTEN` (ещё 2 слова), печать `N3NW`, 16 окт. цифр
и decimal HI/LO для каждого из 6 слов.

## 4. Ограничения и обходы (главная ценность отчёта)

### 4.1 48 бит не помещаются в один INTEGER → две arrays в COMMON

FOREX 2.02 литерал `2^36` даёт `ПЕРЕПОЛ МАНТИССЫ`, INTEGER ≤ 2²⁵−1
(`docs/plan-f77-full/34-arfa-lowering.md:57-61`). Проба `probe.out`
подтвердила рабочий диапазон до `16777215 = 2**24-1`. Слово 48 бит поэтому
хранится парой `HI(8), LO(8)` в `COMMON /EMBUF/`; счётчик `NW` там же.
**Как это кормит code writer:** каждая пара `(HI(i),LO(i))` →
`((HI<<24)|LO).to_bytes(6,'big')` — ровно формат `build_forex_perso.py:421`,
поэтому N3.8 (выход object-кода) получает готовый поток 6-байтовых слов без
дополнительных преобразований.

### 4.2 Баг 2.02: вложенные скобки с индексированными массивами

`(B(1)*256 + B(2))*256 + B(3)` в GOSTEN **молча выдавало 0** (трассировка
`dbgmain.out`: `GWR 5 0 0`, хотя `dbgloop.out`: `GВ6 44 2 63 68 45 72`).
Обход — пошаговый Horner (`EMIT.FTN:100-106`):

```fortran
         HIW = B(1)
         HIW = HIW*256 + B(2)
         HIW = HIW*256 + B(3)
```

После этого все слова совпали. Это не ошибка исходника, а особенность
транслятора 2.02; все future-lowerings должны избегать вложенных выражений
с массивами.

### 4.3 Off-by-one в ASCII→GT

`TEXT_DUBNA[0] = ' '` (ASCII 32), `TEXT_DUBNA[33] = 'A'` (ASCII 65), но
`TEXT_DUBNA[1] = '.'`, а не `'!'` и т.п. (`tools/besm6_text_scan.py:65-66`).
Поэтому `IC = IA(I) - 32` терял пробел и сдвигал все буквы на один код
(`dbgloop.out`: `'N'` давал `GT(46)=44` вместо `GT(47)=69`). Исправлено на
`IC = IA(I) - 31` с предварительной свёрткой не-ASCII символов в 0.

### 4.4 Расхождение таблиц TEXT_TO_GOST (важно для главного агента)

`gost_table.py` нашёл **14 расхождений** между
`tools/besm6_text_scan.py:117-128` (на которую указывает задача) и первичным
`monitor80-re/tools/encoding.cpp:614-679`:

```
TEXT 044: tool=044 cpp=077 ('D')     TEXT 054: tool=053 cpp=104 ('L')
TEXT 056: tool=056 cpp=105 ('N')     TEXT 057: tool=106 cpp=056 ('O')
TEXT 060: tool=057 cpp=060 ('P')     TEXT 061: tool=107 cpp=106 ('Q')
TEXT 062: tool=105 cpp=107 ('R')     TEXT 064: tool=111 cpp=062 ('T')
TEXT 065: tool=112 cpp=111 ('U')     TEXT 066: tool=113 cpp=112 ('V')
TEXT 067: tool=114 cpp=113 ('W')     TEXT 070: tool=115 cpp=065 ('X')
TEXT 071: tool=116 cpp=063 ('Y')     TEXT 072: tool=117 cpp=114 ('Z')
```

Первичная (cpp) таблица **байт-точно воспроизводит** эталон `TEST/4` из
doc 31; tool-копия — нет (`0o2222251022206004` против
`0o1442251014406004`). Поэтому в `EMIT.FTN` вшита cpp-таблица. Если главный
агент решит, что target runtime использует tool-вариант, достаточно заменить
8 строк `DATA GT` (строки 82-89 `EMIT.FTN`) на значения из `expected.py`
старой версии; механизм и самотест остаются прежними.

### 4.5 «8 шестибитных ГОСТ-байт» физически невозможно с этой таблицей

`TEXT_TO_GOST` содержит коды до `0o117 = 79` (7 бит). В 6-битную группу они
не влезают. Документированный формат ГОСТ-слов БЭСМ-6 — **6 байт × 8 бит**
(`docs/plan-f77-full/31-fortran-arfa-bridge.md:63-70`, `dec_gost8` в
`besm6_text_scan.py:277-279`); 8×6 бит — это формат **TEXT** (Дубна), который
строится другой таблицей (`text_encode` в `build_forex_perso.py:158-162`).
Реализован именно GOST8 = 6×8. Если системе нужна 8×6 TEXT-упаковка, это
отдельный кодировщик (N3.5/N3.8), сюда не входящий.

### 4.6 Лимит NLV≤31 → 4 маленьких program unit через COMMON

N1 (`/var/tmp/b1-f77-fix/n1/REPORT.md:312-317`): `NLV=32` ⇒
`ПЕРЕПОЛ РАБ ОБЛ ТР-РА`. Монолитный компилятор с `C(132,NLV)` не влез бы.
Здесь каждый unit мал: `N3EMT` 34 строки, `GOSTEN` 37 (из них 8 — DATA),
`EMIT48` 8, `OCT8` 10. Общий COMMON:
`/EMBUF/(HI,LO,NW)` + `/TXTBF/(IA,NI)` + `/OCTBF/(OD)`. Сборка прошла без
`ПЕРЕПОЛНЕНА ПАМЯТЬ`. Это точно та схема, которую+N3.7 предлагает развить
(локальные COMMON/BSS вместо `*A*` 2048B).

### 4.7 Внешние SUBP остаются (ожидаемо для N3.1/N3.2)

`PRINT`/`FORMAT` в наших модулях по-прежнему резолвятся через `FORMAT` и
`FORTLIBR` из `*perso:602300` — см. `build.out` (список
`ИСПОРЧЕНЫ ПОДПРОГРАММЫ`). Это допустимо в пути (a) N2, но N3.5
(`FORMAT/PRINT → *64 descriptor`) должен убрать эту зависимость; до тех пор
модуль не является полностью автономным.

## 5. Вывод о применимости F77-подмножества

**N3.1: ДА, FULLY FEASIBLE.** `INTEGER` 24 бита, `INTEGER`-массивы, `COMMON`,
`DATA`, `DO`, `IF`, арифметика и `PRINT n` с `In` — всё компилируется 2.02 и
исполняется. Единственная цена — пары `HI/LO` вместо одного 48-битного слова
(§4.1) и отказ от вложенных скобочных выражений с массивами (§4.2).

**N3.2: ДА, FEASIBLE с оговоркой о формате.** ASCII→GOST конверсия и упаковка
в слова работают и проверены обратным декодированием. Оговорка: реализован
GOST8 (6×8), а не буквально «8 six-bit GOST bytes»; последнее невозможно с
таблицей, указанной в задании (§4.5). Требуется решение главного агента,
какой формат целевой (см. §4.4 / §4.5).
