## 1. Точная последовательность `*64` из A3 (ФАКТ)

Источник: `/var/tmp/b1-f77-fix/59-a3/REPORT.md`, `a3.py`, `a3_code.bin`,
`fxbanner_body.bin`, `runs/ab_our_base/out.txt`; шапка — O412B (`call.out`, 30 слов),
тело зоны N+1=0o1745, зоны N+3..N+40 обнулены, зона N+2 живая.

Слова тела, реально исполняемые (A3 `body[9..21]`, смещение 9 после префикса B0..B8):

| тело | RAM\* | слово (8) | роль |
|---:|---:|:--|:--|
| 9  | 0o1770 | `0064177202200000` | `Э64` с ADR=0o1772 → дескриптор |
| 10 | 0o1771 | `6700000002200000` | возврат `uj 0(15)` |
| 11 | 0o1772 | `0000177400001774` | дескриптор, слово 0: addr0=addr1=0o1774 |
| 12 | 0o1773 | `0001000040000000` | дескриптор, слово 1: fmt=0, off=1, final=8 |
| 13..19 | 0o1774..0o2002 | 7 слов | GOST-текст `FOREX 5.00 / 19.11.2026 (RE-FOREX)'231'` |
| 20 | 0o2003 | `0000000041000002` | хвост модуля FXBANNER |
| 21 | 0o2004 | `0000000041000004` | хвост модуля FXBANNER |

\*アドрес RAM восстановлен по якорю A3: `body[11] → 0o1772`, `body[13] → 0o1774`
(т.е. `body[k] → 0o1757 + k`). MTR-трасса нашего прогона подтверждает: первое слово
нашего тела (`body[9]`) исполняется по PC=0o1770 (`MTR 01770L ...`), т.е. якоренная
карта адресов верна.

#### 1.1 Команда `*64` (ФАКТ, декод `siprod_asm.decode`)

`0o00641772` (левая половина слова 9): `name=Э64, reg=0, arg=0o1772, op=0o64`.
T.e. `Э64 ADR` кодируется как `0o640000 + ADR` (2-я структура, 12-битный адрес).
Правая половина `0o02200000` — `мода` (нейтральный хвост, из FXBANNER).

#### 1.2 Дескриптор `*64` (ФАКТ, `extra.c:622-660` копии `/home/azizz/Yandex.Disk/dispak/dispak/extra.c`)

Формат信息ного массива по `extra.c`:

```
слово 0:  iiii ........ xxxxxxxxxxxx    ; addr0 = x + R[i]
          jjjj ........ yyyyyyyyyyyy    ; addr1 = y + R[j]
слово 1:  ffff bbbbbbbb dddddddddddd    ; f=формат, b=позиция, d=цифры
          esss wwwwwwww rrrrrrrrrrrr    ; e=финал(бит 8 => flush), s=пропуск строк,
                                        ; w=ширина, r=повтор
```

У A3: `i=j=0`, `x=y=0o1774` (оба полуслова `0o001774`, R[0]=0);
`f=0` (GOST-текст), `b=1` (отступ 1 колонка), `e=0o10` ( flush по final&8 ), `d=w=r=0`.

Форматы `extra.c`: 0/8 = GOST-текст, 1 = команда, 2 = восьмеричное, 3 = вещественное,
4 = ITM. Terminator GOST-строки: байт `0o231` (case 0231 в `print_gost`,
`extra.c:253`), поэтому FXBANNER печатает только часть литерала до `0o231`.

#### 1.3 Кодировка GOST (ФАКТ, EMIT.FTN `GOSTEN` + таблица `GT`)

6-битные коды ГОСТ 10859 (`GT` из `src/newcomp/EMIT.FTN:82-89`, авторитет —
`monitor80-re/tools/encoding.cpp:614-679`) упаковываются **по 6 байт в 48-битное слово**:
HI = байты 0..2, LO = байты 3..5, каждый байт — 8-битное поле со значением 0..0o100.
Это подтверждено побайтовой расшифровкой 7 слов FXBANNER (`20027107...` →
`100,56,107,45,65,17` = `FOREX ` и т.д.).

## 4. Почему текст статический: что именно осталось (ФАКТ / ГИПОТЕЗА)

**ФАКТ (MTR-трасса `runs/a5_seq_mtr3/trace.err`, окно 0o1770..0o2040, N=5000):**
исполнение нашего тела начинается по PC=0o1770, но вместо наших команд в trace видны
совсем другие (трансформированные загрузчиком):

```
MTR 01770L ita    15(0)      ; вместо 'сч 0o2014'
MTR 01770R utc    2050(0)    ; вместо 'зп 0o2010'
...
MTR 01773L asn    134(0)
MTR 01774L aax    2047(0)
MTR 01775R asn    44(0)
MTR 01776L aex    73(0)
MTR 01777L uza    2001(0)   ; переход сразу к печати, БЕЗ повторов цикла
MTR 02001L vtm    2261(16)  ; transformed *64 → вызов обработчика печати
```

Счётчики вхождений: `01770:2` (L+R), `01772:2`, `01774:2`, `01776:2`, `01777:1` —
ровно **один** проход. Это совпадает с выводом A2 (`VJM 0o64002`, §1): загрузчик
`#print` копирует тело в ОЗУ с **трансформацией полей**, «ни одно слово не встречается
дословно». Наш `*64`-блок чудом выживает, потому что повторяет проверенный A3-идиом.

**ГИПОТЕЗА (ранг 2):** трансформация — это переупаковка полей DMS/1-й структуры
загрузчиком (A2: `0o660..0o667` собирает INF-слово, `0o701..0o711` пишет с подстановкой).
Чтобы выполнить настоящий счётный цикл, нужно либо инвертировать эту переупаковку
и подать на вход уже «трансформированные» слова, либо найти режим `*TRANS`, где
тело копируется дословно.

**Чего не хватает для вычисляемого вывода (`21` из N, `1.00`/`3.00` из X/Y):**
1. Инверсия трансформации загрузчика (или обход) — иначе арифметика не исполняется.
2. Форматтер: `FT*003`/`FT*571`/`FT*002` из N3 — подпрограммы SYSTEM FOREX, в нашем
   теле их нет. Для `I4` достаточно перевести N=21 в две GOST-цифры (код цифры `d` = `d`,
   по GT: `'0'→0 … '9'→9`), но для `F10.2` нужно масштабирование мантиссы/порядка.
   Альтернатива — использовать `*64` format 2 (octal) / 3 (real) из `extra.c`, но это
   даст `25` и экспоненциальную запись, не `21 1.00 3.00`.
3. При желании — динамически портить GOST-байты перед `*64` (наш `вч`/`зп` в теле),
   но это опять упирается в п.1.

## 5. Эмиттер (шаг 5, скеч)

`A5_EMITTER.FTN` — скеч в стиле `EMIT.FTN` (COMMON /EMBUF/, NLV≤31, 25 слов):
DATA с 25 октальными константами из `a5_seq_words.txt`, цикл `DO 10 I=1,25`
разбивает 48-битное слово на HI/LO. Важно: формула `EMIT48` из N3 пригодна только для
self-test; для реальных команд ACM需要使用 таблицу `re-siprod/tools/siprod_asm.py`
(как `gen_words.py`). Интеграция в O412C: эмитировать 25 слов сразу после префикса
B0..B8 (тело 9..33); зоны N+3..N+40 — нули; зона N+2 — живая (блокер A3/A4).
