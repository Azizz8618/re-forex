## ВЕРДИКТ: **DONE** (M80 executable found/disassembled)

**ФАКТ.** Исполняемый код именно MONITOR-80 `NEWCOMP*` (обработчик `*TRANS`) найден
не отдельным DMS-модулем на диске/ленте, а в **дампе оперативной памяти монитора**,
снятом живым прогоном C-симулятора `dispak` decks `t412.b6`
(`*TRANS:FOREX3*,,411550`).

**ФАКТ.** Получен пословный дизассемблинг и **полная покадровая трасса с регистрами**
(90000+ инструкций), которая напрямую показывает, как разбирается 4×12-битный
дескриптор каталога. Монсийский двойник `TRNSLTOR` здесь не используется: это
другая сборка с другими абсолютными адресами и другим форматом каталога.

## 3. Дизассемблинг кода M80 NEWCOMP* (0o3000..0o3077)

Получен `disbesm6` из дампа (`/var/tmp/b1-f77-fix/m80-newcomp/m80_3000.bin`,
`m80_640.bin`). Ниже — проверенный трассой листинг с аннотациями.

### 3.1 Вход и чтение каталога (0o3000–0o3022)

```
3000 счи М15 / счм 15          ; сохранить M15 (возврат)
3001 сда 64+10 / сда 64-10     ; выделить биты параметра
3002 уи М13 / слиа '2000'(М13) ; M13 = 0o6000  ← буфер каталога
3003 уии М14(М13) / уиа '1146'(М12) ; M14 = M13; M12 = 0o1146 ← буфер дескрипторов
3004 счи М13 / сда 64-20
3005 или '424' / зп 1(М17)     ; собрать INF-слово в (M17)+1 = 0o53405
3006 Э70 1(М17)                ; ← *70, читает диск 30 / зону 0o0050
3007 уиа D03064-1(М16) / пв A03033(М15) ; M16 → строка поиска, переход в 3033
3010–3014: обработка ошибок чтения (уиа '577'/'640', зп '765', пб)
...
3020 asn 54 / aox 77           ; собрать INF = 0o10030000411550
3021 atx 1(17) / Э70 1(17)     ; ← *70, читает диск 41 / зону 0o1550 (КАТАЛОГ)
3022 vtm 577(16) / vjm 3033(15); M16 = 0o577 (Target name), goto 3033
```

**Трасса (ФАКТ, `t412.trace.err`):**
```
MTR 03006L *70    1(17) AU=10030000300050 ...
MTR 03021L atx    1(17) AU=10030000411550 ...
MTR 03021R *70    1(17) AU=10030000411550 ...
DD pc=03022L r016=53405 u=41 z=1550 RD uil=10/0/300 uir=41/0/1550
```
То естьpacked-слово `*70` = `0o0010030000411550`: старшие 12 бит `0o001003` —
код операции/режим, младшие 6 октальных цифр `41 1550` — носитель 41, зона 0o1550.

### 3.2 Сканирование каталога и разбор 4×12-битного дескриптора (0o3033–0o3055)

```
3033 mtj 13(14) / utc 0         ; M13 = M14 = 0o6000 (начала каталога)
3034 xta 0(13)                 ; AU = core[M13]  (имя из каталога)
      uza 0(15)                 ; если 0 → конец каталога, возврат
3035 aex 0(16)                 ; AU = имя XOR core[M16] (M16 = искомое имя)
      uza 3037                  ; если AU=0 → совпадение, идём в 3037
3036 utm 2(13) / uj 3034        ; M13 += 2, следующая пара «имя/дескриптор»
3037 xta 1(13)                 ; AU = core[M13+1] = 48-битный ДЕСКРИПТОР
      utc 3076                  ; MODREG из константы 0o3076 = 0o777777
3040 aax 3076                  ; AU = AU AND core[эффективный адрес]
      atx 1(17)                 ; → core[0o53405] = f0  (младшие 12 бит дескриптора)
3041 xta 0(13) / atx 0(12)      ; скопировать имя в буфер M12
3042 xta 1(13) / atx 1(12)      ; скопировать дескриптор в буфер M12+1
3043 utm 2(13) / utm 2(12)      ; M13 += 2; M12 += 2
3044 xta 0(13) / uza 3055       ; следующее имя; 0 → готово
3045 xta 1(13)                 ; его дескриптор
3046 aax 3076                  ; HH извлечь f0
      aex 1(17) / uza 3055      ; f0 XOR f0(эталон) → сделать выход, если равно
3047 aex 1(17) / aex 1(13)
3050 aex 1(13) / uza 3055
3051 mtj 16(12) / utm 76612(16) ; M16 = M12 − 0o1166
3052 v1m 3041(16)               ; вернуться к копированию
3055 xta 1(17) / uj 0(15)       ; вернуться по M15
```

**Семантика команд (ФАКТ, из исходника C `ispak/dispak/arith.c`):**
- `aax` (строка 122): `acc &= enreg` — побитовое И с памятью.
- `aex` (строка 131): `acc ^= enreg` — побитовое ИСКЛЮЧАЮЩЕЕ ИЛИ (НЕ вычитание!).

**Доказательство извлечения f0 (ФАКТ, трасса):**

| Дескриптор в каталоге (core[M13+1]) | AU после `aax 3076` | Комментарий |
|:--|:--|:--|
| `0o0400402757101760` (FOREX3*) | `0o0000000001760` | f0 = 0o1760 |
| `0o0401423673031551` (LO*SYN) | `0o0000000031551` | f0 = 0o1551 |
| `0o0411023634031551` (LO*GEN) | `0o0000000031551` | f0 = 0o1551 |

То есть пара `utc 3076` / `aax 3076` выделяет **младшие 12 бит**
(маска `0o7777`) дескриптора = поле `f0`.

### 3.3 Извлечение остальных полей и чтение тела (0o660–0o671)

```
660 сч 1(М16) / сда 64+15   ; AU = дескриптор из буфера 0o1153; сдвиг влево 15
661 уи М3 / сда 64+15       ; M3 = старшая часть → используется в 674 (пио)
662 зп (М17) / и 0752       ; → core[0o53402]; AND маска 0o37
663 сда 64-5 / зп (М17)     ; → core[0o53403]
664 слц 35 / зпм 153
665 сда 64-37 / слц 153
666 зпм 153 / сда 64+5
667 и 0753 / слц 146
670 зп 145 / Э70 145        ; собрать INF = 0o10320000411551 и читать зону 0o1551
671 сч 3(М5) / зп 151       ; M5 = f0 = 0o1760 → core[0o1763] в 0o151
672 сч 4(М5) / зп 152       ; core[0o1764] в 0o152
673 уии М6(М5) / мода
674 пио A00656+28(М3)       ; ветвление по M3 (старшие поля дескриптора)
676 уи М11 / сда 64+15 / уим М12 / и 0750 ...
700–711: цикл копирования зон тела в ОЗУ (M6 = адрес приёмника, растёт)
```

Константы (`core.py`, дамп):
```
000750: 4000000000000000   000751: 0000000000077777   (маска 18 бит)
000752: 0000000000000037   000753: 0000000000000777   (маски 6/9 бит)
003076: 0000000000077777   003077: 0000000000777777
```

**Трасса (ФАКТ):**
```
DD pc=00671L r016=00145 u=41 z=1551 RD uil=10/0/3200 uir=41/0/1551
```
То есть дескриптор определяет префикс INF-слова (для тела `0o1032` вместо
каталожного `0o1003`), а зона тела — **N+1 = 0o1551** (каталог был в 0o1550).

## 4. Точная семантика дескриптора 2148:0o1550 (ФАКТ / ГИПОТЕЗА)

Каталог (зона 0o1550 диска 41, загружен в ОЗУ по 0o6000) — это последовательность
пар «TEXT-имя (8×6 бит) / 48-битный дескриптор», завершённая нулевым словом:

| Слово зоны | Значение | Расшифровка |
|:--|:--|:--|
| 1550.0000 | `0o5557565164576212` | `MONITOR*` |
| 1550.0001 | `0o0000000000000370` | короткий дескриптор |
| 1550.0002 | `0o4657624570231200` | `FOREX3*` |
| 1550.0003 | `0o0400402757101760` | `f3=0400 f2=4027 f1=5710 f0=1760` |
| 1550.0004 | `0o5457126371560000` | `LO*SYN` |
| 1550.0005 | `0o0401423673031551` | `f3=0401 f2=4236 f1=7303 f0=1551` |
| 1550.0006 | `0o5457124745560000` | `LO*GEN` |
| 1550.0007 | `0o0411023634031551` | `f3=0411 f2=0236 f1=3403 f0=1551` |
| 1550.0012..16 | ISO `OVERLA`, ` OT  `, `27.06`, `85 M3 `, `<<-->>` | комментарий сборки 4.12 |

**ФАКТ (подтверждено трассой):**
1. `f0` = младшие 12 бит дескриптора; извлекается командой `aax` с маской `0o7777`
   по адресу 0o3040. Для главного модуля `f0=0o1760`, для спутников `f0=0o1551`.
2. `f0` сравнивается с `0o1760` операцией XOR по адресу 0o3046; несовпадение
   запускает цикл копирования пары и продолжения扫描 (0o3051–0o3052).
3. Все пары (FOREX3*, LO*SYN, LO*GEN) копируются в рабочий буфер 0o1152..0o1157.
4. Поля `f3/f2/f1` (старшие 36 бит) используются загрузчиком 0o660..0o674 через
   сдвиги (`сда 64+15`, `сда 64-5`, `сда 64-37`, `сда 64+5`) и маски `0o37`,
   `0o777`, `0o777777` для сборки INF-слова чтения тела (`0o10320000411551`)
   и для выбора ветви загрузки (`M3` → `пио A00656+28(М3)`).
5. Тело читается из **зоны N+1 = 0o1551**, затем зоны 0o1552..0o1600 (150 DD-чтений
   в длинной трассе), и копируется в ОЗУ начиная с адреса ~0o30000 (M6 растёт).

**ГИПОТЕЗА (обоснованная, но не доказанная statically):**
- `f0=0o1760` у FOREX3* совпадает с полем `cmd=0o1760` в DMS-шапке тела (1551.0003)
  — вероятно, это «идентификатор главного раздела»; `f0=0o1551` у спутников
  указывает на зону их DMS-тел.
- Старшие поля задают режим загрузки/оверлейные параметры; MONSYS-двойник
  эти поля не использует вообще, поэтому вывести их смысл из его исходника
  невозможно — только из этого дампа/трассы.

**ОПРОВЕРЖЕНО (как побочный результат):** MONSYS-гипотеза «f0 = M16 base»
неверна: в M80 f0 — это 12-битное поле дескриптора, а M16 — указатель строки поиска.

## 6. Что осталось не闭合 (открытые пункты)

1. **ФАКТ:** точный переход в загруженный компилятор (после ~7000 итераций цикла
   копирования 0o707–0o711) не попал в 90000-инструкционное окно трассы. Тело
   грузится в ОЗУ ~0o30000+; ветвь загрузки управляется `M3`, получаемым из
   старших полей дескриптора (`piо A00656+28(М3)`, pc 0o674). Чтобы поймать
   финальный прыжок, нужно поставить `BESM6_MTR_LO` на pc сразу после цикла
   (например 0o736) с большим `BESM6_MTR_SKIP` либо трассировать 200K+ инструкций.
2. **ГИПОТЕЗА:** точные численные значения f3/f2/f1 как «длина/адрес загрузки/entry»
   требуют ещё одного A/B-эксперимента (подмена полей дескриптора в копии зоны
   0o1550 с наблюдением за INF-словом) — статический дамп даёт только механизм,
   а не семантику каждого бита.
3. **ФАКТ:** исходника именно MONITOR-80 `NEWCOMP*` как файла не существует ни в
   одном локальном репозитории. Единственный материальный след — этот RAM-дамп
   и трасса; найденный MONSYS `TRNSLTOR` — двойник с другим форматом каталога.
