  `besm6.net/tapes`, hash `cc27c8d9…908ec` = `DUBNA/monsys`), **но в диапазоне

  `0o4247401540101762` (`043454`), `0o4010177702640161` (`043456`),
  `0o0042001500004022` (`043343`). Второго экземпляра TRNSLTOR/NEWCOMP* нет.
  `TEXT "NEWCOMP*"` по `0o423226` — запись STABLE (имя), не код (`docs/08-forex3.md:128`).
* Инструменты: собственный reader (6 байт/слово, big-endian) `dump.py`,
  собственный **линейный** дизассемблер `lindis.py` на таблице opcode из
  `dtran/dtran.cc:70-135`. `disbesm6` непригоден: он помечает недостижимые
  слова как `конд` (достижимость не проходит через `VLM`/`VJM`), поэтому
  предыдущий дизассемблинг обрывался на 119 словах.

**Ключевые ФАКТы:**

* **`CODE=OVERLA`** проверяется по `CAT+0o1762` (`043454 lo` / `043455 hi`), константа
  лежит по `0o043570`. В живом каталоге M80 маркер `OVERLA` (= то же ISO-слово
  `0o2365310524446101`) стоит по слову **0o12** зоны 1550 (comparison.json:58-67),
  т.е. формат каталога в M80 **переделан**. Это объясняет, почему диагностика
  «ПЛОХОЙ OV.-КАТАЛOГ» из MONSYS не встречается в опытах.
* **`1023`** — десятичное число; в machine-коде `0o043456 hi` = `XTA M8,1777B`.
  Счётчик зон лежит по `CAT+0o1777`, **не** по `0o1023`.
* **Передача управления компилятору отсутствует.** `UJ,F*INF0` (`0o043507`)
  передаёт управление *внутри MONSYS* загрузчику `F*INF0` (тело по `0o40065`,
  исходник 9253-9261), который лишь настраивает `INF0`, `STATIC*` и возвращается
  через `RET`. Адрес входа в сам компилятор MONSYS не вычисляется вообще:
  его определяет DMS-шапка загружаемого модуля и системный загрузчик.

**Следствие (ФАКТ):** искать в этом коде «final UJ на наш код» бессмысленно —
его нет ни в MONSYS-двойнике, ни (судя по эмпирике M3/M4) в M80. Точка входа
задаётся **дескриптором каталога + DMS-шапкой тела**.

## 5. СЕМАНТИКА ПОЛЕЙ f3 / f2 / f1 / f0

### 5.1 Битовый ФАКТ

Дескриптор = 48 бит = `f3<<36 | f2<<24 | f1<<12 | f0` (comparison.json,
`decode_412.py:g12`). Для FOREX3* `0o0400402757101760`:

| поле | значение | как 24-битная половина | дизассемблинг половины |
|:--|:--|:--|:--|
| f3 | `0o400` | HI=`0o04004027` | `ATX M1,4027B` |
| f2 | `0o4027` | (в HI) | — |
| f1 | `0o5710` | LO=`0o57101760` | `VJM M11,'01760'` |
| **f0** | **`0o1760`** | (в LO) | **адрес вызова `VJM` = f0** |

**ФАКТ:** дескриптор — не «чистая структура данных», а **пара команд БЭСМ-6**
(та же идея, что в каталоге MONSYS зоны 64, `include/catalog.md:61-63,167-183`).
**ФАКТ:** `f0` буквально присутствует как адрес перехода/вызова во второй команде:
FOREX3* → `VJM M11,'01760'`; LO*SYN → `UJ M14,'31551'` (старшие биты адреса
`0o30000` + `f0=0o1551`); LO*GEN → `XTS M7,1551B` (адрес = `f0=0o1551`).

### 5.2 Таблица семантики

| поле | FOREX3* | LO*SYN | LO*GEN | MONITOR* | вердикт |
|:--|:--|:--|:--|:--|:--|
| f3 | 0o400 | 0o401 | 0o411 | 0 | **ФАКТ:** высокий 12-битный индекс/тип раздела; значения 0o400/401/411 у трёх разделов 4.12. **ГИПОТЕЗА:** идентификатор «главный/оверлейный» + номер записи. |
| f2 | 0o4027 | 0o4236 | 0o0236 | 0 | **ФАКТ:** адресная часть первой команды (0o4027/0o4236/0o0236). **ГИПОТЕЗА:** смещение transfer vector / смещение в зоне (модель PERSO: `off+0o2010` сюда НЕ подходит, т.к. f3<0o2010). |
| f1 | 0o5710 | 0o7303 | 0o3403 | 0 | **ФАКТ:** код+mодifier второй команды. **ГИПОТЕЗА:** параметр загрузки (длина/атрибут); напрямую из кода TRNSLTOR не выводится. |
| f0 | **0o1760** | 0o1551 | 0o1551 | 0o370 | **ФАКТ:** (a) требуется ровно 0o1760 для главного раздела (f0-свип M4); (b) равен адресу `VJM` в дескрипторе; (c) равен базе `уиа …(М16)` в cmd[1] тела. **ГИПОТЕЗА:** f0 = базовый адрес/секционный ID раздела; `0o1551` = зона тела (N+1), `0o370` = монитор. |

### 5.3 Проверка на FOREX3* (как просил main agent)

* Подставляем `0o400402757101760`: `f0 = 0o1760`.
* **Сходится:** cmd[1] тела (`1551.0005`) = `0o7240176003000464` =
  `уиа 1760(М16)/пб 464` — база **ровно f0** (`412-objfmt/REPORT.md` §1.3).
* **Сходится:** дескрипторная половина `VJM M11,'01760'` Имеет адрес **ровно f0**.
* **Частично расходится:** печать монитора даёт `01770` для FOREX* (output.gold.txt:32);
  `0o1770 − 0o1760 = 0o10` — ГИПОТЕЗА: `0o1770` = адрес первой исполняемой
  команды после 0o10-словного загрузочного преамбула (маркер `0o73461`,
  stub, таблица дескрипторов); прямого доказательства нет.
* **ГИПОТЕЗА (вопрос):** `f0=0o1551` у LO*SYN/LO*GEN = номер зоны N+1, где лежит
  тело — это «ov0760/ov1551» пара из cmd[2]/cmd[3] тела
  (`0o0003770010073377`, `0o0004660000031551`).

**Итог:** f0 однозначно отождествлён с **базой/ID главного раздела = 0o1760**.
f1/f2/f3 однозначно *не* выведены: их интерпретация — ГИПОТЕЗА, требующая
дизассембла M80 NEWCOMP* (которого на образах нет, §7).

## 6. РЕКОМЕНДАЦИЯ ПО ЛАЙАУТУ НАШЕГО КОМПИЛЯТОРА

**ФАКТ-база** (подтверждена эмпирикой и настоящим дизассемблом):

| смещение | слово | что класть |
|:--|:--|:--|
| зона N.0000 | `0o5557565164576212` | TEXT `MONITOR*` (sentinel) |
| зона N.0001 | `0o370` | дескриптор монитора |
| зона N.0002 | TEXT имя, например `OURMRK*` | имя из `*TRANS:<name>,,41/N` |
| зона N.0003 | `0o400402757101760` | **дескриптор main с f0=0o1760** (менять f3/f2/f1 только если знаете зачем) |
| зона N+1.0000 | 0 | служебное слово зоны |
| зона N+1.0001 | `head\|sym<<12\|debug<<36` | шапка w0, минимально `head=1` |
| зона N+1.0002 | `set\|data<<15\|long<<30` | шапка w1, минимально 0 |
| зона N+1.0003 | `cmd\|bss<<15\|const<<30` | `cmd=NC` (длина кода), bss=const=0 |
| зона N+1.0004 | `0o73461` | стартовый маркер 4.12 (общий у FOREX3*/LO*) |
| зона N+1.0005 | `0o7240176003000464` | **entry stub** `уиа 1760(М16)/пб 464` — база = f0 |
| зона N+1.0006+ | наши команды | код; все адреса — относительно базы M16=0o1760 |
| … | TEXT наше имя | head-секция (1 слово) |
| зоны N+2… | 0 | загрузчик читает непрерывный пробег |

**Минимальный Fortran-эмиттер (продолжение `src/newcomp/EMIT.FTN`, HI/LO, NLV≤31):**

```fortran
C     O412 -- EMIT MINIMAL FOREX-4.12 MAIN SECTION (см. REPORT §6)
      SUBROUTINE O412
      INTEGER HI(32), LO(32), NW
      COMMON /EMBUF/ HI,LO,NW
      NW = 0
C-- каталог N: sentinel + имя + дескриптор f0=0o1760 -------------------
      CALL EMIT48(0,0,0, 0,0,0)
      HI(NW)=11991977                    ! 0o55575651
      LO(NW)=13827210                    ! 0o64576212  TEXT MONITOR*
      CALL EMIT48(0,0,0, 0,0,248)        ! 0o370
      CALL EMIT48(0,0,0, 0,0,0)
      HI(NW)=12541101                    ! TEXT OURMRK* hi
      LO(NW)=13283968                    ! TEXT OURMRK* lo
      CALL EMIT48(0,0,0, 0,0,0)
      HI(NW)=1050647                     ! 0o04004027 (f3/f2)
      LO(NW)=12354544                    ! 0o57101760 (f1/f0=0o1760)
C-- тело N+1: шапка + маркер + stub + код ----------------------------
      CALL EMIT48(0,0,0, 0,0,0)          ! B0 = 0
      CALL EMIT48(0,0,0, 0,0,1)          ! B1 w0: head=1
      CALL EMIT48(0,0,0, 0,0,0)          ! B2 w1: 0
      NC = 8
      CALL EMIT48(0,0,0, 0,0,NC)         ! B3 w2: cmd=NC
      CALL EMIT48(0,0,0, 0,0,30513)      ! B4: 0o73461 marker
      CALL EMIT48(7,20,1008, 0,24,308)   ! B5: уиа 1760(M16)/пб 464
C-- B6+: N=0; PRINT через *64 + GOSTEN (БЕЗ внешних SUBP!) -----------
      CALL EMIT48(0,41,15, 0,0,0)        ! зп 0 в ячейку 15
      CALL EMIT48(0,0,0, 13,0,0)         ! return
      PRINT 90, NW
   90 FORMAT(1X,'N3OBJ NW ',I3)
      RETURN
      END
```

**Почему именно так (ФАКТ/ГИПОТЕЗА):**

* `f0=0o1760` — **ФАКТ** (только это значение проходит свип M4).
* stub `уиа 1760(М16)/пб 464` — **ГИПОТЕЗА ранга 1**: он дословно скопирован с
  живого 4.12 и задаёт базу = f0. Именно отсутствие правильной базы
  (M16=0o40011 вместо 0o1760) даёт `Interrupt 00707 atx` (M4 §7).
* **Ноль внешних SUBP** — **ФАКТ**: попытка PRINT через `C=0o6300`/FT*003/FT*571
  в M4 приводила к `00707`; прямой вывод `*64`/`*21` + GOSTEN работает.
* `пб 464` — **ГИПОТЕЗА (неразрешено):** абсолютный адрес `0o464` или база+0o464
  (`0o2244`) — без трассы M80 NEWCOMP* не различается; на эмиттер не влияет,
  stub копируется дословно.
