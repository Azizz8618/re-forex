## ВЕРДИКТ: **DONE** (карта + рекомендация)

Главный результат — **КОРРЕКЦИЯ M4d**: `VJM 0o64002` — это вход в
**резидентный** компилятор монитора (загружен с диска 30, зона 0o51 при старте),
а НЕ точка, куда копируется наше тело. Тело зоны N+1 копируется загрузчиком
в ОЗУ с **0o1760** (цикл 0o701–0o711), с трансформацией полей. Доказательства
ниже.

`disbesm6 -a640 -e640 loader.bin` (копия из `core-pc.bin` слов 0o640..0o737).
Ключевые фрагменты (нейтральные мнемоники disbesm6; в скобках — мнемоники

0o666 зпм 153 / сда 64+5
0o667 и 0753 / слц 146           ; маска 0o777
0o670 зп 145 / Э70 145           ; ← *70, чтение тела зоны N+1

0o672 сч 4(М5) / зп 152          ; ← здесь в AU = 0o7240176003000464 = наше B5

**ФАКТ (трасса `live64002/ld2.err`, `BESM6_MTR_LO=0660 HI=0736 N=20000`):**
- на входе в цикл `M6 = 0o1760`, `M5 = 0o1760`, `M3 = 0o3530` (1832), `M11 = 0o70`;
- за один проход записано **1116 слов** по адресам **0o01760 … 0o02133**;
- M6 инкрементируется на 1 на каждой итерации → копия **плотная**, word 0
  попадает в **0o1760**, word 1 → 0o1761, …, word k → **0o1760 + k**;
- **слова 0 НЕ пропускается.**

Первые слова, реально записанные загрузчиком (ФАКТ, MTR `atx 0(6)`):

| RAM | записанное слово | ближайшее слово зоны N+1 | комментарий |
|:--|:--|:--|:--|
| 0o1760 | `0o5156606564434154` | B0 `0o1600043` | TEXT-слово, поле заменено |
| 0o1761 | `0o0003770010053377` | B2 `0o0003770010073377` | ↔ различается 1 цифра |
| 0o1762 | `0o0002240000001760` | B3 `0o0002220000001760` | ↔ `0222`→`0224` |
| 0o1763 | `0o0000000000053461` | B4 `0o0000000000073461` | ↔ `73461`→`53461` |
| 0o1764 | `0o0000000000000000` | — | терминатор |
| 0o1765 | `0o0003770010053377` | B6 `0o0003770010073377` | ↔ 1 цифра |
| 0o1766 | `0o0004160000005510` | B7 `0o0004660000031551` | поля переставлены |

**ФАКТ:** ни одно слово зоны N+1 не встречается в ОЗУ дословно; загрузчик
подставляет/переставляет поля (подтверждает ГИПОТЕЗУ M4d о «трансформации»,
но transformed-копия лежит в 0o1760+, а не в 0o64000+).

## 2. Что такое `0o64002` (ФАКТ, коррекция M4d)

### 2.1 Сам переход подтверждён

Собственный прогон (`live64002/jmp.err`, `BESM6_MTR_LO=00455 HI=00456`):

```
MTR 00455L vjm  64002(15) AU=5557565164576217  (M15=00401 → 00456)
MTR 64002L wtc  43(0)
MTR 64002R uj   64012(0)
MTR 64012L wtc  17(0)
MTR 64012R vtm  770(16)        ; M16 = 0o770
MTR 64013L atx  0(16)          ; записать ACC в 0o770
MTR 64013R xta  16(0)
MTR 64014L atx  1(16) AU=3770010053377
MTR 64015L atx  0(17)          ; R17 = 0o53403
```

То есть **первое, что исполняет CPU по 0o64002 — `wtc 43` / `uj 64012`:**
это не наш B4 (`0o73461`) и не наш B5 (`UIA/UJ`), а **код резидентного
компилятора**.

### 2.2 Решающий контроль: запуск БЕЗ `*TRANS`

Deck `live64002/notrans.b6` (обычная компиляция `PROGRAM MAIN / PRINT / END`,
**без `*TRANS`**) — `BESM6_CORE_ON_PC=064002`:

- PC=0o64002 **достигается** (`CORE DUMPED at pc=64002`);
- дамп ядра **побайтово совпадает** (32768/32768 слов) с дампом при
  `*TRANS:FOREX3*,,411550`;
- AAA-тесты: подмена слов тела 0, 1, 4 (B0, TEXT-имя, маркер) даёт
  **0 отличий** в полном дампе ядра при PC=0o64002 (хотя подмена B0
  ломает саму загрузку: `ОШИБКА МД ЭВМ` / `ПЕРЕПОЛНЕНИЕ АУ`).

**ФАКТ:** 0o64000+ — область **резидентного** FOREX 4.12 (в трассе виден
`*70` с INF `0o10320000300051` = диск 30, зона 0o51 на старте монитора).
`VJM 0o64002` — вызов резидентного компилятора монитором, а не переход
в загруженное нами тело. Формулировка M4d «точка входа в загруженный
компилятор» уточняется: **компилятор резидентный; загружается только его
каталог/оверлейное тело в 0o1760+**.

### 2.3 Роль B4/B5 (ФАКТ / A/B)

| слово | значение | роль | A/B |
|:--|:--|:--|:--|
| B4 | `0o0000000000073461` | наш маркер, данные/метка | обнуление в M4c не меняло консоль; в M4d FULL присутствует; замена на `0o5757…` в моём A/B не изменила дамп 0o64000 и не сломала `HELLO-CTRL` |
| B5 | `0o7240176003000464` | **ДАННЫЕ загрузчика** | в MTR на pc=0o00672L `atx 152` AU=ровно это слово; исполняемым кодом не является |

Косвенно подтверждается объяснение M4c: обнуление B4/B5 не ломало консоль,
потому что точка входа лежит в резидентном коде, а не в этих словах.

## 4. Минимальный набор слов префикса (ФАКТ / ГИПОТЕЗА)

| слово | статус | доказательство |
|:--|:--|:--|
| **B0** `0o1600043` | **обязательно** | M4c: B0=0 → TIMEOUT; мой A/B: сдвиг младшего бита → `ОШИБКА МД ЭВМ`/`ПЕРЕПОЛНЕНИЕ АУ` до вызова компилятора |
| **B5** `0o7240176003000464` | **обязательно** как данные | M4d: AU на pc=0o736 = это слово (загрузчик его читает) |
| B1 (TEXT-имя) | не обязательно | A/B: `ZZZZZZZZ` → прогон успешен (баннер, `HELLO-CTRL`, `КОНЕЦ ЗАДАЧИ`) без изменений |
| B4 (маркер) | не обязателен для загрузки/перехода | A/B: `0o5757…` → дамп 0o64000 тот же, progн успешен |
| B2,B3,B6..B15 | **ГИПОТЕЗА: нужны как живая шапка** | M4c: урезанная шапка (`head=1`) давала `ПЕРЕПОЛНЕНИЕ АУ` + `Interrupt 00707`; полная живая шапка работает. Индивидуальные A/B не ставились |

**Минимум для «принять и перейти» (ФАКТ + осторожная ГИПОТЕЗА):**
`B0 + B5 + B2/B3 + B6..B15` (живая 16-словная шапка 1551.0..15),
где B1 и B4 могут быть заменены на наши слова **без нарушения**
загрузки. B5 нельзя заменять кодом — это данные загрузчика.

## 5. Рекомендация для A3 (конкретная раскладка)

**ФАКТ, который нужно принять:** автономное «печатающее ядро» нельзя
положить по 0o64002 — это резидентный код монитора, он не перезаписывается
телом. Наш код должен жить в области загружаемого тела (0o1760+ и зоны
N+2…), а резидентный компилятор вызывается как есть.

Предлагаемая раскладка зоны **N+1** (адреса 0o1760+k) для A3:

| k | RAM | содержимое | 역할 |
|---:|:--|:--|:--|
| 0 | 0o1760 | `0o0000000001600043` (B0) | оставить как есть — обязателен |
| 1 | 0o1761 | **наш код/данные** | B1 не критичен (A/B) |
| 2–3 | 0o1762–0o1763 | живые `0o0003770010073377`, `0o0002220000001760` | шапка/f0 |
| 4 | 0o1764 | **наш код/маркер** | B4 свободен (A/B): замена на `0o5757…` не ломает прогон |
| 5 | 0o1765 | `0o7240176003000464` (B5) | **НЕ трогать** — данные загрузчика |
| 6–15 | 0o1766–0o1775 | живые слова 6..15 шапки | проверенный минимум |
| 16+ | 0o1776+ | наш entry-stub + вызов `*64`/GOSTEN + RETURN | первая свободная зона для нашего кода |

**Практический шаг A3:** ставить отладочный PRINT/маркер не в B4/B5, а
в слово **k=16 (RAM 0o1776)** и дальше; оставить 16-словную шапку и B0/B5
нетронутыми. B4 можно использовать как флаг/сигнатуру (M4d уже печатает
`M4D-O412B-MARK` именно с ним), но не как точку входа.

Если цель — **полностью убрать чужие оверлеи**, одного A3 недостаточно:
резидентный компилятор по 0o64002 остаётся, и M4d-результат достигается
именно с живыми зонами N+2..N+40. Здесь нужен A4/A5 (перенос кодогенератора
и оверлеев в наше тело), а не подмена 0o64002.
