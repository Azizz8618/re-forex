`0o113405` **точно** совпадает с дtran-строкой

Замечание (ФАКТ, интересная деталь): слово 0001 одновременно является
TEXT-словом `FOREX3*`, потому что числа `head=0o1200 sym=0o7023 debug=0o4657`
в 6-битной кодировке дают «FOREX3* ». То есть «TEXT-имя в word1» из M4 — это
**не альтернативный формат**, а то же самое поле `head|sym<<12|debug<<36`,
прочитанное как TEXT. Это объясняет, почему подстановка TEXT-имени
`OURMRK*` в word1 (варианты V_name/W_name) не лечит: она меняет `head` с 1 на
`0o1200`, `sym` с 2 на `0o7023`, заставляя загрузчик ждать 640+3603 слов
таблиц, которых в 20-словном модуле нет → `Interrupt 00711/00710`.

| word0 шапки | `0o4657624570231200` = head=`0o1200` sym=`0o7023` debug=`0o4657` — одновременно TEXT `FOREX3*` | `0o0000020001` = head=1 sym=2 (числовое, не TEXT) |
| word1 | set=`0o73377` data=`0o100` long=`0o377` | set=0 data=0 long=2 |
| word2 | cmd=`0o1760` bss=0 const=`0o222` | cmd=`0o11` const=3 |
| cmd[0] | маркер `0o73461` | первая команда `0o3444001047140006` |

| внешние ссылки | 0o7023 sym-записей (LINK-схема 740xx) | 2 записи C=`0o6300` → FT*003/FT*571 |
| длина | 0o113405 слов (~38 зон) | 20 слов |

ГИПОТЕЗА (ранг 1, подтверждена дампом W_hybrid): NEWCOMP* — **не
универсальный DMS-загрузчик**, а загрузчик специфического объектного формата
4.12. Он:
1. читает зону-каталог N и ищет имя из `*TRANS`;
2. сверяет f0 дескриптора с жёстко заданным «главным» ID `0o1760`;
3. грузит непрерывный пробег зон N+1, N+2, …;
4. ঔстанавливает базовый регистр **M16 = f0 = 0o1760** (ФАКТ: в дампе
   `W_hybrid/out.txt:30` регистры `02034 00001 65255 00000 **01760** 44274 00000 03332`
   — пятый регистр = `0o1760`);
5. передаёт управление по схеме компилятора (уиа/пб-stub в cmd[1]).

Подстановка нашего PERSO-DMS (с M16=`0o40011`, внешними C=`0o6300` и 20 словами)
в эту схему даёт `Interrupt 00707 atx` **до** PRINT (M4 §4/§5: обнуление
маркерной константы 0o14 не меняет диагностику — значит до PRINT действие не
доходит).

ГИПОТЕЗА (ранг 2, M4 §7.2): внешние `C=0o6300` не разрешаются NEWCOMP*;
путь (a) `*perso:602300` + `*call` обновляет LINK-таблицу, а `*TRANS`-путь —
нет (опыт P1 с `*perso:602300` перед TRANS эффекта не дал).

## 3. АНАЛИЗ ТОЧКИ ПАДЕНИЯ `00707 atx`

ФАКТ (M4 `runs/C2b/out.txt:29-30`, `CORRUPT14`, `V_hybrid`, `W_hybrid`):

```
Interrupt
 00707  17 100 7773	atx
```

Формат дампа dispak (`besm6-legacy/dispak/dispak.c:390`): ` Interrupt` — SIGINT
по таймауту (бесконечный цикл/зависание), затем слова отладчика:
`PC: IR KOP ADR mnemonics`, `acc`, `Y`, `R`, регистры. В `W_hybrid/out.txt`:

```
00707: 07 005 4503	a-x
  acc = 7760000037777774237 Y = 0000000030000000000 R = 001011 i=00000
       02034 00001 65255 00000 01760 44274 00000 03332
```

ФАКТ: PC=`0o00707` — **низкая память** (область резидента), а не наше тело.
Команда `a-x` с адресом `0o4503`; регистр M16 = `0o1760`. Значит управление
ушло в резидентный код компилятора с базой `0o1760`, но с **неквалифицированным
состоянием** (наш 20-словный модуль не задал нужные LINK/COMMON-ячейки и не
имеет загрузочной таблицы в cmd[0..5]).

Диагностика по обнулению (M4 §5, ФАКТ):

| обнулено слово зоны 1745 | Interrupt |
|---|---|
| — (эталон C2b) | `00707 … atx` |
| word 1 (head/sym) | `00704` |
| word 2 | `00711` |
| word 3 (cmd/const) | `00710` |
| word 4 (первая команда) | `00711`, затем `00707` |
| word 0o14 (маркер) | `00707` (без изменений) |

Вывод (ФАКТ): шапка **читается и влияет** на загрузку; падение 00707 —
уже после чтения шапки и первых cmd-слов, до исполнения PRINT.

## 4. СПЕЦИФИКАЦИЯ ЭМИТТЕРА ДЛЯ `src/newcomp/EMIT.FTN`

### 4.1 Что эмиттер должен выдавать (порядок слов)

Ниже — **минимальный 4.12-совместимый main-section объект**. Обозначения:
`N` — номер зоны каталога; тело — зона `N+1`.

#### Каталог (зона N), 4 слова:

| # | слово (восьм.) | decimal для Fortran DATA | смысл |
|---|---|---|---|
| K0 | `0o5557565164576212` | 201192002223242 | TEXT `MONITOR*` — обязательный sentinel |
| K1 | `0o370` | 248 | дескриптор монитора |
| K2 | `0o5765625562531200` | 210404773638784 | TEXT имя нашего модуля (здесь `OURMRK*`) |
| K3 | `0o400402757101760` | 17626944013296 | **дескриптор main**: f3=`0o400` f2=`0o4027` f1=`0o5710` f0=`0o1760` |

#### Тело (зона N+1):

| # | смещение | слово /-field | смысл |
|---|---|---|---|
| B0 | 0000 | 0 | служебное слово зоны (как в 1551.0000 / M4 1745.0000) |
| B1 | 0001 | `head\|sym<<12\|debug<<36` | шапка w0; **минимально**: head=1, sym=0, debug=0 → `1` |
| B2 | 0002 | `set\|data<<15\|long<<30` | шапка w1; минимально `0` |
| B3 | 0003 | `cmd\|bss<<15\|const<<30` | шапка w2: `NCmd + (NConst<<30)`, bss=0 |
| B4 | 0004 | `0o73461` = 30513 | маркер cmd[0] (общий для 4.12-модулей) |
| B5 | 0005 | HI=`0o72401760`=15336432; LO=`0o03000464`=786740 | cmd[1]: `уиа 0o1760(M16)/пб 0o464` — 4.12 entry stub |
| B6.. | 0006+ | машинные команды | код `N=0; PRINT 100; FORMAT(1X,I4)` |
| … | +cmd+const | TEXT имя модуля | head-секция (1 слово) |
| … | | sym/long/debug | **пусто** (минимальный вариант, без внешних SUBP) |

**Если нужен PRINT через FORMAT** (полный вариант), sym-секция получает
записи вида `(0o4000+X)<<24 | C<<12 | D` с `C=0o6300` (постоянная библиотека
монитора), long-имена `FT*003` (`0o4664122020230000`) и `FT*571`
(`0o4664122527210000`) — ровно как у N2MRK (`0o4620..0o4623`). **Но именно
этот путь в M4 привёл к `00707`**, поэтому рекомендуемый минимальный путь —
**без внешних SUBP**: PRINT заменить прямой выдачей через экстракод `*64` /
`*21` с GOST-строкой, сгенерированной `GOSTEN` из `EMIT.FTN`.

### 4.2 Кодирование слов (проверено по EMIT.FTN)

`EMIT48(IR1,K1,A1,IR2,K2,A2)` даёт `HI = IR1*2097152+K1*32768+A1`,
`LO = IR2*2097152+K2*32768+A2`. Проверка на stub:

* `EMIT48(7,20,1008, 0,24,308)` → HI=`15336432`=`0o72401760`,
  LO=`786740`=`0o03000464` ✓ (уиа 1760(M16) / пб 464).

### 4.3 Что требует помощи хоста

1. **Запись каталога и тела на диск 41** (`besmtool write` / копия 2148) —
   Fortran-эмиттер может только напечатать/сформировать слова; размещение
   зон N и N+1 делает host. Адреса `--start` в `besmtool` — **десятичные**,
   в мониторных картах — восьмеричные (M4 §1, ловушка `01744` vs `1744`).
2. **Проверка непрерывного пробега зон**: загрузчик читает N+1, N+2, …; host
   должен обнулить/заполнить последующие зоны, чтобы не подсунуть чужие слова.
3. **Дескриптор K3 и имя K2** должны совпадать с записью `*TRANS:<name>,,41/N`.
4. **TEXT/GOST-таблица** уже есть в `EMIT.FTN` (`GT`); host должен
   зафиксировать выбор `encoding.cpp:text_to_gost` (N3.2, §4.4 отчёта N3).
5. **Компиляция самого эмиттера** системным FOREX 2.02 через
   `*perso:602300` + `*forex`, `*to perso:6024xx` (ограничение NLV≤31).

имена ≤6 символов, массив HI(32)/LO(32) укладывается в NLV≤31.

```fortran
C     O412 -- EMIT MINIMAL FOREX-4.12 MAIN-SECTION OBJECT
C     catalog zone N: 4 words; body zone N+1: header + code.
C     NOTE: 48-bit constants are stored as two 24-bit INTEGERs HI/LO;
C     EMIT48 cannot be used for them (INTEGER mantissa limit 2**25-1).
      SUBROUTINE O412
      INTEGER HI(32), LO(32), NW
      COMMON /EMBUF/ HI,LO,NW
      NW = 0
C-- K0: TEXT 'MONITOR*' = 0o5557565164576212 ---------------------------
      CALL EMIT48(0,0,0, 0,0,0)
      HI(NW) = 11991977                   ! 0o55575651 (high 24 bits)
      LO(NW) = 13827210                   ! 0o64576212 (low 24 bits)
C-- K1: MONITOR descriptor 0o370 -------------------------------------
      CALL EMIT48(0,0,0, 0,0,248)         ! LO=248
C-- K2: TEXT 'OURMRK*' = 0o5765625562531200 ----------------------------
      CALL EMIT48(0,0,0, 0,0,0)
      HI(NW) = 12541101                   ! 0o57656255
      LO(NW) = 13283968                   ! 0o62531200
C-- K3: descriptor 0o400402757101760 (f0=0o1760) ----------------------
      CALL EMIT48(0,0,0, 0,0,0)
      HI(NW) = 1050647                    ! 0o4004027
      LO(NW) = 12354544                   ! 0o57101760
C-- B0..B3: body header -----------------------------------------------
      CALL EMIT48(0,0,0, 0,0,0)           ! B0 = 0 (service)
      CALL EMIT48(0,0,0, 0,0,1)           ! B1 w0: head=1 sym=0 debug=0
      CALL EMIT48(0,0,0, 0,0,0)           ! B2 w1: set=0 data=0 long=0
      NC = 8                             ! cmd length (marker+stub+code)
      CALL EMIT48(0,0,0, 0,0,NC)          ! B3 w2: cmd=NC, bss=0, const=0
C-- B4: start marker 0o73461 -----------------------------------------
      CALL EMIT48(0,0,0, 0,0,30513)
C-- B5: 4.12 entry stub ----------------------------------------------
      CALL EMIT48(7,20,1008, 0,24,308)    ! уиа 1760(M16) / пб 464
C-- B6..B(NC+2): our code (N=0; PRINT via *64) ------------------------
C     N3.3..N3.5 lowering supplies the IR/KOP/ADR pairs here.
      CALL EMIT48(0,41,15, 0,0,0)         ! example: зп 0 into cell 15
      CALL EMIT48(14,0,0, 0,64,0)         ! example: *64 print descriptor
      CALL EMIT48(0,0,0, 13,0,0)          ! example: UJ back / return
C-- head section (1 word): TEXT 'OURMRK*' -----------------------------
      CALL EMIT48(0,0,0, 0,0,0)
      HI(NW) = 12541101                   ! 0o57656255
      LO(NW) = 13283968                   ! 0o62531200
      PRINT 90, NW
   90 FORMAT(1X,'N3OBJ NW ',I3)
      RETURN
      END
```

Примечания к скетчу (ФАКТ/ГИПОТЕЗА):
* Значения halves проверены побайтово против `disk412_forex3_root.words`
  (`dump_root.py`): `0o5557565164576212 >> 24 = 0o55575651`,
  `& 0xffffff = 0o64576212`.
* `EMIT48(7,20,1008, 0,24,308)` даёт ровно `HI=0o72401760`, `LO=0o03000464`
  — точная копия cmd[1] живого 4.12 (проверено арифметически).
* `уиа 1760(M16)/пб 464` — **главный кандидат** на обязательный stub
  (ГИПОТЕЗА, ранг 1).
* `пб 464` — адрес из эталона; если NEWCOMP* передаёт управление не на cmd[0],
  а сразу на cmd[1] (после маркера), stub будет избыточен, но безвреден.

## 6. РЕКОМЕНДУЕМЫЙ МИНИМАЛЬНЫЙ ПОДХОД (steps 4 задания)

1. Каталог: sentinel `MONITOR*`/`0o370` + наше имя + дескриптор с **f0=`0o1760`**
   (иначе `НЕТ РАЗДЕЛА`).
2. Тело: 3-словная шапка с `head=1 sym=0 long=0 set=0`, `cmd=Nconst=0`,
   `bss=0`, MARКЕР `0o73461`, stub `уиа 1760(M16)/пб 464`, затем код.
3. **Ноль внешних SUBP** — никаких C=`0o6300`, никаких FT*003/FT*571,
   никаких sym/long-записей. PRINT заменить прямой выдачей `*64`/`*21` +
   GOSTEN-строка из `EMIT.FTN`.
4. С базой M16 = `0o1760` (f0): все адреса в коде — относительно M16.
5. Обнулить зоны N+2… (загрузчик читает их как продолжение тела).
6. Host записать зоны на копию диска 2148 и подать
   `*TRANS:<name>,,41/N`.

Это устраняет **обе** причины M4 §7: несовместимость LINK и неверную базу
M16=`0o40011`.

## 7. ПРОВЕРКА ГИПОТЕЗЫ О БАЗЕ (почему именно 00707)

ФАКТ: в N2 `уиа '40011'(М16)` задаёт базу PERSO (zone 0o2400).
ФАКТ: в 4.12 `уиа '1760'(М16)` задаёт базу = f0, и дамп W_hybrid показывает
M16=`0o1760` в момент падения.
ГИПОТЕЗА (ранг 1): при `*TRANS` загрузчик выставляет M16=f0=`0o1760`, но
наш код скомпилирован под M16=`0o40011`. Все абсолютные адреса our-кода
(`0o40006`, `0o40011`, LINK `0o74001` и т.д.) сдвинуты на
`0o40011-0o1760 = 0o37051` → переход в чужую область → зависание на `atx`
по адресу 00707. Лечится пересборкой кода с базой 0o1760 (§6.4).

## 8. ЧТО ОСТАЛОСЬ НЕИЗВЕСТНЫМ (честно)

1. **Точный адрес передачи управления.** В cmd[1] `пб 464`: это абсолютный
   адрес `0o464` (резидент) или смещение от базы `0o1760+0o464=0o2244`?
   disbesm6 печатает `пб '464'` без `(М16)`, но M16=`0o1760` установлен
   предыдущей половинкой. Без трассы на живом 4.12 (BESM6_DD_DEBUG) или
   дизассембла NEWCOMP* (PC `0o3000-0o3022`) это не различается.
   **Влияние на эмиттер**: минимально — stub копируется дословно.
2. **Семантика маркера `0o73461`** в cmd[0]. Известно только, что он
   одинаков у всех трёх модулей 4.12. Копируется дословно.
3. **Внутренняя структура LO*SYN/LO*GEN** (packed/entry-table form,
   первые слова `0o200022`, TEXT, `0o000377…`, `0o000466…`, `0o73461`, `0`,
   `0o000377…`, …) не сведена к unpacked-шапке; для главного раздела она
   не нужна.
4. **Адреса entry-точек 5 SUBP** (CONST/COMEQ/OPRTR/ПP/FOREX) и карта
   «адрес ↔ символ» отсутствуют (`docs/06-core-modules.md` §7).
5. **Дизассембл NEWCOMP\*** — отдельного DMS-модуля на доступных образах
   нет, только запись в STABLE `monsys.9:0o423226`.
