## 3. Разбор дескриптора (ФАКТ + ГИПОТЕЗА)

### 3.1 Полный перебор f0 (дескриптор FOREX3*: f3/f2/f1 = 0400/4027/5710)

| f0 | консоль |
|:--|:--|
| `0o1760` | `Interrupt 00711: 06 25 00001 utm` — **проходит проверку раздела**, грузит тело |
| `0o1761`, `0o1757`, `0o1762`, `0o1770`, `0o1551`, `0o140`, `0o24`, `0o11`, `0o20`, `0o100`, `0o4027` | `НЕТ РАЗДЕЛА OURMRK* 01770` |
| `0` | `СВОБОД 01770`, запись не находится |

**ФАКТ.** Для главного раздела компилятора требуется **ровно f0 = `0o1760`**,
независимо от 실제 `cmd` нашего DMS (`0o11`). f0 — это не «длина нашего cmd» и не
номер зоны: это идентификатор/адрес раздела главного компилятора (ср. `01770` в
сообщении об ошибке и `загрузка FOREX* @01770` в `logs/banner_recheck.txt:58`).

### 3.2 Дескриптор от LO*SYN (f3=0401 f2=4236 f1=7303)

| f0 | консоль |
|:--|:--|
| `0o1760` | `НЕТ РАЗДЕЛА OURMRK* 01770` |
| `0o11` | то же |
| `0o1551` | то же |

**ФАКТ.** Дескриптор оверлея для главного раздела не подходит; годится только
дескриптор FOREX3* с f0=`0o1760`. Это уточняет рекомендацию M3 §5: f2/f1
«можно скопировать с рабочего модуля» — но **именно с главного** (FOREX3*),
не с оверлея.

### 3.3 Трасса загрузки (BESM6_DD_DEBUG=1)

```
DD pc=03022L u=41 z=1744 RD uil=10/0/300      <- NEWCOMP* читает КАТАЛОГ
DD pc=00671L u=41 z=1745 RD uil=10/0/3200      <- загрузчик читает ТЕЛО (зона 1745)
DD pc=00744L u=41 z=1746 RD uil=10/0/3200      <- и далее зоны 1746, 1747, ... 2010
```

**ФАКТ.** NEWCOMP* читает одну зону-каталог, затем загрузчик читает **непрерывный
пробег зон** начиная с N+1 (в рабочем случае 4.12: 1745..2002, ~30 зон). Поэтому
в все опыты с телом в одной зоне 1745 и нулями дальше падали: загрузчик читает
дальше и получает нули. Это объясняет, почему первые попытки (f0=0o11, только
зоны 1744/1745) давали `НЕТ РАЗДЕЛА`/Interrupt.

## 7. Диагноз: чего не хватает (ГИПОТEЗЫ, ранг по правдоподобию)

1. **Формат DMS нашего модуля отличается от формата тела NEWCOMP*.** У 4.12
   `FOREX3*` слово 1 зоны 1551 — TEXT-имя раздела, `head=0o1200`, `sym=0o7023`,
   `cmd=0o1760`. У нашего N2MRK word1 = `0o020001` (числовые `head=1 sym=2`),
   имя живёт в long-символах (word 0o17), `cmd=0o11`. Подстановка TEXT-имени
   (варианты `name`/`hybrid`) проблему не снимает — значит дело не только в имени.
2. **Переадресация/LINK.** Наш модуль — релоцируемый DMS с двумя внешними
   `C=0o6300` (FORMAT `FT*003`, FORTLIBR `FT*571`). В пути (a) N2 они
   разрешаются из LINK-таблицы, обновлённой `*perso:602300`. В пути `*TRANS`
   загрузчик NEWCOMP*, по-видимому, не выполняет ту же перенастройку LINK для
   чужого DMS: старт уходит в неверный адрес → `00707 atx`. Подключение
   `*perso:602300` в опыте P1 эффекта не дало.
3. **Точка входа.** f0=`0o1760` — адрес/идентификатор раздела главного
   компилятора; NEWCOMP* передаёт управление по схеме компилятора, а наш модуль
   — подпрограмма с entry в начале загружаемой части (PERSO-каталог f0=0).
   Минимальное добавление для FULL: либо скомпилировать наш Fortran-маркер
   **самим 4.12** и снять его объектный DMS в формате NEWCOMP*, либо написать
   obj-эмиттер (план 57 N3/EMIT), выдающий DMS с `cmd=0o1760`, TEXT-именем
   раздела в word1 и корректными LINK-ячейками — **без** внешних SUBP.

**ГИПОТЕЗА (проверенная частично):**NEWCOMP* — это не универсальный DMS-загрузчик,
а загрузчик *специфического формата объектного модуля FOREX 4.12*; произвольный
DMS-модуль из PERSO в него не вставляется простой подменой зоны.

## 8. ФАКТ / ГИПОТЕЗА — коротко

- **ФАКТ:** карта `*TRANS:OURMRK*,,411744` находит имя в зоне 1744 и читает тело из 1745.
- **ФАКТ:** дескриптор должен быть `f3=0400 f2=4027 f1=5710 f0=1760`; любое другое f0 → `НЕТ РАЗДЕЛА`.
- **ФАКТ:** загрузчик читает непрерывный пробег зон N+1, N+2, ... (не одну зону).
- **ФАКТ:** наше тело меняет консоль и при обнулении наших слов диагностика меняется →это LOAD PROOF.
- **ФАКТ:** маркер `N2MARK-7391` не печатается ни в одном варианте.
- **ГИПОТЕЗА:** причина — несовместимость DMS-формата/LINK/entry; minimal fix — объект в формате 4.12 (см. §7).
