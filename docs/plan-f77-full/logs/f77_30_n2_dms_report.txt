### 3.1 Сколько внешних SUBP и почему «ноль SUBP» здесь не требуется

`siprod_lib.Library(z2400_n2.bin)` + разбор sym-секции (аналог
`f2b-inline/check_sym.py`):

```
sym[0] w=0o000400463000000 field[12..23]=0o6300  C=0o6300 EXTERNAL-SUBP
sym[1] w=0o000400363000000 field[12..23]=0o6300  C=0o6300 EXTERNAL-SUBP
RESULT: C=0o6300 external-SUBP entries = 2
```

long-секция модуля: `FT*003`, `FT*571` — записи FORMAT-трансфера. То есть два
внешних ссылки — **FORMAT и FORTLIBR** (рантайм `PRINT 100` / `nH`-FORMAT).
Они обновляются при `*perso:602300`, поэтому `*call` работает. Контроль
(`build_zero.deck`, `zeroext/2348`, `SUBROUTINE N2ZERO / RETURN / END`):

```
[0002] name='N2ZERO' rec=0o2250430000700000 f3=2250 f2=4300 f1=0070 f0=0000 L=7
at 0o4600 head=1 sym=0 cmd=0o7 const=0
C=0o6300 EXTERNAL-SUBP: 0
```

**Вывод:** требование F2b «ноль SUBP» относится к *автономному* head-модулю,
который грузят без системной PERSO. Для пути (a) с `*perso:602300` внешние SUBP
допустимы и разрешаются (доказано ещё в `tests/plan-f77/e1/callfortran/call/out.txt`:
`*CALL НЕLLО` → `*CALL WОRКS*`).

**Инлайнинг под NLV<=31 нереализуем.** По N1 (`/var/tmp/b1-f77-fix/n1/REPORT.md:312-317`)
граница `NLV ≤ 31`; при `NLV=32` → `ПЕРЕПОЛ РАБ ОБЛ ТР-РА`. Каркас уже держит
`RAW(72,NC)` и `C(132,NLV)` = 132×31 = 4092 слова. Модули `FORMAT`/`FORTLIBR`
занимают по каталогу `f1=0o750` и `f1=0o1050` (десятки/сотни слов кода + свои
BSS), а `N2FRON` уже имеет sym=0o1170 и 24 внешние `C=0o6300`. Втиснуть это в
лимит N1 вместе с tables и аллокатором невозможно; правильная стратегия —
оставить FORMAT/FORTLIBR во внешней PERSO и не инлайнить.

## 5. N2.5 / путь (b) — проверка гипотезы «FOREX* из PERSO»

### 5.1 Почему гипотеза выглядела правдоподобно

`/home/azizz/Yandex.Disk/monitor80-re/permanent/givtran%.asm:11-30`:
`SETTRAN*` берёт карту `MONCARD*`, вызывает `TTABLE*`
(`:20 M14,VTM,TTABLE*`), имя из `для*тип*трн` передаёт в `STACOMP*` (`:27-28`).
`permanent/ttable%.asm:22-23`: `*FOREX → TEXT,8НFOREX*`, `:32-33`:

### 5.3 Вывод по (b)

Директивы транслятора (`*FOREX`, `*FORX3`) **не берут модуль из temp-каталога
PERSO**: `*FOREX` всегда резолвится в системный `FOREX*` (баннер 2.02, системный
листинг), а `*FORX3` — в системную библиотеку, где `FOREX3*` отсутствует.
`*STAND` на это не влияет (в отличие от `*CALL *PASCAL` в pascal-re).
Исходники `givtran%.asm`/`ttable%.asm` относятся к сборке «Монитор-80 ИАЭ»;
целевой эмулятор — «Монитор-80 (3.7) ДУБНА», и поведение на нём иное.
Путь (b) закрыт: он требует правки монитора/системной библиотеки, что планом
(§3) и условием задачи запрещено. Тест «обнулить наше тело → исчезла
компиляция» в пути (b) непроведим, потому что наш модуль никогда не выбирается
транслятором (негативный результат получен на этапе выбора, до тела).
