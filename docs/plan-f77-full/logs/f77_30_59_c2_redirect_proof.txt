## 2. Ловушка N1: редирект без `NEXT` ничего не меняет

Первая версия патча `cu.c` просто ставила `pc = 0o1770; right = 0` в отладочном блоке
после декодирования инструкции. **ФАКТ 4:** это не работало — консоль и E64-трейс были
побайтово идентичны непатченному прогону, хотя в stderr было `REDIRECT pc=00455 -> 01770`.
Причина: после блока执行 switch всё равно исполнял уже декодированный `VJM`, который
перезаписывал `pc = 0o64002`. Исправление: добавить `NEXT;` (`goto _cont`) сразу после
установки `pc`, чтобы пропустить исполнение VJM. Это **ключевая деталь рецепта**.

Дополнительный ФАКТ: редирект на заведомо неверный адрес `0o77777` (без `NEXT`) тоже не
менял консоль — ложно создавало впечатление, что PC 0o455 «не на критическом пути».
С `NEXT` всё встало на места.

## 3. Чистый A/B с РАЗНЫМИ маркерами (решающий опыт)

Чтобы отделить печать нашего кода от баннера, дисковый GOST и RAM-GOST сделаны **разными**:

* диск (зона N+1, слова 13..19): `BANNER-DISK-7391`;
* RAM (инъекция по редиректу, слова 13..19): `OUR-CODE-RAN-7391`.

Оба кодируются одним и тем же эмиттером `gostenc.py` (GT-таблица из
`src/newcomp/EMIT.FTN`, `fmt=0, off=1, final=8` в дескрипторе).

| опыт | редирект | `body[9]` | консоль | disk маркер | RAM маркер |
|:--|:--:|:--:|:--|:--:|:--:|
| `clean_base` | нет | intact | ` BANNER-DISK-7391` | ДА | НЕТ |
| `clean_base_zero9` | нет | **0** | только `КОНЕЦ ЗАДАЧИ` | НЕТ | НЕТ |
| `fix_redir` | ДА | intact | ` OUR-CODE-RAN-7391` | **НЕТ** | **ДА** |
| `fix_redir_zero9` | ДА | **0** | только `КОНЕЦ ЗАДАЧИ` | НЕТ | НЕТ |

**ФАКТ 5 (A/B замкнут в обе стороны при редиректе).** При редиректе баннер с диска
**не печатается** (компилятор обойдён), а печатает исключительно наш код. Обнуление
нашего `*64` убирает маркер, восстановление возвращает.

**ФАКТ 6 (E64-трейс при редиректе, `--trace-e64`):**
только один вызов печати, и он идёт через **наш** дескриптор:

```
*** E64  01774-00000  format=0 offset=1 FINAL=010
*** E64  gost -056-111-107-013-061-056-077-045-013-107-040-105-013-007-003-011-001-231

```

(дескриптор `0o1772` указывает на GOST `0o1774`; `FINAL=010` = `final=8`+флаг вывода).
В непатченном прогоне E64-адреса были `53450/53464/05307` — резидентные дескрипторы.
Значит при редиректе печать действительно performs **нашим** `*64` и **нашим** дескриптором.

## 4. CORE DIFF: наши слова и GOST-байты в ОЗУ

## 6. Рецепт воспроизведения

1. **Патч КОПИИ `cu.c`** (не трогать `/usr/local/share/besm6` и не коммитить):
   взять `/home/azizz/Yandex.Disk/dispak/dispak/cu.c`, скопировать в свой каталог,
   вставить перед `if (dbg && montrace > 0)` блок из §7 (`BESM6_REDIRECT_PC/TO/WORDS`),
   обязательно с `NEXT;` после `pc = redir_to; right = 0;`.
   Сборка: `cmake .. -DCMAKE_BUILD_TYPE=Release && make -j4 dispak`.
2. **Сборка тела** (`c2.py`, `--marker BANNER-DISK-7391 --inject-marker OUR-CODE-RAN-7391`):
   каталог из 16 слов O412B; зона N+1 = 0..8 из O412B + 11 наших слов (§5) + хвост из root;
   зона N+2 = 526..900 из live 1552; зоны N+3..N+40 = 0. Deck из §1.
3. **Инжекция**: записать `redirect-words.bin` = 11 слов (body[9..19]) в  
   `BESM6_REDIRECT_WORDS`. Это локальная симуляция patched boot image C1, который должен
   разместить наш код по `0o1770` в RAM.
4. **Прогон**:
   ```
   cd runs/fix_redir
   BESM6_PATH=$PWD/disks \
   BESM6_REDIRECT_PC=455 BESM6_REDIRECT_TO=1770 \
   BESM6_REDIRECT_WORDS=$PWD/redirect-words.bin \
   ../dispak-patched -l deck.b6
   ```
   Ожидаемый вывод: ` OUR-CODE-RAN-7391` и ` КОНЕЦ ЗАДАЧИ`.
5. **A/B**: `--zero-body-word 9` → маркер исчезает; убрать опцию → возвращается.

**Что нужно от C1 для «настоящего» (не симулированного) уровня (a):**
patched boot image, который (1) кладёт наши 11 слов по `0o1770..0o1782` в RAM и
(2) меняет слово PC `0o455` с `VJM 0o64002` на переход к `0o1770`, **не давая**
декодированному VJM перезаписать PC (аналог нашего `NEXT`). Как только такой образ
появится в `/var/tmp/b1-f77-fix/59-c1/`, достаточно подменить `dispak-patched` на
обычный `dispak` и убрать env-переменные — deck и тело остаются теми же.

## 7. Точный текстpatcha cu.c

(вставка в отладочный блок главного цикла, сразу перед `if (dbg && montrace > 0) {`:)

```c
            /* === C2 REDIRECT (local simulation of C1 patched boot image) ===
             * BESM6_REDIRECT_PC  : octal PC to intercept (e.g. 455, the VJM 64002)
             * BESM6_REDIRECT_TO  : octal target PC (e.g. 1770, our code)
             * BESM6_REDIRECT_WORDS: file of 6-byte big-endian words to load
             *                      into core starting at REDIRECT_TO (our body
             *                      words 9..); loaded once before the jump. */
            {
                static int redir_pc = -1, redir_to = 0, redir_loaded = 0;
                if (redir_pc < 0) {
                    const char *rp = getenv ("BESM6_REDIRECT_PC");
                    const char *rt = getenv ("BESM6_REDIRECT_TO");
                    redir_pc = rp ? (int) strtol (rp, NULL, 8) : 0;
                    redir_to = rt ? (int) strtol (rt, NULL, 8) : 0;
                }
                if (redir_pc > 0 && abpc == redir_pc) {
                    if (!redir_loaded) {
                        const char *wpath = getenv ("BESM6_REDIRECT_WORDS");
                        redir_loaded = 1;
                        if (wpath) {
                            FILE *wf = fopen (wpath, "rb");
                            if (wf) {
                                int q = redir_to, n = 0;
                                unsigned char b[6];
                                while (fread (b, 1, 6, wf) == 6) {
                                    int k;
                                    for (k = 0; k < 6; ++k)
                                        core[q].w_b[k] = b[k];
                                    cflags[q] &= ~C_UNPACKED;
                                    ++q; ++n;
                                }
                                fclose (wf);
                            }
                        }
                    }
                    pc = redir_to;
                    right = 0;
                    NEXT;   /* skip the decoded VJM; fetch from redirect target */
                }
            }
```

## ГИПОТЕЗЫ

* **ГИПОТЕЗА (ранг 1, подтверждена ФАКТАМИ 5-7):** при редиректе `PC 0o455 -> 0o1770`
  с обходом VJM (`NEXT`) резидентный компилятор не вызывается, баннер с диска не
  печатается, а исполняется наш `*64` из RAM и печатает наш GOST-маркер через наш же
  дескриптор `0o1772 -> 0o1774`. Это и есть искомое доказательство «наш код исполняется».
* **ГИПОТЕЗА (ранг 2):** вpatched boot image C1 должен дополнительно решить задачу
  загрузки наших 11 слов в `0o1770..0o1782`, которую мы здесь симулировали инъекцией
  через env-переменную. Без этой загрузки переход на `0o1770` уйдёт в нули/резидентный код.
