Получен патчированный C-симулятор `dispak`, который **без единой env-переменной** (никаких
`BESM6_REDIRECT_*`, никаких `WORDS=`):
1. исполняет патченное слово по RAM `0o455` и переходит на `0o1770`;
2. берёт наши 11 слов **из реального образа диска** `2148`, зона `N+1 = 0o1745`, слова `9..19`,
   и кладёт их в RAM `0o1770..0o1782` **до** самого перехода;
3. при `*TRANS:OURMRK*,,411744` на консоли печатает `OUR-CODE-RAN-7391` из НАШЕГО `*64`,
   баннер `BANNER-DISK-7391` не печатается;
4. CORE DIFF и A/B замкнуты: в RAM наши слова и наши GOST-байты; обнуление `body[9]`
   убирает печать, восстановление возвращает.

## 1. Что именно пропатчено (ФАКТ)

Два файла КОПИИ исходников `/var/tmp/b1-f77-fix/59-c3/src-dispak/`. Точные diff-ы лежат в
`patches/defs.h.patch` и `patches/cu.c.patch`.

### 1.1. `dispak/defs.h`, макрос `STORE` (патч C1, без env)

При записи монитором слова `6710000202200000` по адресу `0o455` (это слово конструируется
рантайм-циклом `0o64415..0o64427` из страницы `0o64000`, см. C1) подставляется адресное поле
`2 -> 0o15770 = 0o1770 - 0o64000`:

```
БЫЛО: 6710000202200000   байты dc 80 02 09 00 00   vjm 64002(15)
СТАЛО:6711577002200000   байты dc 9b f8 09 00 00   vjm 1770(15)
```

Проверка адреса: `0o15770 + 0o64000 = 0o77770`, `0o77770 & 0o77777 = 0o1770`.
Патч стоит **до** декодирования, поэтому отдельный `NEXT;` из C2 не нужен: когда PC становится
`0o455`, CPU читает уже патченное слово (C1, §4).

### 1.2. `dispak/cu.c`, функция `c3_install_our_words()` (новое, вместо C2-env-инъекции)

Блок C2 с `BESM6_REDIRECT_PC/TO/WORDS` **удалён полностью**. Вместо него в точке того же
`STORE`-хука вызывается функция, которая:
- `disk_open(2148, DISK_READ_ONLY)`;
- `disk_readi(dh, 01745, buf, NULL, NULL, DISK_MODE_QUIET)` (тот же зонный протокол, которым
  харнесс записал тело через `besmtool write 2148 --start=01745`; в `disk_readi2` для
  `DISK_MODE_QUIET` происходит `zone += ZONE_OFFSET(4)`, поэтому читается та же физическая зона);
- копирует 6 байт слова `i` из `buf[(9+i)*6 ..]` в `core[01770+i].w_b[0..5]` для `i = 0..10`,
  сбрасывает `C_UNPACKED`;
- делает это один раз (`static int done`).

Слово **не захардкено**: при смене маркера в теле на диске меняются и байты в RAM, и печать
(см. §5). Это и есть доказательство, что источник слов, диск, а не константа в исходнике.

```

`BANNER-DISK-7391` в консоли: **0 вхождений**. Слово `0o455` в дампе ядра:
`6711577002200000` (в базе `6710000202200000`).

Трасса (`runs/c3_final/trace.err`) ровно по две строки патча:

```
C3: loaded 11 body words from disk 2148 zone 01745 into RAM 01770..01782
C3PATCH pc=64425 0o455: 6710000202200000 -> 6711577002200000
```

E64-трасса (`--trace-e64`) показывает, что печать идёт через **наш** дескриптор `0o1772`:

```
*** E64  01774-00000  format=0 offset=1 FINAL=010
*** E64  gost -056-111-107-013-061-056-077-045-013-107-040-105-013-007-003-011-001-231

`0o1774` это адрес нашего GOST; `FINAL=010` = `final=8` плюс флаг вывода. В непатченном
прогоне C2 E64-адреса были `53450/53464/05307` (резидентные дескрипторы).

| опыт | `body[9]` | RAM `0o1770` | консоль |
|:--|:--|:--|:--|
| `c3_final` | `0064177202200000` | `0064177202200000` | `OUR-CODE-RAN-7391` |
| `c3_zero9` | `0` | `0000000000000000` | только `КОНЕЦ ЗАДАЧИ` |

В `c3_zero9` GOST-байты в RAM остаются на месте (маркер в дампе есть), но печати нет: значит
печать действительно выполняется НАШИМ кодом по `0o1770`, а не просто присутствует в памяти.

## 6. Точный рецепт воспроизведения

1. Копия исходников: `cp -a /var/tmp/b1-f77-fix/59-c1/src-dispak /var/tmp/b1-f77-fix/59-c3/src-dispak`
   (в C1-копии уже есть патч `defs.h`; здесь он сохранён и дополнен вызовом `c3_install_our_words`).
2. Применить `patches/defs.h.patch` и `patches/cu.c.patch` (от inplace-копии C2; `cu.c.patch`
   одновременно удаляет env-блок C2). `disk.c` не менялся (дифф пустой).
3. Сборка:
   ```
   cd /var/tmp/b1-f77-fix/59-c3/src-dispak
   cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
   cmake --build build --target dispak -j4
   cp build/dispak/dispak /var/tmp/b1-f77-fix/59-c3/dispak-c3
   ```
4. Харнесс `c3.py` строит диски в `runs/<case>/disks` из локальных копий (`disks/2048,2053,2099`
   и копии `/usr/local/share/besm6/2148`), пишет каталог в зону `0o1744`, тело (O412B-префикс
   слова `0..8` + наши 11 слов в `9..19`) в зону `0o1745`, `N+2` и нулевые зоны `N+3..N+40`,
   кладёт deck и переменную `BESM6_PATH`. Все `BESM6_REDIRECT_*` принудительно
   вычищаются из env.
5. Прогон:
   ```
   cd /var/tmp/b1-f77-fix/59-c3
   python3 c3.py c3_final --trace-e64 --core-pc 1770
   ```
6. A/B: `python3 c3.py c3_zero9 --core-pc 1770 --zero-body-word 9`; затем без опции
   `python3 c3.py c3_restore --core-pc 1770`.
