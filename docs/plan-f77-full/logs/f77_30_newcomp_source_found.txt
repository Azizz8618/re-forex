## 2. КОНТРАКТ ПО ИСХОДНИКУ (FACT)

### 2.1 Синтаксис карты (комментарий authors, строки 9073-9102)

```
*TRANS<РАЗД-ЛЬ1><ИМЯ ТРАНСЛЯТОРА><РАЗД-ЛЬ2>[<УК.МЛ>]
```

* `РАЗД-ЛЬ1` = `:` или `-`: порядок просмотра статических библиотек
  (`:` = основная → дополнительная → личный OVERLAY; `-` = наоборот).
* `РАЗД-ЛЬ2` = `,` или `.`: `,` = статическая библиотека, `.` = временная
  (динамическая).
* `<УК.МЛ>` — **указатель носителя**, 6 октальных цифр.

Дословный пример из исходника (строки 9098-9100):

```
*TRANS-FORTRAN,67200  -  TP-P BЫБEPETCЯ
   ИЗ OVERLAY,HAXOДЯЩEЙCЯ HA HOCИTEЛE,
   ЗAKAЗAHHOM ПOД MAT.HOMEPOM 67 C 200-Й ЗOHЫ.
```

**FACT:** это ровно та же кодировка, что в опытах: `67200` = «носитель 67, зона 200»;
`411550` = «носитель 41, зона 0o1550». Подтверждено трассой:
`DD pc=03022L ... u=41 z=1550 RD` и словом `*70` = `0o0010030000411550`.

### 2.2 Разбор карты и проверка указателя (строки 9265-9296)

```
 TRANS:  ,ATX,S/CALL
         ,ATX,PRIOR
     10,VTM,0        ,CALL,PARAMT*.HACTPOЙКА
     14,V1M,OШФOPM
     11,VZM,ALIBPR  / 11,UTM,-MINUS / 11,V1M,TRA
 TRA:    ...        10,VTM,3  ,CALL,PARAMT*.ЗA ИMEHEM
     14,V1M,OШИMЯ   ,ATX,TRNAME*
     11,VZM,TR1     / 11,UTM,-POINT / 11,VZM,SWT1
     9,VTM,INFT     10,VTM,4   ,CALL,PARAMT*.ЗA YKAЗAT.
     14,V1M,OШYKAЗ  12,VZM,OШYKAЗ
     ,ARX,C500000   ,AEX,B19   ,AAX,CH/IW   ,U1A,OШ YKAЗ
```

* имя берётся **из карты** (`PARAMT*` параметр 3 → `TRNAME*`) и больше нигде не
  сравнивается с заголовком загружаемого модуля;
* 4-й параметр (`PARAMT*` параметр 4) → `INFT` (ячейка `0o4054` вmachine-коде);
* три константы проверки: `C500000=0o500000`, `B19=0o1000000`,
  `CH/IW=0o1006000` (маска «100 6000»); нарушение → `*** ОШИБКА В УКАЗАТЕЛЕ`.

### 2.3 Чтение каталога (строки 9297-9317)

```
 ,XTA,/NP
 ,AOX,INFT
 ,ATX,INFT
 ,TAPE,INFT          <-- *70 с INF-словом /NP + введённый указатель
 C,VTM,CAT           <-- C = 0o40000, CAT = 0o4000 (2048-словный буфер)
 C,XTA,1762B         <-- слово CAT+0o1762
 ,AEX,CODE           <-- CODE = ISO,6HOVERLA
 ,U1A,OШKAT          <-- "ПЛОХОЙ OV.-КАТАЛОГ"
 C,XTA,1023          <-- 1023 БЕЗ B = ДЕСЯТИЧНОЕ = 0o1777 (доказано machine-кодом)
 ,UZA,MAЛMЛ          <-- "ПРИ СБОРКЕ МАЛО МЛ"
 14,VTM,CAT+1762B / ITS 14 / 14,UTM,12 / ITS 14 / 14,VTM,21 / ITS 14
 C,VTM,CAT-2 ,CALL,PRINT8     <-- печать комментария OVERLAY
```

**FACT (важно):** `C,XTA,1023` — это **десятичное 1023**, в machine-коде слово
`0o043456` содержит `XTA M8,1777B`. То есть счётчик зон лежит по адресу
`CAT+0o1777`, а маркер `OVERLA` — по `CAT+0o1762`, а не по `0o1023`.

### 2.4 Дальнейшая обработка (строки 9318-9362)

1. Перенос прочитанного каталога на барабан 25 (`DRUM,RD/25`, проверка слов
   `1024`/`1025`, запись `DRUM,WD/25`).
2. Цикл `T*LIB`: `XTA,B1 / ARX,INFT / ATX,INFT` — **увеличение номера зоны на 1**;
   затем `TAPE,INFT` + `DRUM,INFD`; повторяется `L` раз, где `L` — счётчик из
   `CAT+0o1777`.
3. `PUT*25`: `XTA,INF/25 / UJ,F*INF0` — подключение библиотеки 25 как
   `INF/25 = LOG,10 0000 0025 0000`, затем передача управления загрузчику.

**FACT:** в версии MONSYS тело компилятора **копируется зона за зоной с носителя
на барабан 25**, начиная со зоны, следующей за зоной каталога (инкремент `INFT`
в `T*LIB`). Это качественно совпадает с эмпирическим «тело в зоне N+1 и далее».

## 4. СООТНЕСЕНИЕ С ЭМПИРИКОЙ M3/M4

| Эмпирический факт (logs M3/M4) | Исходник/machine-код TRNSLTOR | Вердикт |
|:--|:--|:--|
| `*TRANS` → `NEWCOMP*` | `ltable%.asm:37-38`; комментарий в `MonitorDubna.txt:311-312` | **FACT, подтверждено** |
| параметр `411550` = 6 окт. цифр: диск 41 / зона 0o1550 | пример `67200` = «носитель 67, зона 200»; `PARAMT*`.param4 → INFT | **FACT, подтверждено** |
| `*70` = `0o0010030000411550` | `XTA,/NP; AOX,INFT; ATX,INFT; *70,INFT` — INF собирается из базового `/NP` + введённого указателя; префикс `0o001003` найден в monsys.9 по адресу 0o100471 | **FACT (механизм), детали сборки /NP в MONSYS не совпадают с M80** |
| имя из `*TRANS` произвольное; имя внутри DMS игнорируется | имя идёт только из карты (`PARAMT*.ЗA ИMEHEM` → `TRNAME*`), заголовок модуля не читается | **FACT, подтверждено** |
| зона N = каталог; тело начинается с N+1 и читается последовательно | `TAPE,INFT` читает каталог; `T*LIB` инкрементирует `INFT` на 1 и читает зону за зоной | **FACT, подтверждено качественно** |
| каталог содержит пары «TEXT-имя / 4×12-бит дескриптор» (1550.0002/3 и т.д.) | исходник MONSYS ищет `OVERLA` по `CAT+0o1762` и счётчик по `CAT+0o1777`; **описывает другой формат каталога** | **НЕ ПОДТВЕРЖДЕНО** (версия DUBNA ≠ M80). ГИПОТЕЗА: M80 переделал формат каталога, сохранив маркер `OVERLA` (он реально есть в зоне 1550 по слову **0o12**, см. ниже) |
| `f0 = 0o1760` обязателен | в исходнике TRNSLTOR 4×12-битных дескрипторов нет вообще; `M1000 = 0o200000...` — битовый флаг `FLG`, а не base-регистр | **ОПРОВЕРЖЕНО как «M16 = f0»**: M16 в исходнике — флаг загрузки транслятора. Что такое f0 в M80 — по-прежнему ГИПОТЕЗА (идентификатор раздела главного компилятора) |
| «тело должно иметь cmd=0o1760» | TRNSLTOR не смотрит DMS-шапку; в опытах M4 our module с `cmd=0o11` **загружался** (менялась диагностика Interrupt), но падал позже | **ОПРОВЕРЖЕНО**: 0o1760 требуется в каталожном f0, а не в cmd тела |
| ошибка `НЕТ РАЗДЕЛА` при f0≠0o1760 | в MONSYS соответствующие сообщения другие: `ПЛОХОЙ OV.-КАТАЛОГ`, `ПРИ СБОРКЕ МАЛО МЛ`, `ОШИБКА В УКАЗАТЕЛЕ` | **ГИПОТЕЗА**: диагностика M80 переписана; прямого исходника нет |

### Дополнительный ПОДТВЕРЖДАЮЩИЙ ФАКТ

Каталог `2148:0o1550` (копия диска взята в `z1550.bin`) содержит по слову
`0o12` ровно то же ISO-слово `0o2365310524446101` = `OVERLA`, что и константа
`CODE` в machine-коде TRNSLTOR (`0o043570`). То есть **маркер OVERLAY в каталоге
M80 присутствует**, но смещён относительно MONSYS (слово 0o12 вместо 0o1762).
Слова `0o13..0o16` зоны 1550 ISO-текстом дают ` OT  `, `27.06`, `85 M3 `, `<<-->>`
— это комментарий сборки 4.12, который в MONSYS печатается через `PRINT8`.

## 5. ЧТО ОСТАЛОСЬ НЕПОДТВЕРЖДЁННЫМ

1. **FACT:** исходника именно MONITOR-80 `NEWCOMP*` в локальных репозиториях нет.
   Проверены: `monitor80-re`, `besm6-new`, `re-dispak`, `dispak`, `re-forex`,
   `simh/BESM6` (включая бинарные файлы, регистр, KOI7/GOST-варианты написания).
2. **FACT:** образ с memory-адресом `02404` (MONITOR-80) не найден: в `monsys.9`
   этот адрес — DATA (нули/другая таблица); код TRNSLTOR найден в зоне 0o21,
   но это сборка DUBNA с другими абсолютными адресами.
3. **ГИПОТЕЗА (высокая):** ف0=0o1760 в каталоге M80 — это «идентификатор главного
   раздела 4.12/2.02», а не длина и не base. f2/f1 (`4027`/`5710`) скорее всего
   задают адрес загрузки/оверлейные параметры; исходник MONSYS эти поля не
   использует, поэтому вывести их точный смысл из найденного кода невозможно.
4. **ГИПОТЕЗА:** расхождение форматов каталога (TEXT-пары в M80 против
   `OVERLA@1762` + счётчика@1777 в MONSYS) — результат доработки утилиты в ИАЭ;
   это объясняет, почему `НЕТ РАЗДЕЛА/ОТСУТСТВУЕТ` появляются в опытах, но нет в
   монсийской диагностике.

## 6. ИТОГ ДЛЯ MAIN AGENT

* Можно перестать искать «исходник NEWCOMP*» как отдельный файл: его нет ни в одном
  локальном репозитории. Есть исходник **его монсийского двойника TRNSLTOR** —
  он даёт точный синтаксис `*TRANS`, кодировку 6-значного указателя, схему
  `TAPE`→каталог→инкремент зоны→`DRUM`/`INF` и точные сообщения об ошибках.
* Эмпирический контракт M3/M4 **не опровергнут**: подтверждены указатель, имя из
  карты, и каталог+тело в N+1. Опровергнуты только две спекуляции:
  «f0 = M16 base» и «cmd тела обязан быть 0o1760».
* Для полного подтверждения формата 4×12-битного дескриптора нужен machine-код
  MONITOR-80 по адресу `03022` (или исходник его версии), которого в доступных
  образах нет.
