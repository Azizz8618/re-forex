STEP 2 — question: FILMAP in PERSO 0o2320 or in ARFA catalog?
  ARFA catalog slot format (arfa.c:60-65, 307-339): 13 words, name 12 GOST bytes,
    owner, nzones, zone, rights, dates. NO free fields for Fortran unit,
    RECPOS, EOF, IOSTAT. Adding them = patch arfa.c + on-disk volume format,
    breaking real volumes (out of scope, READ-ONLY here).
  ARFA catalog is persistent across emulator restart (arfa.c:41-43); Fortran unit
    state is per-job. Storing it there leaks state between jobs.
  => DECISION: /FILMAP/ lives in PERSO 0o2320 as labeled COMMON. ARFA stays the
    persistent namespace; FILMAP is the volatile runtime binding
    Fortran u -> GOST name -> U(030..067) -> zone/position/EOF/IOSTAT.
  This is an EXTENSION of /J24STT/ OPN(16), not a new mechanism.

STEP 3 — field layout chosen (32-f77-on-arfa.md §3.2)
  FMNAM(2,NF)  = 12 GOST bytes, exactly arfa.c:115/321 representation (6/words)
  FMLU         = Fortran unit u (search key; NOT the ARFA LUN)
  FMARU        = ARFA logical number U from Э63 12 acc.r (arfa.c:1174)
  FMOWN        = schifr owner for Э63 01/02
  FMMOD        = 0 closed / 1 R / 2 RW (W12 in op_order)
  FMACC/FMFRM  = cached profile attrs (ARFA cannot report them)
  FMREC        = requested RECL, words (profile only)
  FMZON        = nzones from Э63 07 / set at 01
  FMPOS/FMEOF  = current zone index; EOF when FMPOS >= FMZON
  FMIST/FMRAW  = profile IOSTAT + raw M16 octal code
  FMGRB        = grab flag 0/1/2 (one area per task, arfa.c:1305-1307)
  NF=16 (->32 trivial). Invariants + procedure set FOPEN/FCLOSE/FINQ/FINQE/
  FINQX/FREAD/FWRIT documented in §3.3.
