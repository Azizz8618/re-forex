## 1. ФАКТ: точный диапазон и способ acquiring хвоста

`reference/412/disk412_forex3_root.words` = 2112 48-битных слов (6 байт/слово).
Слова `0..18` этого файла — живая шапка тела B0..B18; в A4 харнесс `a4c.py`
использовал `body = O412C[16:35] + live_root[19:1024]`, то есть **хвост
`live_root[19:1024]` — ровно 1005 слов** — брался из живого файла. Это и был
последний источник неавтономности.

ФАКТ (побайтовая сверка): `O412D` эмитирует эти 1005 слов как десятичные
константы; сверка с живым файлом — **1005 / 1005 совпадений**.

---

## 2. ГИПОТЕЗА (подтверждённая экспериментом): причина старого сбоя 394/1415

ГИПОТЕЗА A4 («ресурс/память FOREX 2.02 исчерпаны, лимит вывода ~400 слов»)
**опровергнута**. Проведены три опыта с одним и тем же генератором
(`gen_tail.py --single`), отличавшихся только размером массива `/EMBUF/`:

| опыт | слов в эмитенте | `INTEGER HI(n),LO(n)` | строк Fortran | результат |
|:--|:--|:--|:--|:--|
| `single1005` | 1005 | `HI(1100)` | 4071 | `O412DNW 1005`, **1005/1005 слов**, 0 ERR |
| `lim1415_a1100` | 1415 | `HI(1100)` | 5711 | `O412DNW *723`, выведено **317** слов, NW испорчен |
| `lim1415_a1500` | 1415 | `HI(1500)` | 5711 | `O412DNW 1415`, **1415/1415 слов**, 0 ERR |

ФАКТ: система FOREX 2.02 компилирует 5711 строк / 1415 слов без единой `ERR`
и печатает все слова. Причина сбоя A4 — **недосылка массива COMMON**:
`HI(1100),LO(1100)` при записи 1415 слов. Раскладка `/EMBUF/` —
`HI(1..1100), LO(1..1100), NW`; при `NW=1101` запись `LO(1101)` перекрывает
сам `NW`, после чего счётчик портится и цикл `DO 10 I=1,NW` печатает обрывок.
(Точное число 394 в старом опыте зависит от того, каким словом перекрыли `NW`;
в нашем воспроизведении с `HI(1100)` получилось 317 и `NW=*723`.)

Итог: **лимит вывода FOREX 2.02 не существует**; достаточно корректно
размерить `/EMBUF/` либо разбить эмиссию на несколько подпрограмм.

## 3. ФАКТ: итоговый эмиттер `O412D.FTN` (chunked, канонический)

Как и требовалось в задании, выбран **многоUNIT-вариант** (устойчивый к любым
будущим лимитам размера одного UNIT):

```
      SUBROUTINE DRIVER          NW=0; CALL EMT00..EMT03; CALL DUMP
      SUBROUTINE EMT00           слова 0019..0270  (252 слова)
      SUBROUTINE EMT01           слова 0271..0522  (252 слова)
      SUBROUTINE EMT02           слова 0523..0774  (252 слова)
      SUBROUTINE EMT03           слова 0775..1023  (249 слов)
      SUBROUTINE DUMP            prints O412W HI/LO + O412D <n> <HI> <LO>
      SUBROUTINE OCT8            24-bit INTEGER -> 8 октальных цифр
```

- 4089 строк, `INTEGER HI(1100),LO(1100),NW` в каждом UNIT, `COMMON /EMBUF/`.
- Все 1005 слов записаны парой `NW=NW+1; HI(NW)=<dec>; LO(NW)=<dec>`.
- Вывод: `O412D <n> <HI-dec> <LO-dec>` + служебные `O412D-412`, `O412DNW 1005`.
- Компиляция: `build_rc=0 call_rc=0 build_ERR=0 DSE=1 DNW=1 O412D=1007`
  (1007 = 1005 слов + 2 служебные строки; 1005/1005 значений совпали с живым
  хвостом). Проверено и для `full_chunked` в полном харнессе.

Альтернатива (проще, тоже PROVEN): `O412D_single.FTN.bak` — один UNIT
`EMTALL`, 4071 строка, `HI(1100)`, те же 1005/1005 слов. Разница между ними
только в числе SUBROUTINE; обе дают идентичный вывод.

## 4. ФАКТ: полный прогон (харнесс `b1.py`)

`b1.py` **вообще не читает** живой файл при построении диска (только опционально
для контрольной сверки). Он берёт `runs/build_o412c/call.out` (410 слов) и
`runs/single1005/call.out` (1005 слов), собирает тело 1024 слова и пишет зоны
на локальную копию 2148.

```
case=full_auto rc=0 banner=True endtask=True C=410 D=1005 body=1024
live_compare diff=10 outside_our_code=0 first_outside=[]
```

Консоль (`runs/full_auto/out.txt`) дословно:

```
           *TRANS:OURMRK*,,411744
 FOREX 5.00 / 19.11.2026 (RE-FOREX)
 06147: 07 070 0332	*70
  acc = 0000320000300000 Y = 0000000000000000 R = 000110         i=06000
 КОНЕЦ ЗАДАЧИ
```

`diff=10` — это ровно 10 наших слов в диапазоне 0..18 (B9..B18), отличающихся от
живой шапки; **вне наших кодовых слов 0..18 отличий 0**. Строка `*70` на
`06147` присутствует и в эталонном A4-прогоне (`runs/baseline/out.txt`), то есть
не является ошибкой.

Жёсткое доказательство независимости: файл
`ref/disk412_forex3_root.words` был временно переименован в `.BAK`, после чего
`b1.py no_live_file --no-live-check` дал тот же результат
(`rc=0 banner=True endtask=True`), затем файл возвращён.

## 5. ФАКТ: A/B-доказательство на эмитированных словах хвоста

Полное сканирование `scan_ab.py` (обнулить каждое из 1005 эмитированных слов
хвоста по очереди, 3-секундный таймаут) нашло **6 критических слов**:

| слово тела | индекс в O412D | результат при обнулении |
|:--|:--|:--|
| 36 | 18 | TIMEOUT |
| 147 | 129 | TIMEOUT |
| 387 | 369 | rc=0, баннера нет |
| 670 | 652 | rc=0, баннера нет |
| 910 | 892 | TIMEOUT |
| 919 | 901 | TIMEOUT |

Контрольная точка A/B на слове `body=36` (эмиттерный индекс 18) в обе стороны:

```
базис:                   rc=0  banner=True  endtask=True  FOREX 5.00 ... КОНЕЦ ЗАДАЧИ
обнулить O412D[18]:      rc=TIMEOUT  banner=False  (только *TRANS, тишина)
восстановить (снова):    rc=0  banner=True  endtask=True  FOREX 5.00 ... КОНЕЦ ЗАДАЧИ
```

ФАКТ: A/B замкнут на слове, сгенерированном **нашим** Fortran. Остальные 999
слов по отдельности не критичны (как и в зоне N+2, где по отдельности критичны
были лишь 526 и 900); хвост в целом обязателен: обнуление диапазона `19..118`
тоже даёт TIMEOUT.

## 6. Точная рецептура воспроизведения

Все команды выполнять в `/var/tmp/b1-f77-fix/59-b1/` с теми же локальными
копиями дисков (`disks/2048,2053,2099,2348,2348-wr`, `ref/*`, `dispak`).

```bash
# 1) Эталонный эмиттер A4 (каталог + 19 слов тела + 375 слов зоны N+2)
python3 build_o412c.py                       # -> runs/build_o412c/call.out, 410 слов

# 2) Новый эмиттер хвоста N+1 (4 UNIT x ~252 слова)
python3 gen_tail.py --chunks 252 --arr 1100 --out O412D.FTN
python3 build_call.py chunk252 O412D.FTN DRIVER   # -> runs/chunk252/call.out, 1005 слов

# 3) Сборка и прогон полностью автономного тела
python3 b1.py full_chunked --o412d runs/chunk252/call.out
# ожидаем: rc=0 banner=True endtask=True, live_compare outside_our_code=0

# 4) A/B (слово body=36 = индекс 18 в O412D)
python3 b1.py ab_zero18 --no-live-check --zero-tail-index 18   # TIMEOUT
python3 b1.py ab_restore                                       # баннер снова

# 5) (опционально) полное A/B-сканирование всех 1005 слов
python3 scan_ab.py 0 1004
```

Ключевые файлы: `O412D.FTN` (канонический chunked-эмиттер, 4089 строк),
`O412D_single.FTN.bak` (одноUNIT-альтернатива, 4071 строка), `gen_tail.py`,
`build_call.py`, `b1.py`, `scan_ab.py`, `runs/full_auto/out.txt`,
`runs/full_chunked/out.txt`, `scan_ab.log`.
