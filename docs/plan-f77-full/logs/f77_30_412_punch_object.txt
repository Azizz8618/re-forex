## 2. ШАГ 2 — разбор формата punch-объекта (DONE)

### 2.1 Байтовая структура punch-файла (ФАКТ)

`dispak/extra.c:2493-2570` (`punch()`):

- `max = (a2-a1+1)*6`; пишутся байты `core[a1].w_b[1..5]` — **старший байт
  каждого 6-байтового слова НЕ пишется** (`if (bytecnt % 6)`), т.е. **5 байт
  на слово**.
- В конце — добивка до кратного 24 словам нулевыми 5-байтовыми группами.
- Итого `p1_main.bin` = 96×5 = 480 байт; `p3_empty.bin` = 72×5 = 360 байт.

**Восстановление 48-битного слова:** `word = int.from_bytes(b'\x00' + group5, 'big')`.

### 2.2 Тэгированная структура во входной очереди (ФАКТ)

Снято через `strace -e trace=write -s 20000` при включении `p1_main.bin`.
Файл `/home/azizz/.besm6/input_queue/<NNN>`, записи по 8 байт:
`tag(1) | spare(1) | word(6)`. `dispak/input.c:84-97,110-156`:

| tag | мнемоника | смысл |
|:--|:--|:--|
| 1 | `W_IADDR` | установить адрес загрузки `iaddr = word & 077777` |
| 2 | `W_DATA` |записать слово в `core[iaddr++]`, `convol |= CV_NUMBER` |
| 4 | `W_CODE` | записать слово в `core[iaddr++]` (исполняемое) |

Первые тэги в очереди (ФАКТ, 1704 байт = 213 записей):

## 3. ШАГ 3 — A/B через NEWCOMP* (NEGATIVE, BLOCKED)

### 3.1 Постановка (ФАКТ)

Каталог зоны `0o1744` на копии 2148:

```
1744.0000 = enc('MONITOR*')   ; 1744.0001 = 0o370
1744.0002 = enc('OURMRK*')    ; 1744.0003 = 0o400402757101760 (f0 варьировался)
```

Тело зоны `0o1745` — слова punch-объекта (ВНИМАНИЕ: сперва была ошибка —
запись 5-байтовых групп как 6-байтовых слов; исправлено в `ab2.py`:

Дека: `*TRANS:OURMRK*,,411744` + `PROGRAM MAIN / PRINT 100 /

### 3.2 Результаты свипа f0 (ФАКТ)

| f0 | rc | консоль |
|:--|:--|:--|
| `0o1760` | 0 | `ОШИБКА МД ЭВМ`, `disk_writei: disk 2048 is read only`, `00743 00 070 0145 *70`, `i=01760`, `ПЕРЕПОЛНЕНИЕ АУ` |
| `0o12`, `0o1551`, `0o370`, `0o1770`, `0o1000`, `0o0`, `0o2000`, `0o1761` | 0 | молча (TRANS принимается, но `НЕТ РАЗДЕЛА`/нетrunner) |

Проверено также:
- f0=0o1760 + **невыровненные** 5→6 байт (первая попытка) → TIMEOUT (бесконечное чтение зон 1745..2003).
- f0=0o1760 + наши слова + оверлеи 4.12 в зонах 1746+ (`hybrid.py`) → TIMEOUT.
- SUBROUTINE N2MRK (`p2_sub.bin`) вместо MAIN → тот же результат.
- `N2MARK-7391` НЕ печатается ни в одном варианте.

### 3.3 Трасса загрузки (ФАКТ, `BESM6_DD_DEBUG=1`)

Рабочий эталон (FOREX3* с зоны 1550):

```
DD pc=03022L u=41 z=1550 RD          <- читает КАТАЛОГ
DD pc=00671L u=41 z=1551 RD uil=10/0/3200   <- FOREX3* (зоны 1551..1553)
DD pc=00671L u=41 z=1553 RD uil=10/0/3700   <- LO*SYN (1553..1572)
DD pc=00671L u=41 z=1572 RD uil=10/0/3700   <- LO*GEN (1572..1606)
```

Наш объект (f0=0o1760):

```
DD pc=03022L u=41 z=1744 RD          <- каталог
DD pc=00671L u=41 z=1745 RD uil=10/0/3200
DD pc=00744L u=41 z=1746..2000 RD uil=10/0/3200   <- 28 зон подряд!
DD pc=00744L u=25 z=0026 WR uil=125/5/2525        <- мусорная команда вместо чтения
```

**ФАКТ (ключевой):** PC `00744L` — это код САМОГО загрузчика. Пока он читал
зоны, в `core` по адресу ~0o744 оказались записаны данные нашего объекта;
инструкция по 00744 заменилась с `RD` на `WR uil=125/5/2525`, после чего
последовал вывод на read-only диск и `ОШИБКА МД ЭВМ`.

**Вывод (ФАКТ):** загрузчик NEWCOMP* компонует объект по адресам, которые
пересекают его собственный код. Причина — отсутствие DMS-шапки с корректными
полями загрузки: NEWCOMP* не знает, куда класть тело, и пишет его по нулевому
(или фиксированному) смещению.

### 3.4 Почему f0 обязан быть 0o1760 (ФАКТ, подтверждено M3/M4)

`f0` — не длина и не зона, а **идентификатор главного раздела компилятора**.
Любое другое значение → `НЕТ РАЗДЕЛА OURMRK* 01770`. Error message показывает
фиксированный `01770`, т.е. проверка в NEWCOMP* захардкожена.

## 4. ШАГ 4 — спецификация эмиттера (что и как писать)

### 4.1 Для обычного загрузчика монитора (ДОСТИЖИМО, proven)

Чтобы наш Fortran-эмиттер (EMIT.FTN, план 57 N3) выдавал объект, который
загружается через `` `N `` и исполняется (как `p1_main.bin`), он должен:

1. Формировать последовательность тэгированных записей входной очереди:
   - `tag=1 (W_IADDR)` — адрес загрузки (например `0o4000`, `0o4020`, `0o1`);
   - `tag=4 (W_CODE)` — исполняемые слова;
   - `tag=2 (W_DATA)` — данные/константы;
   - каждая запись = 8 байт: `tag | spare=0 | word(6, big-endian)`.
2. Выдавать punch-файл как **5 байт на 48-битное слово** (пропускать `w_b[0]`),
   с добивкой до 24 слов нулями (`extra.c:2553-2565`).
3. Обеспечить релокацию: внешние SUBP (`FT*003`, `FT*571`, `PRINT8`) должны
   быть оформлены как LINK-ячейки с адресами из LINK-таблицы монитора
   (в p1_main symbol table: `FT*003 E 01556`, `FT*571 E 01023`,
   `PRINT8 E 03274`, `MAIN 01000`).

### 4.2 Для NEWCOMP* (НЕВОЗМОЖНО без полной DMS-эмуляции 4.12)

Чтобы объект грузился через `*TRANS`, эмиттер должен выдавать **не punch-объект,
а DMS-модуль формата 4.12**:

```
слово 0: служебное (в 4.12 = 0o0000000001600043)
слово 1: TEXT имя раздела (8×6 бит) + head=0o1200 + sym=0o7023
слово 2: set=0o73377, data=0o100, long=0o377
слово 3: cmd=0o1760, bss=0, const=0o222
слово 4..0o1757: 0o1760 команд
далее: 0o222 констант, long-символы, LINK
```

В каталоге: `f3=0400 f2=4027 f1=5710 f0=1760` (f0 зафиксировано).

**ФАКТ:** это требует от нашего модуля ровно `cmd=0o1760` команд и полного
набора оверлеев LO*SYN/LO*GEN (38 зон). Наш маркер имеет `cmd=0o11`. Простая
подстановка формата (шапка 4.12 + наш код) уже пробовалась в M4 (`V_hybrid`) —
`Interrupt 00707/00703/00710`. Попытка с нашим 4.12-punch-объектом (этот M4b) —
`ОШИБКА МД ЭВМ` / TIMEOUT. Минимальный путь к FULL — **не подмена формата, а
реализация полного DMS-образа 4.12 с cmd=0o1760 и LINK-схемой**, что выходит
за рамки M4b и является отдельной задачей (M4c/M5).

## 5. ФАКТ / ГИПОТЕЗА — коротко

- **ФАКТ:** `*PUNCH` + `--punch-binary -c` с живым 4.12 работает и выдает валидный
  объект; обратная вставка через `` `0 `` печатает `N2MARK-7391`.
- **ФАКТ:** punch-файл = 5 байт на слово, MSB пропущен; слово = `0x00 || 5 байт`.
- **ФАКТ:** объект во входной очереди — тэги 1(IADDR)/2(DATA)/4(CODE), 8 байт/запись.
- **ФАКТ:** NEWCOMP* требует `f0=0o1760`;любые другие значения → `НЕТ РАЗДЕЛА`.
- **ФАКТ:** с f0=0o1760 наш punch-объект заставляет загрузчик записать данные
  по адресу 0o744 (собственный код) → `ОШИБКА МД ЭВМ`, `i=01760`.
- **ФАКТ:** `N2MARK-7391` не печатается через NEWCOMP* ни в одном варианте.
- **ГИПОТЕЗА:** причина — несовместимость форматов: NEWCOMP* грузит DMS-модули
  компилятора (cmd=0o1760, 38 зон, TEXT-имя в слове 1), а `*PUNCH` выдает
  релоцируемый объект пользователя.
- **ГИПОТЕЗА:** точная схема LINK/релокации требует дизассемблирования NEWCOMP*
  из памяти монитора (дамп снят: `/var/tmp/b1-f77-fix/412-m4b/runs/a2/core-pc.bin`,
  код NEWCOMP* по адресам 0o3000..0o3077).
