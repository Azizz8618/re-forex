## 2. Код по подэтапам (литерально, из `/var/tmp/b1-f77-fix/n1/FRONT.FTN`)

Файл — один Fortran-исходник на 131 строку с двумя маркерами инъекции
(`C@@DECL@@` в строке 28, `C@@DATA@@` в строке 41), в точности как
`src/f77prep/F77PREP.FTN:30,54`. Ограничения подмножества соблюдены:
INTEGER-массивы, `PARAMETER`-размерности, `DATA` до исполняемых операторов
(`ERR 04441` из `docs/plan-f77-full/34-arfa-lowering.md:62`), без `IMPLICIT`,
`SAVE`, `CHARACTER`, `PRINT *`, `READ`. Имена ≤6 символов. Собственные исходные
строки ≤72 колонок (FORTRAN-метки ` 9001` — в колонках 2–5, не в колонке 6).

### Инъекция (host, `gen.py`, только для прогона)

```fortran
      PARAMETER (NC=9,NLV=8,LL=132,LW=72)
      INTEGER RAW(LW,NC)
      INTEGER C(LL,NLV)
      INTEGER SEQ(NLV)
...
      DATA SEQ /1,2,3,4,5,7,8,9,0/
      DATA RAW /80,82,73,71,82,65,77,32,78,49,84,69,
     1...
```

`RAW` — ASCII-коды **физических** карт (72 колонки), `SEQ` заполняется host,
но **склейку делает Fortran**.

### N1.1 — `FRONT.FTN:42-64`

```fortran
C-- N1.1: physical cards -> logical lines, SEQ and continuation ------------
      NL = 0
      DO 100 IC = 1, NC
         IF (RAW(6,IC) .EQ. 32) GOTO 110
         IF (NL .EQ. 0) GOTO 110
         DO 120 J = 7, LW
            IF (LNL(NL) .GE. LL) GOTO 120
            LNL(NL) = LNL(NL) + 1
            C(LNL(NL),NL) = RAW(J,IC)
  120    CONTINUE
         GOTO 100
  110    NL = NL + 1
         SEQ(NL) = IC
         LNL(NL) = LW - 6
         DO 130 J = 7, LW
            C(J-6,NL) = RAW(J,IC)
  130    CONTINUE
  100 CONTINUE
      DO 140 I = 1, NL
         DO 141 J = LNL(I)+1, LL
            C(J,I) = 32
  141    CONTINUE
  140 CONTINUE
```

Это точный порт `logical_lines()` из `prep_tools.py:344-356`: непустая кол. 6
клеит кол. 7..72 к предыдущей логической строке, до LL=132, `SEQ` — номер
первой физической карты. BASE77-текст (`tiny.f77`) содержал continuation:

```
      DO 10 I = 1, 3
         S = S
     1     + I
   10 CONTINUE
```

В IR карта `6` отсутствует, а `CONTINUE` имеет `SEQ=7`:
`777001 5 …`, `777001 7 …` (см. `front.out` выше).

### N1.2 — `FRONT.FTN:29-40,65-99`

```fortran
      INTEGER LNL(NLV)
      INTEGER IV(132)
...
      INTEGER PATPRN(7)
      DATA MR1 /777001/
      DATA MR2 /777002/
      DATA PATPRN /80,82,73,78,84,32,42/     ! "PRINT *"
...
C-- classify logical lines (N1.2: PAT token matching) ----------------------
      NR = 0
      DO 200 I = 1, NL
         IRULE = 0
         ITYPE = 0
         LV = 0
         IFIRST = 1
  210    IF (IFIRST .GT. LL) GOTO 220
         IF (C(IFIRST,I) .EQ. 32) GOTO 215
         GOTO 220
  215    IFIRST = IFIRST + 1
         GOTO 210
  220    MATCH = 1
         DO 221 J = 1, 7
            IF (C(IFIRST+J-1,I) .NE. PATPRN(J)) MATCH = 0
  221    CONTINUE
         IF (MATCH .EQ. 0) GOTO 250
         IRULE = 3
         K = IFIRST + 7
  231    IF (K .GT. LL) GOTO 233
         IF (C(K,I) .EQ. 32) GOTO 232
         IF (C(K,I) .EQ. 44) GOTO 232
         GOTO 233
  232    K = K + 1
         GOTO 231
  233    IF (K .GT. LL) GOTO 250
         ITYPE = 2
         IF (C(K,I) .GE. 73 .AND. C(K,I) .LE. 78) ITYPE = 1
  234    IF (K .GT. LL) GOTO 240
         IF (C(K,I) .EQ. 32) GOTO 235
         LV = LV + 1
         IV(LV) = C(K,I)
  235    K = K + 1
         GOTO 234
  240    IF (LV .LE. 0) IRULE = 0
```

Совпадает с логикой `F77PREP.FTN:64-116`: пропуск Leading spaces, PAT-сравнение,
`s=0`, `itype=1` для I..N, список переменных в `IV(132)`. В каркасе оставлен
**один** PAT-шаблон (`PRINT *`) вместо 16, как в `F77PREP.FTN:34-53` — остальные
относятся к N3 и упираются в память (см. §3).

**Оговорка (честно):** преобразование символ→ASCII (`card_codes()`,
`prep_tools.py:364-372`) физически остаётся на host — это та же инъекция, что и
в F77PREP (`prep_tools.py:396-399`). В Fortran портированы **представление**
ASCII-кодов в `INTEGER C(LL,NLV)` и PAT-таблицы; чтение настоящих текстовых
карт Fortran'ом без `CHARACTER` в этой волне не делалось.

```bash

python3 -c "…pt.make_deck2('lowered_reg.f77')…"

```

`recs_reg.json` (дословно):

```json
{"records": [{"seq": 1, "line": 1, "rule": 0, "itype": 0}, …,
             {"seq": 7, "line": 7, "rule": 3, "itype": 2}, …],
 "varcodes": {"7": {"1": 83}},
 "aux": [{"seq": 7, "kind": 21, "pos": 0, "value": 90000}],
 "summary": {"lines": 8, "rewrites": 1}}
```

`lowered_reg.f77` содержит `C@ PRINT *, S -> PRINT 9000,S` и
`9000 FORMAT(1X,F12.4)`, а pass2 печатает:

```
           *ЕХЕСUТЕ
       6.0000
 КОНЕЦ ЗАДАЧИ
```

**Найденный host-баг (важно для интеграции):** если continuation стоит **до**
`PRINT *`, host `lower` падает `no variable codes for PRINT * on line 7`
(`prep_tools.py:935-938`): `varmap` ключуется SEQ-номером (`prep_tools.py:608`),
а читается по индексу логической строки. Это **не** ошибка FRONT: F77PREP с
таким же исходником даст тот же сбой. Наш `cont`-вариант (`front.out`) поэтому
проверен до уровня IR, а `reg`-вариант — полным проходом 2. Минимальный фикс
хоста (вне зоны этого субагента): в `prep_tools.py:608` брать
`seq_to_line.get(int(k), int(k))` как ключ `varmap`.

## 3. Лимит памяти и минимальный split

Эксперимент на КОПИИ диска (увеличение числа логических строк при том же
`LL=132`, `LW=72`):

| NLV (логических строк) | Результат |
|---|---|
| 8, 25, 27, 28, 29, 30, **31** | OK, 0 ошибок |
| **32** и более (пробовались 32/33/35/40/45/85) | `ПЕРЕПОЛ РАБ ОБЛ ТР-РА` → `ПЕРЕПОЛНЕНА ПАМЯТЬ` |

Точная граница для этой конфигурации: **NLV ≤ 31**. Это совпадает с известным
жёстким потолком трансляции 2.02 (`docs/plan-f77-full/34-arfa-lowering.md:64-65`,
`07-implementation-prep.md:164-169`), из-за которого правила 34–40 в F77PREP
уже вынесены в host.

**Вывод:** весь «полный каркас» (все 16 PAT-массивов F77PREP + симтаблица +
эмиттер кода N3) в одной Fortran-программе 2.02 **не поместится**. Минимальный
split, который сохраняет доказанный контур:

1. **Оставляем в FOREX/Fortran (N1, этот файл):** `RAW(72,NC)`, `C(132,NLV)`,
   `SEQ(NLV)`, `IV(132)`, 1–2 PAT-таблицы, аллокатор, `PRINT`-эмиттер IR.
   Порция исходника ≤31 логической строки; `SEQ` — глобальный номер физической карты,
   поэтому куски склеиваются host-ом без потери порядка.
2. **Оставляем на host (уже работает):** char→ASCII инъекция (`card_codes`,
   `data_statement`), разбиение на куски, полный набор правил 0–40,
   `records`/`lower`, materialisation, deck2, проверки 21/21.
3. Граница раздела — **набор записей 777001/2/3/4**: Fortran печатает IR куска,
   host объединяет куски по `SEQ` и применяет правила. Это ровно та же граница,
   что у F77PREP (`prep_tools.py:344-410` против `F77PREP.FTN:55-331`).

## 5. Честная оценка труда

- Перенос/отладка этого каркаса (N1.1–N1.6 на копиях): **~0.5 агент-дня**
  (несколько итераций компиляции: дубли маркеров в комментариях, метка `9001`
  в кол. 6, затем collision-скан по `C` вместо `RAW`).
- Интеграция в репозиторий с тестом и логами (шаги 1–6): **~1 агент-день**.
- Дальше по плану 57: N2 3–6, N3 10–20, N4 5–10, N5 2–4 дня
  (`57-new-compiler-plan.md:148-150`) — **не** выполнено и здесь не оценивается
  как сделанное. Главный риск остаётся N3 (отсутствие object writer);
  память 2.02 ограничивает Fortran-часть ≈31 строкой за проход, поэтому
  кодогенератор придётся либо дробить, либо оставлять в host — это решение
  главного агента.
