## 1. Что на самом деле делает TRNSLTOR (MONSYS) — шаги 1–2 задания

Источник: `reference/412/TRNSLTOR_SOURCE.txt` (system2.txt:9065-9425),
машинный код: `reference/412/TRNSLTOR_DISASM.txt` (monsys.9 зона 0o21).

### 1.1 Формат каталога, который ждёт MONSYS (ФАКТ)

| строка исходника | machine word | действие |
|:--|:--|:--|
| 9123 | — | `CATLG:PC,BLOCK,CAT(2048)` — буфер каталога 2048 слов |
| 9124 | — | `NP:,P/P,(CAT)16` — базовое INF-слово чтения |
| 9298-9301 | 043450-043451 | `XTA,/NP; AOX,INFT; ATX,INFT; TAPE,INFT` — чтение зоны каталога |
| 9303-9306 | 043452-043453 | `C,VTM,CAT; C,XTA,1762B; AEX,CODE; U1A,OШKAT` — **маркер OVERLA по `CAT+0o1762`** |
| 9307-9308 | 043454 | `C,XTA,1023` (десятичное 1023 = **0o1777**, дизассемблёр: `XTA M8,1777B`); `UZA,МАЛMЛ` — **счётчик зон по `CAT+0o1777`**, ноль → `ПРИ СБОРКЕ МАЛО МЛ` |
| 9309-9317 | 043455-043460 | печать комментария OVERLAY (`CAT+0o1762` и further) через `PRINT8` |
| 9318-9345 | 043461-043502 | перенос каталога на барабан 25 (`DRUM,RD/25`, проверка слов 1024/1025, `DRUM,WD/25`) |
| 9346-9357 | 043502-043504 | `T*LIB`: `XTA,B1 / ARX,INFT / ATX,INFT` (**инкремент зоны на 1**), `TAPE,INFT`, `DRUM,INFD`, цикл `L` раз |
| 9358-9362 | — | `PUT*25: XTA,INF/25; UJ,F*INF0` — подключение библиотеки 25 |
| 9253-9257 | — | `F*INF0: AOX,PRIOR; ATX,INF0; XTA,INFLOA; ATX,STATIC*` |
| 9258-9261 | — | сверка имени с `FOREX=TEXT'INITFOR*'`, `UZA,PUT 1000`, иначе `UJ,RET` |
| 9403-9404 | 043531 | `RET:,WTC,I13; ,UJ,` — **возврат монитору** |

**ФАКТ (главный для шага 2).** MONSYS `TRNSLTOR` **не передаёт управление в тело
загружаемого модуля**. Он читает каталог, копирует его и `L` зон (`L = CAT+0o1777`)
на барабан 25, объявляет его `STATIC*` и возвращается. Компилятор вызывается
позже обычным механизмом монитора по имени из `*TRANS`. Именно поэтому в M4c
обнуление B4/B5/«нашего кода» не меняло консоль: эти слова не являются точкой
входа, по которой MONSYS делает `UJ`.

**ФАКТ.** `M1000 = OCT,2 00000` (строка 9119) — битовый флаг в `FLG`
(`,AOX,M1000.TPAHCЛЯTOPA`, строки 9136-9139), **не base-регистр** и не `f0`.

### 1.2 Сравнение с реальным каталогом M80 (зона 2148:0o1550)

**ФАКТ.** Форматы **различны**:

| | MONSYS (TRNSLTOR) | M80 (NEWCOMP*, наша сборка) |
|:--|:--|:--|
| структура | «сырой» 2048-словный буфер | пары `TEXT-имя / 48-бит дескриптор` со слова 0, terminates zero word |
| маркер | `OVERLA` по `CAT+0o1762` | ISO `OVERLA` = `0o2365310524446101` по слову **0o12** |
| счётчик зон | `CAT+0o1777` | нет; число зон идёт из полей дескриптора |
| `f0` | отсутствует как поле | младшие 12 бит дескриптора, извлекаются `AAX` с маской `0o7777` |

Реальные пары каталога 1550 (ФАКТ, `ref/z1550.bin`):

```
000 5557565164576212 MONITOR*    001 0000000000000370
002 4657624570231200 FOREX3*     003 0400402757101760  f3=400 f2=4027 f1=5710 f0=1760
004 5457126371560000 LO*SYN      005 0401423673031551  f0=1551
006 5457124745560000 LO*GEN      007 0411023634031551  f0=1551
010 0000000000000000 (конец таблицы)
012 2365310524446101 ISO OVERLA  013..016 комментарий сборки 4.12
```

**ФАКТ.** Кодировка указателя подтверждена дословным примером исходника
(строки 9098-9100): `*TRANS-FORTRAN,67200` = «носитель 67, зона 200»;
наш `411550` = «носитель 41, зона 0o1550».

## 2. Точка входа в загруженный компилятор (новый результат M4d)

Использован RAM-дамп и адреса субагента m80-newcomp
(`docs/plan-f77-full/logs/f77_30_m80_newcomp_live_disasm.txt`) и наш собственный
покадровый_TRACE с окном `BESM6_MTR_LO=0700 BESM6_MTR_HI=0777 BESM6_MTR_N=300000`
(`runs/ctrl/trace700.err`, 300 000 инструкций).

**ФАКТ (найдено M4d):**

```
MTR 00455L vjm 64002(15) AU=7240176003000464
MTR 64002L wtc 43(0)
MTR 64002R uj  64012(0)
MTR 64012L wtc 17(0)
MTR 64012R vtm 1760(16)     <-- M16 = f0 = 0o1760
MTR 64013L atx 0(16)
MTR 64014L atx 1(16) AU=3770010053377
```

То есть финальный переход из загрузчика NEWCOMP* — **`VJM 0o64002` по адресу
0o00455**;(addr 0o64000+ — область ОЗУ, куда загружено тело 4.12.) Первые
инструкции по 0o64002/0o64012 настраивают `M16 = 0o1760` — **уже внутри
загруженного компилятора**, а не в `TRNSLTOR`.

**ФАКТ.** В том же_trace по адресу `pc=0o736` аккумулятор равен
`7240176003000464` — ровно слову B5 `уиа 1760(M16)/пб 464`. Значит B5 —
**реальные данные загрузчика**, а не «фэйковый stub», как предполагалось в M4c.
Убирать его из эмиттера нельзя (это исправление инструкции главного агента
«no fake M16 stub»).

**ФАКТ (подтверждение m80-newcomp):** `f0` выделяется на `pc=0o3040`
(`AAX` с константой `0o3076 = 0o7777`) и сравнивается XOR с `0o1760` на
`pc=0o3046`; поля `f3/f2/f1` через сдвиги `0o660-0o674` собирают INF-слово
`0o10320000411551`. Главный модуль грузится из зоны N+1 (0o1551).

**ГИПОТЕЗА.** Точка 0o64002 — не абсолютный адрес монитора, а адрес в области загрузки тела;
её смещение зависит от описателя f3/f2/f1. Прямого доказательства формулы
пересчёта нет (тело в ОЗУ копируется с трансформацией: ни одно слово тела не
встречается в core dump дословно).

## 3. Эмиттер O412B.FTN (шаг 3)

Файл: `src/O412B.FTN` (копия в рабочем каталоге; репозиторий не тронут).
Сгенерирован `gen_o412b.py`, чтобы исключить ошибки перевода octal→decimal.

**Что изменено относительно O412 (ФАКТ):**

1. Заголовок/комментарии переписаны под реальные факты: f0 = 12-бит поле
   дескриптора (`0o3040`/`0o3046`), `f0=0o1760` требуется **в каталоге**,
   `cmd` тела не обязан равняться `0o1760`, B5 — данные загрузчика.
2. Каталог — **16 слов** живого формата M80 (включая пары LO*SYN/LO*GEN,
   `ISO OVERLA` по слову 0o12 и комментарий сборки); имя word 2 заменено на
   `OURMRK*`. Это «то, что загрузчик реально ожидает», а не 4-словный урезанный
   вариант.
3. B0 = `0o1600043` (живое служебное слово; при B0=0 M4c получал TIMEOUT).
4. B1..B3 — живая DMS-шапка (`head=0o1200`, `const=0o222`) как минимальный
   проверенный вариант. **ГИПОТЕЗА/опровержение:** «head=1» с минимальными
   длинами в опытах M4c/M4d давал `ПЕРЕПОЛНЕНИЕ АУ` + `Interrupt 00707`,
   поэтому head=1 **не** рабочий выбор для `*TRANS`.
5. B4 = маркер `0o73461`, B5 = stub `UIA/UJ` **сохранён** как данные.
6. B6..B14 = первые 9 слов живого cmd (включая проверенное слово
   `0o6700000002200000`); head-секция TEXT не эмитируется в префикс, потому что
   в живом модуле она лежит по смещению `0o75704`, а подстановка её в word 0o16
   портит исполняемый код (этот баг был найден и исправлен).
7. Эмитируется ровно 30 слов: 16 каталог + 14 тело.

**Компиляция (ФАКТ):**

```
BESM6_PATH=./dispak ./dispak -l build.deck   -> rc=0, 0 ошибок, ДЛИHA LIBRARY 004 ЗОН
BESM6_PATH=./dispak ./dispak -l call.deck    -> rc=0, 'O412B-412', 'O412BNW  31'->30
python3 verify_o412b.py                       -> VERIFY PASS: 30/30
```

Ловушка, найденная при компиляции: метки FORMAT должны начинаться в колонке 4
(3 пробела для 2-значной), иначе FOREX 2.02 выдаёт
`METKA И ПPИЗHAK ПPOДOЛЖEHИЯ` и модуль не сохраняется.

## 7. ФАКТ / ГИПОТЕЗА — что осталось открытым

* **ФАКТ.** MONSYS-исходник даёт только механизм «каталог + N+1, N+2… + возврат»;
  его формат каталога (OVERLA@0o1762, счётчик@0o1777) **не совпадает** с M80.
  Поэтому старый spec (`f0 = M16 base`, `cmd = 0o1760`) опровергнут.
* **ФАКТ.** В M80 `f0` — поле дескриптора; `M16=0o1760` выставляется кодом по
  адресу 0o64012 **после** перехода `VJM 64002`.
* **ФАКТ.** Точка входа `0o64002` найдена; как именно из f3/f2/f1 выводится
  адрес загрузки тела — **ГИПОТЕЗА** (тело в ОЗУ копируется с трансформацией).
* **ГИПОТЕЗА.** Самодостаточный 30-словный «мини-компилятор» под `*TRANS`
  невозможен: NEWCOMP* ожидает штатные оверлеи и LINK/COMMON-таблицы 4.12.
  Для FULL без заимствования живых зон нужен либо полный эмиттер оверлеев,
  либо демонстрация печати маркера напрямую из кода по адресу 0o64002+ (после
  того как будет выведена формула пересчёта адреса из дескриптора).
* **ФАКТ (исправление инструкции).** «No fake M16 stub» — неверно: B5 является
  данными загрузчика (AU=stub word при pc=0o736) и сохранён в O412B.
