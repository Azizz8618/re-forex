### 2.4 Интерпретация (ФАКТ / ГИПОТЕЗА)

* **ФАКТ:** переход на абсолютный адрес резидентной подпрограммы **работает** (PC подтверждён дампом).
* **ФАКТ:** переход через LINK-ячейку `0o740nn` в `*TRANS` уходит по нулевому содержимому, возвращается в монитор и завершается `КОНЕЦ ЗАДАЧИ` без печати.
* **ФАКТ:** PRINT8 принял управление, но не напечатал: он ожидает подготовленный `BUFFER` (0o2000 слов, `LINK 0o74001` как база M14 в WRITLIBR) и регистры M7/M14 (см. `include/RUNTIME_DISASM.registers.md`: `PRINT8: M14 := база констант BAS61=*00061; M7 — указатель; M13 — linkage`). * **ГИПОТЕЗА:** чтобы использовать FT\*003/PRINT8 «по-настоящему», пришлось бы эмулировать полную среду FORMAT/FORTLIBR (11 transfer-ячеек, 0o2000-словный BUFFER, M7/M12/M14/M15, LINK-слоты). Это несовместимо с задачей минимального автономного тела (A3: ≤30 слов кода + живая зона N+2).

## 5. Точная последовательность машинного кода (шаг 5)

### 5.1 Кодирование `vjm`

Формат 24-битного полуслова (по `besm6tape.py:84-94`): `reg = (h>>20)&0xF`, `long = (h>>19)&1`, для длинных `op = (h>>12)&0xF8`, `name = LONG[(op>>3)&0xF]`.
`vjm` — индекс **9** в `LONG`, значит `op = 9<<3 = 0o110`:

```
h = (reg << 20) | (1 << 19) | (0o110 << 12) | addr
word = (h << 24) | LO Halfword
```

| вызов | `h` (восьм.) | слово 48 бит | дизасм |
|:--|:--|:--|:--|
| `vjm 3274` (PRINT8, reg=0) | `03103274` | `0o0310327400000000` | `vjm 3274` |
| `vjm 1556` (FT\*003, reg=0) | `03101556` | `0o0310155600000000` | `vjm 1556` |
| `vjm 1023` (FT\*571, reg=0) | `03101023` | `0o0310102300000000` | `vjm 1023` |
| `vjm 74013(15)` (LINK) | `077174013` | `0o07717401300000000` | `vjm 74013(17)` |

(в дизассемблере регистр печатается восьмеричным: `17` = M15.)

### 5.2 Проверенная последовательность в теле (слова 9+)

```
B9  = 0o064177202200000   ; *64 1772  — РАБОЧАЯ печать (А3)
B10 = 0o06700000002200000 ; uj (13) — возврат в MONSYS/NEWCOMP*
B11 = 0o0177400001774     ; слово дескриптора 1
B12 = 0o01000040000000    ; слово дескриптора 2
B13..B19                  ; GOST-10859 7 слов текста
```

Если заменить B9 на `0o0310327400000000` (`vjm 3274`), PC действительно дойдёт до `03274`, но печать пропадёт. **Рекомендуемая последовательность — оставить B9 как есть.**

### 5.3 EMIT48-эквивалент (для `EMIT.FTN`)

`EMIT48(IR1,K1,A1, IR2,K2,A2)`: HI = IR1·2²¹ + K1·2¹⁵ + A1, LO = IR2·2²¹ + K2·2¹⁵ + A2.

* `*64 1772, utc`: `EMIT48(0,64,0o1772, 0,22,0)` → HI=`0o0641772`, LO=`0o0260000` → слово `0o06417720260000` (в A3 LO=`0o220000`, т.е. `utc` с другим регистром; важно только HI).
* `vjm 3274, utc`: `EMIT48(0,0o110,0o3274, 0,22,0)` → HI=`0o03103274`, LO=`0o0260000` → `0o031032740260000`.
* `uj (13)`: `EMIT48(13,0o110,0, 0,22,0)` → HI=`0o067110000`, LO=`0o0260000`.

**ФАКТ:** все три кодировки проверены дизассемблером `besm6tape.disasm_word` и реальным прогоном.
