### 0.2 Принцип раздела «lowering vs ассемблер»

1. **Source-to-source lowering** (F77PREP + `prep_tools.py`) меняет только текст
   программы. Он может удалять/заменять операторы, подставлять явные
   объявления, метки, FORMAT-строки и вызовы внешних процедур.
2. **Runtime (F77LIBR)** добавляет имена, видимые линковщику. Он не может
   изменить парсер (`LO*SYN`), таблицу операторов (`LO*GEN:0532..0623`),
   таблицу FORMAT-процедур (11 entry `FT*nnn`) или правила проверки типов.
3. Поэтому граница проходит там, где требуется **новая лексема, новый
   edit-дескриптор, новый тип-вариант или новый opcode** — это §3.

### 0.3 Версионная оговорка

Все вердикты ниже относятся к **FOREX 2.02** (диск 2048, PERSO `0o2300`) —
первичной среде репозитория. 4.13 поддерживает `CHARACTER*30`, но в этой
среде чистого 4.13 нет (`07-experiments.md` §«Что не удалось», п.3), поэтому
проект строит эмуляцию строк для 2.02 и не зависит от версии.

### 1.1 SEQ-номер строки (M1)

Сегодня `F77PREP.FTN` хранит `INTEGER C(72,20)` (строка 35) и печатает
`777001 I IRULE ITYPE`, где `I` — порядковый номер. Это делает номер строки
зависимым от позиции в массиве и ограничивает программу 20 картами.

Решение: host проставляет в колонки 73–80 каждой физической карты SEQ
(монотонный номер, можно `%05d`) и инъецирует вместо `C@@DATA@@`:

```
      PARAMETER (NLV=200)
      INTEGER C(132,NLV)
      INTEGER SEQ(NLV)
      DATA NL /137/
      DATA SEQ /1,2,3,...,137/
      DATA C /.../          ! 132*137 ASCII-кодов
```

F77PREP печатает `777001 <seq> <rule> <itype>`; host сортирует записи по SEQ
и-materializes вывод в том же порядке. Пакетная обработка: если строк больше
`NLV`, host режет исходник на батчи по SEQ и делает несколько deck1; итоговый
`lowered.f77` склеивается. Никакого изменения логики правил не требуется.

### 1.2 Continuation (M2)

Host до инъекции выполняет лексический проход:

* карта с непустой колонкой 6 — продолжение предыдущей; её колонки 7–72
  приклеиваются к логической строке;
* логическая строка усекается до `LL=132` (F77 разрешает до 19 продолжений,
  но практически достаточно 132 символов);
* ведётся карта `logical_line → [physical card numbers]` для якорей `C@`.

F77PREP классифицирует **логические** строки (правила распознаются от первой
непробельной колонки, как сегодня). Host при материализации разбивает новый
оператор обратно на карты: колонки 1–5 метка, колонка 6 — `C`-подобный маркер
продолжения (непустой символ), колонки 7–72 — текст. Якорь `C@ … -> …`
вставляется перед первой физической картой фрагмента.

Важно: `PARAMETER`, `DATA`-массивы и `FORMAT` сегодня уже используют
продолжение в самом F77PREP (`data_statement()`), так что механизм совместим.

### 1.3 Динамические метки (M3)

Текущие базы `FMT_BASE=9000`, `LOOP_BASE=7000`, `READ_BASE=9500`
(`prep_tools.py:45-47`) — фиксированные. При совместном использовании с SEQ-пакетами и новыми
правилами (END=, EQUIVALENCE, inline intrinsic) mereka могут коллидировать.

Новый аллокатор:

1. сканирует все строки исходника и собирает `used = {метки из кол. 1–5}`;
2. резервирует диапазон 90000–99999 под генерируемые метки; если исходник
   использует его — сначала переименовывает пользовательские метки (homeomorphic
   mapping, `05-decision.md` §5 уровень 2), затем выделяет метку;
3. выдаёт метки монотонно из свободных с шагом, заданным типом правила
   (2 для `DO WHILE`: top/bottom; 1 для FORMAT);
4. эмитирует `777004 <seq> <kind> <label>`, чтобы host мог восстановить
   соответствие без повторного parsing-а.

### 1.4 Несколько переменных (M4)

`777002 <line> <pos> <char-code>` сегодня используется только rule 3 и не
различает, какому оператору принадлежит список. Расширение — новая запись:

```
777004 <seq> <rule> <pos> <char-code>
```

`prep_tools.py` продолжает понимать `777002` (v1/v2-совместимость), но
`varmap` ключуется парой `(seq, rule)`. Это позволяет:

* `READ *, A, B, N` — список из трёх переменных с подбором `F12.4/F12.4/I10`;
* `PRINT *, S, T` — mixed INTEGER/REAL/CHARACTER с правильным набором
  дескрипторов (уже частично работает в v2);
* строковые операции — передача имён операндов в `STRCAT`/`SUBSTR`.

### 1.5 CHARACTER любой длины (M5)

БЭСМ-6: слово 48 бит; TEXT-символ — 6 бит (`ASCII−0x20`), т.е. до 8 символов
на слово. Но максимальная ширина `A`-дескриптора ФОРЭКСа — 6 (`5A6` для
`CHARACTER*30` в Dhrystone), поэтому **рабочей единицей сделаем 6 символов**:

```
n = объявленная длина
W = CEIL(n/6)
INTEGER I<S>(W)          ! хранилище
DATA I<S>(k)/6H<6 символов>/   ! последнее слово — 6H с пробегами-падингом
PRINT 9000, I<S>(1),...,I<S>(W)
9000 FORMAT(1X, A6, A6, ..., A<ost>)   ! ost = n - 6*(W-1)
```

Конкатенация `S = A // B`:

```
CALL STRCAT(IA, IB, IS, LA, LB)   ! F77LIBR: посимвольная перестановка 6-битных групп
```

Подстрока и сравнение:

```
CALL SUBSTR(IS, FROM, TO, IT)     ! IT = S(FROM:TO)
K = ISTRCM(IS, IT)                ! -1/0/+1, лексикографически по TEXT-коду
```

`STRCAT`/`SUBSTR`/`ISTRCM` пишутся на поддерживаемом подмножестве ФОРЭКСа:
извлечение символа — `MOD(IWORD/64**P, 64)`, вставка — сложение
`ICODE*64**P`; `64` = `2**6`. Это чистая арифметика `INTEGER`, без ассемблера.
Стоимость — O(n) на операцию; для hot-loop строковых программ (Dhrystone)
предусмотреть inline-оптимизацию на уровне F77PREP для `n ≤ 6`.

## 2. Конструкции, реализуемые чистым lowering-ом (без ассемблера)

Ниже — **новые и расширенные правила** F77PREP v3. Нумерация продолжает v2
(0–8); правила 9+ предлагаются к добавлению.

### 2.1 IMPLICIT — rule 1 (уже есть), rule 9 (новый, typed IMPLICIT)

**Алгоритм.** `IMPLICIT NONE` — удалить (rule 1, сегодня без анализа
семантики; усилить: проверить, что все имена объявлены явно, иначе diagnostic
в `C@`). `IMPLICIT t(a-z,…)` — удалить и сгенерировать явные объявления для
всех неявно типизированных имён program unit-а, руководствуясь списком
букв. Сканирование имён — регулярное выражение по всем оператора unit-а;
уже объявленные имена (INTEGER/REAL/LOGICAL/COMPLEX/DOUBLE PRECISION/DIMENSION/
DATA/COMMON/PARAMETER) исключаются.

```
Вход:                          Выход:
      IMPLICIT INTEGER (A-Z)   C@ IMPLICIT INTEGER (A-Z) -> (removed; explicit decls)
      X = 3.5                       INTEGER X
      K = 2                    C@ X = 3.5 -> (X is INTEGER by IMPLICIT)  ! якорь
      END                           X = 3
                                    K = 2
                                    END
```

Оговорка: `IMPLICIT INTEGER(A-Z)` в F77 меняет неявный тип; если исходник
полагается на REAL `X`, lowering меняет семантику — это корректно (так требует
F77), но требует gold-теста. `IMPLICIT NONE` — расширение F90, удаляется
без подстановок.

### 2.2 SAVE — rule 2 (расширенный)

**Алгоритм.** Если Variables программы уже размещены в статической памяти
(требуется проба F0: вызов подпрограммы дважды и проверка сохранения значения),
`SAVE` просто удаляется — сегодняшнее поведение. Если статичность не
подтверждена, `SAVE v` lower-ится в `COMMON /<unit>SV/ v` + `DATA v/…/`
(инициализация по умолчанию 0), что гарантирует ту же ячейку между вызовами.

```
Вход:                          Выход (без статичности):
      SUBROUTINE ACC(N)        SUBROUTINE ACC(N)
      SAVE S                   C@ SAVE S -> COMMON /ACCSV/ S ; DATA S/0/
      S = S + N                     COMMON /ACCSV/ S
      END                           DATA S /0/
                                    S = S + N
                                    END
```

Имя COMMON-блока ≤6 знаков (`<unit>SV` усекается), не конфликтует с
`glkern.b6` блоками.

### 2.3 PRINT * — rule 3 (уже есть, расширяется на M2/M3/M4)

**Алгоритм.** `PRINT *, v1,…,vk` → `PRINT <fmt>, <renamed>…` + FORMAT с
дескриптором на каждую переменную: `I10` (I..N), `F12.4` (Real),
`A6/A4/A2` ( CHARACTER по §1.5), `L1` (LOGICAL), `D22.15` (DP — важная
ловушка из E1 §4). FORMAT-метка выделяется динамически (M3), список берётся
из `777004` (M4).

```
Вход:                          Выход:
      PRINT *, N, X, S         C@ PRINT *, N, X, S -> PRINT 9000,N,X,IS
                                    PRINT 9000,N,X,IS
                               9000 FORMAT(1X,I10,F12.4,A4)
```

### 2.4 READ * и END=/ERR= — rule 4 (расширен), rule 10, rule 11

**rule 10 — list-directed READ, несколько переменных.** `READ *, v1,…,vk`
и `READ(*,*) v1,…,vk` → `READ <fmt>, v1,…,vk` **без номера юнита**
(единственная рабочая форма, E1 §1); FORMAT без `1X`, дескрипторы по
первой букве, как в rule 3.

```
Вход:  READ *, A, B, N
Выход: C@ READ *, A, B, N -> READ 9500,A,B,N
       READ 9500,A,B,N
       9500 FORMAT(F12.4,F12.4,I10)
```

**rule 11 — END=/ERR=.** В dispak нет сигнала EOF у карточной очереди и нет
`IOSTAT` у безъюнитного READ. Lowering — **sentinel по согласованию с host**:

1. host дописывает в `deck2` последнюю карту-ловушку с числом-сентинелом
   (например `-999999.`, для INTEGER `-999999`), выбранным так, чтобы не
   коллидировать с данными;
2. F77PREP эмитирует после READ проверку первой переменной:

```
Вход:                            Выход:
      READ(*,*,END=99) X         C@ READ(...,END=99) X -> READ 9500,X / IF (X .EQ. -999999.) GO TO 99
      ...                        READ 9500,X
   99 CONTINUE                   IF (X .EQ. -999999.) GO TO 99
                                 ...
   99 CONTINUE
```

Для `ERR=` — тот же механизм с отдельным сентинелом (например `-888888.`)
и проверкой `IF (X .EQ. -888888.) GO TO <err-label>`. Для нескольких
переменных проверяется первая; при необходимости host вставляет отдельную
сентинную карту перед каждым READ.

Оговорка (обязательна в документации): это **эмуляция EOF по значению**, а не
настоящий `IOSTAT`; сентинал задаётся host и не должен встречаться в данных.
Полноценный `END=` требует правки рантайма ввода (за пределами чистого
lowering-а, §3).

### 2.5 DO WHILE — rule 5/6 (уже есть), rule 17 (новый: без обязательного END DO)

**Алгоритм rule 5/6 не меняется:** `NN CONTINUE` / `IF (.NOT.(cond)) GO TO NN+1`
в начале, `GO TO NN` / `NN+1 CONTINUE` в конце, стек меток для вложенности.

**rule 17 — неявное закрытие цикла.** Когда `END DO` отсутствует, F77PREP
закрывает все открытые `DO WHILE` на операторе `END` (или `STOP`) program unit-а,
в порядке LIFO. Для вложенных циклов требуются явные `END DO` (иначе уровень
вложенности неоднозначен) — host проверяет баланс стека и падает с
`unbalanced DO WHILE / END DO`, как сегодня.

```
Вход:                          Выход:
      DO WHILE (N .LT. 3)      7000 CONTINUE
        N=N+1                  IF (.NOT.(N .LT. 3)) GO TO 7001
      END                      N=N+1
                               GO TO 7000
                          7001 CONTINUE
                               END
```

### 2.6 CHARACTER и строки — rule 7/8 (есть), rule 12/13/14 (новые)

См. §1.5 для представления. Пример полного lowering:

```
Вход:                            Выход:
  CHARACTER*10 S                 C@ CHARACTER*10 S -> INTEGER IS(2)
  CHARACTER*4  T                 C@ CHARACTER*4 T -> INTEGER IT
  S = 'ABCDEF'                   C@ S='ABCDEF' -> DATA IS(1)/6HABCDEF/
  T = S(2:4) // 'XY'             INTEGER IS(2)
  PRINT *, S, T                  INTEGER IT
  END                            DATA IS(1)/6HABCDEF/
                                 DATA IS(2)/6H      /
                                 DATA IT /4HXY  /
                                 C@ T = S(2:4)//'XY' -> CALL SUBSTR(IS,2,4,IW)
                                 CALL SUBSTR(IS,2,4,IW)
                                 C@ ... // 'XY' -> CALL STRCAT(IW,IT,IT)
                                 CALL STRCAT(IW,IT,IT)
                                 C@ PRINT *,S,T -> PRINT 9000,IS(1),IS(2),IT
                                 PRINT 9000,IS(1),IS(2),IT
                            9000 FORMAT(1X,A6,A4,A4)
                                 END
```

`S(2:4)` → `CALL SUBSTR(IS,2,4,IW)` извлекает 3 символа в младшие 18 бит
`IW`; `STRCAT` склеивает 3+2=5 символов, записывает `IT` как `5H…` с
дозаписью пробела. `ISTRCM(IS,IT)` сравнивает по 6-битным TEXT-кодам,
эквивалентно `STRCMP` из F77LIBR (§4).

### 2.7 COMPLEX intrinsics и DOUBLE PRECISION — rule 0 (keep)

**Не lowering-овать!** Согласно `05-decision.md` §6 и E1 §4, оба типа
поддерживаются генератором и считаются точнее любого программного
разбиения. Единственные действия препроцессора:

* `DOUBLE PRECISION` + печать → подставить `D22.15` вместо `F…`
  (иначе `I/O-ERROR 227`, E1 §4);
* `CMPLX(A,B)` → `(A,B)` — чисто синтаксическая замена (rule 19, inline);
* `CONJG(Z)` → оставить как внешнюю ссылку на F77LIBR, если нативная
  форма не подтверждена пробой F0;
* `CABS`, `CSQRT`, `SNGL`, `SQRT(DP)` — keep (rule 0).

```
Вход:  X = SQRT(2.0D0)
       PRINT *, X
Выход: X = SQRT(2.0D0)
       C@ PRINT *,X -> PRINT 9000,X
       PRINT 9000,X
  9000 FORMAT(1X,D22.15)
```

### 2.8 H-константы — rule 0 / rule 8 (расширенный)

`nH…` уже работает в `FORMAT` и в `DATA INTEGER` (`07-experiments.md` §5).
Rule 8 обобщается: любое присваивание строкового литерала переменной-INTEGER
заменяется на `DATA <iname>/nHliteral/`, а константы в выражениях
переписываются в именованную `DATA`-переменную. Сохранение 8 символов на
слово (`8HABCDEFGH`) допустимо для `COMMON`/`DATA`, но для печати через `A`
используем 6-символьные группы (§1.5).

### 2.9 ASSIGN / computed GO TO — rule 15 (новый)

**Алгоритм.** Для каждого INTEGER `I`, встречающегося в `ASSIGN ll TO I`,
собрать множество меток `L_I`; присвоить им ordinal-ы 1..k. `ASSIGN ll TO I`
→ `I = ordinal(ll)`; `GO TO I` → цепочка `IF (I .EQ. j) GO TO L_I[j]`;
`GO TO (l1,…,lk),I` → та же цепочка (F77-семантика выхода за диапазон —
«продолжить», последняя `IF` не имеет `ELSE`).

```
Вход:                          Выход:
      ASSIGN 100 TO I          C@ ASSIGN 100 TO I -> I = 1
      GO TO I                  I = 1
  100 CONTINUE                 C@ GO TO I -> IF (I.EQ.1) GO TO 100
                               IF (I .EQ. 1) GO TO 100
                           100 CONTINUE
```

Если `GO TO I` встречается без `ASSIGN` в том же unit-е — host падает с
диагностикой (неизвестное множество меток).

### 2.10 EQUIVALENCE — rule 16 (новый)

**Алгоритм (типизированный случай).** Для перекрытия однотипных переменных
host строит rename-карту: `EQUIVALENCE (A(1),B(1))` → все `B(i)` заменяются
на `A(i)`, оператор удаляется. Для частичного перекрытия
`EQUIVALENCE (A(2),B(1))` → `B(i)` → `A(i+1)`. Сохранение формы массива и
размеров проверяется host-ом.

```
Вход:                          Выход:
      INTEGER A(10), B(5)      INTEGER A(10)
      EQUIVALENCE (A(2),B(1))  C@ EQUIVALENCE -> B(1..5) переименовано в A(2..6)
      B(1) = 7                 A(2) = 7
```

**Ограничение:** EQUIVALENCE между разными типами (INTEGER ↔ REAL ↔ COMPLEX),
а также перекрытие с «хвостом» word-а, чисто текстовым lowering-ом не
выражается — rule 16 отклоняет такой случай с диагностикой (см. §3).

### 2.11 BLOCK DATA — rule 0 (keep)

`BLOCK DATA` уже работает на 2.02 (`glkern.b6:50-93`, `01-gap-analysis.md`
§1 п.15). Никакого lowering-а; rule 0 сохраняет оператор как есть. Единственное
вмешательство F77PREP — не путать `DATA` внутри `BLOCK DATA` с правилами
строк (rule 8): disable rule 8 в unit-е `BLOCK DATA`, если строковых
присваиваний там нет.

## 3. Что НЕ реализуемо чистым lowering-ом

| Конструкция | Почему нельзя (доказательство) | Что требуется | Обход в рамках проекта |
|---|---|---|---|
| **Новые FORMAT-дескрипторы** (`E`, `ES`, `EN`, `G`, `A` без ширины, `T`, `TR`, `BN`) | FORMAT — закрытая таблица из 11 entry `FT*nnn` (`UJ FT*nnn / ATX 77xxxB`, `libra211.l21:15565-15586`; `03-fortran-path.md` §2.3); генераторная пара «дескриптор+TEXT» фиксирована в `LO*GEN:0532..0623`. Внешняя процедура не может добавить entry в таблицу парсера | правка ассемблера `LO*GEN` + LIBREFER | для `A` → `A4/A6` (source rewrite, rule 7/12); для `E` → переписать в `F` с масштабированием и отдельной печатью порядка **только если** допустимо изменить вид вывода |
| **Unformatted I/O** (`WRITE(u) X`, `READ(u) X` без FORMAT) | `LO_GEN` содержит только `FT*nnn` для форматированного вывода (`01-gap-analysis.md` §2.3); синтаксис без FORMAT отвергается в `LO*SYN`. Имена юнитов 1/2/5/6/10/40/45 не работают вообще (E1 §1), поэтому дажеnamed-CALL не даёт настоящего Fortran-unit I/O | новые opcode/ entry + правка монитора/рантайма (E4) | хостовый redirect `> out.txt` и карты в `deck2`; длясовместимости — only formatted I/O |
| **`REWIND`, `BACKSPACE`, `ENDFILE`** | Генератор имеет слова `*REWIN` (0o615), `*BACKS` (0o617), `*ENDFI` (0o621) (`src/LO_GEN.mad:528-530`), но **нет Fortran-оператора**, который в них транслируется; низкоуровневый вызов из Fortran-процедуры = ассемблерная вставка | new keyword в `LO*SYN:1517..1777` + код в `LO*GEN` | эмуляция на уровне deck: перезапуск задачи / новая дека; не для произвольной программы |
| **«Настоящие» типизированные объявления, если GENERATOR блокирует проверку типов** | `A4` с `INTEGER 12345` → `I/O-ERROR 232` (`07-experiments.md` §5); `CHARACTER` + присваивание → `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ`. Lowering меняет **текст**, но не тип, который чипы присваивает переменной в симтаблице. Если GENERATOR требует тип-вариант (CHARACTER-typed операнд для `A`, substring semantics), INTEGER-эмуляция будет отвергнута или сгенерирует неверный код | новый тип-вариант в `LO*GEN` + правка `LO*SYN` (E4) | эмуляция через `INTEGER`+`nH` работает **только** для хранения/печати (§1.5); подстроки/сравнения — через F77LIBR, но не как нативный тип |
| **`IMPLICIT NONE` как ключевое слово компилятора** | `НЕДОПУСТИМ КЛЮЧ СЛОВО` (`01-gap-analysis.md` §2.1); «объявить» новое ключевое слово Fortran-процедурой нельзя | new lexeme в `LO*SYN` | удаляется rule 1 (этоqquad политика препроцессора, не язык) |
| **Настоящий `IOSTAT=`/EOF-статус ввода** | безъюнитный READ не возвращает статус; очередь карт не имеет EOF-сигнала (E1 §1) | правка рантайма ввода (dispak `extra.c` / монитор) | sentinel по согласованию с host, rule 11 |

## 4. Расширение F77LIBR: полный список F77 intrinsic

### 4.1 Принцип и соглашение вызова

F77LIBR лежит в отдельной PERSO-библиотеке зон `0o2310..0o2313` (4 зоны,
9 имён в каталоге после v2 — `08-runtime.md` §3). Подключение:
`*perso:602300` + `*perso:602310,cont` (не `603100`!). Имя ≤6 знаков, не
системное. Аргументы передаются по адресу через блок M16/M14/M7, возврат
FUNCTION — M13/M15; `EXTERNAL` не нужен.

Эффективность: **каждый вызов = VJM + передача аргументов**, то есть десятки
слов и циклов на оператор. Поэтому приоритет:

1. **rule 0 (keep)** — если intrinsic уже в компиляторе;
2. **rule 19 (inline)** — для простых 2-аргументных операций:
   `T=A; IF (B .GT. T) T=B` вместо `AMAX1(A,B)`;
3. **F77LIBR** — только для того, что нельзя inline (DP/COMPLEX/строки/
   преобразования типов).

### 4.2 Классификация полного списка

Обозначения: **N** = native (rule 0, keep), **I** = inline-expand (rule 19),
**L** = нужен F77LIBR, **?** =_required ping-проба F0.

| Intrinsic | Статус | Реализация на поддерживаемом подмножестве | Приоритет |
|---|---|---|---|
| `ABS` | N | уже встроен (`01-gap` §1 п.17) | — |
| `SQRT` | N | встроен, работает и для DP (`SQRT(2.0D0)`, E1 §4) | — |
| `SIN` | N | встроен (`02-extension-points.md` §3.3) | — |
| `COS` | N? | проба F0; при отсутствии — L (`COS(X)=SIN(X+1.5707963)`) | P2 |
| `EXP` | N | встроен (`01-gap` §1 п.17) | — |
| `MOD` | N? | проба F0; при отсутствии — L как `AMOD` | P2 |
| `AMOD` | N | встроен (`01-gap`, `glkern.b6:107`) | — |
| `FLOAT` | N | встроен (`01-gap` §1 п.17) | — |
| `ICHAR` | N | встроен (`01-gap` §1 п.17) | — |
| `CHAR` | N | встроен (`01-gap` §1 п.17) | — |
| `INT`, `REAL` | N? | проба F0; при отсутствии — rule 19 (`INT=IFIX`, `REAL=FLOAT`) | P2 |

| `CMPLX` | I | `CMPLX(A,B)` → `(A,B)` (rule 19, inline) | P1 |
| `AINT` | I/L | `AINT(X) = REAL(INT(X))` (усечение к нулю); если `INT` нет — L | P1 |

inline-ом** (rule 19), **6 требуют новых процедур в F77LIBR** (`CONJG`,
`ANINT`, `IDINT`, `DMOD`, `STRCAT`, `SUBSTR`, `ISTRCM` — часть из них уже
есть: `STRCMP`, `ISGN0`, `IMAX0`, `IDIV`, `MYABS`, `MYMAX`, `FMTLNK`).

### 4.3 Реестр новых процедур F77LIBR (v3)

| Имя | Сигнатура | Назначение |
|---|---|---|
| `STRCAT` | `SUBROUTINE STRCAT(A,B,C,LA,LB)` | конкатенация 6-битных групп → C |
| `SUBSTR` | `SUBROUTINE SUBSTR(A,I,J,C)` | подстрока A(I:J) → C |
| `ISTRCM` | `INTEGER FUNCTION ISTRCM(A,B)` | лексикографическое сравнение (аналог `STRCMP`) |
| `DMOD2` | `FUNCTION DMOD2(X,Y)` | DP-остаток (имя `DMOD` может конфликтовать — проверить F0) |
| `DINT2` | `FUNCTION DINT2(X)` | `IDINT` / `ANINT` для DP |
| `CONJG` | `FUNCTION CONJG(Z)` | сопряжение COMPLEX, если нативное отсутствует |

Имена, уже занятые в 2.02 (`ISIGN`) или в F77LIBR (`STRCMP`, `IMAX0`,
`ISGN0`, `IDIV`, `MYABS`, `MYMAX`, `FMTLNK`) не переиспользуются. Новые
процедуры пишутся строго на поддерживаемом подмножестве (без `IMPLICIT`,
`SAVE`, `PRINT *`, `CHARACTER`), компилируются `*forex`, пишутся
`*to perso:602310`. Рост каталога может потребовать зон `0o2314..0o2317`;
базовый образ `0o2300` и тест Глиссады 14/14 не трогаются.

### 4.4 Влияние calling convention на эффективность

| Способ | Стоимость на оператор | Рекомендация |
|---|---|---|
| rule 0 (нативный intrinsic) | 0 лишних операторов | всегда предпочтительно |
| rule 19 (inline `IF`) | 1 присваивание + 1 сравнение + 1 conditional GO TO | hot loop: min/max/abs/dim — **да** |
| вызов F77LIBR | блок аргументов + VJM(15) + RETURN | только DP/COMPLEX/строки/преобразования |
| `**` (уже `ПВ ROWER`) | один вызов, приемлемо (`05-decision.md` §6) | не трогать |

### Заключение

Полный FORTRAN 77 на Fortran-пути достижим **частично**: ~25 из 30
рассмотренных конструкций реализуются source-to-source lowering-ом и внешней
библиотекой. Граница — закрытая таблица FORMAT-дескрипторов, отсутствие
Fortran-синтаксиса для позиционирования файлов и проверка типов в генераторе:
эти позиции требуют E4 (MADLEN) и не должны маскироваться preprocessor-ом.
Ключевое условие успеха — **не трогать** уже работающие `DOUBLE PRECISION`,
`COMPLEX`, `BLOCK DATA`, блочный `IF` (rule 0) и держать новую библиотеку в
отдельных зонах, не перезаписывая базовую PERSO `0o2300`.
