## 1. Что реально умеет АРФА (справка из кода, без домыслов)

Экстракод **Э63 «КЛЮЧАР»**: `АИСП` в `reg[016]`, тип работы в разрядах 48–43 слова ИС,
параметры на РМР (`accex` → `prm`), ответ в `M16`: `0` = успех, иначе код ответа
(`dispak/dispak/arfa.c:1-32`, dispatch `:1339-1391`).

| Оп. | Функция | Что делает | Ключевые строки |
|---|---|---|---|
| `01` | `op_create` | создать область: имя ГОСТ ≤12, **обязательный шифр хозяина**, длина = **число зон** `W16_1(prm)`, вид/группа/индивидуальность; место — после последней области, не раньше зоны `0030`; запись слота 13 слов в каталог | `arfa.c:771-859` |
| `02` | `op_destroy` | уничтожить: по имени, проверка `owner`/`schifr`, пароль `W` при `has_w`, чистит слот и ссылки `unit_area[]` | `arfa.c:865-907` |
| `03/04/05/06` | password/grant/confirm/list | пароли, права, допущенные лица — **не имеют аналога в F77 OPEN** | `arfa.c:1365-1368` |
| `07` | `op_info` | сведения: `acc.l=owner`, `acc.r` = флаги `has_r/has_w/group/individual` + **`nzones` (длина в зонах)** | `arfa.c:1047-1063` |
| `10В` | `op_catalog` | каталог областей верхнего уровня: 2-словные записи `имя(9)+owner`, терминатор `0xffffff`; буфер/счётчик в `prm` | `arfa.c:1069-1109` |
| `12` | `op_order` | **дозаказ**: связать область со свободным лог. номером `030..067`; `disks[u].diskno=arfa_diskno`, `mode = W12(is) ? RO : RW`, `offset = zone + shift`, `unit_area[u]=idx+1`, `acc.r=u`. Лимит ≤12 виртуальных устройств | `arfa.c:1133-1176` |
| `13/14/15` | link/set_shift/get_shift | имя/идентификатор ↔ область, сдвиг по области в зонах | `arfa.c:1184+` |
| `30В` | `op_grab` | захват (совместный/монопольный); **одна задача — одна захваченная область** | `arfa.c:1290-1310` |
| `31В` | `op_release` | освобождение (без захвата — фатальный авост) | `arfa.c:1316-1332` |

Коды ответа (восьмеричные, `arfa.c:67-84`): `0 OK`, `1 NO_NAME`, `2 BAD_NAME`, `4 NO_VIRT`,
`5 BAD_SCHIFR`, `6 EXISTS`, `010 BUSY`, `012 NO_VOLUME`, `013 VIRT_N`, `015 TOO_LONG`,
`022 NO_SPACE`, `023 NO_RIGHTS`, `024 IS_CATALOG`, `027 BAD_KIND`, `031 NEED_PASS`,
`032 VIRT_BUSY`, `0100000 AVOST` (фатально, `E_TERM`).

**Обмен данными** — не Э63, а **Э70 `ddio()`** (`dispak/dispak/extra.c:2063+`): адресация
**зоной** 12 бит (`uir.i_addr & 07777`, `extra.c:2090-2093`), зона = **6144 байта**
(`dispak/dispak/disk.h:28`). Прямой обмен с архивным томом закрыт; исключение — лог. номер,
к которому Э63 подключил область (`arfa_area_unit(u)`, `extra.c:2083-2089`).

> **Ключевой вывод:** в АРФЕ есть **имя**, **область (непрерывный диапазон зон)**, **длина в зонах**
> и **лог. номер для Э70**. **Нет** notion записи, `RECL`, номера записи, EOF-маркера внутри области.

Том архива ищется: `BESM6_ARFA` → подключённые LUN `030..067` с меткой «АRFA» → пути `BESM6_PATH`
(`arfa.c:381-494`). Каталог персистентен на диске; пароли/захваты/шифры — только в памяти эмулятора
(`arfa.c:41-45`).

## 2. ТАБЛИЦА СООПВЕТСТВИЯ: F77 → АРФА

Обозначения: `u` — Fortran-юнит исходника; `U` — лог. номер АРФЫ `030..067`, возвращённый `12`.

| F77 оператор / атрибут | Операция АРФА | Передача параметров | Возврат / IOSTAT |
|---|---|---|---|
| `OPEN(u,FILE='NAME',STATUS='NEW')` | `01` создать + `12` дозаказ | Имя: слова ИС+1.. в ГОСТ, способ `W4_1=010` («по-новому», `arfa.c:520-559`); шифр хозяина после `/` в имени (`arfa.c:541-558`); длина = зоны в `W16_1(prm)`; вид `W20_18(prm)`; `W12(is)` = read-only | `M16` → `IOSTAT`: `0`, `2 BAD_NAME`, `5 BAD_SCHIFR`, `6 EXISTS`, `15 TOO_LONG`, `22 NO_SPACE`, `013 VIRT_N`. `U` из `acc.r` → в FILMAP |
| `OPEN(u,FILE='NAME',STATUS='OLD')` | `07` сведения + `12` дозаказ | Имя ГОСТ в ИС+1; `07` проверяет существование (`acc.l=owner`, `acc.r=nzones`) | `0` → открыт; `1 NO_NAME` → `IOSTAT>0`; `24 IS_CATALOG` при обращении к каталогу |
| `OPEN(...,STATUS='UNKNOWN')` | `07`, при `NO_NAME` → `01`, затем `12` | Как выше; шифр обязателен для ветки `01` | Код `01` или `07` |
| `OPEN(...,STATUS='SCRATCH')` | `01` + `12` (только с **синтетическим** именем), `02` на CLOSE |_host_ генерирует ГОСТ-имя ≤12 + шифр; АРФА «безымянных» областей не знает | `0`/`5`/`6`; след в каталоге остаётся — см. §5.2 |
| `OPEN(...,ACCESS='SEQUENTIAL'|'DIRECT')` | — (нет операции) | Записать запрошенный код в FILMAP; АРФА не различает доступ | `IOSTAT=0` фиктивно; `DIRECT` — profile-оговорка |
| `OPEN(...,FORM='FORMATTED'|'UNFORMATTED')` | — | Код в FILMAP | `IOSTAT=0` фиктивно |
| `OPEN(...,RECL=n)` | — (длина только в **зонах**, `arfa.c:844`) | `n` сохраняется в FILMAP как запрос; в Э63 не передаётся | `IOSTAT=0`; реальная длина — `nzones` из `07` |
| `OPEN(...,IOSTAT=k)` | `M16` любой из выше | `k` = профильный код (таблица §4.4) | `0` / положительный код; `AVOST` не возвращается (задача гибнет) |
| `OPEN(...,ERR=L)` | — | lowering: `IF (k.NE.0) GO TO L` | см. `IOSTAT` |
| `CLOSE(u,STATUS='KEEP')` | `31В` освободить; LUN оставить привязанным | Имя/лог. номер из FILMAP; `W24(is)` — монопольный флаг захвата | `0`/`1`/`2`/`010`; сброс `OPENED` в FILMAP |
| `CLOSE(u,STATUS='DELETE')` | `31В` + `02` уничтожить | Имя + `schifr` (проверка `owner`, `arfa.c:885-886`); пароль `W` при `has_w` (`arfa.c:887-891`) | `0`/`1`/`23 NO_RIGHTS`/`031 NEED_PASS`; при отсутствии шифра — ошибка |
| `INQUIRE(UNIT=u,OPENED=v)` | — (FILMAP) | `FMLU(u)` → `OPENED` | `IOSTAT=0` |
| `INQUIRE(FILE='NAME',EXIST=e)` | `07` | Имя ГОСТ в ИС+1 | `e = (M16==0)`; `NO_NAME` → `e=.FALSE.`, `IOSTAT` — по профилю (F77 для `EXIST` не считает отсутствие ошибкой) |
| `INQUIRE(...,NAME=,NUMBER=)` | `07` + `10В` частично | `07` даёт `owner/nzones`, `10В` — каталог; **номера юнита АРФА нет как стабильного атрибута** | `NAME` — из FILMAP; `NUMBER` — profile-оговорка |
| `INQUIRE(...,ACCESS=,FORM=,RECL=,DIRECT=,SEQUENTIAL=)` | — | Только из FILMAP (кэш запроса) | Значения — те, что были переданы в OPEN, не проверены АРФОЙ |
| `READ(u,fmt,...,END=L,IOSTAT=k)` unformatted → АРФА | `Э70` по `U` из FILMAP | `U` от `12`, зона = `offset + FMPOS`; сдвиг `14/15` | `k=-1` при `FMPOS ≥ NZONES` (синтетический EOF), `k>0` при ошибке Э70 |
| `READ(u,fmt,...,END=L,IOSTAT=k)` formatted (unit 5/stdin) | — (эмуляция сентиналом) | `19-eof-iostat.md §3.2`: `-999999.` / `-888888.` | `k=-1` / `+1`, переход на `L` |
| `WRITE(u,...)` unformatted → АРФА | `Э70` по `U`, `W12(is)=0` | Как READ; рост `FMPOS`, контроль `NZONES` | `0` / `015 TOO_LONG` (при выходе за область) |
| `REWIND/BACKSPACE/ENDFILE` на АРФА-юните | `15` (сдвиг), либо сброс `FMPOS` в FILMAP | Переполнение/отрицательная позиция в FILMAP | `0`; `ENDFILE` не пишет маркер в область |

**Ответ на прямой вопрос задания.** Для `ACCESS='DIRECT'/RECL` в АРФЕ **нет notion записи
фиксированной длины** — есть только **зоны (6144 байт)** и **диапазон зон** (`nzones`).
«Запись» может быть только **эмуляцией в FILMAP/PERSO**: `zone = base + record*ceil(RECL/6144)`.
Это даёт адресацию, но не даёт настоящей F77-записи (дробная зона теряется, границы записи
АРФЕ неизвестны, нет таблицы записей). Статус — **PARTIAL / profile-оговорка**, не поддержка DIRECT.

## 3. Структура `/FILMAP/`

### 3.1 Где жить

**Рекомендация: в PERSO `0o2320`, как labeled COMMON. НЕ в каталоге АРФЫ.**

Обоснование:

1. Каталог АРФЫ — фиксированный формат: слот 13 слов, имя 12 ГОСТ-байт, `owner`, `nzones`,
   `zone`, права, даты (`arfa.c:60-65`, `:307-339`). **Свободных полей под Fortran-юнит,
   `RECPOS`, EOF и IOSTAT нет.** Добавить их — значит править `arfa.c` и формат реальных томов
   (здесь READ-ONLY, и это сломает совместимость).
2. Каталог **персистентен на диске** и переживает перезапуск (`arfa.c:41-43`); состояние
   Fortran-юнита — **потоковое**. Хранить его в каталоге — грязное состояние между задачами.
3. Механизм уже доказан: `COMMON /J24STT/ OPN(16)` разделяется между main и PERSO-процедурами
   (`20-open-close.md §4`, строки 186-189). `/FILMAP/` — его расширение: те же 3–8 процедур
   в зоне `0o2320`, 0 слов в оверлеях. Рецепт сборки — `20-open-close.md §2` (строки 112-135).
4. Роль АРФЫ — **персистентное пространство имён** (имя →-area→зоны); роль `/FILMAP/` —
   **рантайм-связка** `Fortran u → GOST-имя → U (030..067) → зона/позиция/EOF/IOSTAT`.

### 3.2 Проект структуры (Fortran, labeled COMMON)

```
      INTEGER NF
      PARAMETER (NF=16)                     ! 16→32 тривиально (29-dubna-port.md:323)
      INTEGER FMNAM(2,NF)                   ! 2 слова = 12 ГОСТ-байт имени (как arfa.c:115,321)
      INTEGER FMLU(NF)                      ! Fortran-юнит u исходника (0 = свободно)
      INTEGER FMARU(NF)                     ! лог. номер АРФЫ U из Э63 12, 0 = не привязан
      INTEGER FMOWN(NF)                     ! шифр хозяина (для Э63 01/02)
      INTEGER FMMOD(NF)                     ! 0=закрыт, 1=R, 2=RW (W12(is) в Э63 12)
      INTEGER FMACC(NF)                     ! 0=SEQUENTIAL, 1=DIRECT (profile)
      INTEGER FMFRM(NF)                     ! 0=FORMATTED, 1=UNFORMATTED (profile)
      INTEGER FMREC(NF)                     ! запрошенный RECL, СЛОВА (profile; АРФА не знает)
      INTEGER FMZON(NF)                     ! длина NZONES из Э63 07 / заданная при 01
      INTEGER FMPOS(NF)                     ! текущая зона/запись (0..NZONES)
      INTEGER FMEOF(NF)                     ! 0/1 — синтетический EOF по позиции
      INTEGER FMIST(NF)                     ! профильный IOSTAT последней операции
      INTEGER FMRAW(NF)                     ! сырой код M16 (октальный) для диагностики
      INTEGER FMGRB(NF)                     ! 0/1/2 — захват 30В (одна область на задачу)
      COMMON /FILMAP/ FMNAM,FMLU,FMARU,FMOWN,FMMOD,FMACC,FMFRM,
     *                FMREC,FMZON,FMPOS,FMEOF,FMIST,FMRAW,FMGRB
```

Инициализация — в первой PERSO-процедуре (`FOPEN` при первом вызове) или в главной программе;
`FMLU=0` означает свободную запись. Индекс записи — **не** `u`: ищем по `FMLU(i)==u`
(Fortran u и АРФА `U` — разные диапазоны, `17-lun-p7c.md`, `23-luntyp-patch.md`).

**Инварианты:**

- `FMARU(i)≠0` ⟹ Э63 `12` выполнен, `disks[U]` привязан (`extra.c:2086-2089` разрешает Э70).
- `FMEOF(i)=1` ⟺ `FMPOS(i) ≥ FMZON(i)` (для unformatted ARFA-юнита).
- `FMGRB(i)≠0` только для одной записи (`arfa.c:1305-1307`).
- `FMNAM` хранится **уже в ГОСТ** (host транскодирует `FILE=` статически — см. H6); формат
  2 слова × 6 байт совпадает с представлением имени в каталоге (`arfa.c:321`).

### 3.3 Набор PERSO-процедур (имена ≤6 символов для ФОРЭКС)

| Процедура | Назначение | Экстракоды |
|---|---|---|
| `FOPEN(u,nm,st,ac,fm,rl,k)` | создать/найти область, `12`, заполнить запись FILMAP | `01`/`07`/`12`, при `st=SCRATCH` — `30В` |
| `FCLOSE(u,del,k)` | `31В`, при `del=1` — `02`, очистить запись | `31В`/`02` |
| `FINQ(u,opn,k)` | базовый INQUIRE: `OPENED` | — (FILMAP) |
| `FINQE(u,ex,k)` | `EXIST` по имени из FILMAP | `07` |
| `FINQX(u,ac,fm,rl,k)` | кэшированные `ACCESS/FORM/RECL` | — (FILMAP) |
| `FREAD(u,buf,n,k)` / `FWRIT(u,buf,n,k)` | unformatted обмен зоной, сдвиг `FMPOS`, синтетический EOF | `Э70`, `Э63 14/15` |

6–7 процедур × ≈29 слов + заголовок (`20-open-close.md:109-110`) — с запасом влезают в `0o2320`.

## 4. Lowering-контракт для `prep_tools.py` (spec; владелец правила — другой агент)

Все правила — **чистая текстовая замена в fixed-form (cols 7–72) до ФОРЭКС 2.02**. Ни одного
слова в `LO_SYN/LO_GEN`. Базовый механизм и сигнатуры — `20-open-close.md §1`, прототип
`/tmp/.private/azizz/opencode/p7c-proto/open/src/lower_j24.py` (в `src` **не** установлен).

### 4.1 R32-OPEN

**Вход:** `OPEN(u [,FILE='lit'] [,STATUS='lit'] [,ACCESS='lit'] [,FORM='lit'] [,RECL=n] [,IOSTAT=k] [,ERR=L])`

**Выход (порядок строк строго фиксирован):**

```
[1] C@ F77A OPEN u ...                     ! комментарий-метка для gold/diff (опц.)
[2] INTEGER k                              ! ТОЛЬКО если нет явного IOSTAT=k; имя FIO<u>
[3] INTEGER FMN<u>(2)/<oct_bytes>/         ! ТОЛЬКО если есть FILE=; GOST-байты, см. H6
[4] CALL FOPEN(u, FMN<u>, st, ac, fm, rl, k)
[5] IF (k .NE. 0) GO TO L                  ! ТОЛЬКО если есть ERR=L
```

Коды `st`: `UNKNOWN=0, OLD=1, NEW=2, SCRATCH=3`. `ac`: `SEQUENTIAL=0, DIRECT=1`.
`fm`: `FORMATTED=0, UNFORMATTED=1`. `rl` — `RECL` или `0`. `FILE=` без значения → `FMN<u>=0`
(для `SCRATCH` host генерирует синтетическое имя — H7).

### 4.2 R32-CLOSE

**Вход:** `CLOSE(u [,STATUS='DELETE'|'KEEP'] [,IOSTAT=k] [,ERR=L])`

```
[1] C@ F77A CLOSE u ...
[2] INTEGER k                              ! если нет IOSTAT=
[3] CALL FCLOSE(u, d, k)                   ! d=1 для DELETE, 0 для KEEP/по умолчанию
[4] IF (k .NE. 0) GO TO L                  ! если есть ERR=L
```

### 4.3 R32-INQUIRE

**Вход:** `INQUIRE(UNIT=u,OPENED=v [,EXIST=e] [,IOSTAT=k] [,ERR=L])`
или `INQUIRE(FILE='lit',EXIST=e [,IOSTAT=k] [,ERR=L])`

```
[1] INTEGER k                              ! если нет IOSTAT=
[2] INTEGER FMN<u>(2)/<oct_bytes>/         ! только для формы FILE=
[3] CALL FINQ(u, v, k)                     ! базовая форма (совместима с 20-open-close.md)
[4] CALL FINQE(u, e, k)                    ! только если есть EXIST=
[5] CALL FINQX(u, ac, fm, rl, k)           ! только если есть ACCESS=/FORM=/RECL=
[6] IF (k .NE. 0) GO TO L                  ! если есть ERR=L
```

`EXIST=.FALSE.` **не** считается ошибкой: если `M16=1 (NO_NAME)`, `FINQE` выдаёт `e=.FALSE.`,
а `k` оставляет `0` (оговорка X3.9-совместимости).

### 4.4 R32-READ / WRITE с `END=`/`IOSTAT=`

Два **взаимоисключительных** профиля; host знает, какие юниты были lowered через ARFA-OPEN.

**Профиль A — ARFA unformatted (юнит в FILMAP, `FMARU≠0`):**

```
[1] k = 0                                  ! только если есть IOSTAT=
[2] CALL FREAD(u, buf, n, k)                ! Э70 по FMARU(u), позиция FMPOS
[3] IF (k .EQ. -1) GO TO Lend               ! только если есть END=
[4] IF (k .GT.  0) GO TO Lerr               ! только если есть ERR=
```

`k=-1` выставляется PERSO, когда `FMPOS ≥ FMZON` (синтетический EOF), **не** сентиналом.

**Профиль B — formatted / stdin: дословно `19-eof-iostat.md §3.2` (строки 156-162):**

```
[1]  k = 0                                  ! если есть IOSTAT=
[2]  READ <fmt>,v1,…,vn                      ! юнит отбрасывается
[3]  IF (v1 .EQ. -999999.) k = -1            ! если есть IOSTAT=
[4]  IF (v1 .EQ. -888888.) k = 1             ! если есть IOSTAT=
[5]  IF (v1 .EQ. -999999.) GO TO Lend        ! если есть END=
[6]  IF (v1 .EQ. -888888.) GO TO Lerr        ! если есть ERR=
```

`WRITE` → `CALL FWRIT(u,buf,n,k)` только для профиля A; профиль B — существующий путь печати.

### 4.5 Отображение `M16` → `IOSTAT` (профиль)

`IOSTAT<0` = EOF (только `-1`, профиль), `IOSTAT>0` = ошибка, `0` = успех.

| M16 (восьм.) | IOSTAT | M16 (восьм.) | IOSTAT |
|---|---|---|---|
| `0` | `0` | `012 NO_VOLUME` | `8` |
| `1 NO_NAME` | `1` | `013 VIRT_N` | `9` |
| `2 BAD_NAME` | `2` | `015 TOO_LONG` | `10` |
| `4 NO_VIRT` | `3` | `022 NO_SPACE` | `11` |
| `5 BAD_SCHIFR` | `4` | `023 NO_RIGHTS` | `12` |
| `6 EXISTS` | `5` | `024 IS_CATALOG` | `13` |
| `010 BUSY` | `6` | `027 BAD_KIND` | `14` |
| `031 NEED_PASS` | `7` | `032 VIRT_BUSY` | `15` |

`AVOST (0100000)` → `E_TERM` (`arfa.c:1387-1389`): задача завершается, `IOSTAT` не возвращается.
Сырой код дублируется в `FMRAW` для диагностики. `END=` и `IOSTAT=` вместе — profile-оговорка
`19-eof-iostat.md:166-168` (сначала `k=-1`, затем переход на `Lend`).

### 4.6 Обязательства HOST (без них lowering не исполняемо)

| # | Обязательство |
|---|---|
| H1–H5 | Полностью из `19-eof-iostat.md §3.2`: сентинал сразу после данных, две карты при `END=`+`ERR=`, неколлизия, FORMAT без `1X`, сентинал после последней карты цикла, `-888888.` только по инициативе host. |
| H6 | `FILE='lit'` — ГОСТ-имя ≤12 символов. Host **статически** транскодирует DUBNA TEXT → ГОСТ 10859 и излучает 2 слова октальных байт в `DATA`. Недопустимый символ (`arfa.c:176-181`) или длина >12 → **жёсткая ошибка**, не молчаливая обрезка. МС-80 (`W4_1=014`) не поддерживается (`arfa.c:671-673`). |
| H7 | Для `STATUS='NEW'/'SCRATCH'` host обязан задать шифр хозяина (profile option, напр. `ARFA_OWNER=4199`) и записать его в `FMOWN`; без него Э63 `01` → `ARF_BAD_SCHIFR` (`arfa.c:792-793`).Для `SCRATCH` — синтетическое ГОСТ-имя ≤12, уникальное на задачу. |
| H8 | Дек грузит PERSO: `*perso:602300` + `*perso:602320,cont` (`20-open-close.md:134`). Иначе `CALL FOPEN/...` не разрешаются. |
| H9 | Том АРФЫ доступен до старта: `BESM6_ARFA=<n>` или LUN `030..067` с меткой «ARFA» (`arfa.c:381-494`). Иначе все Э63 → `012 NO_VOLUME`. |
| H10 | `FOPEN` обязан вызывать Э63 `12` (дозаказ), а не `Э50 0131`: без `arfa_area_unit(U)` Э70 к архивному тому закрыт (`extra.c:2086-2089`). `U` из `acc.r` (`arfa.c:1174`) сохраняется в `FMARU`. |
| H11 | Уровень B (`ERRLUN`/`LUNTYP`) по-прежнему блокирует FOREX-каналы (`17-lun-p7c.md §3`, `23-luntyp-patch.md`): обмен должен идти **внутри PERSO** через Э70, либо требуется патч монитора. Не решено в этой волне. |
| H12 | `RECL` и `ACCESS='DIRECT'` только кэшируются в FILMAP; АРФА работает зонами. Профиль обязан declarative-оговорить игнорирование. |
| H13 | `CLOSE(STATUS='DELETE')` требует шифр и (при `has_w`) пароль (`arfa.c:885-891`); область, созданная вне программы, может не удалиться → `023/031`. |
| H14 | `INQUIRE(FILE=...)` использует `07`: АРФА возвращает `owner/nzones`, но **не** `OPENED/ACCESS/FORM/RECL` — они берутся из FILMAP либо `.FALSE./неизвестно`. |

**Честность.** Профиль обязан содержать оговорку: «`OPEN/CLOSE/INQUIRE` над АРФА — управление
записью `/FILMAP/` + экстракоды Э63 01/02/07/12/30В/31В; `ACCESS/RECL/FORM` и `IOSTAT` —
профильная эмуляция; `END=` для formatted-ввода — сентинал, для unformatted АРФЫ — позиция
в области. Нативная семантика X3.9 требует правки системной зоны 2348 (P7c/monitor)».

## 5. Что НЕЛЬЗЯ выразить через АРФА (непреодолимые расхождения)

| # | Расхождение | Почему (доказательство) | Что остаётся |
|---|---|---|---|
| 5.1 | **Запись фиксированной длины / `ACCESS='DIRECT'`, `RECL=`** | АРФА хранит длину в **зонах** (`arfa.c:844`), Э70 адресует зону (`extra.c:2090-2093`), зона = 6144 байт (`disk.h:28`). Нет таблицы записей, нет номера записи, нет дробной зоны. | Эмуляция `record → zone` в PERSO; PARTIAL, profile-оговорка. Не calling it DIRECT. |
| 5.2 | **`STATUS='SCRATCH'` без имени** | Э63 `01` требует ГОСТ-имя (`arfa.c:777-791`) и шифр хозяина (`arfa.c:792-793`). Безымянной области нет. | Синтетическое имя + `02` на CLOSE; след в каталоге, нет гарантии удаления при аварии. OK\*/оговорка. |
| 5.3 | **`END=` как подлинный EOF formatted-READ** | `Э60` ставит `reg[016]=0`, но `monread%` уходит в `STOP*` (`19-eof-iostat.md §1.3`), ячейки статуса нет. | Сентинал `-999999.` + сравнение `v1`; OK\*. Нативный EOF — только патч 2348. |
| 5.4 | **EOF внутри АРФА-области** | В области нет маркера конца; длина — только `nzones` в каталоге (`arfa.c:1061`). | Синтетический EOF по `FMPOS ≥ FMZON` в FILMAP. Не F77 EOF-флаг. |
| 5.5 | **Formatted `READ(u,fmt)` на АРФА-юните** | FOREX-рантайм formatted READ идёт в очередь карт; нельзя перенаправить его на PERSO-буфер без правки `READ*`/`IOEND*`. | Только unformatted `FREAD/FWRIT` через PERSO. Formatted остаётся stdin. |
| 5.6 | **Нативный `IOSTAT` X3.9** | `M16` — восьмеричные коды АРФЫ; фатальный `AVOST` завершает задачу (`arfa.c:1387-1389`). | Таблица §4.5, `IOSTAT=-1` для EOF по профилю. Не системный статус. |
| 5.7 | **Длинные/не-ГОСТ имена** | Имя ≤12 ГОСТ-байт; МС-80 не поддержан (`arfa.c:671-673`); кодировка исходника — DUBNA TEXT. | Статическая транскодировка host (H6); >12 символов — жёсткая ошибка lowering-а. |
| 5.8 | **Ограничения ёмкости АРФЫ** | ≤60 областей (`ARFA_MAX_AREAS`), ≤12 виртуальных устройств (`arfa.c:1145-1149`), LUN `030..067`, одна захваченная область на задачу (`arfa.c:1305-1307`). | Profile-лимиты; F77 их не знает. |
| 5.9 | **Прямой доступ к архивному тому** | `arfa_protected()` + absence `arfa_area_unit(U)` → `E_CWERR` (`extra.c:2083-2089`). | Обязательный Э63 `12` (H10); Fortran-юнит ≠ АРФА-LUN. |
| 5.10 | **Уровень B / каналы LUN** | `НЕТ КАНАLA LUN 45` при прохождении проверки уровня B раньше Э70 (`17-lun-p7c.md §3.2`, `23-luntyp-patch.md`). | Обмен внутри PERSO или отдельный патч монитора; не закрыто в этой волне. |

**Итог:** через АРФА выразимо **именованное хранилище с длиной в зонах + привязка к LUN**;
не выразимо — **record-модель F77, безымянный SCRATCH, нативный EOF/IOSTAT и formatted I/O
на таком юните**. Любая заявка «J24 реализована через АРФА» без оговорок 5.1–5.10 будет
завышением статуса.
