## 0. Главный вывод (пересмотр вердикта 08-madlen-impl)

`08-madlen-impl.md` зафиксировало: «P7 целиком требует полной пересборки оверлеев
(40–80 чел.-дн.)». **Прямые пробы на системном ФОРЭКСЕ 2.02 опровергают это для
большинства элементов P7.**

| Утверждение 08 / 03 | Факт пробы (`logs/p7_alt_probes.txt`) |
|---|---|
| «новые FORMAT-дескрипторы E/G/L требуют правки таблицы» | **E, L, / , P, D работают НАТИВНО** (0 слов). G — единственный реальный отказ. |
| «unformatted I/O требует новых opcode» | `WRITE(54) X` / `READ(54) X` **компилируются и исполняются** (0 слов). |
| «REWIND/BACKSPACE/ENDFILE уже работают» | подтверждено ещё раз (0 слов). |
| «CHARACTER и IOSTAT — MADLEN-spine» | CHARACTER: `ТИП ОП-ДА НЕ СООТВЕТ ОПЕРАЦ` (TRUE MADLEN), но **`INTEGER`+`4H…`+`A6` работает** → lowering. IOSTAT/END=/ERR=: отказ трансляции в ЛЮБОЙ форме → true-семантика требует правки ввода, но это **не оверлей**, а runtime/monitor. |

**Итог:** из шести элементов P7 только **настоящий тип CHARACTER в GENERATOR** и
**истинный возврат IOSTAT/EOF** требуют правки компилятора/рантайма. Всё остальное
закрывается существующими механизмами. Рекомендация родителю — заменить «полный
F77 = 200/200 OK» на **«F77 conformance profile on FOREX 5.00»** (§5).

## 4. Конкретные обходные пути: CHARACTER и CABS

### 4.1 CHARACTER (2.02) — «хранение/печать + F77LIBR»

**Проба-доказательство (`CH_HA6`):**
```fortran
      INTEGER W
      DATA W/4HABCD/
      PRINT 10,W
   10 FORMAT(1X,A6)
      STOP
      END
```
→ `КОНЕЦ ЗАДАЧИ`, без диагностики; `W = 0o2024110321020040` = ASCII `41 42 43 44 20 20`
(`10-implementation-libr.md:45-56`). Т.е. `nH` даёт **6 символов на 48-битное слово**
и дескриптор `A6` печатает его напрямую.

**Рецепт (0 слов в оверлеях):**
1. `CHARACTER*n S` → `INTEGER S(W)`, `W = ceil(n/6)` (rules 7/8, `03-fortran-path.md:61`);
   инициализация `DATA S1/4HABCD/…`.
2. Печать → `FORMAT(1X,A6,A6,…,A<ost>)` (`03-fortran-path.md:151`); `A` → `A6/A4` (rule 12).
3. `S(2:4)` → `CALL SUBSTR(IS,2,4,IT)` (`10-implementation-libr.md:27`).
4. `A // B` → `CALL STRCAT(IA,IB,IC,LA,LB)` (там же, строка 26).
5. `S .EQ. T` → `KC = ISTRCM(IS,IT)` + `IF (KC .EQ. 0) …` (там же, строка 28).
6. `CHAR/ICHAR` — канал D/нативные; `ICHAR("A")` в моей пробе дал `ОШИБКА В СПИСКЕ
   АРГ` из-за синтаксиса кавычек; по матрице K7 `ICHAR` OK (`01-f77-standard-matrix.md:257`).

**Граница (честно):** арифметика над `nH`-переменными не работает
(`10-implementation-libr.md:58-78`), поэтому `STRCAT/SUBSTR` реализованы над
INTEGER-массивами ASCII-кодов, а не над упакованными словами. Нативный
CHARACTER-тип в GENERATOR остаётся NEEDS-MADLEN — но для conformance profile он
**не нужен**: язык закрыт lowering-ом.

### 4.2 CABS — уже закрыт, ничего делать не надо

- `CABS((3.0,4.0))` → `5.00` (проба `K_CABS`; `01-f77-standard-matrix.md:282`).
- `CSQRT`, `AIMAG`, `CONJG` — нативные (пробы §6). `CONJG` — системное имя: попытка
  завести `CNJG0` в F77LIBR не попала в каталог, но `CONJG(Z)` разрешается
  встроенной и даёт `(3,-4)` (`10-implementation-libr.md:80-93`).
- **Правило:** сначала проба «имя уже встроено?» (канал D); только при отказе —
  Fortran-обёртка в `0o2310` (канал B). Для CABS достаточно правила 0 (keep).

## 5. Сузить критерий: «F77 conformance profile on FOREX 5.00»

Вместо бинарного «200/200 OK» предлагается зафиксировать **профиль соответствия** —
янную границу того, что FOREX 5.00 обещает, и того, что обещано НЕ будет.

### 5.1 Входит в profile (обещание)

| Группа | Что входит | Механизм |
|---|---|---|
| Ядро X3.9-1978 | лексика, типы I/R/D/C/L, выражения, присваивание, IF/DO/GO TO, подпрограммы, массивы, DATA/COMMON/PARAMETER/EQUIVALENCE | нативно + F77PREP rules 1–20 (P0–P3) |
| Форматированный I/O | `PRINT/WRITE/READ(u,fmt)`; дескрипторы **I, F, E, D, A(w), L, X, /, H**, symbol literal, repeat count, P-scale | таблица 11 `FT*` (канал A), 0 слов |
| List-directed I/O | `PRINT *`, `READ *` → явный `FORMAT` по типам | F77PREP rules 3/4 (P6), 0 слов |
| Позиционирование файла | `REWIND`, `BACKSPACE`, `ENDFILE` | `*REWIN/*BACKS/*ENDFI` в эталоне, 0 слов |
| CHARACTER |Storage/печать + конкатенация/подстрока/сравнение | `INTEGER+nH` + `A6` + F77LIBR `STRCAT/SUBSTR/ISTRCM/STRCMP` (P4), 0 слов |
| Интринзики §15 | нативные + реестр F77LIBR v3 | каналы B/D (P5) |
| Decl-расширения | `SAVE`→COMMON+DATA, `IMPLICIT NONE`→явные объявления, computed GO TO→IF chain | F77PREP rules 9–16 (P3) |
| Верификация | gold 32/32, cross 8/8, real 4/4, negative 9/9, gate 20/20 | `04-verification.md` (P8) |

### 5.2 Явные исключения profile (НЕ обещается)

| Исключение | Почему | Что делать пользователю |
|---|---|---|
| `G`-дескриптор (точная Semantics) | нет entry в таблице `FT*` | `E12.4`/`F12.4` (lowering) |
| `IOSTAT=`, `END=`, `ERR=` (истинный статус/EOF) | очередь карт без EOF-сигнала; транслятор отвергает | sentinel по соглашению с хостом; если нужна точная семантика — отдельный проект правки ввода |
| Неформатированный I/O **на диск** | юниты 1/2/5/6/10/40/45 не активированы | отдельная задача `LUN45`/Э70 в dispak C; синтаксис при этом принимается |
| `OPEN/CLOSE/INQUIRE`, прямой доступ, `ASSIGN`-FORMAT | крупная задача монитора/рантайма | держать в реестре расширений |
| Нативный CHARACTER-typed операнд в GENERATOR | нет `FS*`, проверка типов на `A` | lowering через §4.1 |
| `A` без ширины, `ES/EN/T/TR/BN` | ОТКАЗ/нет entry | `A6/A4`, переписать в поддерживаемые дескрипторы |
| Численная эквивалентность IEEE | 40-битная мантисса, `D` vs `F` | отдельные контрольные векторы (`00-master-plan.md:88`) |
| Побайтовая симтаблица при пересборке | недостижима | opcode-сверка + homeomorphic mapping (уже в критерии) |

### 5.3 Переформулированный критерий приёмки

```
F77_PROFILE_FOREX_5 = (все элементы §5.1.executable подтверждены пробой/gold) and
                      (gold 32/32) and (cross 8/8) and (real 4/4) and
                      (negative 9/9) and (gate 20/20) and
                      (0 FAIL в check-* ) and
                      (исключения §5.2 зафиксированы в реестре, НЕ считаются FAIL)
```

Численно: вместо «200/200» — «≈188–192 элемента profile + 8–12 документированных
исключений». Точный пересчёт делается на этапе P8 по фактическим прогонам; важно, что
**ни одно исключение не требует правки 1024-словных оверлеев**.

## 6. Рекомендация родителю

1. **Отменить эскалацию «P7 = 40–80 чел.-дн. пересборки».** Она верна только для
   «нативного CHARACTER в GENERATOR» и «истинного IOSTAT/EOF» — и то вторая часть
   лежит в рантайме ввода, а не в оверлее.
2. **Переклассифицировать P7:** разбить на
   - **P7a (0 слов, делается сейчас):** E/L///P/G-lowering/unformatted-syntax/
     REWIND-BACKSPACE-ENDFILE — занести в F77PREP как правила, добавить 5–8 gold-проб;
   - **P7b (F77LIBR/PERSO, уже готово):** CHARACTER-lowering, CABS/CONJG-алиасы —
     зафиксировать в profile как закрытые;
   - **P7c (отложить, вне владения):** CHARACTER-typed GENERATOR, true IOSTAT/EOF,
     disk LUN45 — реестр исключений profile.
3. **Заменить критерий «полный F77» на profile §5.** Это убирает искусственный
   FAIL по 8–12 элементам, которые физически не реализуемы без правки монитора,
   и делает P8 достижимым.
4. **Обновить `03-fortran-path.md:416-421`:** утверждения «E не реализуемо lowering»
   и «unformatted-синтаксис отвергается» опровергнуты пробами (`logs/p7_alt_probes.txt`
   §1, §3). (Правка документа — за родителем/владельцем того файла; здесь не трогалась.)
5. **Инструменты:** `tools/compare_opcodes.py` уже присутствует в репозитории —
   замечание `08-madlen-impl.md:94-98` устарело.
