# План 58. Компилятор на базе живого FOREX 4.12

## 0. Постановка (решение пользователя, 21.11.2026)

Новая база — **живой FOREX 4.12** (`F O R E X ... 4.12 ОТ 25.06.85`), который
реально исполняется в C-симуляторе `dispak` через карту:

```
*TRANS:FOREX3*,,411550
```

Эта карта резолвится в `NEWCOMP*` (`ltable%.asm:37-38`), который грузит тело
компилятора с диска 41, зоны `0o1550`. Тело содержит `FOREX3*`, `LO*SYN`,
`LO*GEN` (проверено `besmtool view 2148 --start=01550`).

**Цель:** наш компилятор (разработка плана 57 на Fortran-77, DMS-модули в PERSO)
должен вызываться **таким же образом** — через `*TRANS:...` / `NEWCOMP*`, а не
через `*call` с ручной загрузкой PERSO.

**Почему 4.12, а не 4.13:** 4.13 недOSTупен как исполняемый бинарник в нашем
контуре (только C# `besm6.net` + .NET 8, установка не разрешена). 4.12 —
реально работающий компилятор в dispak, при этом ближе к 4.13 по времени
сборки (25.06.85), чем системный 2.02 (15.07.80).

## 1. Что обязательно изучить

1. **Тексты 4.12:** тела `FOREX3*`, `LO*SYN`, `LO*GEN` в зоне `0o1550` диска
   `/usr/local/share/besm6/2148`; их DMS-шапки, точки входа, внешние SUBP,
   таблицы констант, формат загрузки.
2. **Сравнение с нашими:** `src/LO_SYN.mad`, `src/LO_GEN.mad`,
   `build/LO_{SYN,GEN}.words`, `build/CORE_ROOT.words`, `src/FOREX_CORE.mad`,
   `include/FOREX_ROOT.mad`. Наши реконструкции сделаны из дампов `monsys.9`
   (надпись `FOREX 412`) —可能是 тот же 4.12, требуется побайтовая сверка.
3. **Вспомогательные программы:** `FORMAT` (`FT*002/003/571/621`),
   `FORTLIBR` (`PRINT8`, `WRITLIBR`), `DATAPR*`, `OCTTDEC`, `INSLIB`,
   `LIBREFER` — где лежат, какие интерфейсы, как вызываются 4.12,
   версионно-зависимые отличия от наших `XDATAPR`, `OCTTDE*`, PERSO-модулей.
4. **Механизм `NEWCOMP*`:** как интерпретирует параметр `41/1550`, какой
   формат тела ожидает (DMS? сырой field-0 дамп?), какие LINK/COMMON
   ячейки использует, можно ли подсунуть своё тело в другой зоне.

## 4. Текущее состояние

- M0-M3 **DONE** (коммиты `c4eb2e0`, `3338d2d`, `c4eb2e0`, `5cda8ea`, `961cdf9`).
- **M4 (6d5e413):** наш DMS-модуль `(N2MRK, 20 слов, cmd=0o11)` упакован в каталог
  NEWCOMP* зоны 1744/1745. f0 дескриптора обязан быть `0o1760` (идентификатор
  главного раздела), с нашим `cmd=0o11` → `НЕТ РАЗДЕЛА`. A/B: подмена тела 1745
  нашим → `Interrupt 00707 atx`, восстановление → `HELLO 412` (LOAD PROOF).
  Маркер НЕ печатается: NEWCOMP* — загрузчик специфического объектного формата
  4.12, а не универсальный DMS. Нужно: obj-эмиттер N3 плана 57 с `cmd=0o1760`
  и корректными LINK-полями, либо компиляция нашего маркера самим 4.12.
- **Контракт NEWCOMP* (M3, EXPERIMENT):** `41/1550` — упакованное слово `*70
  0o0010030000411550` (диск 41 / зона 0o1550). NEWCOMP* читает **одну зону** —
  каталог пар `TEXT-имя / дескриптор` (например `FOREX3* / 0o400402757101760`);
  DMS-тело лежит **в следующей зоне N+1**. Имя из `*TRANS` произвольное:
  переименование записи в `OURCOM*` + `*TRANS:OURCOM*` грузит тот же компилятор.
  Порча дескриптора/тела ломает загрузку (`НЕТ РАЗДЕЛА`, `Interrupt 00707 utm`).
  IMPLICATION: чтобы наш компилятор вызывался как 4.12, нужно положить его DMS-тело
  в зону N+1 и сделать каталог в зоне N на диске с нашим именем.
- Живой 4.12 воспроизведён: `tests/plan-f77/t412/run-4.12.sh`, коммит `1911199`.
- План 57 N0-N3 завершены; N4-N5 (полный компилятор, A/B) впереди.
- Ключевой риск M3/M4: `NEWCOMP*` может ожидать сырой field-0 дамп, а не
  DMS-модуль; тогда придётся写的 obj-эмиттер (N3 плана 57) адаптировать под
  формат 4.12.
