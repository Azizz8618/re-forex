G отсутствует в таблице 11 `FT*` (`src/lib21/FORMAT.mad:35-99`) — единственный
реальный отказ среди edit-дескрипторов.

**Правило R13 (точное, для волны 2):**

| F77-конструкция | Тип переменной | Lowered FORMAT | Проба |
|---|---|---|---|
| `G12.4` | REAL | `E12.4` (предпочтительно) или `F12.4` | `3.5000+00` / `3.5000` |
| `G22.15` | DOUBLE PRECISION | `D22.15` | `3.500000000000000+000` |
| `G12.4` | COMPLEX | `2` × `E12.4` (по одному на Re/Im) | `3.5000+00   4.5000+00` |
| `G w.d` | LOGICAL | `L1` | см. J15 |
| `G w.d` | INTEGER | `Iw` | по типу |

Алгоритм F77PREP: заменить в `FORMAT` токен `G` на `E` (REAL/COMPLEX), `D` (DP),
`L` (LOGICAL), `I` (INTEGER); ширину `w` и точность `d` сохранить. Для COMPLEX
дублировать дескриптор. Повторный счётчик (`2G12.4`) сохраняется.

Обоснование допустимости: форма вывода G в X3.9-1978 — implementation-defined
(автовыбор F/E по порядку числа); профиль FOREХ 5.00 фиксирует конкретный
выбор E/D/F, что не нарушает conformance. Точная G-семантика (автовыбор) —
P7c/NEEDS-MADLEN, в профиль не входит.

## 4. List-directed и END=/ERR=: что lowering-ится сегодня и правила волны 2

### 4.1 Исходный отказ (нативные формы)
| Форма | Диагностика |
|---|---|
| `PRINT *,N` | `ОШИБКА В ССЫЛКЕ НА ФОРМАТ` (`ERR 04324`) |
| `READ *,X` | `ОШИБКА В ССЫЛКЕ НА ФОРМАТ`; `ЗНАЧЕН. X НЕ ОПРЕДЕЛЕНО` |
| `READ(5,10,END=99) X` | `ОТСУТСТВ ЗАКРЫВ СКОБКА` (`ERR 04325`) |
| `READ(5,10,ERR=99) X` | та же ошибка |
| `READ(*,*,END=99) X` | `НЕДОПУСТИМ СИМВОЛ * В ВЫРАЖ` (двойной отказ: `*` + `END=`) |

### 4.2 Работающие lowering-ы (эти deck/gold сданы)
```
PRINT *,N,X,L        -> PRINT 9000,N,X,L ; 9000 FORMAT(1X,I10,F12.4,L1)
READ *,A,N           -> READ 9500,A,N   ; 9500 FORMAT(F12.4,I10)
READ(*,*,END=99) X   -> READ 9500,X
                        IF (X .EQ. -999999.) GO TO 99
READ(*,*,ERR=99) X   -> READ 9500,X
                        IF (X .EQ. -888888.) GO TO 99
```
`FORMAT` для READ — **без `1X`** (иначе теряется первый символ числа).
Дескрипторы по первой букве имени: `I…N`→`I10`, REAL→`F12.4`,
DP→`D22.15`, LOGICAL→`L1`, CHARACTER (lowering `INTEGER`+`nH`)→`A6/A4`.

### 4.3 Точные правила волны 2 (sentinel вместо потери семантики)

**Проблема сегодняшней rule 4 (v1):** `READ(*,*,END=LL) var` → просто `READ … var`,
ссылка `END=LL` **удаляется**, метка `LL` остаётся — ветвление по EOF теряется
(`01-f77-standard-matrix.md:211`). Это и есть «потеря семантики».

**R10 (list-directed READ):** как в §4.2; вместо `*` подставляется динамическая
метка `9500+seq`; FORMAT генерируется по типам списка; юнит не указывается.

**R11-END (замена rule 4):**
```
ВХОД:  READ(*,*,END=LL) v1,…,vk     (равно READ(5,fmt,END=LL) — при рабочем юните)
ВЫХОД: READ <fmt>,v1,…,vk
       IF (v1 .EQ. -999999.) GO TO LL
```
**R11-ERR:**
```
ВХОД:  READ(*,*,ERR=LL) v1,…,vk
ВЫХОД: READ <fmt>,v1,…,vk
       IF (v1 .EQ. -888888.) GO TO LL
```

**Обязательства HOST (без них lowering не работает):**
1. дописать последнюю карту-ловушку со сентинелом в первом поле (`-999999.`
   для REAL, `-999999` для INTEGER, `(-999999.,-999999.)` для COMPLEX);
2. выбрать значение, не коллидирующее с данными; при нескольких READ подставлять
   отдельную сентинную карту перед каждым;
3. проверять только первую переменную (это оговорка профиля, не полная F77-семантика);
4. для END=/ERR= в одном READ использовать разные сентиналы и две проверки.

**Оговорка (обязательна в документации):** это **эмуляция EOF/ошибки по значению**,
а не настоящий `IOSTAT`. Истинный возврат статуса требует EOF-сигнала в очереди
карт и правки рантайма ввода (P7c) — вне владения этой волны. IOSTAT= пока не
lowering-ится вообще (`11-p7-alternatives.md:27-37`).

## 6. Почему J25/J26/J27 — OK, а J2/J4/J23 — нет

Позиционирующие операторы `*REWIN/*BACKS/*ENDFI` (`src/LO_GEN.mad:508-531`)
не передают данные через LUN-канал, поэтому на юнитах 1 и 54 они исполняются
чисто: ` РОS ОК`. На 40/45 — `НЕТ КАНАЛА`, на 54 для REWIND/BACKSPACE —
`ЗАПРЕЩЕННЫЙ РЕЖИМ`; профиль фиксирует рабочие юниты (1 для REWIND/BACKSPACE,
54 для ENDFILE). Передачи данных (J2/J4/J23) требуют реального канала —
поэтому там PARTIAL/NO. Важное уточнение к документу 11: «REWIND 10 → ОШ.В
ИНФ.СЛ.ЭКСТ» — это ошибка юнита 10, а не трансляции; на юните 1 тот же
