# 36 — Прогон колоды в полной ОС ДИСПАК под SIMH без КРАБа

## Назначение

`tools/run_besm6_deck.py` автоматизирует штатный пакетный путь:

```
колода перфокарт/перфоленты → vu0 → ОС ДИСПАК → исполнение → prn0 (АЦПУ) → разбор выдачи
```

Система КРАБ **не участвует**: колода подаётся непосредственно на устройство ввода
`vu0`, сигнал начала чтения FS8 формируется командами симулятора, результат
читается из **папки `simh/BESM6/ACPU/`**: штатно `prn0 → output.txt`,
`prn1 → output1.txt`. Именно туда ОС печатает (`НЕLLО WОRLD`, `КОНЕЦ ЗАДАЧИ`).
Перехватывать prn0/prn1 временными файлами НЕЛЬЗЯ — результат уходит мимо и
кажется, что вывода нет (эта ошибка была допущена и исправлена).

Источники механизма:
- `simh/BESM6/docs/ВВОД_АНАЛИЗ.md` §§3.2, 3.3, 6, 9.2, 9.3;
- `re-dispak/docs/DISPAK_AGENT.md` §6 — директивы operator-level `ДАЙ A0/A1`,
  `ПОВ`, `СБО`, `СБВ` и буфер вывода АЦПУ;
- `re-dispak/acpu_analyze.pl` — штатный разбор подвалов АЦПУ.

## Правила чтения консоли

Источник истины о состоянии ОС — **живая панель сессии**, снятая командой
`tmux capture-pane -p -S -<history> -t <session>` (как `pane()` в
`tools/run_besm6_deck.py:69-70`). Для изолированных прогонов `TMUX_TMPDIR`
задаётся перед **каждым** вызовом tmux. Команды подаются через `tmux send-keys`
затем `send-keys Enter`: `tmux pipe-buffer` в сборке 3.7b отсутствует.
Сохранённые на диск pane-дампы и `console.log` — только подсобный материал,
по ним нельзя делать вывод о текущем состоянии машины.

**Надёжный маркер загрузки (22.11.2026, SIMH):** ожидать `CM1П` как признак
готовности ОС **нельзя** — в живой панели SIMH появляется строка даты/времени
`ДATA:DD.MM.YY BPEMЯ:HH.MM.SS` (гомоглиф-варианты `DATA:`/`ДATA:`), а
`tools/run_besm6_deck.py` при `--timeout 90/180` падает `TimeoutError: не
дождались промпт ОС`, хотя машина уже давно загружена и принимает команды.
Правильный порядок для изолированного прогона: дождаться `ДATA:` в
`capture-pane`, сразу подать колоду через `send-keys` (`at vu0 …`, `d 6 1`,
`d 5 10`, `set cpu req`, `go`), завершение брать из файла АЦПУ и `КОНЕЦ ЗАДАЧИ`
в панели, **не** ожидая regex `sim>` или `CM1П`. Этот драйвер не правит
`tools/run_besm6_deck.py` (в нём есть пользовательская правка) — обход делает
внешний скрипт.

## Что делает программа

1. Создаёт рабочий каталог в `/var/tmp` (в `/tmp` мало места), пишет колоду.
2. Берёт `simh/BESM6/OSZAGR/dispak.ini` как основу и:
   - **не** подключает `vu0` при загрузке (иначе SIMH может обнулить файл колоды);
   - перенаправляет `prn0` в рабочий файл АЦПУ.
3. Поднимает SIMH в отдельной tmux-сессии, ждёт промпт `CM1П:`.
4. Подаёт операторские директивы `ДАЙ А0` / `ДАЙ А1` — **обязательно**: без них
   АЦПУ не в конфигурации системы и выдача не печатается (сообщение
   `ОСВОБ БУФ.ВЫВ` в `DISPAK_AGENT.md §6`). `СБО` без параметров НЕ применять.
5. Останавливает CPU (`Ctrl+G`), подаёт колоду:
   `at vu0 <файл>`, `d 6 1`, `d 5 10`, `set cpu req`, `go`.
6. Ждёт `КОНЕЦ ЗАДАЧИ` / `КЗ(...)` / `СБО`, даёт стечь асинхронной печати.
7. Печатает сырую распечатку АЦПУ **и** её разбор через `acpu_analyze.pl`
   (`--summary`, `--jobs`, `--errors`).

### ШИФР — критично

`ШИФР` в паспорте должен быть **зарегистрирован в списках ОС**. С незарегистрированным
шифром задача не исполняется: в распечатке появляется `З ШИФР` («пользователь с данным
шифром не числится в списках операционной системы», `Dispak-programmer-guide.md §8.1.1`),
затем `ВВЕД … ШИФР` и `ОЗ(<N>)<ШИФР>` (`ОШИБКА ЗАДАЧИ`), а в консоли `СБО,ВВЕДИ ПО ИНС`.

Рабочий шифр в этой ОС — `410300` (в распечатке `*ИЛЬИН А.П.*`, задача доходит до
`КОНЕЦ ЗАДАЧИ`). Шифры из документации (`123456`, `190200000000`, `412201`) и системный
`419999` в этой сборке не проходят. По умолчанию в `--hello` используется `410300`.
Не путать `ОЗ(...)` (ошибка задачи) с `КЗ(...)` (штатное завершение).

Параметры: `--hello` — эталонная колода HELLO WORLD из `ВВОД_АНАЛИЗ.md §9.2`;
`--deck` — готовая колода; `--source` — Fortran-исходник (из него строится колода);
`--cipher` — уникальный шифр задачи (не `419999`, это системный); `--session` —
имя tmux-сессии; `--keep` — не убивать сессию после прогона.

## Как разбирать выдачу АЦПУ

Распечатка — не плоский текст, а последовательность «подвалов» задач. Штатный
разбор (`re-dispak/acpu_analyze.pl`):

- начало подвала — строка `КОНЕЦ ЗАДАЧИ` или `СБО,...`;
- конец — строка из `*` или `555555...` (абсолютные маркеры, `ВВОД_АНАЛИЗ.md §6.1`);
- внутри: регистры (`АП Э РК И1..И17 КРА ЗПСЧ`), дата/версия ОС, времена
  ввода/решения, ресурсы и список заданий;
- `СБО,ВВЕДИ ПО ИНС` — аварийный останов (неверный адрес, защита, деление на ноль);
- успешная трансляция в листинге: `ЧИСЛО ОШИБОК=0. МАКС СЕРЬЕЗН=0.`

Поэтому результат прогона определяется НЕ grep'ом по тексту, а разбором подвала
(задание, ошибки, регистры). Это важно: пустой `prn0` может значить либо
«задача с ТЕЛЕ» (`ВВОД_АНАЛИЗ.md §3.6`), либо «АЦПУ не подключён» (`ДАЙ A0/A1`).

## Оговорки

- Программа — транспорт колоды и разбор выдачи; корректность самой
  Fortran-программы и её компиляции она не гарантирует (это видно по подвалу).
- Символ `^` в колодах — возведение в степень; `*` — не комментарий.
- Все пути абсолютные: SIMH не раскрывает `~`.
