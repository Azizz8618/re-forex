## 1. Архитектура

1. **Э63/Э70 issuing — только в МАДЛЕН**: 8 микропроцедур `ZE01, ZE12, ZE30, ZE02,
   ZE07, ZE31, ZE70W, ZE70R` в PERSO `0o2320`.
2. **Верхний уровень — 5 ФОРТРАН-процедур** (там же, `*forex`). FOREX сам формирует
   соглашение «аргументы по адресу», обходя блокер F2 со скалярами по значению.
3. **FORTRAN ↔ MADLEN** — через COMMON /FILMAP/: Fortran пишет параметры в scratch,
   вызывает микропроцедуру без аргументов, читает M16/результат из того же блока.
4. **Адрес /FILMAP/ в МАДЛЕН захардкожен** (MADLEN не умеет внешних символов FOREX):
   для полной деки `*FILMAP* С 03033`, scratch FM(248)=`03422`, FM(249)=`03423`;
   для контрольной деки база `01347` → `01736`/`01737`. Это prototype-ограничение:
   смена длины главной программы требует пересборки движков.

Имена `Z...` уникальны (`FOPEN` и т.п. заняты в lib21).

## 2. Формат COMMON /FILMAP/ и ISTAT

```
      INTEGER FM(320)
      COMMON /FILMAP/ FM
```

16 слотов × 15 слов, `B = 1 + 15*(s-1)`, s=0..15:
`B+0..1 NAME1/NAME2` (12 ГОСТ-байт; `B+1=0` → слот свободен), `B+2 LUN`,
`B+3 ARU` (051B), `B+4 OWNER`, `B+5 MODE`, `B+6 NZON`, `B+7 POS`,
`B+8 EOF`, `B+9 ISTAT`, `B+10 RAW`, `B+11..14` резерв.
Scratch: FM(241/242)=NM1/NM2, FM(244)=NZ, FM(245..247)=CW/BUFADR/NARG,
FM(248)=ARU/контрольное слово, **FM(249)=IRET (сырой M16)**, FM(250)=OPER,
**FM(257..320) = область данных BUF** (Fortran-обёртка ←→ МАДЛЕН ←→ `0o10000`).
Адрес `FM(257)` подставляется в МАДЛЕН числом при сборке (`build/mklib.py`):
для базы `01347` это `01747`, для базы `01217` — `01617`.

Инварианты: `ARU≠0` ⟺ Э63 12 выполнен; `EOF=1` ⟺ `POS ≥ NZON`; поиск слота по LUN.

ISTAT (эмулируемый, не системный X3.9): M16 `0→0`, `1→1`, `2→2`, `4→3`, `5→4`,
`6→5`, `010→6`, `031→7`, `012→8`, `013→9`, `015→10`, `022→11`, `023→12`,
`024→13`, `027→14`, `032→15`; **−1 = синтетический EOF** по позиции.
Сырой M16 дублируется в FM(249).

## 5. Точные рабочие константы (исправленный рецепт)

| Что | Значение | Почему |
|---|---|---|
| ИС 01 create | `01510000 00000010` | `op_create()` игнорирует поле LUN — работает как у F2 |
| ИС 12 order | `12000000 00000010` | LUN **обязан быть 0**, иначе `resolve_area()` ищет по юниту |

## 6. Первопричина прежнего сбоя (разбор)

1. F2-ИС `12510000` имеет `W48_37 = 051`. `arfa.c:660 resolve_area()` сначала
   проверяет это поле: ненулевое значение → поиск `unit_area[u]`; дозаказ ещё не
   связывал LUN → `ARF_NO_NAME`. `op_order` возвращал ошибку, `disks[051]` оставался
   пустым, а Э70 получал `E_CWERR` (`extra.c:2245`, нет диска на LUN).
   **Исправление: обнулить разряды 48–37 в ИС 02/07/12/31** (`12510000`→`12000000`).
2. Дополнительно: `op_create` игнорирует LUN-поле, поэтому Э63 01 у F2 работал —
   это маскировало ошибку и породило ложный вывод «E_CWERR нет».
3. Э63 31 без предшествующего Э63 30В → фатальный `авост` («освобождение без
   захвата»). Добавлен `ZE30`.
4. CW `00001010 00510000` декодируется как WR; для RD нужно `00101000 00510000`
   (проверено перебором 10 вариантов левой половины, `rdbrute.sh`).
5. Побочные ловушки сборки МАДЛЕН: `,NAME,` только первым оператором секции,
   `UTM` требует символа-константы, а не литерала, `=:` — ровно 8 окт. цифр.

## 8. Остаточные оговорки (честно)

- Переносятся **до 8 слов** BUF за один Э70-вызов (раскрученный копирователь в МАДЛЕН);
  при `N>8` передаётся только первая восьмёрка — profile-ограничение прототипа.
- Адрес FILMAP (и FM(257)) в МАДЛЕН захардкожен и пересчитывается `build/mklib.py`
  по базе из `*full list` деки (см. §1 п.4).
- `ACCESS/RECL/FORM` — profile-кэш, АРФА работает зонами; уровень B ФОРЭКС по-прежнему
  блокирует стандартный `WRITE(41,…)` (doc 17/31).
