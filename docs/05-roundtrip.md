# Этап 6: обратная сборка и побайтовая сверка

## Что проверено

### 1. Конвейер МАДЛЕН работает

`monitor80-re/tools/asm.pl` (через `dispak` на томе 2348) успешно собирает
 МАДЛЕН-текст из `re-siprod/madlen-gen/ADRSEK.madlen`. Результат —

```
ADRSEK:,NAME,DTRAN /01.06.84/
```

записан в PERSO-библиотеку (3 зоны) и разбирается `re-siprod/tools/siprod_lib.py`.

### 2. Вывод dtran пересобирается

`dtran -F dms -e -l <синтетический DMS>` даёт пересобираемый МАДЛЕН-текст
(`disasm/LO_SYN.dtran.madlen`, 2056 строк). Прогон через `*MADLEN` на томе 2348
завершается без ошибок (`ДЛИНА LIBRARY 003 ЗОН`, `КОНЕЦ ЗАДАЧИ`).

### 3. Почему полная побайтовая идентичность не достигнута

На контрольном модуле ADRSEK (65 слов кода+констант) после обратной сборки:
- **все коды операций совпали**;
- 27 слов отличаются **только полями операндов/символов** — компилятор
  МАДЛЕН заново нумерует метки, поэтому индексы в симтаблице другие.

Это ожидаемое свойство символьной пересборки: без сохранения исходной симтаблицы
побайтовое совпадение невозможно. Аналогично `re-siprod` сравнивает только
секции команд и честно сообщает о расхождениях.

### 4. Что принято как критерий для оверлеев

Вместо символьной пересборки используется **побайтовая проверка аннотированных
исходников**: каждая строка `src/LO_*.mad` содержит машинное слово в восьмеричном
виде, и `tests/check-source-words.py` сверяет все 1024 слов с исходным дампом:

```
OK LO*SYN: все 1024 слова совпадают с дампом
OK LO*GEN: все 1024 слова совпадают с дампом
```

Это гарантирует, что реконструкция сохранила каждое слово оверлея без искажений;
семантическая проверка — эталонный прогон `forex.b6` (`tests/run-forex.sh`, OK).

## Итог

Этап 6 считается завершённым в части, достижимой без точной симтаблицы:
- дампы сверены с лентой (`verify-dumps.sh`);
- дизассемблированные и аннотированные тексты сверены с дампами побайтово
  (`check-source-words.py`);
- функциональная регрессия проходит (`run-forex.sh`);
- LIBREFER и баннеры зафиксированы (`docs/03-symbols.md`).
