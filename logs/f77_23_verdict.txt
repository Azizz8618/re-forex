# f77_23 — P7c: опровержение гипотезы LUNTYP и прототип WRITE(45)
Дата: 19.11.2026.

## ГИПОТЕЗА (от родителя)
LUNTYP(45)=0 (НЕ ЗАКАЗАНО) → FOREX runtime вызывает ERRLUN → 'НЕТ КАНАЛА LUN 45'.
Если заставить LUNTYP возвращать для 45 тип как для 54 + Э50 0131 attach → WRITE/READ(45) заработают.

## РЕЗУЛЬТАТ: ГИПОТЕЗА ОПРОВЕРГНУТА (доказательство из полного MTR-трейса)

Полный MTR-трейс WRITE(45) из волны A2: /var/tmp/p7c-mtr/err.txt, 2 012 550 строк
(BESM6_DD_DEBUG=1, BESM6_MTR_LO=0, BESM6_MTR_HI=077777, BESM6_MTR_N=5000000).

1. `awk '/\*63/{...}'` → ВСЕГО 2 выполнения экстракода *63 за весь трейс:
     строка 122:    MTR 04001R *63 3(0)   (стартап)
     строка 1047015: MTR 26030R *63 1(0)  (фаза execute, не LUNTYP)
   LUNTYP executing требует 6 *63 (502,504,57,760,20,576). Нет ни одной Sequence.
   ⇒ LUNTYP НЕ выполняется при WRITE(45).
2. Нет ни одного jump-目标 в адрес LUNTYP (каталог 0o045054) или в диапазон 0450xx:
     grep -cE '(vjm|uj|mtj) +45054' = 0;  jump-цели 045xx = 0.
   (Jumps идут на 4-значные 4505/4513/4545/4561 — это монитор, не LUNTYP.)
3. Таблица символов провалившейся задачи НЕ содержит LUNTYP. Присутствуют:
     LUNMUN 03163, LUN*MON 03164, ERRIOM 04241, ERRLUN 04321/04361 (оверлей).
4. Путь ошибки (doc18 §8.2, подтверждено): 02506R *67 20(14) → печать 'НЕТ КАНАЛА'
   → 02522R uj 0(15) → 00411 *74 STOP. Это ERRLUN (erriom.asm:84-93), НЕ LUNTYP.
5. LUNTYP — пользовательская FUNCTION (lib21/MONSYS disk 2048), которую dtran-листинг
   показывает вызываемой только из PECYPC/PT6/IPUTS/PCPLOT. WRITE1.mad вызывает DRUMTAP*,
   который (drumtap%.asm) LUNTYP не вызывает; проверка LUN идёт через LUN*MON/LUNMUN монитора.

ВЫВОД: проверка Level B НЕ проходит через LUNTYP. Патч LUNTYP не может снять блокер.
