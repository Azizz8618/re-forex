=== 3. ГДЕ СИГНАЛ ТЕРЯЕТСЯ (монитор/рантайм) ===
monitor80-re/permanent/monread%.asm (стандартная программа МС ДУБНА):
  34/54  M15,*70,1            — чтение карты Э70 в MONCARD* (LUN 45)
  55-73  разбор карты: M8,XTA MONCARD*-1 / AEX 57B / AAX 60B / U1A NO*END
  99-104 вMOНИTOP: ITS M6 / M13,VTM,STOP* / UJ,LUN*MON
  119    TNO*END: ISO,12НNO *END FILE
  => при EOF/не-текстовой карте monread% НЕ возвращает статус, а переходит
     в монитор на STOP* — задача завершается (*END FILE / КОНЕЦ ЗАДАЧИ).
monitor80-re/permanent/iocont%.asm:
  1-5    IOCONT* — «пользовательская процедура для продолжения ввода-вывода»
  56     STOP*   : , SUBP,     (импорт)
  163    IOEND*  : , ENTRY,    — вход по окончании записи/формата
  167-180 нет ячейки статуса, нет ветвления по EOF
re-forex/src/lib21/LFSCAN.mad:89-94: IOCONT*/IOEND* объявлены SUBP (внешние).
=> Транслятор ФОРЭКС 2.02 НЕ генерирует END=/ERR=/IOSTAT=: нативная форма
   READ(5,10,END=99) даёт «ОТСУТСТВ ЗАКРЫВ СКОБКА» (15-io.md §4.1).

ИТОГО: FIFO карт → Э60 (reg[016]=0) → monread% → STOP* (конец задачи).
Между reg[016]=0 и Fortran-программой НЕТ ни ячейки статуса, ни ветки.
Сигнал «теряется» на границе monread%→рантайм: он превращается в аварийное
( но rc=0 ) завершение задачи, а не в возврат из READ.
