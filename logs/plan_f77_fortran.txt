--- КЛЮЧЕВОЙ ФАКТ: ПРОБЫ Ф77 УЖЕ ЕСТЬ, НО ИХ КЛАССИФИКАЦИЯ ОШИБОЧНА ---
tests/plan-f77/probe.sh запускал системный ФОРЭКС 2.02 (лен 41(2048), *forex)
на 15 конструкциях и писал logs/plan_f77_probes.txt. Лог помечает OK/FAIL
только по grep 'ERROR|ОШИБКА|ОШ. ТРАНСЛЯТОРА|НЕДОПУСТИМ|UNRECOGNIZED' и
наличию 'КОНЕЦ ЗАДАЧИ'. Проверка выявила ошибку классификации: ФОРЭКС
печатает диагностику вида 'ERR 03106 ПК 2' и 'АТТ 00305 ПК 4', которые
не ловились фильтром. Прямой подсчёт строк ERR/АТТ по out.txt:

  BASE         errlines=0   -> OK
  DOLOOP       errlines=0   -> OK
  BLOCKIF      errlines=0   -> OK  (IF/THEN/ELSE/ENDIF компилируется!)
  DOUBLPR      errlines=0   -> OK  (DOUBLE PRECISION, 1.0D0, SNGL)
  COMPLEX      errlines=0   -> OK  (COMPLEX Z, Z=(1.0,2.0))
  DATAST       errlines=0   -> OK
  PARAMETER    errlines=0   -> OK
  INTRINSIC    errlines=0   -> OK  (SQRT, ABS)
  EXTERNAL     errlines=0   -> OK  (необъявленная FOO(2.0) -> внешняя ссылка)
  LOGICAL      errlines=0   -> OK  (LOGICAL, .TRUE., IF(L) GOTO)
  CHARSTAR     errlines=6   -> FAIL (но не из-за типа CHARACTER:
                                   'S="ABCDE"' — двойные кавычки не
                                   поддерживаются: 'ТИП ОП-ДА НЕ СООТВЕТ
                                   ОПЕРАЦ'; FORMAT(1X,A) ->
                                   'ДОЛЖНА БЫТЬ ЦИФРА', нужен A4.
                                   Лог ошибочно отнёс это к runtime.)
  LISTDIR      errlines=2   -> FAIL 'ОШИБКА В ССЫЛКЕ НА ФОРМАТ' (PRINT *)
  IMPLICIT     errlines=3   -> FAIL 'НЕДОПУСТИМ КЛЮЧ СЛОВО'
  ENDREAD      errlines=2   -> FAIL 'НЕДОПУСТИМ СИМВОЛ * В ВЫРАЖ' (END=)
  SAVE         errlines=2   -> FAIL 'НЕДОПУСТИМ КЛЮЧ СЛОВО'

Вывод: посылка задания «END IF -> labeled IF+GO TO, COMPLEX -> 2 REAL,
DOUBLE PRECISION -> REAL» уже не соответствует реальности 2.02: эти формы
компилируются. Настоящие пробелы: list-directed I/O, IMPLICIT NONE, SAVE,
END=/ERR-метки, двойные кавычки, дескриптор A без ширины, плюс СЕМАНТИЧЕСКИЕ
ограничения (точность DP, COMPLEX-intrinsics, CHARACTER-substring) — их надо
проверять численным тестом, а не фактом компиляции. Это отражено в документе.

--- ИНФРАСТРУКТУРА (docs/14,15,16 и тесты) ---
PERSO: рабочая копия 2348, зона 0o2300 = 1216 dec, образ
build/FOREX_PERSO_2300.bin, 5 зон, 9 каталожных модулей:
FOREX* LO*SYN LO*GEN FORMAT FORTLIBR DATAPR* OCTTDE* GIV/PG TAK/PG.
Свободный интервал 0o2300..0o2477 (128 зон), первая занятая — 0o2500.
Загрузка: *perso:602300, дозапись/перекрытие: *perso:...,CONT.
Имена каталога — 8 TEXT-символов, но МАДЛЕН различает первые 6 знаков.
Вызов ФОРЭКСа: *forex, конец исходника — *execute, конец дека — *end file.
Полный листинг: *full list, подавление: *no list.
Формат I/O: FORMAT диспетчеризует 11 точек FT*571..FT*003 через LINK
0o74001..0o74013 и ячейки 0o77xxx; FORTLIBR экспортирует PRINT8/WRITLIBR.
OCTTDE* — псевдоним во избежание конфликта с системным OCTTDEC (docs/16).

--- МЕХАНИЗМ ДВУХ ПРОХОДОВ (проверено / требует EXPERIMENT) ---
Проверено: один dispak-запуск = один цикл *forex ... *execute; исходник
читается из карт до *execute. Поэтому «препроцессор -> FOREX -> EXECUTE»
естественно раскладывается в ДВА запуска dispak (две деки), склеенные
host-скриптом. Возможность включения второго прохода: '`N' подставляет
данные из punch.inN (возможность симулятора dispak, whetstone.b6:26-28) —
требует проверки на текстовых строках. Надёжный fallback — вывод
препроцессора на печать с последующей экстракцией по маркеру.
Назначение Fortran-юнитов на дисковый файл/карты в ДИСПАК не проверено —
помечено как обязательный короткий эксперимент.
